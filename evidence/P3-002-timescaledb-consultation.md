## 1. Verdict: Migration WILL FAIL as currently designed

The autogenerated migration + `patch-migration.py` **will fail** on `create_hypertable()` for all 4 hypertables. The failure is deterministic and blocks the entire `upgrade()`.

### Root Cause

TimescaleDB 2.x enforces a hard constraint:

> **"All unique indexes (including PRIMARY KEY) on a hypertable MUST include the time/partitioning column."**

Source: [TimescaleDB docs — Create a Hypertable](https://docs.timescale.com/use-timescale/latest/hypertables/create/)

Current `models.py` defines all 4 hypertables as:

```python
class Episodes(Base):
    id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True), primary_key=True,           # <-- PK on id ONLY
        server_default=text("gen_random_uuid()"),
    )
    started_at: Mapped[datetime] = mapped_column(       # <-- partition column NOT in PK
        TIMESTAMP(timezone=True), nullable=False
    )
    # ...
```

When `patch-migration.py` calls:

```python
op.execute("SELECT create_hypertable('memory.episodes', 'started_at', ...)")
```

TimescaleDB errors with:

```
ERROR: cannot create a unique index without the partitioning column
DETAIL: …the PRIMARY KEY constraint on "id" is not valid for hypertables
```

### Affected Tables & Columns

| Table | Partition Key | Current PK | Will Fail? |
|---|---|---|---|
| `memory.episodes` | `started_at` | `id` UUID | **YES** |
| `surveillance.events` | `occurred_at` | `id` UUID | **YES** |
| `financial.transactions` | `occurred_at` | `id` UUID | **YES** |
| `audit.audit_trail` | `occurred_at` | `id` UUID | **YES** |

## 2. Solution Options

### Option A (RECOMMENDED): Composite Primary Key

Change the PK on all 4 hypertable models to `(id, time_column)`.

**Model change:**
```python
class Episodes(Base):
    __tablename__ = "episodes"
    __table_args__ = (
        PrimaryKeyConstraint("id", "started_at", name="pk_episodes"),
        {"schema": "memory"},
    )
    id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        server_default=text("gen_random_uuid()"),
    )
    started_at: Mapped[datetime] = mapped_column(
        TIMESTAMP(timezone=True), nullable=False
    )
    # ... rest unchanged
```

**FK impact — must remove 3 FK constraints referencing hypertables:**

| FK Column | Table | Referenced Hypertable | Action |
|---|---|---|---|
| `source_episode` | `memory.semantic_facts` | `memory.episodes(id)` | Remove FK constraint, keep column |
| `episode_id` | `memory.emotional_events` | `memory.episodes(id)` | Remove FK constraint, keep column |
| `audit_event_id` | `audit.evidence_register` | `audit.audit_trail(id)` | Remove FK constraint, keep column |

**Why this is safe:** UUIDs generated by `gen_random_uuid()` are globally unique. The composite PK `(id, started_at)` is strictly more unique. Application-level integrity replaces DB-enforced FK here because TimescaleDB makes FK enforcement to hypertables impractical.

**Add non-unique B-tree index on `id` column alone** for fast FK lookups:
```sql
CREATE INDEX CONCURRENTLY ix_episodes_id ON memory.episodes (id);
```

**Pros:**
- Minimal model changes (only 4 tables + 3 FK removals)
- TimescaleDB constraint satisfied
- No data migration needed (existing schemas are empty)
- Clear intent: TimescaleDB requirement met

**Cons:**
- Lose DB-level FK enforcement to hypertables
- ORMs need app-level integrity checks for cross-table references

---

### Option B: No PK + Unique Constraint (alternative)

```python
class Episodes(Base):
    __tablename__ = "episodes"
    __table_args__ = (
        UniqueConstraint("id", "started_at", name="uq_episodes_id_started_at"),
        {"schema": "memory"},
    )
    # id is NOT primary_key=True
    id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True),
        nullable=False,
        server_default=text("gen_random_uuid()"),
    )
```

**Not recommended.** Same FK impact as Option A but weaker semantics — no explicit PK, and many ORMs require a PK definition.

---

### Option C: Keep `id` as PK + Skip TimescaleDB

Don't call `create_hypertable`. Treat all tables as regular PostgreSQL tables.

**Not recommended.** This abandons the ADR-approved TimescaleDB partition benefits for high-volume tables (surveillance events, audit trail, transactions).

## 4. Rollback / Downgrade Safety

### Current downgrade in patch-migration.py is INCOMPLETE

Current code:
```python
op.execute("SELECT remove_compression_policy('memory.episodes', if_exists => TRUE)")
op.execute("SELECT remove_retention_policy('memory.episodes', if_exists => TRUE)")
```

This **only removes policies** — it does NOT convert the hypertable back to a regular table. The tables remain as hypertables after downgrade.

### Correct downgrade requires:

```python
# 1. Remove retention/compression policies first
op.execute("SELECT remove_compression_policy('memory.episodes', if_exists => TRUE)")
op.execute("SELECT remove_retention_policy('memory.episodes', if_exists => TRUE)")

# 2. Convert hypertable back to regular table (TimescaleDB 2.x experimental)
op.execute("SELECT timescaledb_experimental.remove_hypertable('memory.episodes', if_exists => TRUE)")
```

**Note:** `remove_hypertable` is experimental in TimescaleDB 2.x but stable in later versions. For a clean rollback on an empty DB (baseline state), the safest path is to simply **drop the table and let Alembic recreate it** via `op.drop_table()` in the downgrade.

Since the DB is at baseline `2bed93fd1dd0` (empty), the downgrade can safely drop all 4 hypertable tables and recreate them as regular tables. This is the recommended rollback approach.

## 6. Key Takeaways

1. **Current migration WILL fail** — TimescaleDB rejects `id`-only PK on hypertables.
2. **Composite PK `(id, time_col)` is required** — minimally invasive model change.
3. **3 FK constraints must be removed** — acceptable because UUIDs are globally unique.
4. **Regenerate migration** — don't rely on fragile regex-patching (`patch-migration.py`).
5. **Empty DB = safe rollback** — just drop + recreate tables in downgrade.
6. **Always test on staging first** — this is not production-ready as-is.
