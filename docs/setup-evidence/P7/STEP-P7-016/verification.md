# P7-016: Tasker Clipboard Profile — Verification

## Verification Checklist

### 1. Prerequisites Verification

- [ ] Tasker 5.8+ installed and running
- [ ] AutoTools plugin installed (Android 10+)
- [ ] AutoTools accessibility service enabled in Settings
- [ ] Consent scope `surveillance.clipboard` is active
- [ ] HMAC signing key configured per P7-017
- [ ] Guinevere server endpoint is reachable from device

### 2. Profile Trigger Verification

**Test: Clipboard change detection**

1. Enable the Tasker profile
2. Copy text to clipboard: `test clipboard event`
3. Check Tasker logs for profile trigger
4. Verify `%CLIP_TEXT` variable contains the copied text
5. Confirm task executed without errors

**Expected result:** Task fires within 2 seconds of clipboard change.

### 3. Debounce Verification

**Test: Rate limiting**

1. Copy text to clipboard multiple times in rapid succession (less than 5 seconds apart)
2. Check Tasker logs for skipped events
3. Verify only one event per 5-second window is processed

**Expected result:** Rapid clipboard changes are throttled. `%LAST_CLIP_EVENT` timestamp prevents duplicate processing.

### 4. JSON Payload Verification

**Test: Event structure**

1. Copy test text to clipboard: `verification test payload`
2. Capture the JSON payload before transmission (use Tasker's Flash or log action)
3. Verify structure matches specification:

```json
{
  "event_type": "clipboard",
  "device_id": "<device-id>",
  "occurred_at": "<iso-8601-timestamp>",
  "payload": {
    "text": "verification test payload",
    "length": 25
  }
}
```

**Expected result:**
- `event_type` is exactly `"clipboard"`
- `device_id` matches configured device identifier
- `occurred_at` is valid ISO 8601 format
- `payload.text` matches clipboard content
- `payload.length` equals character count of text

### 5. HMAC Signing Verification

**Test: Signature generation**

1. Copy test text to clipboard
2. Capture the HMAC signature generated by Tasker
3. Verify signature is included in HTTP request headers
4. Server-side: verify signature matches expected HMAC-SHA256 output

**Expected result:**
- Request includes `X-HMAC-Signature` header (or configured header name)
- Signature is 64-character hex string (SHA256 output)
- Server accepts signature and processes event

### 6. Event Transmission Verification

**Test: Server ingestion**

1. Copy test text to clipboard: `transmission test event`
2. Check Tasker HTTP Request action logs for successful POST
3. Verify HTTP response code is 2xx (success)
4. Server-side: query event database for the clipboard event
5. Confirm event was stored with correct metadata

**Expected result:**
- HTTP POST succeeds with 2xx response
- Event appears in server database within 5 seconds
- Event metadata matches transmitted payload

### 7. Secret Scanning Verification

**Test: Redaction of sensitive data**

Use synthetic test secrets (never real credentials):

1. Copy text with test API key: `My key is sk_test_1234567890abcdef1234567890abcdef`
2. Wait for event to be processed server-side
3. Query stored event in database
4. Verify the API key is replaced with `[REDACTED]`

**Expected result:**
- Stored event shows: `My key is [REDACTED]`
- Event is preserved (not dropped)
- Metadata (device_id, occurred_at, length) remains intact

**Additional test patterns:**

```
Test password: password=SuperSecret123
Test token: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Test AWS key: AKIAIOSFODNN7EXAMPLE
```

All should be redacted to `[REDACTED]` in stored events.

### 8. Consent Revocation Verification

**Test: Consent enforcement**

1. Revoke consent scope `surveillance.clipboard` via Guinevere control interface
2. Copy text to clipboard
3. Verify Tasker profile does not process the event
4. Check Tasker logs for consent check failure

**Expected result:**
- Profile detects revoked consent
- No HTTP request is sent to server
- Event is not captured or stored

### 9. Battery Impact Verification

**Test: Power consumption**

1. Enable profile for 24 hours with normal clipboard usage
2. Check Android battery stats (Settings > Battery > Tasker)
3. Verify Tasker battery usage is reasonable (less than 5% of total)

**Expected result:**
- Debounce prevents excessive wake-ups
- Battery impact is minimal and acceptable

### 10. Error Handling Verification

**Test: Network failure**

1. Disable network connectivity on device
2. Copy text to clipboard
3. Verify Tasker logs the network error
4. Re-enable network
5. Copy new text to clipboard
6. Verify profile resumes normal operation

**Expected result:**
- Network errors are logged but don't crash Tasker
- Profile recovers automatically when network returns
- No clipboard functionality is blocked

### 11. Documentation Verification

- [ ] tasker-clipboard.md includes all required sections
- [ ] No real clipboard content in documentation
- [ ] No hardcoded secrets in examples
- [ ] No em dashes used
- [ ] References to P7-009, P7-012, P7-017 are present and accurate
- [ ] Privacy classification (Restricted) is clearly stated
- [ ] Secret scanning pipeline is explained correctly
