## 8. Design Decisions/Caveats

- **ExecStart**: Uses `.venv/bin/hermes --config .../config.yaml gateway` as the entrypoint. This assumes Hermes Agent CLI is installed in the venv and exposes a `gateway` subcommand. If the production Hermes install uses a different entrypoint (e.g., `python -m hermes.server`), the VPS unit may differ — the comment in the template flags this sync requirement.
- **ReadWritePaths**: Six explicit paths scoped to Guinevere code, data, logs, evidence, Hermes config, and `.hermes` runtime directory. No broad access.
- **Group=guinevere**: Explicitly set for consistency with monitoring service pattern.
- **SyslogIdentifier**: `hermes-gateway` for Promtail/Loki aggregation matching.
- **No `systemd-analyze security`**: Local-only template creation; `systemd-analyze` is a VPS-host-side command not available in this environment. Hardening score is inferred from the flags present.
- **No live deployment claim**: Phase 7b explicitly excludes deployment. This is a repository template only.

## 10. Security Scan

Hardening flags verified (15 total):
- `Type=exec` — execve-based service start
- `NoNewPrivileges=true` — prevents privilege escalation via setuid/setgid
- `ProtectSystem=strict` — read-only /usr and /etc
- `ProtectHome=read-only` — read-only /home
- `PrivateTmp=true` — isolated /tmp
- `ProtectKernelTunables=true` — blocks /sys and /proc modifications
- `ProtectKernelModules=true` — blocks kernel module loading
- `ProtectControlGroups=true` — blocks cgroup manipulation
- `RestrictSUIDSGID=true` — blocks SUID/SGID bit changes
- `MemoryHigh=512M` — soft memory limit
- `MemoryMax=1G` — hard memory OOM limit
- `Slice=guinevere.slice` — resource accounting under guinevere cgroup
- `ReadWritePaths` — six explicit paths, no broad access

No secrets exposure, no dangerous capabilities, no root execution.
