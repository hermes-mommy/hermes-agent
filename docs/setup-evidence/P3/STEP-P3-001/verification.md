- `alembic downgrade -1` removes `ops.alembic_version` entry (baseline has no downgrade operations — table stays)
- Re-running `alembic upgrade head` is idempotent

- The baseline revision can be regenerated by deleting and re-running `alembic revision --autogenerate`

## Design Decisions/Caveats

- `src/memory/models.py` contains only `Base = declarative_base()` — P3-002 will add all 47 table models
- `guinevere_core` was granted `CREATE ON DATABASE guinevere` and `ALL ON SCHEMA ops` — this is necessary for Alembic to function and future table creation
- The `ops` schema was created via `docker exec` since `guinevere_core` lacked CREATE privilege
- Auth method for PG superuser `guinevere` is password-based; no password known, so `docker exec` was used for privileged operations
- 12 canonical schemas are filtered in env.py: `memory`, `persona`, `surveillance`, `financial`, `projects`, `social`, `agents`, `consent`, `security`, `audit`, `ops`, `extensions`
- Existing DB schemas (`audit`, `config`, `financial`, `loops`, `memory`, `persona`, `surveillance`, `public`, TimescaleDB internal) are untouched
