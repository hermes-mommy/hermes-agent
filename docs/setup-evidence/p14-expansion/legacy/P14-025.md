## Goal

Deploy a hardened, isolated `guinevere-health.service` systemd unit that runs the full wearable pipeline (WebDAV fetch worker, ingestion, analysis scheduler, health monitoring) as a separate service under the shared `guinevere.slice` resource group.

---

## Context

The main `guinevere-core.service` handles the Hermes agent, persona engine, and Discord bot. Adding health data processing to that service creates unnecessary coupling: a health pipeline bug (e.g., WebDAV timeout, malformed SQLite causing high CPU) could degrade core agent responsiveness.

ADR-021 mandates service isolation per the requirements spec section 8: "guinevere-health.service -- separate from main guinevere.service (isolation priority). Same guinevere.slice resource group (shared memory budget)." This step creates that service with the same hardening profile as existing Guinevere systemd units (Deployment Guide section 3 patterns) plus additional constraints specific to health data processing.

**Services bundled under `guinevere-health`** (single process with internal workers):
1. **WebDAV fetch worker** -- APScheduler job, 1h interval, downloads SQLite from WebDAV (P14-002)
2. **Ingestion pipeline** -- reads SQLite, parses via P14-005, POSTs internally to `/surveillance/health` (P14-006)
3. **Analysis scheduler** -- APScheduler jobs: baseline (P14-009), anomaly detection (P14-010), GHI scoring (P14-011), daily summary (P14-012)
4. **Health monitoring** -- 30min freshness/battery/WebDAV checks (P14-024)

**Why Type=simple instead of Type=exec?** The deployment guide core services use `Type=simple` because they include `ExecStartPre` for SOPS decryption. `guinevere-health` uses the same pattern, so `Type=simple` is consistent. The `Type=exec` from the task spec is applicable for services without `ExecStartPre`.

**Security hardening rationale:**
- `NoNewPrivileges=true` -- blocks setuid and privilege escalation
- `ProtectSystem=strict` -- /usr, /boot, /etc read-only
- `PrivateTmp=true` -- private /tmp and /var/tmp
- `MemoryDenyWriteExecute` -- W^X enforcement; **caveat**: Python CFFI (cryptography, asyncpg) may need rwx pages. Disabled by default, test on VPS first
- `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX` -- no raw sockets
- `RestrictNamespaces=true` -- no container escape

**Resource allocation** (under `guinevere.slice`):
- MemoryMax=1G, CPUQuota=100%, TasksMax=256

### Step 2: Create health service entry point

Create `src/surveillance/health_service.py` as the single process orchestrating all workers via APScheduler:

```bash
ssh guinevere-vps << 'ENTRY'
mkdir -p /home/guinevere/code/guinevere/src/surveillance
cat > /home/guinevere/code/guinevere/src/surveillance/health_service.py << 'PYCODE'
"""P14-025: guinevere-health.service entry point.

Orchestrates the full wearable health pipeline:
  - WebDAV fetch worker (APScheduler, hourly)
  - Ingestion pipeline (SQLite parse -> POST /surveillance/health)
  - Analysis scheduler (baseline, anomalies, GHI, daily summary)
  - Health monitoring (freshness, battery, WebDAV checks)
"""
from __future__ import annotations
import asyncio, os, signal, sys
from datetime import timezone
from pathlib import Path
import structlog
from apscheduler.schedulers.asyncio import AsyncIOScheduler

sys.path.insert(0, str(Path(__file__).resolve().parent.parent.parent))
logger = structlog.get_logger(__name__)

DATABASE_URL = os.environ.get("GUINEVERE_DATABASE_URL", "postgresql+asyncpg://guinevere@localhost:5433/guinevere")
WEBDAV_URL = os.environ.get("GUINEVERE_WEBDAV_URL", "")
WEBDAV_USER = os.environ.get("GUINEVERE_WEBDAV_USER", "")
WEBDAV_PASS = os.environ.get("GUINEVERE_WEBDAV_PASS", "")
DEVICE_ID = os.environ.get("GUINEVERE_HEALTH_DEVICE_ID", "xiaomi-watch-s3")

async def main():
    logger.info("health_service_starting", pid=os.getpid())
    from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
    engine = create_async_engine(DATABASE_URL, echo=False, pool_pre_ping=True, pool_size=5)
    session_factory = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)
    scheduler = AsyncIOScheduler(timezone=timezone.utc)

    _register_webdav_fetch(scheduler, session_factory)
    _register_analysis_jobs(scheduler, session_factory)

    from src.surveillance.monitoring.health_freshness import register_monitor_jobs
    register_monitor_jobs(scheduler=scheduler, session_factory=session_factory, discord_channel=None, device_id=DEVICE_ID)

    scheduler.start()
    logger.info("health_service_scheduler_started", jobs=len(scheduler.get_jobs()))

    stop_event = asyncio.Event()
    def _handle_signal(signum, frame):
        logger.info("health_service_shutdown_signal", signal=signum)
        stop_event.set()
    signal.signal(signal.SIGTERM, _handle_signal)
    signal.signal(signal.SIGINT, _handle_signal)
    await stop_event.wait()

    logger.info("health_service_shutting_down")
    scheduler.shutdown(wait=True)
    await engine.dispose()
    logger.info("health_service_stopped")

def _register_webdav_fetch(scheduler, sf):
    scheduler.add_job(_webdav_fetch_and_parse, "interval", hours=1, id="webdav_fetch",
        name="WebDAV health data fetch + parse", kwargs={"session_factory": sf}, misfire_grace_time=600, coalesce=True)

async def _webdav_fetch_and_parse(session_factory):
    import httpx, sqlite3, tempfile
    if not WEBDAV_URL or not WEBDAV_USER:
        logger.warning("webdav_fetch_skipped", reason="credentials not configured")
        return
    try:
        async with httpx.AsyncClient(timeout=httpx.Timeout(60.0), verify=False) as client:
            response = await client.get(WEBDAV_URL.rstrip("/") + "/gadgetbridge-export.db", auth=(WEBDAV_USER, WEBDAV_PASS))
            response.raise_for_status()
    except Exception:
        logger.exception("webdav_fetch_failed")
        return
    with tempfile.NamedTemporaryFile(suffix=".db", delete=False) as tmp:
        tmp.write(response.content)
        tmp_path = tmp.name
    try:
        conn = sqlite3.connect(tmp_path)
        conn.execute("PRAGMA integrity_check")
        from src.surveillance.parsers.gadgetbridge_parser import parse_gadgetbridge_export
        events = parse_gadgetbridge_export(tmp_path)
        logger.info("webdav_fetch_parsed", events=len(events))
        async with httpx.AsyncClient(timeout=httpx.Timeout(30.0)) as ic:
            for evt in events:
                try:
                    await ic.post("http://localhost:8000/surveillance/health", json=evt, headers={"X-Device-ID": DEVICE_ID})
                except Exception:
                    logger.exception("health_ingest_post_failed", metric=evt.get("metric"))
        conn.close()
    except Exception:
        logger.exception("webdav_parse_failed")
    finally:
        Path(tmp_path).unlink(missing_ok=True)

def _register_analysis_jobs(scheduler, sf):
    scheduler.add_job(_run_baseline, "cron", hour=3, minute=0, timezone="Asia/Jakarta",
        id="health_baseline", name="Health baseline computation", kwargs={"session_factory": sf}, misfire_grace_time=1800, coalesce=True)
    scheduler.add_job(_run_ghi_scoring, "cron", hour=3, minute=30, timezone="Asia/Jakarta",
        id="health_ghi", name="GHI composite score", kwargs={"session_factory": sf}, misfire_grace_time=1800, coalesce=True)
    scheduler.add_job(_run_daily_summary, "cron", hour=4, minute=0, timezone="Asia/Jakarta",
        id="health_daily_summary", name="Daily health summary", kwargs={"session_factory": sf}, misfire_grace_time=1800, coalesce=True)

async def _run_baseline(sf):
    try:
        from src.surveillance.analysis.baseline import compute_baseline
        async with sf() as s: await compute_baseline(s)
    except Exception: logger.exception("baseline_failed")

async def _run_ghi_scoring(sf):
    try:
        from src.surveillance.analysis.ghi_engine import compute_ghi_score
        async with sf() as s: await compute_ghi_score(s)
    except Exception: logger.exception("ghi_failed")

async def _run_daily_summary(sf):
    try:
        from src.surveillance.analysis.daily_summary import compute_daily_summary
        async with sf() as s: await compute_daily_summary(s)
    except Exception: logger.exception("daily_summary_failed")

if __name__ == "__main__":
    asyncio.run(main())
PYCODE
echo "OK: health_service.py created"
ENTRY
```


## Troubleshooting

- **Issue: `systemd-analyze verify` fails with "Unknown key name MemoryHigh"**
  - **Solution:** MemoryHigh requires systemd >= 232. Ubuntu 24.04 ships systemd 255 -- check with `systemctl --version`. If on older system, remove MemoryHigh line and rely on MemoryMax only.
- **Issue: Service starts but immediately exits with code 1**
  - **Solution:** Check journal: `journalctl -u guinevere-health -n 100 --no-pager`. Common causes: SOPS decryption failed (wrong age key), Python import error (missing dependency in venv), DATABASE_URL unreachable (PostgreSQL not running).
- **Issue: `ExecStartPre` fails with "sops: command not found"**
  - **Solution:** sops must be at `/usr/bin/sops`. If installed elsewhere, update ExecStartPre path. Verify: `which sops`. If missing: `sudo mv /usr/local/bin/sops /usr/bin/sops`.
- **Issue: `ProtectSystem=strict` causes import errors**
  - **Solution:** Python virtualenv at `/home/guinevere/code/guinevere/.venv` needs to be readable. Verify `ReadWritePaths` includes `/home/guinevere/code/guinevere/logs` and `/home/guinevere/data`. If venv is outside these paths, add it: `ReadWritePaths=... /home/guinevere/code/guinevere/.venv`.
- **Issue: MemoryDenyWriteExecute kills process during cryptography import**
  - **Solution:** This is the CFFI issue documented. The directive is commented out by default. If you uncommented it and the service crashes, re-comment it. Post-launch: compile cryptography without CFFI bindings or use pymalloc.
- **Issue: Service starts but APScheduler jobs never fire**
  - **Solution:** Check if scheduler is actually started: `journalctl -u guinevere-health | grep scheduler_started`. If missing, the `main()` coroutine may have an exception before `scheduler.start()`. Check for import errors in the journal.

## Notes

- **Service isolation** is the primary design goal. If any health pipeline component fails (WebDAV timeout, SQLite parse error, DB connection loss), the main Guinevere core agent and Discord bot remain unaffected.
- **`After=postgresql.service redis.service`** assumes these are systemd services. If running PostgreSQL/Redis via Docker with `docker-compose`, ensure the Docker container names match the service names. Alternative: `After=docker.service` and add a health-check loop in `health_service.py` to wait for DB readiness.
- **Health service runbook** -- operational commands for daily management:

```bash
# Start, stop, restart
sudo systemctl start guinevere-health
sudo systemctl stop guinevere-health
sudo systemctl restart guinevere-health

# View status
sudo systemctl status guinevere-health --no-pager

# View live logs
journalctl -u guinevere-health -f

# View last 100 lines
journalctl -u guinevere-health -n 100 --no-pager

# Check resource usage
systemctl show guinevere-health | grep -E "MemoryCurrent|CPUUsage"
```

- **MemoryDenyWriteExecute caveat** is documented in the unit file comments. This is the only non-default hardening directive. Test post-deployment: uncomment the line, restart the service, and if it stays active for >60 seconds, the Python runtime is compatible. If it crashes, re-comment.
- Cross-reference: P14-002 (WebDAV endpoint), P14-005 (parser), P14-006 (ingestion endpoint), P14-009 (baseline), P14-012 (daily summary), P14-024 (monitor), P14-026 (mock data -- useful for testing without real device).
