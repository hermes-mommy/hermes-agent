## Goal

Configure a TLS-secured WebDAV endpoint on the VPS that accepts Gadgetbridge auto-export uploads with SOPS-encrypted basic auth credentials, storing `.db` files in `/var/lib/guinevere/webdav/health/`.

---

## Context

Gadgetbridge's auto-export feature needs a WebDAV endpoint to push hourly SQLite dumps. This endpoint is the bridge between Faiz's Android phone and the VPS ingestion pipeline. The design follows the existing Guinevere infrastructure pattern: nginx as a lightweight TLS-terminated reverse proxy with basic auth, all credentials encrypted via SOPS.

**Why nginx + WebDAV module** instead of a dedicated WebDAV server (Apache mod_dav, lighttpd, or Python-based): nginx is already installed on the VPS (P0 infrastructure) and the WebDAV module adds minimal overhead. No separate service process — just an additional nginx `server` block.

**Security considerations:**
- TLS mandatory (Let's Encrypt certificate, already provisioned in P0-024)
- Basic auth credentials stored in SOPS — no plaintext passwords in nginx config
- Upload directory permissions restricted to `guinevere` user
- No rate limiting needed (Gadgetbridge pushes once per hour — well under any abuse threshold)
- Directory listing disabled (only `PUT`, `MKCOL` allowed for upload; `GET` for download if needed by parser)

**Binding decisions from ADR-021:**
- Wearable data classified CRITICAL, same as P7 surveillance data
- No separate encryption key for MVP — reuse existing SOPS age key
- Health data path: Gadgetbridge → WebDAV → VPS → P14-005 parser → P14-006 ingestion

## Commands

### Step 1: Generate WebDAV Credentials

```bash
# On VPS — generate random username and password for WebDAV basic auth
ssh guinevere-vps << 'EOF'
WEBDAV_USER="gadgetbridge_$(openssl rand -hex 4)"
WEBDAV_PASS=$(openssl rand -base64 24 | tr -d '=+/' | head -c 32)

echo "webdav_user: $WEBDAV_USER"
echo "webdav_pass: $WEBDAV_PASS"

# Store in SOPS — append to existing secrets file
cd /home/guinevere/code/guinevere
sops -d secrets/guinevere-secrets.yaml > /tmp/decrypted-secrets.yaml

cat >> /tmp/decrypted-secrets.yaml << SECRETS

# Health/Wearable WebDAV
health_webdav:
  username: "${WEBDAV_USER}"
  password: "${WEBDAV_PASS}"
SECRETS

AGE_PUBKEY=$(grep "public key:" /home/guinevere/secrets/age-key.txt | awk '{print $4}')
sops --encrypt --age "$AGE_PUBKEY" /tmp/decrypted-secrets.yaml > secrets/guinevere-secrets.yaml
rm /tmp/decrypted-secrets.yaml

# Verify decryption includes new keys
sops -d secrets/guinevere-secrets.yaml | grep -A 3 "health_webdav"
EOF
```

### Step 2: Create Upload Directory

```bash
ssh guinevere-vps << 'EOF'
# Create WebDAV upload directory structure
sudo mkdir -p /var/lib/guinevere/webdav/health

# Set ownership to guinevere user (nginx worker runs as guinevere)
sudo chown -R guinevere:guinevere /var/lib/guinevere/webdav
sudo chmod 750 /var/lib/guinevere/webdav
sudo chmod 770 /var/lib/guinevere/webdav/health

# Verify
ls -la /var/lib/guinevere/webdav/
# Expected: drwxr-x--- guinevere guinevere ... /var/lib/guinevere/webdav/health
EOF
```

### Step 3: Generate htpasswd File

```bash
ssh guinevere-vps << 'EOF'
# Install apache2-utils for htpasswd
sudo apt install -y apache2-utils

# Extract credentials from SOPS
cd /home/guinevere/code/guinevere
WEBDAV_USER=$(sops -d secrets/guinevere-secrets.yaml | grep "username:" | awk '{print $2}' | tr -d '"')
WEBDAV_PASS=$(sops -d secrets/guinevere-secrets.yaml | grep "password:" | awk '{print $2}' | tr -d '"')

# Create htpasswd file with bcrypt hashing
sudo htpasswd -bcB /etc/nginx/.htpasswd-webdav "$WEBDAV_USER" "$WEBDAV_PASS"
sudo chmod 640 /etc/nginx/.htpasswd-webdav
sudo chown root:guinevere /etc/nginx/.htpasswd-webdav

# Verify htpasswd file
sudo cat /etc/nginx/.htpasswd-webdav
# Expected: <username>:$2y$<hash>...
EOF
```

### Step 4: Nginx WebDAV Configuration

```bash
ssh guinevere-vps << 'EOF'
# If using nginx (primary path):
sudo tee /etc/nginx/sites-available/guinevere-webdav << 'NGINX'
# Guinevere Health WebDAV — Gadgetbridge auto-export upload endpoint
server {
    listen 443 ssl http2;
    server_name <vps-domain-or-tailscale-fqdn>;

    # TLS — reuse existing Guinevere certificate
    ssl_certificate     /etc/letsencrypt/live/<domain>/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/<domain>/privkey.pem;

    # WebDAV upload directory for health data
    location /guinevere/health/ {
        # Enable WebDAV methods
        dav_methods     PUT MKCOL;
        dav_access      user:rw;

        # Restrict to upload-only (no GET listing for security)
        limit_except    PUT {
            deny all;
        }

        # Upload size limit (20MB for SQLite .db files)
        client_max_body_size 20m;

        # Basic auth
        auth_basic           "Guinevere Health WebDAV";
        auth_basic_user_file /etc/nginx/.htpasswd-webdav;

        # Path to upload directory
        alias /var/lib/guinevere/webdav/health/;

        # Auto-create intermediate dirs for WebDAV PUT
        create_full_put_path on;

        # No directory listing
        autoindex off;
    }

    # Access log for audit trail
    access_log /var/log/nginx/guinevere-webdav-access.log;
    error_log  /var/log/nginx/guinevere-webdav-error.log;
}
NGINX

# Enable the site
sudo ln -sf /etc/nginx/sites-available/guinevere-webdav /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# Verify port 443 is listening
ss -tlnp | grep :443
EOF
```

### Step 5: Caddy Alternative (if using Caddy from P0-024)

```bash
# If Guinevere uses Caddy instead of nginx:
ssh guinevere-vps << 'EOF'
# Caddyfile addition (append to existing Caddyfile)
sudo tee -a /etc/caddy/Caddyfile << 'CADDY'

# Guinevere Health WebDAV endpoint
<vps-domain> {
    handle /guinevere/health/* {
        root * /var/lib/guinevere/webdav/health
        basicauth {
            {$HEALTH_WEBDAV_USER} {$HEALTH_WEBDAV_PASS_HASH}
        }
        # WebDAV only allows PUT for uploads
        @allowed method PUT
        route @allowed {
            file_server
        }
    }
}
CADDY

sudo systemctl reload caddy
EOF
```

### Step 6: Test WebDAV Endpoint

```bash
# From any machine (or VPS localhost) — test WebDAV PUT
# Extract credentials from SOPS first
ssh guinevere-vps << 'EOF'
cd /home/guinevere/code/guinevere
WEBDAV_USER=$(sops -d secrets/guinevere-secrets.yaml | grep "username:" | awk '{print $2}' | tr -d '"')

curl -T /tmp/webdav-test.txt \
  -u "${WEBDAV_USER}:${WEBDAV_PASS}" \

  -u "${WEBDAV_USER}:${WEBDAV_PASS}" \

```

## Troubleshooting

- **Issue: `nginx -t` fails with "unknown directive dav_methods"**
  - **Solution:** WebDAV module not compiled into nginx. Install nginx-extras: `sudo apt install nginx-extras`. If using nginx from Docker, use `nginx:alpine` which includes WebDAV.

- **Issue: curl PUT returns 405 Method Not Allowed**
  - **Solution:** The `dav_methods` directive may be in the wrong context. Move it inside the `location` block. Verify the nginx module is loaded: `nginx -V 2>&1 | grep -o http_dav_module`.

- **Issue: curl PUT returns 401 with correct credentials**
  - **Solution:** htpasswd file path mismatch or permissions. Check `auth_basic_user_file` path in nginx config. Verify nginx user can read the file: `sudo -u www-data cat /etc/nginx/.htpasswd-webdav`.

- **Issue: "413 Request Entity Too Large" on SQLite file upload**
  - **Solution:** Gadgetbridge `.db` files can grow over weeks. Increase `client_max_body_size` to 50m in the nginx location block and reload.

- **Issue: Android phone cannot reach VPS WebDAV URL**
  - **Solution:** If using Tailscale, use the Tailscale MagicDNS name (e.g., `https://guinevere-vps.tailnet-name.ts.net/guinevere/health/`). If using VPS public IP, ensure port 443 is open in UFW. Test connectivity from phone browser first.

- **Issue: Caddy alternative — basicauth not working**
  - **Solution:** Caddy's `basicauth` requires bcrypt hashes. Generate with: `caddy hash-password --plaintext "your-password"`. Store hash (not plaintext) in Caddyfile.

## Notes

- **No rate limiting needed**: Gadgetbridge pushes once per hour (1 request/hour). Even with manual export triggers, the volume is trivial. Rate limiting adds complexity without benefit.
- **Certificate renewal**: Let's Encrypt auto-renews via certbot timer. No manual intervention needed for this endpoint.
- **Upload atomicity**: nginx WebDAV `PUT` is not atomic — a partial upload could leave a corrupted `.db` file. P14-005 parser handles this by checking SQLite file integrity before parsing (`PRAGMA integrity_check`).
- **Disk space monitoring**: Health `.db` files grow slowly (~100KB-500KB each). With hourly sync and 365-day retention on raw data, estimate ~125MB/year. Prometheus alert in P14-022 for disk usage.
- **Alternative: rsync/SCP**: Not chosen because Gadgetbridge only supports WebDAV export. The API is fixed — this endpoint must match exactly what Gadgetbridge expects.
- **Cross-reference**: P14-001 (configures Gadgetbridge to point at this URL), P14-005 (reads files from this directory), P14-008 (Mi Fitness fallback uses different path — not WebDAV).
