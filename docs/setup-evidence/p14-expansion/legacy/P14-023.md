## Context

This step creates a standalone Grafana dashboard for P14 health monitoring, separate from the main Guinevere dashboard. Following the grafanalib dashboard-as-code pattern specified in P9-011, P11-021, and P12-025, the dashboard is defined in Python and generated to JSON for file-based provisioning.

The dashboard contains 7 panels:

| # | Panel | Type | Data Source | Description |
|---|-------|------|-------------|-------------|
| 1 | GHI Trend (7-day) | TimeSeries | Prometheus | Color-coded by tier, 7-day window |
| 2 | GHI Trend (30-day) | TimeSeries | Prometheus | Extended trend for baseline context |
| 3 | Sleep Duration + Quality | BarGauge / TimeSeries | TimescaleDB | Bar chart with stages stacked |
| 4 | Heart Rate (min/max/avg) | TimeSeries | TimescaleDB | Line chart with anomaly markers |
| 5 | Step Count | BarGauge | TimescaleDB | Bar chart with 8000-step target line |
| 6 | SpO2 Trend | TimeSeries | TimescaleDB | Line chart with 94% threshold line |
| 7 | Anomaly Events | Table | TimescaleDB / Prometheus | Severity-colored table |

Data sources are mixed: Panels 1-2 use Prometheus (from P14-022 metrics), Panels 3-7 use TimescaleDB (direct SQL queries against `health.*` tables). Both datasources are already provisioned in `monitoring/grafana/provisioning/datasources/datasources.yml`.

The dashboard JSON is generated from Python using `grafanalib >= 0.7`. The Python source lives at `src/observability/p14_dashboard.py` and the generated JSON is written to `monitoring/grafana/dashboards/guinevere-p14-health.json`. Grafana auto-loads it from the provisioning directory within 30 seconds.

This step produces `src/observability/p14_dashboard.py`, generates `monitoring/grafana/dashboards/guinevere-p14-health.json`, and relies on existing provisioning configuration (no changes to `dashboards.yml`).

## Troubleshooting

- **Issue:** `grafanalib._gen.DashboardEncoder` not found
  - **Solution:** The import uses a try/except fallback to `grafanalib.core.DashboardEncoder` for version 0.8+. If both fail, check grafanalib version: `pip show grafanalib`. Install: `pip install "grafanalib>=0.7"`.

- **Issue:** Dashboard JSON generated but not visible in Grafana UI
  - **Solution:** Check Grafana logs: `docker logs grafana 2>&1 | grep -i "provisioning\|dashboard\|p14"`. Common issues: invalid JSON (run JSON validation), wrong UID, or dashboard folder does not exist. Also verify the JSON is in `/var/lib/grafana/dashboards/` (Docker volume mapping).

- **Issue:** TimescaleDB panels show "No data"
  - **Solution:** Verify the PostgreSQL datasource is correctly configured in `monitoring/grafana/provisioning/datasources/datasources.yml`. The datasource UID must match what's used in `SqlTarget`. Also check that `health.*` tables actually contain data: `psql -d guinevere -c "SELECT count(*) FROM health.heart_rate"`.

- **Issue:** Prometheus panels show "No data" for GHI
  - **Solution:** Verify P14-022 metrics are registered and scraped: `curl http://localhost:8000/metrics | grep guinevere_p14`. If metrics are missing, restart the FastAPI service: `systemctl restart guinevere-api`. Check Prometheus targets: `http://localhost:9090/targets`.

- **Issue:** Dashboard JSON grows too large (> 1MB)
  - **Solution:** The SQL queries use LIMIT 100 for anomaly events and 7-day windows for time series. If the JSON is still too large, reduce the number of rows in SQL queries or increase the time aggregation interval.

## Notes

- **Dashboard-as-code**: The Python source (`p14_dashboard.py`) is the source of truth. The JSON is derived and should not be manually edited. Regenerate with `python src/observability/p14_dashboard.py` after any changes to the Python definition.
- **Mixed datasources**: Panels 1-2 use Prometheus (GHI score from P14-022), Panels 3-7 use PostgreSQL (direct queries to `health.*`). This is intentional — Prometheus for real-time metrics, PostgreSQL for historical data with richer query capabilities.
- **Threshold alignment**: GHI thresholds (red < 40, orange < 55, yellow < 70, green >= 70) match the requirements section 3.4 tiers. SpO2 threshold (red < 94%) matches the requirements section 6 critical alert trigger.
- **Dashboard provisioning**: Grafana auto-loads dashboards from `/var/lib/grafana/dashboards/` every 30 seconds. No restart needed. The provisioning file (`dashboards.yml`) is already configured and does not need modification for this dashboard.
- The dashboard uses `editable=False` and `allowUiUpdates: false` — any UI changes are not persisted. This enforces the dashboard-as-code discipline established in ADR-017.
- Post-launch enhancement: add HRV and stress level panels (currently omitted since metrics for these are supplementary per requirements section 3.1).
- Post-launch enhancement: add a "Body Battery" area chart panel when that metric becomes available from Gadgetbridge.
