## Goal

Implement two Discord slash commands — `/sleep-report` and `/activity-today` — that display detailed sleep metrics (duration, stages, quality, 7-day comparison) and daily activity data (steps, distance, calories, active minutes, trend) in rich embed format with ASCII visualization bars — **ALL responses ephemeral (private)**, Faiz-only access.

---

## Context

### Command Specifications

| Command | Description | Parameters |
|---|---|---|
| `/sleep-report` | Detailed sleep: duration, stages (light/deep/REM), quality score, comparison to 7-day average | None (or optional `date` post-launch) |
| `/activity-today` | Steps, distance, calories, active minutes, trend vs 7-day average | None |

### Data Sources

Both commands query `health.sleep_sessions`, `health.sleep_stages`, `health.daily_activity`, and `health.daily_summary` for 7-day comparison data.

| Command | Primary Table | 7-Day Source |
|---|---|---|
| `/sleep-report` | `health.sleep_sessions` (latest) | AVG of last 7 `sleep_sessions` |
| `/activity-today` | `health.daily_activity` (today) | AVG of last 7 `daily_activity` rows |

### Embed Color Coding (activity/sleep quality)

| Quality Tier | Score Range | Color | Hex |
|---|---|---|---|
| Excellent | >= 85 | Green | `0x16A34A` |
| Good | 70-84 | Green | `0x16A34A` |
| Fair | 55-69 | Yellow | `0xCA8A04` |
| Poor | 40-54 | Red | `0xDC2626` |
| Critical | < 40 | Red | `0xDC2626` |

### ASCII Visualization

Since Discord embeds do not support native charts, use descriptive ASCII bars:
- Sleep stages: horizontal bar showing proportion: `[███░░░] 45% Deep | [████░░] 55% Light`
- Activity trend: arrow indicators: `📈 +12% above 7-day avg` or `📉 -8% below 7-day avg`

### Binding Decisions

1. **ALL responses are ephemeral.** Same pattern as P14-016 — `defer_ephemeral()` + `followup.send(ephemeral=True)`.
2. **Faiz-only.** Both commands check `is_faiz_interaction()`.
3. **NEVER confrontational.** Sleep reports say "You slept X hours" — never "You slept too little." Activity reports say "X steps today" — never "Only X steps."
4. **7-day average comparison for context.** Always show current vs average trend arrow.
5. **Stages data from `health.sleep_stages`** if available; fall back to total-only from `health.sleep_sessions` if stages not captured.
6. **No raw vitals.** Sleep reports show duration/stages/quality only — no HR during sleep, no SpO2 dips.

### Integration Points

| System | Interaction |
|---|---|
| `health.sleep_sessions` | Primary: duration, efficiency, quality |
| `health.sleep_stages` | Secondary: deep/light/REM/awake breakdown |
| `health.daily_activity` | Primary: steps, distance, calories, active_min |
| `health.daily_summary` | Fallback: sleep_total_h, steps |
| `src/discord/colors.py` | SUCCESS, WARNING, ALERT |
| `src/discord/_embed_helpers.py` | defer_ephemeral, followup_send, send_denied |

**Stages Bar Helper:**

```python
def _stages_bar(minutes: int, total_minutes: int, length: int = 10) -> str:
    """Render proportional bar: '████████░░'."""
    pct = minutes / total_minutes if total_minutes > 0 else 0
    filled = max(0, min(length, int(pct * length)))
    return "█" * filled + "░" * (length - filled)

def _format_duration(minutes: int) -> str:
    """Format minutes as 'Xh Ym'."""
    h, m = divmod(minutes, 60)
    return f"{h}h {m}m" if h > 0 else f"{m}m"
```

**Trend Section:**

```python
def _trend_line(current: float, avg_7d: float, unit: str = "") -> str:
    """Build trend line: '7.1h (↑ +18min)' or '7,420 steps (↓ -8%)'."""
    delta = current - avg_7d
    arrow = "↑" if delta > 0 else "↓" if delta < 0 else "→"
    if unit == "%":
        pct = (delta / avg_7d * 100) if avg_7d > 0 else 0
        return f"Avg: {avg_7d:.1f} ({arrow} {pct:+.1f}%)"
    return f"Avg: {avg_7d:.1f}{unit} ({arrow} {delta:+.1f}{unit})"
```

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---|---|---|
| Sleep stages section empty/missing | `health.sleep_stages` has no data for latest session | Device may not capture stages (some bands only track total). Fall back to total-only display. |
| 7-day comparison shows "N/A" | Less than 7 days of data (warm-up) | Show warm-up message: "Need 7 days of data for trend comparison (X days remaining)" |
| Goal bar shows full when no steps | `_goal_bar` dividing by zero (goal=0) | Guard: `if goal <= 0: return "░░░░░░░░░░░░░░░░ (no goal set)"` |
| Duration shows "0h 0m" | `total_s` is NULL or 0 in session row | Check `health.sleep_sessions.total_s`; gadgetbridge may store in `total_s` column or compute from end-start |
| Activity trend shows all zeros | `health.daily_activity` has NULL columns | Add COALESCE in SQL: `COALESCE(steps, 0), COALESCE(active_min, 0)` |
| Distance shows in meters not km | `distance_m` column stores meters | Divide by 1000: `distance_km = row.distance_m / 1000.0` |
| Color never changes from green | Quality label string mismatch with dict keys | Verify `SLEEP_QUALITY_COLORS` keys match exactly what `_classify_quality` returns (case-sensitive) |
| `lsp_diagnostics` unused import warning | Added `Enum`, `Protocol` etc. then didn't use | Remove unused imports; follow minimal import pattern from P14-016 |

## Notes

### Safety Boundaries

1. **ALL responses are ephemeral.** Sleep and activity data are health data — never visible to other Discord users.
2. **Faiz-only.** Non-Faiz users are blocked before any DB query fires.
3. **NEVER confrontational.** Sleep reports NEVER say "you slept too little" or "your activity is low." They state facts: "7h 24m" and "8,420 steps." The trend arrows are neutral indicators, not judgments.
4. **No raw vitals.** Sleep reports include stages/duration/quality only. No overnight HR, SpO2 dips, HRV during sleep.

Both files follow the same conventions as:
- `cmd_sleep_report.py` mirrors `cmd_health_status.py` (P14-016) with sleep-specific fields
- `cmd_activity_today.py` mirrors the same pattern with activity-specific builder

- Show current values without comparison section
