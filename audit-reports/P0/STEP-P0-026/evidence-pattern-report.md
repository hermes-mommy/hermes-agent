## 1. Step Overview — P0-026

**Step ID**: P0-026
**Title**: GitHub PAT + SOPS Encrypted Storage
**Type**: Security
**Risk**: High
**Goal**: Generate GitHub Personal Access Token and store encrypted via SOPS; create private repo remote; push initial commit.
**Dependencies**: P0-013 (SOPS installed, `.sops.yaml` active, age key present), P0-025 (git repo initialized at `/home/guinevere/code/guinevere`)
**ADR References**: ADR-015 (secrets management), ADR-016 (version control)
**Acceptance Criteria**: AC-SEC-003 (no plaintext secrets)
**Cost Impact**: $0/month
**Estimated Time**: 1 hour
**Executor**: **Faiz (operator)** for PAT generation; Guinevere for repo creation, remote, push, SOPS encrypt, evidence.

### 1.1 Nature of the Step — Faiz Gate

This is a **Faiz gate step**: the PAT must be generated by the operator at https://github.com/settings/tokens with scopes `repo` and `workflow`. Guinevere cannot generate the token. The token flows through the step as follows:

```
Faiz generates PAT at github.com/settings/tokens
        |
        v
Faiz provides PAT to Guinevere (one-time, session-only)
        |
        v
Guinevere creates repo via GitHub API
  - sets remote origin
  - pushes initial commit (P0-025's commit)
  - encrypts PAT into SOPS at secrets/github-pat.yaml
  - clears PAT from memory/session
        |
        v
Evidence files (PAT REDACTED — only last-4 / fingerprint)
```

### 1.2 Critical Security Invariant

**PAT must NEVER appear in evidence, logs, or artifacts.** Only the following are permitted:
- Last 4 characters of PAT (e.g. `...abcd`)
- SHA-256 fingerprint of PAT (e.g. `sha256:1a2b3c...`)
- SOPS encrypted header showing `ENC[AES256_GCM,` prefix (no plaintext)
- Verification that `sops -d secrets/github-pat.yaml` works — but the **output** of decryption must NOT be captured in evidence text.

## 7. Design Decisions & Caveats

1. **PAT generation is a Faiz gate**. Guinevere cannot generate the token. The operator must navigate to https://github.com/settings/tokens, generate a classic PAT with scopes `repo` and `workflow`, copy the token and paste it to Guinevere (session-only, not stored in chat history).

2. **PAT is never exposed in evidence**. Only last-4 or SHA-256 fingerprint is permitted in evidence files. The `sops -d` verification command is run in-session but its output is NOT captured in any evidence file.

3. **SSH key may need GitHub registration**. If the VPS SSH key (`~/.ssh/id_ed25519.pub`) is not registered in GitHub Settings, the `git push` via SSH will fail. Alternative: use HTTPS remote with PAT, but this embeds PAT in `.git/config` — not recommended. Register SSH key first.

4. **CHECKLIST path discrepancy**: CHECKLIST references `/home/guinevere/config/github-pat.enc.yaml` but StepPrompts writes to `secrets/github-pat.yaml` (relative to `/home/guinevere/code/guinevere/`). Update CHECKLIST to match.

5. **Branch name**: StepPrompts references `main` branch, but P0-025 created `master` branch (Git 2.43.0 default). Either push to `master` or rename: `git branch -m master main`.

6. **`secrets/.gitignore`** already excludes `*.yaml` (from P0-013), so `secrets/github-pat.yaml` will not be tracked by git. This is correct.

7. **Idempotency**: Creating a GitHub repo with the same name twice will fail (409 Conflict). If re-running, delete the existing repo first via GitHub UI or API.
