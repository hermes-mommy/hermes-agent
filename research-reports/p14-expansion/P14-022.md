## Context

This step extends the existing Prometheus metrics registry in `src/core/main.py` with 7 health-domain metrics for P14 wearable monitoring. Following the established `guinevere_` prefix convention, the new metrics provide visibility into health data freshness, GHI scores, anomaly events, watch battery status, and ingestion pipeline health.

The 7 metrics and their specifications:

| Metric Name | Type | Labels | Description |
|---|---|---|---|
| `guinevere_p14_ghi_score` | Gauge | `tier` | Current GHI composite score (0-100) |
| `guinevere_p14_data_freshness_seconds` | Gauge | — | Seconds since last health data was received |
| `guinevere_p14_sync_status` | Gauge | — | 1 = sync active, 0 = stale |
| `guinevere_p14_anomaly_count` | Counter | `severity`, `metric` | Anomaly events by severity and metric type |
| `guinevere_p14_watch_battery_percent` | Gauge | — | Watch battery level (0-100) |
| `guinevere_p14_ingestion_lag_seconds` | Gauge | — | Lag between data generation and ingestion |
| `guinevere_p14_ingestion_total` | Counter | `metric`, `source`, `status` | Total ingested health events |

Data sources:
- GHI score: query `health.daily_summary` for the latest `ghi_score`
- Data freshness: compute `NOW() - MAX(time)` across all `health.*` hypertables
- Sync status: derived from freshness — > 2 hours stale = 0
- Anomaly count: incremented on each anomaly event from P14-010
- Watch battery: extracted from Gadgetbridge sync metadata or `health.sync_log`
- Ingestion lag: `sync_log.sync_time - health.*.time` for latest record
- Ingestion total: incremented on each `POST /surveillance/events` with health scope

Metrics are updated via an APScheduler job running every 5 minutes. The update function queries TimescaleDB for current values and sets gauge metrics directly. Counter metrics are incremented by the ingestion pipeline when events are processed.

This step modifies `src/core/main.py` to register the 7 metrics and add the `/metrics` update job. It also creates `src/observability/p14_metrics.py` as a dedicated module for P14 metric collection logic.

"""P14 Health metrics collector — queries TimescaleDB and updates Prometheus gauges.

Metrics are collected every 5 minutes via APScheduler. Gauges are set directly
from DB queries. Counters are incremented by the ingestion pipeline at event time.

Naming convention: guinevere_p14_{metric_name} following guinevere_ prefix pattern.
"""
from __future__ import annotations

import logging
from datetime import datetime, timezone, timedelta

import asyncpg
from prometheus_client import Gauge, Counter

logger = logging.getLogger(__name__)

WIB = timezone(timedelta(hours=7))
STALE_THRESHOLD_S = 7200  # 2 hours

# ── Metric Definitions ───────────────────────────────────

p14_ghi_score = Gauge(
    "guinevere_p14_ghi_score",
    "Current GHI composite health score (0-100)",
    ["tier"],
)

p14_data_freshness_seconds = Gauge(
    "guinevere_p14_data_freshness_seconds",
    "Seconds since last health data was received from the wearable",
)

p14_sync_status = Gauge(
    "guinevere_p14_sync_status",
    "Health data sync status: 1 = active, 0 = stale (> 2h no data)",
)

p14_anomaly_count = Counter(
    "guinevere_p14_anomaly_count",
    "Total health anomaly events detected",
    ["severity", "metric"],
)

p14_watch_battery_percent = Gauge(
    "guinevere_p14_watch_battery_percent",
    "Xiaomi watch battery percentage (0-100)",
)

p14_ingestion_lag_seconds = Gauge(
    "guinevere_p14_ingestion_lag_seconds",
    "Lag between data generation timestamp and ingestion timestamp",
)

p14_ingestion_total = Counter(
    "guinevere_p14_ingestion_total",
    "Total health data events ingested",
    ["metric", "source", "status"],
)

# ── Data Collection ───────────────────────────────────

async def collect_p14_metrics(pg_pool: asyncpg.Pool) -> None:
    """Query TimescaleDB for current health metrics and update Prometheus gauges.

    Called by APScheduler every 5 minutes. Counter metrics (anomaly_count,
    ingestion_total) are NOT set here — they are incremented at event time.
    """
    try:
        async with pg_pool.acquire() as conn:
            await _collect_ghi(conn)
            await _collect_freshness(conn)
            await _collect_battery(conn)
            await _collect_lag(conn)
    except Exception as exc:
        logger.error("P14 metrics collection failed: %s", exc)

async def _collect_ghi(conn: asyncpg.Connection) -> None:
    """Fetch latest GHI score and tier from daily_summary."""
    row = await conn.fetchrow(
        "SELECT ghi_score FROM health.daily_summary "
        "ORDER BY date DESC LIMIT 1"
    )
    if row is None or row["ghi_score"] is None:
        return

    ghi = row["ghi_score"]
    if ghi >= 85:
        tier = "excellent"
    elif ghi >= 70:
        tier = "good"
    elif ghi >= 55:
        tier = "fair"
    elif ghi >= 40:
        tier = "poor"
    else:
        tier = "critical"

    p14_ghi_score.labels(tier=tier).set(ghi)

async def _collect_freshness(conn: asyncpg.Connection) -> None:
    """Compute seconds since last data point across all hypertables."""
    hypertables = ["heart_rate", "sleep_sessions", "spo2", "hrv"]
    max_ts: datetime | None = None

    for table in hypertables:
        time_col = "start_time" if table == "sleep_sessions" else "time"
        row = await conn.fetchrow(
            "SELECT MAX(" + time_col + ") AS max_t FROM health." + table
        )
        if row and row["max_t"]:
            ts = row["max_t"]
            if max_ts is None or ts > max_ts:
                max_ts = ts

    if max_ts is None:
        p14_data_freshness_seconds.set(STALE_THRESHOLD_S)
        p14_sync_status.set(0)
        return

    now = datetime.now(WIB)
    delta = (now - max_ts).total_seconds()
    p14_data_freshness_seconds.set(delta)
    p14_sync_status.set(1 if delta < STALE_THRESHOLD_S else 0)

async def _collect_battery(conn: asyncpg.Connection) -> None:
    """Extract watch battery from most recent sync_log metadata if available."""
    row = await conn.fetchrow(
        "SELECT status FROM health.sync_log ORDER BY sync_time DESC LIMIT 1"
    )
    if row is None:
        return
    status = row["status"] or ""
    try:
        import json
        info = json.loads(status) if status.startswith("{") else {}
        battery = info.get("battery_pct")
        if isinstance(battery, (int, float)):
            p14_watch_battery_percent.set(float(battery))
    except (json.JSONDecodeError, TypeError, ValueError):
        pass

async def _collect_lag(conn: asyncpg.Connection) -> None:
    """Compute ingestion lag: sync_time - data timestamp for latest record."""
    row = await conn.fetchrow(
        "SELECT sync_time FROM health.sync_log ORDER BY sync_time DESC LIMIT 1"
    )
    if row is None or row["sync_time"] is None:
        return
    sync_time = row["sync_time"]

    row2 = await conn.fetchrow(
        "SELECT MAX(time) AS max_t FROM health.heart_rate"
    )
    if row2 is None or row2["max_t"] is None:
        return
    data_time = row2["max_t"]

    lag = (sync_time - data_time).total_seconds()
    p14_ingestion_lag_seconds.set(max(lag, 0))

# ── Counter Increment Helpers ─────────────────────────

def record_anomaly(severity: str, metric: str) -> None:
    """Increment anomaly counter. Called by P14-010 anomaly detection engine."""
    p14_anomaly_count.labels(severity=severity, metric=metric).inc()

def record_ingestion(metric: str, source: str, status: str) -> None:
    """Increment ingestion counter. Called by P14-006 ingestion endpoint."""
    p14_ingestion_total.labels(metric=metric, source=source, status=status).inc()
PYEOF

## Troubleshooting

- **Issue:** `guinevere_p14_*` metrics not appearing in `/metrics`
  - **Solution:** Ensure the import block is placed BEFORE the `/metrics` endpoint handler in `main.py`. If the module is imported after `app = FastAPI()`, the metrics exist but the Prometheus registry has already been scraped. Move imports to the top of the file (after the existing Counter/Histogram definitions).

- **Issue:** GHI score always shows 0
  - **Solution:** GHI is computed by P14-011 and stored in `health.daily_summary`. If no daily summary exists yet, GHI will not be set. Verify: `psql -d guinevere -c "SELECT date, ghi_score FROM health.daily_summary ORDER BY date DESC LIMIT 5"`.

- **Issue:** Battery percentage always null
  - **Solution:** Battery info is extracted from `health.sync_log.status` JSON. If Gadgetbridge sync does not include battery metadata, check the sync_log entries: `psql -d guinevere -c "SELECT sync_time, status FROM health.sync_log ORDER BY sync_time DESC LIMIT 3"`. The fallback `except` block silently passes if JSON parsing fails.

- **Issue:** APScheduler job fails with "pool not available"
  - **Solution:** The `collect_p14_metrics` function requires an `asyncpg.Pool` instance. Ensure the pool is created before the scheduler job starts. Use `scheduler.add_job(..., next_run_time=datetime.now() + timedelta(seconds=30))` to delay the first run.

- **Issue:** Counter metrics reset on restart
  - **Solution:** This is expected Prometheus behavior — Counter values reset when the process restarts. Use `rate()` or `increase()` in PromQL queries to handle resets correctly. For long-term anomaly counts, query `health.anomaly_events` table directly.

## Notes

- **Metric naming**: Uses `guinevere_p14_` prefix consistent with the established `guinevere_` convention. No `p14_` standalone prefix — all Guinevere metrics share the `guinevere_` namespace.
- **Counter vs Gauge choice**: `anomaly_count` and `ingestion_total` are Counters because they represent cumulative events. All others are Gauges because they represent point-in-time values that can go up or down.
- The 5-minute collection interval is deliberate — health data arrives hourly via Gadgetbridge. More frequent collection would not yield fresher data.
- `collect_p14_metrics` wraps all queries in a single try/except — if one query fails, the others still run. This prevents a single broken hypertable from blocking all metric updates.
- The battery extraction assumes the `sync_log.status` field may contain a JSON object with a `battery_pct` key. If Gadgetbridge does not provide this, battery will remain unset (no error).
- Post-launch enhancement: add `guinevere_p14_sleep_hours` gauge with labels `deep`, `rem`, `light`, `awake` for richer sleep monitoring.
- Post-launch enhancement: add Alertmanager rules for P14 metrics (e.g., `guinevere_p14_data_freshness_seconds > 7200` → SEV2 alert to `#guinevere-health`).
