## Goal

## Context

The P7 consent gate (`src/surveillance/consent_gate.py`) currently manages four surveillance scopes: `surveillance.app_usage`, `surveillance.location`, `surveillance.notifications`, and `surveillance.clipboard`. These are stored in `VALID_SURVEILLANCE_SCOPES` as a `frozenset` and enforced by `check_consent()`.

Health data is the most sensitive surveillance category (CRITICAL classification, 365-day retention). It requires a **separate, explicit consent scope** — `surveillance.wearable.health.explicit` — that is opt-in by design. Unlike the other scopes that may be granted during initial setup, health consent requires the WAC-001..007 activation checklist to pass before consent can be granted.

The consent flow follows the same P7 pattern:
1. Discord command (`/health-consent grant`) triggers the flow
2. Confirmation prompt with scope description and data usage explanation
3. Redis flag set (`consent:scopes:surveillance.wearable.health.explicit` in DB2)
4. Database record written to `consent.consent_ledger`
5. Cache invalidated so next `check_consent()` picks up the new state

Revocation is immediate:
1. Discord command (`/health-consent revoke`) triggers the flow
2. `consent.consent_ledger` status updated to `WITHDRAWN`
3. Redis cache invalidated
4. All health data ingestion stops at the consent gate (fail-closed)
5. Optional data export before deletion (P14-021)

Consent gating occurs at two points:
- **POST /surveillance/health** (P14-006): explicit `check_consent("surveillance.wearable.health.explicit")` in the endpoint handler
- **Consumer pipeline** (P14-006): the health writer validates consent before each write

```python
"""Health consent lifecycle — grant, revoke, WAC checklist enforcement.

P14-007: Extends the P7 consent gate with health-specific consent
operations. All health data ingestion is gated behind the
``surveillance.wearable.health.explicit`` scope.
"""

from __future__ import annotations

import json
from dataclasses import dataclass
from datetime import datetime, timezone
from enum import StrEnum
from typing import Any, Callable, Protocol

import structlog
import redis.asyncio as aioredis

from src.surveillance.consent_gate import (
    CACHE_KEY_PREFIX,
    CACHE_TTL_SECONDS,
    ConsentStatus,
    invalidate_cache,
    _get_redis,
)

logger = structlog.get_logger()

HEALTH_CONSENT_SCOPE: str = "surveillance.wearable.health.explicit"
"""The consent scope that gates all health data ingestion."""

HEALTH_REDIS_KEY: str = f"consent:scopes:{HEALTH_CONSENT_SCOPE}"
"""Redis key for health consent state tracking."""


class WACGate(StrEnum):
    """WAC checklist gate identifiers (001-007)."""

    DEVICE_REGISTERED = "WAC-001"
    GADGETBRIDGE_VERIFIED = "WAC-002"
    WEBDAV_TLS_CONFIRMED = "WAC-003"
    HMAC_KEYS_PROVISIONED = "WAC-004"
    DB_SCHEMA_VERIFIED = "WAC-005"
    CONSENT_FLOW_TESTED = "WAC-006"
    MOCK_DATA_VALIDATED = "WAC-007"


WAC_GATES: tuple[WACGate, ...] = tuple(WACGate)
"""Ordered tuple of all WAC gates that must pass before health consent."""


@dataclass(frozen=True)
class WACChecklistResult:
    """Immutable result of WAC checklist verification."""

    all_passed: bool
    passed: list[str]
    failed: list[str]
    checked_at: datetime


@dataclass(frozen=True)
class HealthConsentResult:
    """Result of a health consent operation (grant/revoke/check)."""

    success: bool
    scope: str
    action: str
    reason: str
    timestamp: datetime


class _AsyncDbSession(Protocol):
    """Minimal protocol for async DB session."""

    async def execute(self, statement: Any, params: dict[str, Any] | None = None) -> Any: ...
    async def commit(self) -> None: ...
    async def rollback(self) -> None: ...
    async def close(self) -> None: ...


async def verify_wac_checklist(
    checklist_state: dict[str, bool],
) -> WACChecklistResult:
    """Verify all WAC-001..007 gates are passed.

    Args:
        checklist_state: Dict mapping gate ID (e.g. "WAC-001") to bool.

    Returns:
        WACChecklistResult with pass/fail details.
    """
    passed: list[str] = []
    failed: list[str] = []

    for gate in WAC_GATES:
        if checklist_state.get(gate.value, False):
            passed.append(gate.value)
        else:
            failed.append(gate.value)

    all_passed = len(failed) == 0
    logger.info(
        "wac_checklist_verified",
        all_passed=all_passed,
        passed_count=len(passed),
        failed_count=len(failed),
        failed_gates=failed if failed else None,
    )
    return WACChecklistResult(
        all_passed=all_passed,
        passed=passed,
        failed=failed,
        checked_at=datetime.now(timezone.utc),
    )


async def grant_health_consent(
    session_factory: Callable[[], _AsyncDbSession],
    granted_by: str = "faiz",
    checklist_state: dict[str, bool] | None = None,
) -> HealthConsentResult:
    """Grant health data consent after WAC checklist passes.

    MUST be preceded by a WAC checklist verification. If checklist_state
    is provided and any gates fail, the grant is blocked.

    Args:
        session_factory: Callable returning an async DB session.
        granted_by: Identifier of the consent granter.
        checklist_state: Optional WAC gate states for verification.

    Returns:
        HealthConsentResult indicating success or failure reason.
    """
    now = datetime.now(timezone.utc)

    # Step 1: Verify WAC checklist
    if checklist_state is not None:
        wac_result = await verify_wac_checklist(checklist_state)
        if not wac_result.all_passed:
            return HealthConsentResult(
                success=False,
                scope=HEALTH_CONSENT_SCOPE,
                action="grant_blocked",
                reason=f"WAC checklist incomplete — failed: {', '.join(wac_result.failed)}",
                timestamp=now,
            )

    # Step 2: Write ACTIVE consent to ledger
    session = session_factory()
    try:
        from sqlalchemy import text

        # Insert consent ledger entry (ACTIVE)
        stmt = text("""
            INSERT INTO consent.consent_ledger (scope, status, granted_by, granted_at, metadata)
            VALUES (:scope, :status, :granted_by, :granted_at, :metadata)
        """)
        await session.execute(stmt, {
            "scope": HEALTH_CONSENT_SCOPE,
            "status": ConsentStatus.ACTIVE.value,
            "granted_by": granted_by,
            "granted_at": now,
            "metadata": json.dumps({
                "wac_passed": True,
                "source": "P14-007",
                "scope_description": "Wearable health data collection for Guinevere care context",
            }),
        })

        # Insert consent event for audit trail
        event_stmt = text("""
            INSERT INTO consent.consent_events (scope, event_type, event_data, triggered_by, triggered_at)
            VALUES (:scope, :event_type, :event_data, :triggered_by, :triggered_at)
        """)
        await session.execute(event_stmt, {
            "scope": HEALTH_CONSENT_SCOPE,
            "event_type": "granted",
            "event_data": json.dumps({"wac_checklist": "PASSED", "granted_by": granted_by}),
            "triggered_by": granted_by,
            "triggered_at": now,
        })
        await session.commit()

        # Step 3: Set Redis flag
        redis_client = _get_redis()
        await redis_client.set(
            HEALTH_REDIS_KEY,
            json.dumps({"status": ConsentStatus.ACTIVE.value, "granted_at": now.isoformat()}),
        )

        # Step 4: Invalidate cached consent verdict
        await invalidate_cache(HEALTH_CONSENT_SCOPE)

        logger.info(
            "health_consent_granted",
            scope=HEALTH_CONSENT_SCOPE,
            granted_by=granted_by,
        )
        return HealthConsentResult(
            success=True,
            scope=HEALTH_CONSENT_SCOPE,
            action="granted",
            reason="Health data consent granted — WAC checklist passed",
            timestamp=now,
        )
    except Exception:
        await session.rollback()
        logger.exception("health_consent_grant_failed", scope=HEALTH_CONSENT_SCOPE)
        return HealthConsentResult(
            success=False,
            scope=HEALTH_CONSENT_SCOPE,
            action="grant_failed",
            reason="Database error during consent grant",
            timestamp=now,
        )
    finally:
        await session.close()


async def revoke_health_consent(
    session_factory: Callable[[], _AsyncDbSession],
    revoked_by: str = "faiz",
    reason: str = "user_requested",
) -> HealthConsentResult:
    """Revoke health data consent — stop collection immediately.

    Args:
        session_factory: Callable returning an async DB session.
        revoked_by: Identifier of the consent revoker.
        reason: Reason for revocation.

    Returns:
        HealthConsentResult indicating success.
    """
    now = datetime.now(timezone.utc)
    session = session_factory()

    try:
        from sqlalchemy import text

        # Update consent ledger to WITHDRAWN
        stmt = text("""
            INSERT INTO consent.consent_ledger (scope, status, granted_by, granted_at, metadata)
            VALUES (:scope, :status, :granted_by, :granted_at, :metadata)
        """)
        await session.execute(stmt, {
            "scope": HEALTH_CONSENT_SCOPE,
            "status": ConsentStatus.WITHDRAWN.value,
            "granted_by": revoked_by,
            "granted_at": now,
            "metadata": json.dumps({"revocation_reason": reason}),
        })

        # Insert revocation event
        event_stmt = text("""
            INSERT INTO consent.consent_events (scope, event_type, event_data, triggered_by, triggered_at)
            VALUES (:scope, :event_type, :event_data, :triggered_by, :triggered_at)
        """)
        await session.execute(event_stmt, {
            "scope": HEALTH_CONSENT_SCOPE,
            "event_type": "revoked",
            "event_data": json.dumps({"reason": reason, "revoked_by": revoked_by}),
            "triggered_by": revoked_by,
            "triggered_at": now,
        })
        await session.commit()

        # Clear Redis flag
        redis_client = _get_redis()
        await redis_client.delete(HEALTH_REDIS_KEY)

        # Invalidate cached consent verdict
        await invalidate_cache(HEALTH_CONSENT_SCOPE)

        logger.info(
            "health_consent_revoked",
            scope=HEALTH_CONSENT_SCOPE,
            revoked_by=revoked_by,
            reason=reason,
        )
        return HealthConsentResult(
            success=True,
            scope=HEALTH_CONSENT_SCOPE,
            action="revoked",
            reason=f"Health data consent revoked: {reason}",
            timestamp=now,
        )
    except Exception:
        await session.rollback()
        logger.exception("health_consent_revoke_failed", scope=HEALTH_CONSENT_SCOPE)
        return HealthConsentResult(
            success=False,
            scope=HEALTH_CONSENT_SCOPE,
            action="revoke_failed",
            reason="Database error during consent revocation",
            timestamp=now,
        )
    finally:
        await session.close()


async def check_health_consent_status() -> dict[str, Any]:
    """Check current health consent status from Redis or DB.

    Returns:
        Dict with status, granted_at, and is_active keys.
    """
    redis_client = _get_redis()
    try:
        raw = await redis_client.get(HEALTH_REDIS_KEY)
        if raw:
            data = json.loads(raw)
            return {
                "status": data.get("status", "unknown"),
                "granted_at": data.get("granted_at"),
                "is_active": data.get("status") == ConsentStatus.ACTIVE.value,
                "source": "redis_cache",
            }
    except Exception:
        logger.exception("health_consent_status_redis_error")

    return {
        "status": "unknown",
        "granted_at": None,
        "is_active": False,
        "source": "unavailable",
    }
```

## Troubleshooting

- **Issue:** `check_consent("surveillance.wearable.health.explicit")` raises `KeyError` or returns `_BLOCK_UNKNOWN_SCOPE`
  - **Solution:** The scope is not in `VALID_SURVEILLANCE_SCOPES`. Verify the frozenset was updated in `consent_gate.py`. Hot-reload the module or restart the service.
- **Issue:** Consent grant succeeds but `check_consent` still returns blocked
  - **Solution:** Cache TTL (300s) may not have expired. Run `await invalidate_cache("surveillance.wearable.health.explicit")` or wait for cache expiry.
- **Issue:** `consent.consent_ledger` has duplicate ACTIVE entries for the same scope
  - **Solution:** The `ORDER BY granted_at DESC LIMIT 1` in `_query_ledger()` means only the latest entry is read. Duplicates are harmless but can be cleaned: `DELETE FROM consent.consent_ledger WHERE scope = 'surveillance.wearable.health.explicit' AND status = 'ACTIVE' AND granted_at < (SELECT MAX(granted_at) FROM consent.consent_ledger WHERE scope = 'surveillance.wearable.health.explicit');`
- **Issue:** WAC checklist verification fails but the gates are actually passed
  - **Solution:** The `checklist_state` dict must contain all 7 gate IDs with `True` values. Missing keys are treated as `False`. Verify the input dict structure: `{"WAC-001": True, "WAC-002": True, ...}`.

## Notes

- **WAC-001..007 activation checklist** is implemented as a blocking gate in `verify_wac_checklist()`. Even if the operator has granted consent, no health data is ingested until all 7 gates pass. This is enforced by `grant_health_consent()` rejecting incomplete checklists.
- The consent scope name `surveillance.wearable.health.explicit` follows the P7 naming convention: `<domain>.<category>.<subcategory>.<granularity>` with `.explicit` suffix indicating opt-in-only status.
- **Confrontation boundary (ADR-001, ADR-002):** Health data is NEVER used for behavioral correction, confrontation, or punishment. This is enforced at the persona engine level (P14-013), not at the consent gate. The consent gate only controls whether data is collected.
- Revocation is immediate — next `check_consent()` call returns `allowed=False`. Any in-flight writes to `health.*` hypertables will fail at the next consent check.
- The `consent.consent_events` audit table captures every grant, revocation, and pause event for compliance.
- Cross-reference: P14-020 (WAC checklist implementation step), P14-021 (data export/deletion on revocation), P14-006 (health ingestion endpoint uses this scope).
