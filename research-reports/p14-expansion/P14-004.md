## Goal

Generate a health-specific 256-bit HMAC secret, encrypt it via SOPS, and provision it for both the VPS ingestion endpoint and the Gadgetbridge companion configuration — following the P7 surveillance HMAC pattern.

---

## Context

P14 health data ingestion reuses the P7 surveillance HMAC authentication pattern (see `src/surveillance/auth.py`). Every POST to `/surveillance/events` with `classification=health` must include a valid HMAC-SHA256 signature.

**Why a separate HMAC secret** instead of reusing the P7 surveillance HMAC:
- Blast radius isolation — compromising the health HMAC does not compromise smartphone surveillance
- Gadgetbridge companion config shares the secret with a third-party Android app (higher exposure surface than Tasker)
- Compliance readiness — post-launch data category encryption separation starts with separate authentication keys

**Binding decisions from ADR-021 and P7 pattern:**
- Same signing algorithm: HMAC-SHA256
- Same SOPS encryption method: `sops --encrypt --age <pubkey>` using existing age key
- Same secrets file: appended to `secrets/guinevere-secrets.yaml` under `health_hmac:` key
- Different from surveillance HMAC: separate file `secrets/health-hmac.yaml` for deployment isolation

## Commands

### Step 1: Generate Health HMAC Secret

```bash
ssh guinevere-vps << 'GEN'
# Generate 256-bit (32-byte) random hex secret
HEALTH_HMAC_SECRET=$(openssl rand -hex 32)
echo "Generated HMAC secret (32 bytes / 256 bits / 64 hex chars)"
echo "Length: $(echo -n $HEALTH_HMAC_SECRET | wc -c) chars"

# Write to temporary file for SOPS encryption
cat > /tmp/health-hmac-plain.yaml << SECRETS
# Guinevere Health HMAC Secret
# Used for Gadgetbridge / Mi Fitness ingestion authentication
# Generated: $(date -u +%Y-%m-%dT%H:%M:%SZ)
# Rotate: every 180 days (schedule in P14-004 notes)

health_hmac:
  secret: "${HEALTH_HMAC_SECRET}"
  algorithm: "HMAC-SHA256"
  created_at: "$(date -u +%Y-%m-%dT%H:%M:%SZ)"
  rotation_days: 180
SECRETS

echo "Plaintext template written to /tmp/health-hmac-plain.yaml"
GEN
```

### Step 2: Encrypt with SOPS

```bash
ssh guinevere-vps << 'ENCRYPT'
cd /home/guinevere/code/guinevere

# Get age public key
AGE_PUBKEY=$(grep "public key:" /home/guinevere/secrets/age-key.txt | awk '{print $4}')
echo "Using age public key: $AGE_PUBKEY"

# Encrypt the HMAC secret
sops --encrypt --age "$AGE_PUBKEY" /tmp/health-hmac-plain.yaml > secrets/health-hmac.yaml

# Set secure permissions
chmod 600 secrets/health-hmac.yaml

# Verify it's encrypted (should show ENC[...])
head -3 secrets/health-hmac.yaml
# Expected: health_hmac:
#           secret: ENC[AES256_GCM,data:...==

# Verify decryption works
sops -d secrets/health-hmac.yaml | head -8
# Expected: plaintext YAML with the actual hex secret

# Clean up plaintext
shred -u /tmp/health-hmac-plain.yaml
echo "Plaintext temp file shredded"
ENCRYPT
```

### Step 3: Append to Main Secrets File (Optional — Redundancy)

```bash
ssh guinevere-vps << 'APPEND'
cd /home/guinevere/code/guinevere

# Decrypt main secrets, append health HMAC, re-encrypt
sops -d secrets/guinevere-secrets.yaml > /tmp/main-secrets-decrypted.yaml

cat >> /tmp/main-secrets-decrypted.yaml << 'SECRETS'

  secret_ref: "secrets/health-hmac.yaml"  # canonical source

AGE_PUBKEY=$(grep "public key:" /home/guinevere/secrets/age-key.txt | awk '{print $4}')
sops --encrypt --age "$AGE_PUBKEY" /tmp/main-secrets-decrypted.yaml > secrets/guinevere-secrets.yaml

# Verify main secrets still decryptable
sops -d secrets/guinevere-secrets.yaml | grep -A 3 "health_hmac"

shred -u /tmp/main-secrets-decrypted.yaml
APPEND
```

### Step 4: Verification Script

Create a reusable verification script at `/home/guinevere/code/guinevere/scripts/verify-health-hmac.sh`:

```bash
ssh guinevere-vps << 'SCRIPT'
cat > /home/guinevere/code/guinevere/scripts/verify-health-hmac.sh << 'VERIFY'
#!/bin/bash
# verify-health-hmac.sh — Validate health HMAC secret provisioning
set -euo pipefail

SECRET_FILE="/home/guinevere/code/guinevere/secrets/health-hmac.yaml"

echo "=== Health HMAC Verification ==="

# 1. File exists with correct permissions
echo -n "1. File permissions: "
if [ -f "$SECRET_FILE" ]; then
    PERMS=$(stat -c '%a' "$SECRET_FILE")
    if [ "$PERMS" = "600" ]; then
        echo "PASS (600)"
    else
        echo "FAIL (got $PERMS, expected 600)"
        exit 1
    fi
else
    echo "FAIL (file not found)"
    exit 1
fi

# 2. SOPS can decrypt
echo -n "2. SOPS decryption: "
if sops -d "$SECRET_FILE" > /dev/null 2>&1; then
    echo "PASS"
else
    echo "FAIL (decryption error)"
    exit 1
fi

# 3. Secret is valid hex (64 chars)
echo -n "3. Secret format: "
SECRET=$(sops -d "$SECRET_FILE" | grep "secret:" | awk '{print $2}' | tr -d '"')
SECRET_LEN=$(echo -n "$SECRET" | wc -c)
if [ "$SECRET_LEN" -eq 64 ] && echo "$SECRET" | grep -qE '^[0-9a-f]{64}$'; then
    echo "PASS (64 hex chars)"
else
    echo "FAIL (${SECRET_LEN} chars or invalid hex)"
    exit 1
fi

# 4. HMAC signing produces valid output
echo -n "4. HMAC signing: "
TEST_PAYLOAD='{"event":"health_test","metric":"heart_rate","bpm":72}'
SIGNATURE=$(echo -n "$TEST_PAYLOAD" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $2}')
SIG_LEN=$(echo -n "$SIGNATURE" | wc -c)
if [ "$SIG_LEN" -eq 64 ]; then
    echo "PASS (signature: ${SIGNATURE:0:16}...)"
else
    echo "FAIL (signature length ${SIG_LEN})"
    exit 1
fi

# 5. Signature is deterministic
SIGNATURE2=$(echo -n "$TEST_PAYLOAD" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $2}')
if [ "$SIGNATURE" = "$SIGNATURE2" ]; then
    echo "5. Deterministic: PASS"
else
    echo "5. Deterministic: FAIL"
    exit 1
fi

echo ""
echo "=== All checks PASSED ==="
echo "Secret file: $SECRET_FILE"
echo "Algorithm: HMAC-SHA256"
echo "Key length: 256 bits"
VERIFY

chmod +x /home/guinevere/code/guinevere/scripts/verify-health-hmac.sh
SCRIPT
```

## Troubleshooting

- **Issue: `openssl rand -hex 32` produces 64-char output but verification expects 64 — this is CORRECT**
  - **Context:** 32 bytes × 2 hex chars per byte = 64 chars. No issue — this is the expected output.

- **Issue: `sops --encrypt` fails with "failed to encrypt: no creation rules matched"**
  - **Solution:** The file path `/tmp/health-hmac-plain.yaml` doesn't match the `.sops.yaml` `path_regex` (which expects `secrets/.*\.yaml$`). Use explicit `--age` flag as shown in commands above — it bypasses `.sops.yaml`.

- **Issue: `shred` command not found on VPS**
  - **Solution:** Install coreutils: `sudo apt install -y coreutils`. For Ubuntu, `shred -u` securely deletes (overwrite 3x + unlink). If unavailable, use: `dd if=/dev/urandom of=/tmp/health-hmac-plain.yaml bs=1 count=1024 && rm -f /tmp/health-hmac-plain.yaml`

- **Issue: HMAC verification produces different signatures for same payload**
  - **Solution:** Check for trailing newlines. Use `echo -n` (no newline) consistently. Gadgetbridge companion must also use `echo -n` or equivalent when computing HMAC.

- **Issue: `SOPS_AGE_KEY_FILE` environment variable not set**
  - **Solution:** Add to `~/.bashrc`: `export SOPS_AGE_KEY_FILE=/home/guinevere/secrets/age-key.txt`. Without this, sops commands will fail with "failed to decrypt". For systemd services, add `Environment=SOPS_AGE_KEY_FILE=/home/guinevere/secrets/age-key.txt` to the service unit file.

- **Issue: Can't decrypt after `newgrp` or SSH session change**
  - **Solution:** The `guinevere` user must have read access to the age key: `chmod 600 /home/guinevere/secrets/age-key.txt && chown guinevere:guinevere /home/guinevere/secrets/age-key.txt`.

## Notes

- **Key rotation schedule**: Every 180 days. Process: generate new secret → SOPS encrypt → update VPS config → update Gadgetbridge companion → keep old secret valid for 24h overlap period → revoke old secret. Automation in post-launch iteration.
- **Isolation from P7**: This HMAC secret is completely independent of the surveillance HMAC. Even if Gadgetbridge companion is compromised, smartphone surveillance (P7 Tasker) remains secure.
- **Same signing algorithm**: HMAC-SHA256 reused from P7's `src/surveillance/auth.py`. The auth module is device-agnostic — it reads the secret and algorithm from environment/settings, not hardcoded.
- **Gadgetbridge companion app**: This is the Android-side component that bundles health data into POST requests. The HMAC secret must be stored securely on the phone (Android Keystore preferred, Tasker variable encryption as fallback).
- **Post-launch consideration**: If complete key separation per data category is required for compliance, a future P14 step can split this into per-metric HMAC keys. Not needed for MVP.
- **Cross-reference**: P14-006 (ingestion endpoint validates this HMAC on every request), P7 surveillance (same auth.py module, different key), P0-012 (age key generation that created the encryption key used here).
