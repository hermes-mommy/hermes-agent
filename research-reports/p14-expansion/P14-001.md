## Goal

Procure a Gadgetbridge-compatible Xiaomi wearable and configure Gadgetbridge on Faiz's Android phone with WebDAV auto-export enabled, verified by a successful first data sync producing a SQLite `.db` file.

---

## Context

P14 wearable integration relies on Gadgetbridge as the primary data pipeline — no Xiaomi cloud dependency, no proprietary app telemetry. ADR-021 classifies wearable as post-launch, meaning all P14 infrastructure (steps P14-002 through P14-027) degrades gracefully when no device is connected.

This step bridges the physical world (buying a watch) with the software world (installing Gadgetbridge on the same Android phone used by P7 Tasker). The WebDAV auto-export feature in Gadgetbridge pushes a SQLite `.db` file every hour — the same file that P14-005 parses and P14-006 ingests.

Faiz is the only person who can complete the hardware procurement and Android-side setup. This step documents the exact procedure and verification commands.

**Binding decisions from ADR-021:**
- Wearable is not required for MVP — all persona, health, and surveillance features must work without it
- No active polling — batch push model via WebDAV
- Health data used ONLY for care context (never confrontation, correction, or punishment)

## Commands

### Phase A: Device Procurement

1. **Select device** from the Gadgetbridge-compatible list:
   - **Primary**: Xiaomi Watch S3 (AMOLED, SpO2, HR, sleep, GPS, body battery)
   - **Budget option**: Xiaomi Smart Band 9 (fewer metrics but all 7 P14 metrics supported)
2. **Purchase** from authorized Xiaomi retailer (Lazada, Shopee, Tokopedia — Indonesia-accessible)
3. **Unbox and charge** the device to 100% before pairing
4. **Initial pairing**: Pair with Xiaomi's Mi Fitness app FIRST (required for initial firmware setup), then unpair before Gadgetbridge install

### Phase B: Gadgetbridge Installation

```bash
# Option 1: F-Droid (recommended — stable releases)
# 1. Install F-Droid from https://f-droid.org
# 2. Search "Gadgetbridge" in F-Droid
# 3. Install nodomain.freeyourgadget.gadgetbridge

# Option 2: Direct APK from GitHub Releases
# 1. Open https://github.com/Freeyourgadget/Gadgetbridge/releases/latest
# 2. Download the .apk file
# 3. Enable "Install from unknown sources" in Android Settings
# 4. Install the APK

# Verify installation
pm list packages | grep nodomain.freeyourgadget.gadgetbridge
# Expected: package:nodomain.freeyourgadget.gadgetbridge
```

### Phase C: Device Pairing in Gadgetbridge

1. Open Gadgetbridge app
2. Tap "+" (Add Device) → your Xiaomi device should appear in Bluetooth scan
3. **IMPORTANT**: If device was paired with Mi Fitness, unpair from Mi Fitness first, then factory reset the watch (Settings → System → Reset)
4. Pair with Gadgetbridge — accept Bluetooth pairing on both phone and watch
5. Grant ALL permissions requested (Notifications, Location, Background access)
6. Verify device shows "Connected" in Gadgetbridge main screen

### Phase D: WebDAV Auto-Export Configuration

```
Gadgetbridge → Settings → Auto Export → Enable

Export location: WebDAV
WebDAV URL: https://<vps-domain-or-tailscale-ip>/guinevere/health/
Username: <from P14-002 SOPS — shared manually by Faiz>
Password: <from P14-002 SOPS — shared manually by Faiz>
Export format: Database (.db)
Export interval: Every 1 hour
Export on charge: Yes (extra sync when charging)
```

### Phase E: First Sync Verification

```bash
# On VPS — wait 1 hour OR trigger manual export in Gadgetbridge:
# Gadgetbridge → Device → "Export now"

# Check WebDAV upload directory on VPS
ssh guinevere-vps "ls -la /var/lib/guinevere/webdav/health/"

# Expected output: at least one .db file, e.g.:
# Gadgetbridge-2026-06-04.db

# Check file size (should be non-zero)
ssh guinevere-vps "find /var/lib/guinevere/webdav/health/ -name '*.db' -exec ls -lh {} \;"
```

## Verification

- [ ] Device purchased and paired with Gadgetbridge (device status = "Connected")
- [ ] Gadgetbridge version >= 0.80.0 installed (`pm dump nodomain.freeyourgadget.gadgetbridge | grep versionName`)
- [ ] WebDAV auto-export enabled with correct URL and credentials
- [ ] At least one `.db` file exists in `/var/lib/guinevere/webdav/health/`
- [ ] `.db` file is > 100KB (non-empty, contains actual health data)
- [ ] File modification time is within last 2 hours (proves automatic sync)
- [ ] Mi Fitness app unpaired and NOT syncing (prevents data conflicts)

```bash
# VPS-side verification
ssh guinevere-vps << 'EOF'
# Files present
ls -la /var/lib/guinevere/webdav/health/

# File recency (within last 7200 seconds = 2 hours)
find /var/lib/guinevere/webdav/health/ -name '*.db' -mmin -120 | head -5

# File integrity — SQLite header check
file /var/lib/guinevere/webdav/health/Gadgetbridge-*.db
# Expected: "SQLite 3.x database"

# Table listing via sqlite3
sudo apt install -y sqlite3 2>/dev/null
sqlite3 /var/lib/guinevere/webdav/health/Gadgetbridge-*.db ".tables"
# Expected output includes: DEVICE, USER, ACTIVITY_SAMPLE, etc.
EOF
```

## Troubleshooting

- **Issue: Gadgetbridge "Authentication required" on pairing**
  - **Solution:** Xiaomi devices require a pairing key. In Mi Fit app, go to Profile → Device → scroll to bottom. Gadgetbridge may auto-detect the key. If not, follow the Gadgetbridge Xiaomi pairing wiki for manual key extraction.

- **Issue: Device disconnects frequently**
  - **Solution:** Disable battery optimization for Gadgetbridge (Android Settings → Apps → Gadgetbridge → Battery → Unrestricted). Enable "Background connection" in Gadgetbridge settings.

- **Issue: WebDAV export fails with "Connection refused"**
  - **Solution:** Check that P14-002 is complete (WebDAV server running on VPS). Verify the phone can reach the VPS (try opening the WebDAV URL in phone browser — should show auth prompt, not timeout).

- **Issue: SQLite file is 0 bytes or has no tables**
  - **Solution:** Wait for the device to actually record data after pairing. Initial sync may be metadata-only. Wear the device for > 1 hour with heart rate monitoring enabled, then force manual export.

- **Issue: Mi Fitness conflicts with Gadgetbridge**
  - **Solution:** Must unpair from Mi Fitness completely. If Mi Fitness continues to interfere, uninstall it on the phone. Gadgetbridge is the sole data source for P14.

- **Issue: Android 14+ restricts background WebDAV**
  - **Solution:** Grant Gadgetbridge "Unrestricted data access" in Android Settings → Apps → Gadgetbridge → Mobile data & Wi-Fi → Allow background data.

## Notes

- **Shared device**: Gadgetbridge runs on the SAME Android phone as P7 Tasker. Both must coexist. No known conflicts — Gadgetbridge uses WebDAV (HTTP), Tasker uses HTTP POST to surveillance endpoint and does not touch Gadgetbridge's data.
- **Battery impact**: Gadgetbridge hourly sync is lightweight. Monitor via P14-022 Prometheus metrics (watch battery percent). Alert at < 20%.
- **Firmware updates**: Xiaomi pushes firmware updates via Mi Fitness. Reinstall Mi Fitness temporarily for firmware updates, then unpair again.
- **Device learning period**: First 28 days establish baseline metrics (per P14-009). No persona adjustments until warmup complete.
- **Fallback path**: If Gadgetbridge breaks (Xiaomi changes protocol), P14-008 Mi Fitness Cloud SDK fallback takes over. This device procurement step still provides value — the device works with both paths.
- **Privacy**: Health data stays local until WebDAV push. No data sent to Xiaomi cloud after uninstalling Mi Fitness.
- **Cross-reference**: P14-002 (WebDAV endpoint must exist before this step's sync can succeed), P14-005 (parses the .db files this step produces), P14-026 (mock data generator for testing without physical device).
