## Goal

Create a CLI tool that generates realistic synthetic health data for all 7 metrics with configurable date ranges, anomaly scenarios, and WebDAV upload, outputting normalized JSON matching the Gadgetbridge parser format for full pipeline testing without a physical device.

---

## Context

The wearable pipeline depends on a Xiaomi Watch S3/Band 9 that is not yet purchased (P14-001). Without mock data, the entire ingestion, analysis, persona integration, Discord commands, and Grafana dashboard cannot be tested. This tool fills that gap by producing synthetic data indistinguishable from real Gadgetbridge exports, enabling full integration testing and local development before the device arrives.

**Why not hand-crafted JSON fixtures?** Health data is temporal and voluminous -- a 30-day simulation for 7 metrics at 5-minute HR resolution produces approximately 8,640 HR data points alone. Manual fixtures would be error-prone, not parameterizable, and impossible to maintain as metric definitions evolve.

**Output format:** Normalized JSON list matching P14-005 `parse_gadgetbridge_export()` return format. Each event has `event_type: "health"`, `payload` with `metric` discriminator and `occurred_at` (ISO 8601 with timezone). The output can be written to a JSON file or POSTed directly to the `/surveillance/health` endpoint via the `--upload` flag.

**Four built-in scenarios:**
1. **normal** -- Healthy baseline: 7-8h sleep, 60-75 resting HR, 8,000-12,000 steps/day, SpO2 95-100%, HRV 40-60ms
2. **sleep-deprived** -- 3-5h sleep, elevated resting HR (+10%), reduced steps (-30%), lower HRV
3. **high-stress** -- 5-6h sleep, HR elevated 20% above baseline, HRV below 30ms, stress score elevated, SpO2 dips
4. **recovery** -- Gradual return to normal: sleep improving day-over-day, HR trending down, HRV trending up

**Mixed mode** (`--scenario mixed`) cycles through all four scenarios across the configured date range, simulating a realistic month.

**CLI interface:**
```
python -m src.surveillance.testing.mock_health_data --days 30 --scenario mixed --output health-mock-30d.json --upload
```

**AC-WEAR-017** requires this generator to "produce realistic test data for all metrics" -- this step fulfills that requirement.

### Step 2: Create `src/surveillance/testing/mock_health_data.py`

**Module structure overview** (detailed inline code at `src/surveillance/testing/mock_health_data.py`):

The generator module has three main components:

**A. Scenario Profiles** -- `MetricProfile` dataclass with per-metric (mean, stddev) tuples:
- `heart_rate_resting: (62.0, 8.0)`, `sleep_hours: (7.5, 0.8)`, `steps_daily: (9500.0, 2500.0)`, `spo2_pct: (97.5, 1.0)`, `hrv_rmssd: (48.0, 8.0)`, `stress_score: (35.0, 15.0)`, `body_battery: (75.0, 15.0)`
- `SCENARIO_PROFILES` dict maps profile names to MetricProfile instances with scenario-specific overrides

**B. `HealthDataGenerator` class** with deterministic seed support:
- `generate_dataset(days, scenario, start_date)` -- main entry point, returns `list[dict]`
- `_generate_day(date, profile)` -- generates one day: 288 HR points (5-min), 1 sleep session + stages, 1 daily activity, 4 SpO2 readings, 2 HRV readings, 1 stress score, 1 body battery
- `_blend_profiles(from, to, factor)` -- linear interpolation for recovery simulation
- `_clamp(value, min, max)` -- bound values to physiological ranges

**C. CLI entry point** (`if __name__ == "__main__"`):
- `argparse` with flags: `--days`, `--scenario`, `--output`, `--seed`, `--upload`, `--webdav-url`, `--webdav-user`, `--webdav-pass`
- `--upload` flag triggers `httpx` PUT to WebDAV endpoint with basic auth
- Prints summary statistics after generation: total events, metrics breakdown, scenario distribution

**Key generator implementation details:**
- Seed default = 42 for reproducible datasets (override with `--seed`)
- Timezone: `Asia/Jakarta` (WIB, UTC+7) -- matches WIB for all timestamps
- Heart rate uses circadian rhythm simulation: sinusoidal factor centered at 6 AM
- Sleep session spans previous night (22:00 to wake time) with stage breakdown
- Recovery profile blends from high-stress to normal via linear interpolation over the final phase

## Troubleshooting

- **Issue: `numpy` not found in virtualenv**
  - **Solution:** Run `.venv/bin/pip install numpy`. If numpy fails on the VPS (ARM/compatibility), use `random` module only with a `--no-numpy` flag that falls back to `statistics.NormalDist` for Gaussian generation.
- **Issue: WebDAV upload returns 401 despite correct credentials**
  - **Solution:** Verify the WebDAV basic auth credentials match the htpasswd file. The generator uses HTTP Basic Auth; ensure nginx/caddy config has `auth_basic_user_file` pointing to the correct path. Test manually with curl first.
- **Issue: Generated sleep data has negative awake time**
  - **Solution:** The stage percentage normalization should handle this. If negative values appear, check the `MetricProfile` sleep stage percentages -- they must sum to <= 1.0. The `_generate_day` method normalizes if awake < 0, but extreme outliers may still cause issues.
- **Issue: 30-day generation is slow (>30 seconds)**
  - **Solution:** The generator creates 288 HR points per day -- 8,640 points for 30 days plus other metrics. This is acceptable for a development tool. For CI pipelines, use `--days 3`. For performance optimization: pre-compute circadian rhythm arrays.
- **Issue: Output format mismatch with P14-005 parser**
  - **Solution:** Reference the actual `parse_gadgetbridge_export` return type from `src/surveillance/parsers/gadgetbridge_parser.py`. If the parser changes, update the generator's `_generate_day` to match. Add a schema validation step comparing generator output against the parser's return type annotation.

## Notes

- **Deterministic seed** (default 42) ensures reproducible test datasets. This is critical for integration tests (P14-027) that need deterministic GHI scores and anomaly detection outputs.
- **Data volume** -- 30 days at full resolution produces approximately 10,000+ events (~2MB JSON). For CI, use 3-7 day windows. The `--days` flag controls this density.
- **Metric physiological bounds** -- all generated values are clamped to realistic physiological ranges: HR 40-180 bpm, SpO2 88-100%, sleep 2-12h, steps 1,000-30,000, HRV 10-100ms, stress 0-100, body battery 5-100. Values outside these bounds indicate a profile configuration error.
- **WebDAV upload is optional** -- the `--upload` flag requires P14-002 to be operational. Without it, JSON files are written locally and can be manually POSTed to `/surveillance/health`.
- Cross-reference: P14-001 (device procurement -- generator bridges the gap before device arrives), P14-005 (parser -- output format must match), P14-002 (WebDAV -- upload target), P14-027 (integration test -- uses this generator for E2E test data).
- AC-WEAR-017 satisfied: "Mock health data generator produces realistic test data for all metrics." Verified via the 7-metric count check in verification.
