## Goal

Compute 28-day rolling statistics (mean, std, min, max, percentiles) for each health metric per day, store in `health.baseline`, handle gap-reset (>7 days) and warm-up periods, and run daily at 04:00 WIB via APScheduler.

---

## Context

Anomaly detection (P14-010) and the Guinevere Health Index (P14-011) both depend on knowing what "normal" looks like for Faiz's health metrics. The 28-day rolling baseline establishes this personal norm.

**Why 28 days?** Clinical convention for establishing a personal baseline in wearable health analytics. Four full weeks capture weekly patterns (weekday vs weekend sleep, activity cycles) while being short enough to adapt to genuine lifestyle changes.

**Baseline computation flow:**

```
Daily at 04:00 WIB:
  1. Query last 28 days of raw data from health.* hypertables
  2. Check for gaps: if any metric has > 7 consecutive days of no data → reset baseline for that metric
  3. If < 28 days of data total → mark as "building" (warm-up period)
  4. Compute statistics: mean, std, p5, p25, p50 (median), p75, p95, min, max
  5. Store one row per metric in health.baseline table
  6. Update baseline status: "active" (>= 28 days) or "building" (< 28 days)
```

**Gap handling rules:**
- ≤ 7 consecutive days of no data: interpolate (use existing baseline, filled values excluded from stats)
- > 7 consecutive days of no data: reset baseline for that metric — start fresh 28-day window
- This prevents stale baselines from masking genuine changes (e.g., Faiz stopped wearing the watch for 2 weeks)

**Warm-up period:**
- First 28 days after data collection begins: baseline status is `"building"`
- The GHI score and anomaly detection use the partial baseline but flag all outputs with `baseline_confidence: "low"`
- After 28 days with ≥ 80% data coverage: status transitions to `"active"`

**Output:** The `health.baseline` table contains one row per metric per computation date. This is consumed by:
- P14-010 (anomaly detection — ±20% threshold against baseline)
- P14-011 (GHI score — normalized scoring against personal norms)
- Grafana dashboard (P14-023 — baseline overlay on metric charts)

"""Personal baseline computation — 28-day rolling statistics per health metric.

P14-009: Computes daily baseline statistics (mean, std, percentiles, min, max)
for each health metric from the last 28 days of data in health.* hypertables.
Handles gap-reset (>7 days consecutive no data), warm-up period (<28 days),
and writes results to health.baseline for consumption by anomaly detection
(P14-010) and GHI scoring (P14-011).

APScheduler cron: daily at 04:00 WIB (21:00 UTC previous day).
"""

from __future__ import annotations

import statistics
from dataclasses import dataclass
from datetime import date, datetime, timedelta, timezone
from math import isnan
from typing import Any, Callable

import numpy as np
import structlog
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from sqlalchemy import text

logger = structlog.get_logger()

WIB = timezone(timedelta(hours=7))

# ---------------------------------------------------------------------------
# Constants
# ---------------------------------------------------------------------------

BASELINE_WINDOW_DAYS: int = 28
"""Rolling window for baseline computation (clinical convention)."""

GAP_RESET_THRESHOLD_DAYS: int = 7
"""Consecutive days without data that trigger a baseline reset."""

MIN_COVERAGE_PCT: float = 0.80
"""Minimum data coverage (80%) for a baseline to be considered 'active'."""

WARMUP_DAYS: int = 28
"""Minimum days of data before baseline transitions from 'building' to 'active'."""

# Metrics to compute baselines for (must match hypertable names / metric types)
BASELINE_METRICS: tuple[str, ...] = (
    "heart_rate",
    "sleep_duration",
    "sleep_efficiency",
    "steps",
    "spo2",
    "hrv",
    "stress",
)

# ---------------------------------------------------------------------------
# Domain types
# ---------------------------------------------------------------------------


@dataclass(frozen=True)
class BaselineStats:
    """Computed baseline statistics for a single metric on a single day."""

    metric: str
    computation_date: date
    mean: float
    stddev: float
    p5: float
    p25: float
    p50: float
    p75: float
    p95: float
    min_val: float
    max_val: float
    sample_count: int
    gap_days: int
    status: str

# Metric-specific data fetchers

async def _fetch_heart_rate_data(
    session: Any,
    start: date,
    end: date,
) -> list[float]:
    """Fetch heart rate values from health.heart_rate for the window."""
    stmt = text("""
        SELECT bpm FROM health.heart_rate
        WHERE time >= :start AND time < :end
    """)
    result = await session.execute(stmt, {
        "start": start,
        "end": end + timedelta(days=1),
    })
    return [float(row[0]) for row in result.fetchall()]

# Metric name → fetcher mapping
_METRIC_FETCHERS: dict[str, Callable] = {
    "heart_rate": _fetch_heart_rate_data,
    "sleep_duration": _fetch_sleep_duration_data,
    "sleep_efficiency": _fetch_sleep_efficiency_data,
    "steps": _fetch_steps_data,
    "spo2": _fetch_spo2_data,
    "hrv": _fetch_hrv_data,
    "stress": _fetch_stress_data,
}


# ---------------------------------------------------------------------------
# Gap detection
# ---------------------------------------------------------------------------


async def _count_consecutive_gap_days(
    session: Any,
    metric: str,
    before_date: date,
) -> int:
    """Count consecutive days with zero data before the given date.

    Queries day-by-day backwards from before_date. Stops counting when
    a day with data > 0 is found.

    Args:
        session: Async DB session.
        metric: Metric name.
        before_date: Date to count backwards from (exclusive).

    Returns:
        Number of consecutive days with zero data.
    """
    gap_days = 0
    check_date = before_date - timedelta(days=1)

    for _ in range(GAP_RESET_THRESHOLD_DAYS + 1):
        fetcher = _METRIC_FETCHERS.get(metric)
        if fetcher is None:
            break
        values = await fetcher(session, check_date, check_date + timedelta(days=1))
        if len(values) > 0:
            break
        gap_days += 1
        check_date -= timedelta(days=1)

    return gap_days


# ---------------------------------------------------------------------------
# Statistics computation
# ---------------------------------------------------------------------------


def _compute_statistics(
    values: list[float],
) -> dict[str, float] | None:
    """Compute baseline statistics from a list of metric values.

    Uses numpy for percentile calculations. Returns None if values
    list is empty or all values are NaN.

    Args:
        values: List of float metric values.

    Returns:
        Dict with mean, stddev, p5, p25, p50, p75, p95, min_val, max_val,
        or None if insufficient data.
    """
    if not values:
        return None

    arr = np.array(values, dtype=np.float64)
    arr = arr[~np.isnan(arr)]  # Remove NaN values

    if len(arr) == 0:
        return None

    return {
        "mean": float(np.mean(arr)),
        "stddev": float(np.std(arr, ddof=1)) if len(arr) > 1 else 0.0,
        "p5": float(np.percentile(arr, 5)),
        "p25": float(np.percentile(arr, 25)),
        "p50": float(np.percentile(arr, 50)),
        "p75": float(np.percentile(arr, 75)),
        "p95": float(np.percentile(arr, 95)),
        "min_val": float(np.min(arr)),
        "max_val": float(np.max(arr)),
    }


def _determine_status(
    sample_count: int,
    gap_days: int,
    days_of_data: int,
) -> str:
    """Determine baseline status: building, active, or reset.

    Args:
        sample_count: Number of data points in the window.
        days_of_data: Number of distinct days with data in the window.
        gap_days: Consecutive days with no data before this computation.

    Returns:
        'building' (< 28 days data), 'active' (>= 28 days + >= 80% coverage),
        or 'reset' (> 7 day gap triggered restart).
    """
    if gap_days > GAP_RESET_THRESHOLD_DAYS:
        return "reset"

    if days_of_data < WARMUP_DAYS:
        return "building"

    coverage = days_of_data / BASELINE_WINDOW_DAYS
    if coverage >= MIN_COVERAGE_PCT:
        return "active"

    return "building"


# ---------------------------------------------------------------------------
# Main baseline computation
# ---------------------------------------------------------------------------


async def compute_baseline(
    session_factory: Callable[[], Any],
    computation_date: date | None = None,
) -> dict[str, BaselineStats | None]:
    """Compute 28-day rolling baseline for all health metrics.

    Args:
        session_factory: Callable returning an async DB session.
        computation_date: Date to compute baseline for (default: today).

    Returns:
        Dict mapping metric name to BaselineStats (or None if computation failed).
    """
    if computation_date is None:
        computation_date = date.today()

    window_start = computation_date - timedelta(days=BASELINE_WINDOW_DAYS)
    window_end = computation_date

    results: dict[str, BaselineStats | None] = {}
    session = session_factory()

    try:
        for metric in BASELINE_METRICS:
            fetcher = _METRIC_FETCHERS.get(metric)
            if fetcher is None:
                logger.warning("baseline_unknown_metric", metric=metric)
                results[metric] = None
                continue

            # Fetch values for the 28-day window
            values = await fetcher(session, window_start, window_end)

            # Check for consecutive gap days
            gap_days = await _count_consecutive_gap_days(session, metric, computation_date)

            # Determine if baseline should reset
            if gap_days > GAP_RESET_THRESHOLD_DAYS:
                logger.info(
                    "baseline_gap_reset",
                    metric=metric,
                    gap_days=gap_days,
                    threshold=GAP_RESET_THRESHOLD_DAYS,
                )
                # Use only data after the gap (last 28 days from today, but
                # if gap > 7, the window effectively shrinks to post-gap days)
                values_post_gap = await fetcher(
                    session,
                    computation_date - timedelta(days=min(gap_days, BASELINE_WINDOW_DAYS)),
                    computation_date + timedelta(days=1),
                )
                values = values_post_gap

            stats = _compute_statistics(values)
            if stats is None:
                logger.info("baseline_no_data", metric=metric, computation_date=computation_date.isoformat())
                results[metric] = None
                continue

            # Count distinct days with data
            days_with_data = len({v for v in values if not isnan(v)}) if values else 0
            # Approximate days with data: for step-level metrics, count unique dates
            actual_days = min(days_with_data, BASELINE_WINDOW_DAYS)

            status = _determine_status(
                sample_count=len(values),
                gap_days=gap_days,
                days_of_data=actual_days,
            )

            baseline = BaselineStats(
                metric=metric,
                computation_date=computation_date,
                mean=stats["mean"],
                stddev=stats["stddev"],
                p5=stats["p5"],
                p25=stats["p25"],
                p50=stats["p50"],
                p75=stats["p75"],
                p95=stats["p95"],
                min_val=stats["min_val"],
                max_val=stats["max_val"],
                sample_count=len(values),
                gap_days=gap_days,
                status=status,
            )

            # Write to health.baseline
            await _store_baseline(session, baseline)
            results[metric] = baseline

            logger.info(
                "baseline_computed",
                metric=metric,
                status=status,
                sample_count=len(values),
                mean=round(stats["mean"], 2),
                gap_days=gap_days,
            )

        await session.commit()
    except Exception:
        await session.rollback()
        logger.exception("baseline_computation_failed", computation_date=computation_date.isoformat())
    finally:
        await session.close()

    return results


async def _store_baseline(
    session: Any,
    baseline: BaselineStats,
) -> None:
    """Write a BaselineStats row to health.baseline (idempotent upsert).

    Uses ON CONFLICT DO UPDATE to handle re-runs on the same date.
    """
    stmt = text("""
        INSERT INTO health.baseline (
            metric, computation_date, mean, stddev,
            p5, p25, p50, p75, p95, min, max,
            sample_count, gap_days, status
        ) VALUES (
            :metric, :computation_date, :mean, :stddev,
            :p5, :p25, :p50, :p75, :p95, :min, :max,
            :sample_count, :gap_days, :status
        )
        ON CONFLICT (metric, computation_date) DO UPDATE SET
            mean = EXCLUDED.mean,
            stddev = EXCLUDED.stddev,
            p5 = EXCLUDED.p5,
            p25 = EXCLUDED.p25,
            p50 = EXCLUDED.p50,
            p75 = EXCLUDED.p75,
            p95 = EXCLUDED.p95,
            min = EXCLUDED.min,
            max = EXCLUDED.max,
            sample_count = EXCLUDED.sample_count,
            gap_days = EXCLUDED.gap_days,
            status = EXCLUDED.status,
            computed_at = NOW()
    """)
    await session.execute(stmt, {
        "metric": baseline.metric,
        "computation_date": baseline.computation_date,
        "mean": baseline.mean,
        "stddev": baseline.stddev,
        "p5": baseline.p5,
        "p25": baseline.p25,
        "p50": baseline.p50,
        "p75": baseline.p75,
        "p95": baseline.p95,
        "min": baseline.min_val,
        "max": baseline.max_val,
        "sample_count": baseline.sample_count,
        "gap_days": baseline.gap_days,
        "status": baseline.status,
    })


# ---------------------------------------------------------------------------
# Scheduler registration
# ---------------------------------------------------------------------------


def register_baseline_job(
    scheduler: AsyncIOScheduler,
    session_factory: Callable[[], Any],
) -> None:
    """Register the daily baseline computation as an APScheduler cron job.

    Runs daily at 04:00 WIB (21:00 UTC previous day) — after the daily
    health summary at 03:00 WIB but before the 06:00 Mi Fitness fallback
    (P14-008). This ensures the baseline is computed using overnight data
    that was summarized at 03:00.

    Args:
        scheduler: APScheduler AsyncIOScheduler instance.
        session_factory: Callable returning an async DB session.
    """
    scheduler.add_job(
        compute_baseline,
        trigger="cron",
        hour=21,  # 21:00 UTC = 04:00 WIB
        minute=0,
        id="p14_baseline_computation",
        name="Health Baseline Computation (28-day rolling)",
        kwargs={
            "session_factory": session_factory,
        },
        misfire_grace_time=3600,
        coalesce=True,
    )
    logger.info("baseline_scheduler_registered", schedule="daily 04:00 WIB")


# ---------------------------------------------------------------------------
# Latest baseline query helper (for consumers)
# ---------------------------------------------------------------------------


async def get_latest_baseline(
    session_factory: Callable[[], Any],
    metric: str,
) -> BaselineStats | None:
    """Retrieve the most recent baseline for a given metric.

    Args:
        session_factory: Callable returning an async DB session.
        metric: Metric name (e.g. 'heart_rate', 'sleep_duration').

    Returns:
        BaselineStats if a baseline exists, None otherwise.
    """
    session = session_factory()
    try:
        stmt = text("""
            SELECT metric, computation_date, mean, stddev,
                   p5, p25, p50, p75, p95, min, max,
                   sample_count, gap_days, status
            FROM health.baseline
            WHERE metric = :metric
            ORDER BY computation_date DESC
            LIMIT 1
        """)
        result = await session.execute(stmt, {"metric": metric})
        row = result.fetchone()
        await session.commit()

        if row is None:
            return None

        return BaselineStats(
            metric=row[0],
            computation_date=row[1],
            mean=row[2],
            stddev=row[3],
            p5=row[4],
            p25=row[5],
            p50=row[6],
            p75=row[7],
            p95=row[8],
            min_val=row[9],
            max_val=row[10],
            sample_count=row[11],
            gap_days=row[12],
            status=row[13],
        )
    except Exception:
        logger.exception("baseline_get_latest_failed", metric=metric)
        return None
    finally:
        await session.close()

## Troubleshooting

- **Issue:** `ModuleNotFoundError: No module named 'numpy'`
  - **Solution:** Install numpy in the guinevere venv: `pip install numpy`. The baseline computation uses `numpy.percentile()` and `numpy.mean()`/`numpy.std()`.
- **Issue:** `health.baseline` table doesn't exist — `relation "health.baseline" does not exist`
  - **Solution:** Run the CREATE TABLE SQL in step 1 of Implementation Commands. If P14-003 already created it, verify: `\d health.baseline` in psql.
- **Issue:** All metrics return `"building"` even after 28 days of data
  - **Solution:** The `_determine_status()` function checks `days_of_data >= WARMUP_DAYS` AND `coverage >= 0.80`. If there are gaps within the 28-day window (e.g., 20 days of data out of 28), coverage is 71% < 80% → still "building". This is intentional — you need 80% data density for a reliable baseline.
- **Issue:** Baseline statistics are suspicious (mean = 0, std = 0)
  - **Solution:** Check raw data quality: `SELECT min(bpm), max(bpm), avg(bpm) FROM health.heart_rate WHERE time > NOW() - INTERVAL '28 days';`. If data is all zeros or constant, the Gadgetbridge parser (P14-005) may have a bug.
- **Issue:** `_count_consecutive_gap_days` is slow
  - **Solution:** The function queries day-by-day backwards. For production with large datasets, consider pre-computing a daily coverage summary table or using TimescaleDB continuous aggregates. The current approach is acceptable for MVP given the daily batch schedule.

## Notes

- **28-day window** is a clinical convention, not arbitrary. It captures 4 full weekly cycles. If Faiz's schedule changes (e.g., new job with different sleep pattern), the 28-day rolling window naturally adapts over time.
- **Gap reset (> 7 days)** is a safety feature. Without it, a 2-week vacation without the watch would produce a "normal" baseline that's actually stale. The reset ensures baselines reflect recent reality.
- **Warm-up period** is communicated to downstream consumers via the `status` field. P14-010 (anomaly detection) and P14-011 (GHI) must check this field and either defer anomaly detection or flag outputs with `baseline_confidence: "low"`.
- The `_METRIC_FETCHERS` registry is extensible. To add a new metric, add a fetcher function and register it. No other code changes needed.
- **APScheduler job ID `p14_baseline_computation`** is namespaced to avoid collision. It runs at 04:00 WIB, after the 03:00 daily summary (P14-012) but before the 06:00 Mi Fitness fallback (P14-008). This ordering ensures baselines include overnight data summarized at 03:00.
- Cross-reference: P14-003 (DB schema), P14-006 (data must be flowing), P14-010 (consumes baseline for anomaly detection), P14-011 (consumes baseline for GHI normalization).
