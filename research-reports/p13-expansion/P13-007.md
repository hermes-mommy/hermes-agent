### Step P13-007: Rate Limiter

**Type:** Expansion
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P13): pending`

**Goal:** Implement the P13 X Auto Poster rate limiter that enforces a 3-hour minimum interval, a maximum of 5 posts per WIB calendar day, night-mode queue holds from 23:00-06:00 WIB, and the `schedule="immediate"` override behavior.
**Dependencies:** P13-005 Queue Polling Loop, P13-006 Sidecar Parser, PostgreSQL or Redis runtime availability, P13 requirements section 3.
**Cost Impact:** $0/month if Redis or PostgreSQL is reused; no new infrastructure.
**ADR References:** ADR-015 (Secrets Management via SOPS+age), existing PostgreSQL/Redis architecture decisions, P13 requirements sections 3.1 through 3.3.
**Acceptance Criteria:** AC-POSTING-002 (Rate Limiting), AC-POSTING-003 (Immediate Post), AC-POSTING-001 (Queue Flow).
**Estimated Time:** 15-30 minutes.

#### Context

The P13 queue engine must avoid over-posting to X. The rate limiter decides whether the next queued item can be posted now, should be held until a later heartbeat, or must wait because the daily cap has already been reached. It tracks the last successful post time and the daily post count in PostgreSQL or Redis. Redis is acceptable for fast state, while PostgreSQL is better for durable audit history; choose one according to the current implementation plan and document the choice.

Core constraints:

- Minimum interval: 3 hours between non-immediate posts.
- Daily cap: maximum 5 successful posts per calendar day.
- Night mode: 23:00 through 06:00 WIB holds queue items without skipping them.
- Immediate override: `schedule="immediate"` bypasses the 3-hour interval and night mode.
- Daily cap still applies to immediate posts because every successful immediate post counts toward 5/day.

The limiter must return explicit English reason strings such as `allowed`, `interval_wait`, `daily_cap_reached`, or `night_mode_hold`. Holding is not failure: a held queue item remains pending and is retried on the next heartbeat.

#### Troubleshooting

- **Issue:** Night mode behaves differently on the VPS.
  - **Solution:** Use `zoneinfo.ZoneInfo('Asia/Jakarta')` explicitly; do not rely on host local timezone.
- **Issue:** Daily count resets at UTC midnight.
  - **Solution:** Store timestamps with timezone and compute day bucket in WIB.
- **Issue:** Immediate post ignores daily cap.
  - **Solution:** Evaluate daily cap first or always evaluate it even after interval/night-mode bypass.
- **Issue:** Held items disappear from queue.
  - **Solution:** Return a hold decision without changing the S3 state prefix.
- **Issue:** Last post time updates after failed X post.
  - **Solution:** Update limiter state only after the compose adapter verifies successful post completion.

#### Notes

- The limiter is a policy component; it should not call Gemini, decrypt cookies, or perform CDP posting.
- All operator-facing reason strings should be English by default.
- Redis keys or PostgreSQL rows must be namespaced to P13 X Auto Poster to avoid collisions with other Guinevere services.
- Use post-launch wording for future multi-account or advanced schedule features only.
- Keep immediate override conservative: it bypasses timing holds, not safety or daily caps.
