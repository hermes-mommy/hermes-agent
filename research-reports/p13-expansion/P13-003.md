### Step P13-003: Obscura CDP Dedicated Instance

**Type:** Infrastructure
**Status:** Not Started
**Risk:** High
**Git Commit:** `feat(P13): pending`

**Goal:** Deploy a dedicated Obscura browser automation instance on port 9223 with `--stealth` enabled, a dedicated `--storage-dir` for X session persistence, 1 worker, 256 MB RAM target, and no interference with existing MCP tools on port 9222.
**Dependencies:** P13-001 S3 Queue Setup completed; existing Obscura instance on port 9222 is operational with known service file; systemd `guinevere.slice` exists (from earlier phase); the X cookie injection in step P13-008 will target this port.
**Cost Impact:** Additional 256 MB VPS memory; no compute cost beyond marginal container usage.
**ADR References:** P13 requirements §5 (Session & Auth), §6 (X Posting Engine); existing Obscura configuration conventions from P6 (MCP Tools).
**Acceptance Criteria:** AC-POSTING-005 (Session Management), AC-POSTING-009 (Operations), AC-POSTING-012 (P13 GATE).
**Estimated Time:** 15-30 min
**Phase:** P13
**Integration:** X posting engine will CDP-connect to this port; port 9222 remains exclusively for MCP browser tools; Discord screen usage still available alongside posting.
**Default Language:** English
**LLM Defaults:** Not directly applicable; the caption and moderation pipeline uses Gemini Flash with Gemini Pro fallback, which operates out of process from the browser.

#### Context

P6 created an Obscura browser automation instance on port 9222 for the MCP tool set. That port runs screenshotting, Playwright control, and Hermes Agent tool connectivity. The X Auto Poster needs a dedicated browser instance on a separate port because:

- MCP tools on port 9222 may be in use when X posting needs to happen.
- The X session (cookies, auth state) must persist independently from generic MCP browsing.
- The `--stealth` flag and resource limits differ between services.
- A dedicated instance isolates X posting from general browsing or scraping loads.

The new instance uses port 9223, 1 worker, 256 MB RAM, and a dedicated storage directory. This mirrors the P6 setup but with X-appropriate config: stealth mode, persistent session, and no MCP tool socket.

#### Commands

```bash
# 1. Set instance variables.
export P13_OBSCURA_PORT=9223
export P13_OBSCURA_STORAGE_DIR="/var/lib/guinevere/x-poster/chromium-data"
export P13_OBSCURA_BIN="/usr/lib/obscura/chromium"  # adjust to actual path

# 2. Create the dedicated storage directory with correct ownership.
sudo mkdir -p "$P13_OBSCURA_STORAGE_DIR"
sudo chown -R guinevere:guinevere "$P13_OBSCURA_STORAGE_DIR"

# 3. Smoke-test the new instance port.
"$P13_OBSCURA_BIN" \
  --remote-debugging-port="$P13_OBSCURA_PORT" \
  --stealth \
  --storage-dir="$P13_OBSCURA_STORAGE_DIR" \
  --headless \
  --no-sandbox \
  --disable-gpu \
  --disable-dev-shm-usage \
  --user-data-dir="$P13_OBSCURA_STORAGE_DIR" \
  --disable-background-networking \
  --no-first-run \
  --disable-sync \
  --max_old_space_size=256 &
# Let process run for 15 s then kill for smoke test.
sleep 15
kill %1 2>/dev/null
```

#### Troubleshooting

- **Issue:** Port 9223 is already in use.
  - **Solution:** `ss -tlnp | grep 9223` to find the process; if it is another instance, either stop it or reassign P13 to 9224 with documentation.
- **Issue:** `--stealth` flag not recognized.
  - **Solution:** Verify the Obscura binary version supports `--stealth`; if not available, skip `--stealth` and document the gap for post-launch mitigation.
- **Issue:** Out-of-memory kill by systemd when both 9222 and 9223 run.
  - **Solution:** Reduce `--max_old_space_size` to 192 MB for the X instance; if the slice has too little memory, request operator approval to adjust `MemoryMax`.
- **Issue:** X pages fail to load in headless mode.
  - **Solution:** Add `--window-size=1280,720` and user-agent override; X sometimes checks `navigator.webdriver` even with stealth patches.
- **Issue:** CDP responds but later Playwright connections fail.
  - **Solution:** Ensure `--remote-debugging-pipe` is not used instead of `--remote-debugging-port`; confirm the Obscura process is running as user `guinevere`.

#### Notes

- This instance is strictly for the X posting engine. Do not use port 9223 for generic Playwright screenshots or data extraction.
- Port 9222 remains dedicated to MCP tools and Discord bot interactions; do not migrate or stop it for this step.
- Session cookies will be injected in P13-008 using the `Network.setCookie` CDP method; the `--storage-dir` ensures the session survives restarts.
- The Gemini Flash LLM for caption generation and Gemini Pro fallback operate independently of the CDP instance; only the x.com posting flow uses the browser.
- All serialized evidence should contain no decrypted session data, cookies, or X account content.
- Use `post-launch` for future enhancements such as multi-account instances on ports 9224+ or video/GIF posting.
