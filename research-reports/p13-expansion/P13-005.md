### Step P13-005: Queue Polling Loop

**Type:** Expansion
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P13): pending`

**Goal:** Implement the P13 X Auto Poster queue polling loop that polls S3 `guinevere-assets/x-poster/pending/`, selects one eligible object per cycle in FIFO order, moves it through the S3 prefix state machine, and recovers stale processing objects safely.
**Dependencies:** P13-001 S3 Queue Setup, P13-002 Windows Watchdog upload path, P13-004 systemd service skeleton, existing boto3 credentials scoped to `guinevere-assets/x-poster/`.
**Cost Impact:** S3 LIST/COPY/DELETE request cost only; no new infrastructure.
**ADR References:** ADR-015 (Secrets Management via SOPS+age), existing S3/IAM decisions in the Guinevere ADR index, P13 requirements section 2.2 and 7.4.
**Acceptance Criteria:** AC-POSTING-001 (Queue Flow), AC-POSTING-004 (Error Recovery), AC-POSTING-009 (Operations).
**Estimated Time:** 15-30 minutes.

#### Context

P13 X Auto Poster uses S3 prefixes as a durable queue. Images uploaded by the Windows watchdog land under `guinevere-assets/x-poster/pending/` with optional sidecar metadata files. The VPS queue engine must poll that prefix using an asyncio loop, claim exactly one post candidate per cycle, move it to `processing/`, and then hand it to downstream caption and posting stages. The queue is sequential by design: one post per cycle, no bulk draining, and no priority queue for this step.

The state machine is prefix-based:

- `pending/` -> ready for polling.
- `processing/` -> claimed by the queue engine.
- `posted/` -> successful X post.
- `failed/` -> terminal failure such as corrupt media.

Processing objects older than 30 minutes must be reclaimed to `pending/` to recover from crashes or interrupted workers. If an image is corrupt or unsupported, move it to `failed/` and record reason `corrupt_file`. If caption generation completed but X posting failed later, the item must return to `pending/` so the next cycle can retry with preserved metadata. Use English as the default language for queue-visible diagnostics and reason strings.

#### Troubleshooting

- **Issue:** `list_objects_v2` returns no contents even when files exist.
  - **Solution:** Verify bucket name, IAM prefix scope, and exact prefix `guinevere-assets/x-poster/pending/` including trailing slash.
- **Issue:** Sidecar JSON is selected as queue item.
  - **Solution:** Filter primary objects by image extension before sorting or claiming.
- **Issue:** Same object is processed twice.
  - **Solution:** Ensure claim transition moves the object to `processing/` before downstream work and re-lists after each claim.
- **Issue:** Crash leaves objects in `processing/` indefinitely.
  - **Solution:** Run stale reclaimer every heartbeat and compare `LastModified` against UTC now minus 30 minutes.
- **Issue:** Caption generated but post action fails.
  - **Solution:** Preserve generated caption metadata and move the image back to `pending/` for retry.
