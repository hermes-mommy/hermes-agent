### Step P13-001: S3 Queue Setup

**Type:** Infrastructure
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P13): pending`

**Goal:** Create the S3 queue foundation for P13 X Auto Poster using prefix `guinevere-assets/x-poster/`, dedicated prefix-scoped IAM credentials, state sub-prefixes, SSE-S3 encryption, posted-object version retention, and a boto3 polling skeleton for downstream queue steps.
**Dependencies:** P13 requirements finalized; existing Guinevere S3 bucket available; SOPS+age available for credential storage; AWS CLI or compatible S3 CLI authenticated with admin/bootstrap credentials.
**Cost Impact:** Low storage and request cost only; media files retained 90 days in `posted/` before archival.
**ADR References:** ADR-015 (Secrets Management via SOPS+age), existing S3/object-storage operational conventions, P13 requirements §2 and §10.
**Acceptance Criteria:** AC-POSTING-001 (Queue Flow), AC-POSTING-009 (Operations), AC-POSTING-012 (P13 GATE).
**Estimated Time:** 15-30 min
**Phase:** P13
**Integration:** whatsapp-adjacent expansion input pipeline; Discord control plane uses `/x-` commands in later steps.
**Default Language:** English
**LLM Defaults:** Gemini Flash primary; Gemini Pro fallback for downstream caption steps.

#### Context

P13 needs a durable queue between Faiz's Windows machine and the VPS posting engine. The queue is implemented as an S3 prefix state machine so Windows can upload images without requiring direct VPS access. The queue states are `pending/`, `processing/`, `posted/`, `failed/`, `held/`, and `archived/` under `guinevere-assets/x-poster/`.

This step only creates the object-storage foundation. It does not implement rate limiting, caption generation, Discord commands, or X posting. Later steps will build the Windows uploader, queue polling loop, session handling, and posting engine on top of this prefix contract.

Security is part of the foundation: the Windows watchdog must receive dedicated IAM credentials scoped only to the P13 prefix, not broad bucket credentials. Store credentials through SOPS-encrypted environment files and never paste raw access keys into evidence.

#### Commands

```bash
# 1. Set shell variables for this setup session.
# Do not write secrets to shell history; use a secure operator shell.
export P13_BUCKET="<existing-guinevere-assets-bucket>"
export P13_PREFIX="guinevere-assets/x-poster"
export P13_IAM_USER="guinevere-p13-x-poster-uploader"

# 2. Create marker objects for all state prefixes.
aws s3api put-object --bucket "$P13_BUCKET" --key "$P13_PREFIX/pending/.keep" --server-side-encryption AES256
aws s3api put-object --bucket "$P13_BUCKET" --key "$P13_PREFIX/processing/.keep" --server-side-encryption AES256
aws s3api put-object --bucket "$P13_BUCKET" --key "$P13_PREFIX/posted/.keep" --server-side-encryption AES256
aws s3api put-object --bucket "$P13_BUCKET" --key "$P13_PREFIX/failed/.keep" --server-side-encryption AES256
aws s3api put-object --bucket "$P13_BUCKET" --key "$P13_PREFIX/held/.keep" --server-side-encryption AES256
aws s3api put-object --bucket "$P13_BUCKET" --key "$P13_PREFIX/archived/.keep" --server-side-encryption AES256

# 3. Verify default bucket encryption or configure SSE-S3 if this bucket is dedicated.
aws s3api get-bucket-encryption --bucket "$P13_BUCKET"
aws s3api put-bucket-encryption --bucket "$P13_BUCKET" --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'

# 4. Create prefix-scoped IAM user for Windows watchdog uploads.
aws iam create-user --user-name "$P13_IAM_USER"

# 5. Write a least-privilege IAM policy document locally for review.
cat > /tmp/p13-x-poster-prefix-policy.json <<'JSON'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListOnlyP13Prefix",
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::<existing-guinevere-assets-bucket>",
      "Condition": {"StringLike": {"s3:prefix": ["guinevere-assets/x-poster/*"]}}
    },
    {
      "Sid": "ReadWriteOnlyP13Prefix",
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject", "s3:CopyObject"],
      "Resource": "arn:aws:s3:::<existing-guinevere-assets-bucket>/guinevere-assets/x-poster/*"
    }
  ]
}
JSON

# 6. Attach the policy after replacing the bucket placeholder.
aws iam put-user-policy --user-name "$P13_IAM_USER" --policy-name guinevere-p13-x-poster-prefix --policy-document file:///tmp/p13-x-poster-prefix-policy.json

# 7. Create access keys, then immediately store them in SOPS-managed env files.
aws iam create-access-key --user-name "$P13_IAM_USER"

# 8. Add lifecycle transition for failed/posted retention and archival.
cat > /tmp/p13-x-poster-lifecycle.json <<'JSON'
{
  "Rules": [
    {
      "ID": "p13-posted-archive-after-90-days",
      "Status": "Enabled",
      "Filter": {"Prefix": "guinevere-assets/x-poster/posted/"},
      "Transitions": [{"Days": 90, "StorageClass": "STANDARD_IA"}]
    },
    {
      "ID": "p13-failed-archive-after-7-days",
      "Status": "Enabled",
      "Filter": {"Prefix": "guinevere-assets/x-poster/failed/"},
      "Transitions": [{"Days": 7, "StorageClass": "STANDARD_IA"}]
    }
  ]
}
JSON
aws s3api put-bucket-lifecycle-configuration --bucket "$P13_BUCKET" --lifecycle-configuration file:///tmp/p13-x-poster-lifecycle.json
```

```python
# 9. Minimal boto3 polling skeleton for later P13-005 Queue Polling Loop.
import boto3

BUCKET = "<existing-guinevere-assets-bucket>"
PREFIX = "guinevere-assets/x-poster/pending/"

s3 = boto3.client("s3")

response = s3.list_objects_v2(Bucket=BUCKET, Prefix=PREFIX)
objects = [item for item in response.get("Contents", []) if not item["Key"].endswith(".keep")]
objects.sort(key=lambda item: item["LastModified"])

for item in objects[:1]:
    print(item["Key"], item["LastModified"], item["Size"])
```

#### Troubleshooting

- **Issue:** `AccessDenied` on `put-object` under `pending/`.
  - **Solution:** Verify the IAM policy resource includes `arn:aws:s3:::<bucket>/guinevere-assets/x-poster/*` and that the object key has no leading slash.
- **Issue:** `ListBucket` works for the whole bucket.
  - **Solution:** Tighten the `s3:prefix` condition to `guinevere-assets/x-poster/*` and retest out-of-prefix denial.
- **Issue:** boto3 returns zero queue objects.
  - **Solution:** Confirm uploaded image key starts with `guinevere-assets/x-poster/pending/` and is not only the `.keep` marker.
- **Issue:** versioning cannot be enabled for only `posted/`.
  - **Solution:** S3 bucket versioning is bucket-level; enable bucket-level versioning if approved, then enforce posted retention via lifecycle rules and evidence the decision.
- **Issue:** lifecycle update would overwrite existing rules.
  - **Solution:** Fetch current lifecycle JSON, merge P13 rules, and apply the merged document only after review.

#### Notes

- The S3 prefix is the contract for all later queue movement: pending → processing → posted, failed, or held → archived.
- Use `post-launch` for future enhancements such as SSE-KMS or cross-region media backup; do not label them as MVP follow-ups.
- Dedicated IAM credentials are mandatory for Windows uploads because the Windows watchdog should not inherit broad Guinevere infrastructure privileges.
- Gemini Flash and Gemini Pro are mentioned here only as downstream caption defaults; this step does not call the LLM.
- The queue should not drain on service startup. Later heartbeat steps poll on schedule and process at most one object per cycle.
