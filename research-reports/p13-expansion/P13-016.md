#### Context

P13-016 owns the irreversible final post action. It must click the inline X post button only after session health, compose text, media upload, and alt text are ready. It must then determine success or failure, move S3 objects to the correct prefix, tag posted objects, capture the post URL when available, and hand off notification data to Discord.

Primary action:

- Click `button[data-testid="tweetButtonInline"]`.

Success indicators:

- Toast containing `Your post was sent`.
- URL redirect or navigation back to timeline.
- Optional extraction of the post URL from the success UI or timeline link when available.

S3 outcome behavior:

- On success: move objects from `pending/` or `processing/` to `posted/`, tag with `Status=Posted` and `PostedAt=<timestamp>`.
- On failure: move to `failed/` or back to `pending/` based on error classification.
- Session expiration routes to `held/` through P13-010 recovery.
- Rate limit routes back to `pending/` for later scheduling.

#### Troubleshooting

- **Issue:** Post button is disabled.
  - **Solution:** Re-check caption length, media upload readiness, and account state. Classify as compose readiness failure if inputs are invalid.
- **Issue:** Toast is not observed but timeline redirects.
  - **Solution:** Treat redirect as success only when the post button click completed and no error dialog appears.
- **Issue:** Post URL cannot be extracted immediately.
  - **Solution:** Mark success with URL unavailable, include a best-effort timeline link, and let notification show that URL capture was not available.
- **Issue:** S3 move succeeds for media but fails for sidecar.
  - **Solution:** Treat as partial state transition failure, record audit evidence, and retry idempotently before notifying success.

#### Notes

- This is the only Tier 1 step in P13-013 through P13-016 that may publish to X.
- Keep final submission isolated behind explicit dry-run checks.
- S3 transition helpers must be idempotent because recovery may re-run after VPS interruption.
- Object tagging must use server timestamps in a consistent timezone-aware format.
- Discord notification must not include private file paths or raw credentials.
- Future post-launch enhancements can improve post URL discovery, but success detection must not depend on it.
