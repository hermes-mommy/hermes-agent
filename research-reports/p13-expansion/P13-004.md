### Step P13-004: Systemd Service

**Type:** Infrastructure
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P13): pending`

**Goal:** Create `guinevere-x-poster.service` systemd unit running as `Type=exec`, user `guinevere`, under `guinevere.slice`, with 256 MB RAM limit, restart on-failure with 3 retries, dependencies on `postgresql.service` and the Obscura 9223 instance, and environment secrets injected from SOPS.
**Dependencies:** P13-003 Obscura 9223 instance running; existing `guinevere.slice` systemd slice active; existing `guinevere` user with home directory; PostgreSQL service active; SOPS+age workflow functional for credential loading.
**Cost Impact:** No additional cost; the service runs on existing VPS allocation.
**ADR References:** ADR-016 (Secrets via SOPS+age), P13 requirements §10 (Operations), P13 requirements §5 (X Cookie Session).
**Acceptance Criteria:** AC-POSTING-009 (Operations), AC-POSTING-005 (Session Management), AC-POSTING-012 (P13 GATE).
**Estimated Time:** 15-30 min
**Phase:** P13
**Integration:** Service depends on Obscura port 9223 and PostgreSQL; Discord bot communicates with the poster through the persistent queue and may later add `/x-` commands.
**Default Language:** English
**LLM Defaults:** The caption pipeline inside this service uses Gemini Flash as primary LLM and Gemini Pro as fallback.

#### Context

The guinevere-x-poster service orchestrates the entire X Auto Poster pipeline: queue polling (P13-005), sidecar parsing (P13-006), rate limiting (P13-007), cookie injection (P13-008), session health checking (P13-009), caption generation (P13-011), content moderation (P13-012), media upload and posting (P13-014 through P13-016), error handling with retries and circuit breaker (P13-018 through P13-020), and Discord notifications (P13-021 through P13-025).

This step creates the systemd unit file that wraps the orchestrator, sets resource limits, declares dependencies, and loads secrets from SOPS-encrypted files. The service itself is marked `Type=exec` so systemd knows exactly when the process starts and stops.

The service is placed under `guinevere.slice` to inherit the existing memory and CPU accounting boundary. The `256M` RAM limit matches the Obscura 9223 resource target, ensuring the combined poster pipeline plus headless browser stays within the slice budget.

#### Pre-flight Checks

- [ ] `guinevere.slice` exists: `systemctl status guinevere.slice`
- [ ] `postgresql.service` is active: `systemctl is-active postgresql`
- [ ] Obscura 9223 instance is running or a systemd template for `obscura@9223` can serve as a dependency.
- [ ] `guinevere` user exists: `id guinevere`
- [ ] SOPS-encrypted environment file exists or a template is ready for the operator to fill.
- [ ] The poster orchestrator script exists or the unit file will point to `bash /usr/local/bin/guinevere-x-poster/run.sh` for now.
- [ ] SOPS decryption key (age key) is available to the `guinevere` user or can be loaded through the existing key path.
- [ ] All Discord slash commands in the P13 spec use `/x-` prefix.
- [ ] The storage path for media downloads before X upload is writable by `guinevere`.

#### Commands


```bash
# 2. Create working directory and media cache with correct ownership.
sudo mkdir -p "$P13_WORKING_DIR/workdir"
sudo mkdir -p "$P13_MEDIA_CACHE"
sudo chown -R guinevere:guinevere "$P13_WORKING_DIR"
sudo chown -R guinevere:guinevere "$P13_MEDIA_CACHE"
```

```ini
# 3. Create the systemd unit file: /etc/systemd/system/guinevere-x-poster.service
[Unit]
Description=Guinevere X Auto Poster — S3 queue engine, caption pipeline, and X posting
Documentation=https://github.com/<gh-org>/guinevere/wiki/P13
After=postgresql.service
After=obscura@9223.service
Requires=postgresql.service
Requires=obscura@9223.service
BindsTo=obscura@9223.service
PartOf=guinevere.slice

[Service]
Type=exec
User=guinevere
Group=guinevere
WorkingDirectory=/home/guinevere/guinevere-x-poster
EnvironmentFile=-/etc/guinevere/secrets/x-poster.env.age
ExecStartPre=/usr/local/bin/guinevere-x-poster/preflight.sh
ExecStart=/usr/local/bin/guinevere-x-poster/run.sh
ExecStopPost=/usr/local/bin/guinevere-x-poster/shutdown.sh
Restart=on-failure
RestartSec=5s
StartLimitBurst=3
StartLimitIntervalSec=60
MemoryMax=256M
MemoryHigh=192M
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/var/tmp/guinevere-x-poster
ReadWritePaths=/home/guinevere/guinevere-x-poster/workdir
PrivateTmp=true
NoNewPrivileges=true
KillMode=control-group
TimeoutStartSec=30s
TimeoutStopSec=15s

[Install]
WantedBy=multi-user.target
```

```bash
# 4. Create the preflight executable.
sudo tee /usr/local/bin/guinevere-x-poster/preflight.sh <<'PREF'
#!/usr/bin/env bash
set -euo pipefail

# Ensure SOPS file exists and is decryption-functional.
if [ -n "${P13_X_POSTER_SOPS_FILE:-}" ]; then
    /usr/bin/sops --decrypt "$P13_X_POSTER_SOPS_FILE" > /dev/null 2>&1 || {
        echo "FATAL: SOPS decryption failed for $P13_X_POSTER_SOPS_FILE"
        exit 1
    }
fi

# Confirm media cache is writable.
test -w "/var/tmp/guinevere-x-poster/media" || {
    echo "FATAL: media cache not writable"
    exit 1
}

# Verify Obscura CDP port 9223 responds.
if command -v curl &>/dev/null; then
    curl -sf http://localhost:9223/json/version > /dev/null || {
        echo "FATAL: Obscura 9223 is not responding"
        exit 1
    }
fi
PREF
sudo chown guinevere:guinevere /usr/local/bin/guinevere-x-poster/preflight.sh
sudo chmod +x /usr/local/bin/guinevere-x-poster/preflight.sh
```

```bash
# 5. Create a stub run.sh that later steps will replace with the real pipeline.
sudo tee /usr/local/bin/guinevere-x-poster/run.sh <<'RUN'
#!/usr/bin/env bash
set -euo pipefail

echo "guinevere-x-poster: starting run.sh (stub — will be replaced by orchestrator)"
echo "guinevere-x-poster: Obscura port 9223, 256 MB limit, user $(whoami)"

# Later: the real Python or Go orchestrator replaces this file.
# Until then, keep-alive so systemd sees the service as active.
sleep infinity
RUN
sudo chown guinevere:guinevere /usr/local/bin/guinevere-x-poster/run.sh
sudo chmod +x /usr/local/bin/guinevere-x-poster/run.sh
```

```bash
# 6. Create a noop shutdown handler.
sudo tee /usr/local/bin/guinevere-x-poster/shutdown.sh <<'SHUT'
#!/usr/bin/env bash
echo "guinevere-x-poster: shutdown handler called at $(date)"
SHUT
sudo chown guinevere:guinevere /usr/local/bin/guinevere-x-poster/shutdown.sh
sudo chmod +x /usr/local/bin/guinevere-x-poster/shutdown.sh
```

```bash
# 7. Install the unit and start the service.
sudo systemctl daemon-reload
sudo systemctl enable guinevere-x-poster.service
sudo systemctl start guinevere-x-poster.service
```

```bash
# 8. Verify the service state and slice accounting.
systemctl status guinevere-x-poster.service --no-pager
systemctl show guinevere-x-poster.service --property=MemoryMax,MemoryHigh,Type,User
systemd-cgtop --user="guinevere.slice" --iterations=1 2>/dev/null || systemd-cgtop --slice="guinevere.slice" --iterations=1
```

```bash

```

#### Troubleshooting

- **Issue:** Service fails to start with `start-limit-hit`.
  - **Solution:** Check `journalctl -u guinevere-x-poster.service --no-pager -n 30`. If preflight exits nonzero, fix the preflight condition. If Obscura 9223 is offline, start it first. Reset the start limit: `systemctl reset-failed guinevere-x-poster.service`.
- **Issue:** `sops --decrypt` fails in preflight.
  - **Solution:** Confirm the age private key is available to the `guinevere` user, and the environment file path is correct.
- **Issue:** Memory limit is too restrictive for the service.
  - **Solution:** Increase `MemoryMax=384M` and `MemoryHigh=256M` with operator approval, then reload the unit.
- **Issue:** `BindsTo=obscura@9223.service` causes dependency cycle.
  - **Solution:** Change `BindsTo` to `Requires=obscura@9223.service` and add `After=obscura@9223.service`. Document the looser binding.
- **Issue:** Service starts but loses S3 access.
  - **Solution:** Verify the `guinevere` user has access to the `[default]` or `guinevere` profile in `~/.aws/credentials` and that the profile is not restricted by `ProtectHome=strict` (use `ReadWritePaths` for `.aws` if needed).

#### Notes

- This step creates the service wrapper only. The actual queue polling, caption pipeline, X posting flow, and Discord notification logic are implemented in later P13 steps.
- All secrets (X cookies, AWS IAM keys) are loaded via SOPS-encrypted environment files; the unit references them as `EnvironmentFile=-/etc/guinevere/secrets/x-poster.env.age`. The leading `-` means missing file is not fatal for manual testing; the preflight script enforces the file presence.
- `ProtectSystem=strict` makes `/usr` and `/etc` read-only. The working directory and media cache are writable through `ReadWritePaths`. The `~/.aws` credentials file may need explicit `ReadWritePaths` if S3 access is configured for the `guinevere` user.
- Commands will use `/x-` prefix for later Discord functionality; no commands hardcoded in this unit.
- Gemini Flash is the primary LLM for caption generation; Gemini Pro is the fallback. Neither LLM runs inside the browser process.
- Use `post-launch` for future enhancements like `CPUAccounting=true`, dedicated cgroup controller tuning, or systemd socket activation.
