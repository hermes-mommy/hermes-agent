### Step P13-027: Daily Summary

**Type:** Application
**Status:** Not Started
**Risk:** Low
**Git Commit:** `feat(P13): pending`

**Goal:** Implement a scheduled daily summary cron job at 20:00 WIB that reports today's X Auto Poster activity — posts posted, failed, pending — with the last 3 post previews — posted to `#guinevere-status`.
**Dependencies:** P13-021 Post Notification, P13-022 Status Commands, P13-026 Grafana Dashboard (per-post PostgreSQL log), existing APScheduler instance (P5), existing Discord integration.
**Cost Impact:** $0/month; uses existing scheduler, Discord, and PostgreSQL infrastructure.
**ADR References:** P13 requirements sections 8.1, 8.2, and 9.2; P5 Agent Loop for scheduler pattern.
**Acceptance Criteria:** AC-POSTING-008, AC-POSTING-012.
**Estimated Time:** 2 hours.

#### 1. Context

Faiz needs a daily digest of X Auto Poster activity without checking the dashboard or running `/x-status` manually. The daily summary runs at 20:00 WIB (12:00 UTC) via the existing APScheduler instance used by the P5 agent loop. It queries the `p13_post_log` table for the current calendar day (WIB timezone), aggregates by status, formats a concise embed, and posts to `#guinevere-status`.

The summary includes:
- **Posted count:** Number of successful posts today.
- **Failed count:** Number of failed posts today, with a breakdown by error reason.
- **Pending count:** Current queue depth.
- **Last 3 posts:** Caption preview (truncated to 100 characters), image count, and timestamp for the three most recent successful posts.

The summary should be informative at a glance. Faiz should be able to tell within seconds whether the system is healthy, whether there are concerning failure patterns, and whether the queue is under control.

#### 4. Implementation Requirements

- Schedule a daily cron job at 20:00 WIB (12:00 UTC) using APScheduler.
- Use the existing P5 scheduler instance; do not create a separate scheduling mechanism.
- Query `p13_post_log` for rows where `timestamp` falls in the current calendar day in WIB timezone.
- Aggregate by `post_status` to get counts per status.
- For failed posts, group by `error_reason` to include a failure breakdown line.
- Query the 3 most recent successful posts (`post_status = 'success'`) ordered by `timestamp DESC`.
- For each of the last 3 posts, extract: caption_preview (first 100 characters), image key basename, and posted timestamp (WIB).
- Query P13-022's queue depth for current pending count.
- Build a Discord embed with the following structure:

```
📊 **P13 X Auto Poster — Daily Summary**
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
**Date:** 2026-06-03 (WIB)

**Today:**
✅ Posted: 3
❌ Failed: 1 (1 content_blocked)
⏳ Pending: 2

**Last 3 Posts:**
1. "Sunset over the rice fields..." — 2026-06-03 14:30
2. "New feature drop incoming..." — 2026-06-03 11:15
3. "Morning inspiration: ..." — 2026-06-03 08:00
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
ℹ️ Dashboard: http://grafana/d/p13-x-poster
```

- Send the embed to `#guinevere-status` channel.
- Handle edge case: no posts today → "No posting activity today." with current queue depth.
- Handle edge case: no failed posts → omit failure breakdown.
- Handle edge case: fewer than 3 posts → show all available.
- Handle edge case: log query returns empty result set → show 0 for all counts.
- Handle edge case: scheduler fires at 20:00 WIB but timezone is misconfigured → log timezone offset for debugging.
- Log daily summary generation with timestamp, counts, and delivery status.
- Implement idempotency guard: if a summary was already sent today (check log or flag), skip and log duplicate prevention.
- Do not include raw S3 keys, full captions, or sensitive data in the summary.

#### 8. Troubleshooting

- **Issue:** Summary fires at wrong time due to timezone misconfiguration.
  - **Solution:** Log the cron job's computed next fire time in both UTC and WIB on registration. Verify against 20:00 WIB (12:00 UTC).
- **Issue:** Last 3 posts show truncated captions that are unreadable.
  - **Solution:** Increase preview to 120 characters or include image identifier for context.
- **Issue:** Summary embed exceeds Discord 2000-character limit.
  - **Solution:** Split into two embeds or compress failure breakdown into single-line summaries.
- **Issue:** APScheduler job fires multiple times.
  - **Solution:** The idempotency guard (check log for today's date) prevents duplicate sends; verify the guard resets at calendar day boundary.
- **Issue:** Log query is slow on large p13_post_log tables.
  - **Solution:** Ensure the timestamp index is created; query by `timestamp::date` in WIB timezone.
- **Issue:** Summary fails because `#guinevere-status` channel ID changed.
  - **Solution:** Use a configurable environment variable for the channel ID; log delivery failures clearly.

#### 9. Notes

- 20:00 WIB is chosen because it falls after typical end-of-day activities in WIB timezone.
- The summary is informational only — it does not trigger any automatic action.
- Failure breakdown by reason helps Faiz identify systemic issues (e.g., repeated content_blocked).
- The summary is sent to `#guinevere-status`, not `#guinevere-alerts` — it is a digest, not an alert.
- Keep the embed suitable for quick mobile viewing — Faiz may be away from desk at 20:00 WIB.
- Post-launch iteration could include average latency, trending hashtags, or caption sentiment.
