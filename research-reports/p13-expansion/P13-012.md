### Step P13-012: Content Moderation

**Type:** Application
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P13): pending`

**Goal:** Implement the LLM-based content moderation gate that scans the image and the generated caption for unsafe content categories — NSFW, violence, hate speech, PII — and blocks the post by moving the S3 object to `failed/` with reason `content_blocked` plus a Discord notification in `#guinevere-alerts`. No auto-blur or redaction is applied; the moderator only blocks or passes.
**Dependencies:** P13-011 Caption Generator (post-generation input), P13-006 Sidecar Parser (image context), LLMRouter as 9Router, Discord notification integration for `#guinevere-alerts`.
**Cost Impact:** $0/month additional (Flash is used for moderation at low cost).
**ADR References:** P13 requirements sections 4.3, 4.4, 7.1, 8.1; existing safety/consent policies.
**Acceptance Criteria:** AC-POSTING-006 (safe content, content moderation blocks unsafe), AC-POSTING-007 (block notification sent).
**Estimated Time:** 4 hours

#### Context

P13 posts are visual content published to a public X account. P13-011 generates the caption, but both the image and the text must be checked before they reach the compose/post pipeline. This step adds a content moderation gate that runs after P13-011 completes and before the compose/post pipeline in P13-014 or P13-016.

The moderator uses an LLM call (Gemini Flash, same 9Router) with a prompt that classifies the image and caption content as either safe or unsafe. If unsafe, it must output one of the block reasons: `nsfw`, `violence`, `hate_speech`, `pii`, or `other_unsafe`. The image can be provided to the LLM via a model that accepts image inputs (Gemini is multimodal) or a caption-only text check with an explicit note that the image context may have been analyzed earlier. For the MVP, a text-only moderation check on the generated caption is the baseline; full image-plus-text multimodal moderation can be enabled after launch if Gemini accepts direct image encoding from S3 URLs.

On block, the system must move the image and sidecar object pair from `processing/` to `failed/` with the moderation reason applied as a structured log field, then send a Discord embed notification to `#guinevere-alerts`. The notification should include the filename and the moderation reason for Faiz to investigate.

No blur, redaction, or selective sanitization is applied. The poster remains responsible for the content policy; the LLM moderator is a best-effort gate that ought to catch the most common violations.

#### Troubleshooting
- **Issue:** LLM false positive — a harmless caption is classified as unsafe.
  - **Solution:** The moderator is a best-effort gate; Faiz reviews alerts and can retry blocked posts. Do not auto-unblock.
- **Issue:** LLM false negative — unsafe caption passes the gate.
  - **Solution:** X may still flag the post. Faiz is responsible for content policy. Log the miss for prompt refinement.
- **Issue:** Moderation LLM fails or times out.
  - **Solution:** Treat as safe-pass-by-default, log the failure, and let the post proceed. The system must not stall on moderation failures.
- **Issue:** Image-based moderation requires direct file access that is not available.
  - **Solution:** MVP uses text-only caption checking. Document that multimodal image moderation is post-launch and will require a Gemini Vision model call with an S3-presigned URL.
- **Issue:** Discord alert contains sensitive personal data in the caption text.
  - **Solution:** Only include the moderation reason, filename, and a truncated/non-sensitive excerpt if generating a summary. Exclude full caption text if it contains potential PII.

#### Notes
- This step is purely a safety gate. It must not alter the image or caption, only block or pass.
- Always pass by default if the LLM call fails; a blocked post due to LLM failure is worse than a false negative.
- Do not add retry logic for blocked posts. `content_blocked` is a final terminal state for the object in the post queue.
- Use Gemini Flash for cost by default. Fallback to Gemini Pro only if Flash is unavailable; moderation failure simply passes the item.
- The alert must be actionable but minimal: `Content blocked: <filename> — Reason: <category>`. No full caption text unless Faiz explicitly requests it.
- Faiz is ultimately responsible for content policy compliance. The moderation gate is a helper, not a guarantee.
- Use `post-launch` for describing future full image-text multimodal moderation.
