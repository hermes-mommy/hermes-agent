### Step P13-017: Dry-Run Mode

**Type:** Application
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P13): pending`

**Goal:** Implement `/x-dryrun <filename>` so Faiz can run the full X Auto Poster pipeline simulation without composing, clicking, or changing S3 object state.
**Dependencies:** P13-005 Queue Polling Loop, P13-006 Sidecar Parser, P13-007 Rate Limiter, P13-009 Session Health Check, P13-011 Caption Generator, P13-012 Content Moderation, P13-015 Media Upload validation.
**Cost Impact:** Low Gemini usage only when caption or alt text is generated; no X posting side effects.
**ADR References:** ADR-015 Secrets Management via SOPS+age, ADR-016 Cookie/session pattern, PersonaSafetyPolicy consent boundaries.
**Acceptance Criteria:** AC-POSTING-006, AC-POSTING-007, AC-POSTING-010.
**Estimated Time:** 3 hours.

#### 1. Context

Dry-run mode is the operator-safe validation path for P13. It must simulate the same decision path as a real post while proving that no external X post is created and no S3 queue state changes are made.

The command is invoked from Discord as `/x-dryrun <filename>` and is restricted to Faiz. It should locate the target object in the queue, read sidecar metadata, run session health checks, generate or reuse caption and alt text, validate media constraints, run content moderation, and evaluate rate-limit readiness.

The implementation must explicitly skip CDP compose navigation, media attachment into X, tweet button interaction, and S3 prefix transition. The result is a Discord embed showing the generated caption, alt text, hashtags, rate-limit result, moderation result, and clear dry-run marker.

#### 4. Implementation Requirements

- Add or update a Faiz-only Discord slash command `/x-dryrun <filename>`.
- Resolve the filename against `guinevere-assets/x-poster/pending/` without moving the object.
- Load the matching sidecar JSON and apply the same validation used by live posting.
- Run session health check because dry-run must prove the account would be ready.
- Run media preparation validation locally, including format, size, image count, and alt text readiness.
- Run rate-limit read-only check and show whether a live post would be allowed now.
- Generate caption and alt text when sidecar values require LLM generation.
- Run content moderation and block the simulated result if moderation would block live posting.
- Do not navigate to `https://x.com/compose/post`.
- Do not click any X post button.
- Do not move, copy, delete, tag, or rewrite the S3 object or sidecar.
- Do not mutate retry counters, circuit breaker counters, or posting metrics except optional dry-run metrics.
- Return a Discord embed labeled `DRY RUN — no post created`.

#### 8. Troubleshooting

- **Issue:** dry-run cannot find filename.
  - **Solution:** Normalize basename matching and reject ambiguous duplicates with an explicit Discord error.
- **Issue:** dry-run attempts live CDP compose navigation.
  - **Solution:** Split pipeline into `simulate_post_plan` and `execute_post_plan`; dry-run may only call the simulator.
- **Issue:** generated caption exceeds 280 characters.
  - **Solution:** Reuse live caption validation and return validation failure in the embed.
- **Issue:** moderation blocks content.
  - **Solution:** Report moderation reason in the dry-run embed and keep S3 state unchanged.

#### 9. Notes

- Dry-run is a safety and QA feature, not a queue-processing feature.
- The command should be useful before launch and throughout post-launch maintenance.
- Dry-run must never hide failures behind generic success text.
- If session is expired, dry-run reports that live posting would fail and links Faiz to re-auth instructions.
- If rate limit is active, dry-run still shows generated content but marks live post as not currently allowed.
