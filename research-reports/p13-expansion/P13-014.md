#### Context

The compose adapter is responsible for reaching a ready X compose box and inserting generated or operator-provided caption text. It must use the dedicated Obscura CDP instance on port 9223 and never share the browser instance used for other MCP or scraping work.

Navigation strategies:

1. Navigate directly to `https://x.com/compose/post`.
2. If direct navigation fails but the home timeline is healthy, click the visible `Post` button.

Text input strategies for X Draft.js contenteditable editor:

1. Primary: `page.locator('[data-testid="tweetTextarea_0"]').fill(caption)`.
2. Fallback: CDP `Input.insertText` after focusing the editor.
3. Fallback 2: clipboard paste after focusing the editor.

The adapter must wait for DOM stability before interacting with the editor. DOM change failures are high-risk because they can break all posting, so selectors should be centralized and observable.

#### Troubleshooting

- **Issue:** Direct compose URL redirects to login.
  - **Solution:** Treat as session expired. Move active queue item to held state through P13-010 recovery path.
- **Issue:** `fill()` fails because Draft.js rejects programmatic editing.
  - **Solution:** Focus the editor and use CDP `Input.insertText`, then verify text content.
- **Issue:** Clipboard fallback is blocked by browser permissions.
  - **Solution:** Keep clipboard as last fallback and surface classified DOM/input failure if it cannot run.
- **Issue:** Inserted text appears duplicated.
  - **Solution:** Clear editor through supported UI interaction before fallback insertion and verify final text exactly once.
