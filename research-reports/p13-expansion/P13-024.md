### Step P13-024: Delete Command

**Type:** Application
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P13): pending`

**Goal:** Implement `/x-delete <post_id>` — a Faiz-only Discord command that navigates to a specific tweet URL via CDP/Obscura, performs the delete action through the browser UI, and verifies deletion success.
**Dependencies:** P13-003 Obscura 9223 Instance, P13-014 Compose Adapter, P13-016 Post Action, P13-021 Post Notification, existing Discord infrastructure.
**Cost Impact:** $0/month; reuses existing Obscura CDP connection on port 9223.
**ADR References:** P13 requirements sections 6.1, 6.2, and 8.2; ADR-015 for credential safety.
**Acceptance Criteria:** AC-POSTING-011, AC-POSTING-012.
**Estimated Time:** 3 hours.

#### 1. Context

Post-launch damage control requires removing incorrect or sensitive posts quickly. `/x-delete` accepts an X post ID (numeric tweet ID) and orchestrates browser-based deletion via the same Obscura CDP instance used for posting. The flow navigates to `https://x.com/guinevere/status/<post_id>`, opens the post menu, clicks Delete, confirms the deletion dialog, and verifies the post is gone.

This is a CDP-based approach because the MVP does not have X API access. Browser deletion is inherently fragile — X's DOM structure changes frequently. The command must include robust selector fallbacks and explicit timeout management. Post-launch integration with the official X API Delete endpoint is a recommended reliability upgrade, not an MVP requirement.

Session health is verified before any deletion attempt. If the session is expired, the command returns an error directing Faiz to re-authenticate first. The deleted post's S3 object in `/posted/` is moved to `/failed/` with reason `"deleted_by_operator"` to reconcile system state.

#### 4. Implementation Requirements

- Register `/x-delete` as a Faiz-only slash command with one required option: `post_id` (string, numeric).
- Accept post_id as a string to handle large numeric values without precision loss.
- Construct tweet URL as `https://x.com/guinevere/status/{post_id}`.
- Perform session health check before any deletion attempt.
- If session expired, return error: "Session expired — please re-authenticate before deleting."
- Navigate to tweet URL via CDP page navigation with 15-second timeout.
- Verify the page loaded and shows a tweet (not "This post was deleted" or "Post not found").
- Locate and click the three-dot menu button near the post (primary selector: `div[data-testid="caret"]`, fallback: `div[aria-label="More"]`).
- Wait for the dropdown menu to appear (primary selector: `div[data-testid="Dropdown"]`).
- Click the Delete menu item (primary selector: `span:has-text("Delete")`, fallback: `div[data-testid="Delete"]`).
- Wait for the confirmation dialog (primary selector: `div[data-testid="confirmationSheetDialog"]`).
- Click the Confirm delete button (primary selector: `button[data-testid="confirmationSheetConfirm"]`).
- Wait for navigation or confirmation that the post is no longer available.
- Verify deletion by checking URL is no longer the tweet page or page shows "Post deleted."
- On success, move S3 object from `/posted/` to `/failed/` with reason `"deleted_by_operator"`.
- If the posted object records tweet URL, clear or update the link field.
- Return ephemeral confirmation embed with post_id, deleted timestamp, and note: "Post removed. S3 state reconciled."
- Handle edge case: post_id does not exist (returns 404 or "Post not found") → return error without further action.
- Handle edge case: delete dialog does not appear → retry selector with fallback; if still not found, abort and report.
- Handle edge case: post already deleted → note the state and reconcile S3 if possible.
- Handle edge case: session lost during flow → abort and report partial state.
- Handle edge case: three-dot menu not found → try alternative selectors for different X UI versions.
- Log delete execution with post_id, timestamp, duration, and outcome status.
- Do not store raw post content or sensitive data in command logs.

#### 8. Troubleshooting

- **Issue:** X three-dot menu selector changed in new UI rollout.
  - **Solution:** Maintain a centralized selector config file; update selectors without code changes; log selector failures with the attempted selector string.
- **Issue:** delete confirmation button is disabled.
  - **Solution:** X may require scrolling within the dialog; add a small delay or scroll action before clicking confirm.
- **Issue:** post_id does not belong to Guinevere's account.
  - **Solution:** Verify the tweet author after navigation; abort if the post is not by Guinevere.
- **Issue:** CDP page crashes or Obscura is unresponsive.
  - **Solution:** Set a 30-second total timeout for the delete flow; report Obscura health status in the error.
- **Issue:** S3 object cannot be found for the deleted post.
  - **Solution:** Log the mapping gap; return delete success but note S3 reconciliation failure separately.
- **Issue:** X rate-limits the delete action (too fast).
  - **Solution:** Add a 2-second delay between navigation and delete actions to mimic human timing.

#### 9. Notes

- `/x-delete` is a damage-control tool, not a regular workflow step.
- Browser-based deletion is inherently fragile. Post-launch migration to X API Delete is the preferred long-term solution.
- The command does not notify followers — X handles deletion visibility internally.
- S3 reconciliation is secondary to actual deletion; never block the delete flow on S3 success.
- Keep the command suitable for post-launch operations where Faiz may be on mobile, but acknowledge that CDP-based flows on mobile are impractical for real-time urgency.
- Do not implement a bulk delete in MVP — single post only.
