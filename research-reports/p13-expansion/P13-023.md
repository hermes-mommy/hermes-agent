### Step P13-023: Edit Command

**Type:** Application
**Status:** Not Started
**Risk:** Low
**Git Commit:** `feat(P13): pending`

**Goal:** Implement `/x-edit <filename> "new caption"` — a Faiz-only Discord command that overrides the caption in a pending post's sidecar JSON before it goes live, with a confirmation embed showing old versus new caption.
**Dependencies:** P13-001 S3 Queue Setup, P13-006 Sidecar Parser, P13-022 Status Commands, existing Discord bot infrastructure.
**Cost Impact:** $0/month; minimal S3 copy/put operations for sidecar updates.
**ADR References:** P13 requirements sections 2.3 and 8.2; ADR-015 for safe credential handling.
**Acceptance Criteria:** AC-POSTING-007, AC-POSTING-012.
**Estimated Time:** 2.5 hours.

#### 1. Context

Faiz may need to correct or improve a caption before a queued post goes live. `/x-edit` accepts a filename (basename without prefix) and a new caption string. It reads the existing sidecar JSON from the pending queue, overwrites the `caption` field, and writes the updated sidecar back. If the file is already in `/processing/`, the command moves it back to `/pending/` first to prevent concurrent processing.

The command returns a confirmation embed showing the old caption (truncated) versus the new caption so Faiz can verify the change before it takes effect. This is a safety net — no destructive operation is confirmed without visible diff context.

The sidecar `caption` field is the source of truth for post text. When non-null, the caption pipeline skips LLM generation entirely (per P13 requirements section 4.5). Overwriting this field is equivalent to approving a fixed caption.

#### 4. Implementation Requirements

- Register `/x-edit` as a Faiz-only slash command with two required options: `filename` (string) and `caption` (string).
- Accept filename as basename without path prefix (e.g., `2026-06-04_083000_a1b2c3`).
- Derive the sidecar key by finding the matching `.meta.json` for the given basename under `guinevere-assets/x-poster/pending/`.
- If the file is in `/processing/` (not `/pending/`), move both image and sidecar back to `/pending/` before editing.
- If the file is in any other state (posted, failed, held), return an error: "File is in <state> and cannot be edited."
- Read the existing sidecar JSON, parse the `caption` field, and store old caption value.
- Overwrite the `caption` field with the new caption string from the command.
- Preserve all other sidecar fields unchanged — do not mutate `custom_alt`, `tags`, `schedule`, `tone`, `language`, or `skip_llm`.
- Write the updated sidecar JSON back to the same S3 key as the read source.
- Return an ephemeral confirmation embed with:
  - Old caption (truncated to 200 characters with ellipsis if longer)
  - New caption (full, up to Discord embed limit)
  - Filename
  - Updated timestamp
  - Note about LLM skip behavior: "Caption locked — LLM generation will be skipped for this post."
- Handle edge case: sidecar JSON is malformed → return parsing error.
- Handle edge case: sidecar JSON exists but `caption` field is missing → create it.
- Handle edge case: filename does not exist in pending or processing → return "File not found in queue."
- Handle edge case: caption exceeds 280 characters (X limit) → warn but accept (the post engine enforces the cap).
- Handle edge case: new caption is empty string → clear the caption field (LLM will generate).
- Log edit command execution with old caption hash, new caption length, filename, and timestamp.

#### 8. Troubleshooting

- **Issue:** sidecar JSON and image are out of sync after edit.
  - **Solution:** Always read sidecar first, verify image exists, then write; use S3 transactions or put-if-match when available.
- **Issue:** Discord slash command input truncates caption at 100 characters.
  - **Solution:** Discord string option limit is 1024 characters; ensure the command option type is STRING and not limited by an intermediate UI.
- **Issue:** file moves from processing to pending but a worker already started posting.
  - **Solution:** The queue polling loop must skip objects that are actively claimed; implement a processing lease or claim timestamp.
- **Issue:** sidecar has no `caption` field initially (LLM generation case).
  - **Solution:** Create the field on write; do not error on missing field.
- **Issue:** old caption is too long for embed display.
  - **Solution:** Truncate at 200 characters with trailing ellipsis; the new caption can be displayed fully if under 1024 characters.

#### 9. Notes

- `/x-edit` is a safety valve — Faiz can fix a caption without SSH or S3 console access.
- The command does not trigger re-generation; it locks the caption field so LLM is skipped.
- Moving from processing back to pending resets processing progress but preserves retry count.
- This is a post-launch refinement that also serves as launch readiness for operator remote control.
- Keep embed concise — the diff context (old vs new) is the most important information.
