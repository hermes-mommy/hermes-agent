### Step P13-011: Caption Generator

**Type:** Application
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P13): pending`

**Goal:** Implement the hybrid caption generation pipeline that reads the sidecar JSON, uses the `caption` field (when non-null) to skip LLM generation entirely, and otherwise invokes Gemini Flash with structured `responseSchema` to produce a tweet caption (max 280 chars), alt text for accessibility (max 125 chars), and up to 3 hashtags. The generator must be resilient to LLM failure via a fallback chain and must never cause a post failure.
**Dependencies:** P13-006 Sidecar Parser, P13-013 Tone Controller, P13-012 Content Moderation (post-gen gate), LLMRouter as 9Router.
**Cost Impact:** $0/month additional (Flash is low-cost, Pro used only if Flash fails).
**ADR References:** ADR-023 (Financial Tracking), P13 requirements sections 4.1, 4.2, 4.3, 4.4, and 4.5.
**Acceptance Criteria:** AC-POSTING-006 (hybrid caption pipeline with sidecar-first and LLM fallback; alt text separate; content moderation blocks unsafe).
**Estimated Time:** 5 hours

#### Context

P13 posts must always have a caption, alt text, and optionally hashtags. Some images arrive with a sidecar JSON file containing explicit values for one or all of these fields. The caption pipeline must examine the parsed sidecar at P13-006 output and choose the source per field: if sidecar `caption` is non-null, use it verbatim; if null, fire the LLM pipeline. The same logic applies to `alt_text` (sidecar `custom_alt`) and `hashtags` (sidecar `tags`).

The LLM call uses Gemini Flash with the `responseSchema` feature to get structured output directly: `{caption: string, alt_text: string, hashtags: string[]}`. This avoids fragile regex parsing of free-form LLM responses. The system must constrain generated captions to 280 characters, alt text to 125 characters for accessibility, and hashtags to at most 3. If the LLM produces a response exceeding any constraint, truncation or clipping must be applied.

The fallback chain for LLM generation: Flash (primary) → Pro (fallback if Flash fails entirely, e.g. 4xx/5xx or schema violation) → hardcoded generic caption (e.g. `"📸 New post from Guinevere"`). A full LLM failure must never block the post; the generic fallback ensures the tweet still goes out.

#### Troubleshooting
- **Issue:** Gemini Flash returns valid JSON but with fields missing or with incorrect structure.
  - **Solution:** Validate that the response matches the schema before extracting; if validation fails, reroute to the Pro fallback.
- **Issue:** Sidecar `skip_llm` is true but both `caption` and `alt_text` are null.
  - **Solution:** Document as edge case; apply generic fallback for caption and warn via log. Do not crash.
- **Issue:** LLM caption generation does not respect the 280-char limit natively.
  - **Solution:** Enforce a hard application-side truncation at 280 characters after LLM response; log when truncation occurs.
- **Issue:** LLM hallucinates PII or unsafe content despite the prompt guardrails.
  - **Solution:** This step generates the content; P13-012 (Content Moderation) runs after this step as the independent safety gate. The two-step pipeline is intentional.
- **Issue:** `responseSchema` JSON-mode consumes too many tokens for the prompt.
  - **Solution:** Keep the prompt concise and focused on the content rules; use succinct examples over verbose instructions.

#### Notes
- Alt text is for accessibility (neutral, factual, visual description). Caption is for the tweet's personality (Guinevere voice). The prompt must enforce this distinction clearly.
- Do not skip the LLM call entirely when sidecar provides caption but not alt text or hashtags; partial LLM fill is valid.
- The generic fallback must be hardcoded in source, not dynamically generated.
- Use Gemini Flash for cost by default. Gemini Pro is only for error recovery.
- Use `post-launch` wording when referencing future enhancements such as tone/language auto-detection beyond the current strategy or richer sidecar-driven override modes.
