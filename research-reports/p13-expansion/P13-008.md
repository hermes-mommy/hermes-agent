### Step P13-008: Cookie Injector

**Type:** Expansion
**Status:** Not Started
**Risk:** High
**Git Commit:** `feat(P13): pending`

**Goal:** Implement the P13 X session cookie injector that decrypts SOPS-encrypted X cookies, injects `auth_token`, `ct0`, and `kdt` into the dedicated Obscura CDP context for `x.com`, and persists the browser session via Obscura `--storage-dir`.
**Dependencies:** P13-003 Obscura 9223, P13-004 systemd service, existing SOPS+age setup, existing age key, dedicated X storage directory, CDP endpoint on port 9223.
**Cost Impact:** $0/month; reuses SOPS, age, Obscura, and existing VPS runtime.
**ADR References:** ADR-015 (Secrets Management via SOPS+age), ADR-016 pattern for encrypted operational secrets, P13 requirements section 5.1.
**Acceptance Criteria:** AC-POSTING-005 (Session Management), AC-POSTING-009 (Operations), AC-POSTING-001 (Queue Flow readiness).
**Estimated Time:** 15-30 minutes.

#### Context

P13 posts to X through a dedicated Obscura browser context on port 9223, separate from any MCP or general browser automation on port 9222. X authentication relies on browser cookies exported manually by Faiz from the laptop, encrypted with SOPS using the existing age key, synced to the VPS, decrypted at service startup, and injected via Chrome DevTools Protocol.

Required cookies:

- `auth_token`
- `ct0`
- `kdt`

Injection must use CDP `Network.setCookie` for the `x.com` domain and should support both `x.com` and `.x.com` cookie-domain behavior if the browser requires it. After injection, Obscura must persist session state using its dedicated `--storage-dir`, so the session survives VPS restarts. Do not create a dedicated age key for this step; reuse the existing Guinevere age key as required for the current launch scope.

This step is security-sensitive. Never print decrypted cookie values, never write cookie plaintext to evidence, never include secrets in logs, and never send secrets to external tools. Evidence must show key names, redacted lengths, CDP success responses, and session persistence proof only.

#### Troubleshooting

- **Issue:** `sops --decrypt` fails because age identity is unavailable.
  - **Solution:** Verify the existing Guinevere age key path and service-user permissions; do not create a new dedicated key for this step.
- **Issue:** CDP `Network.setCookie` returns failure.
  - **Solution:** Verify domain `.x.com`, secure flag, sameSite value, and that Network domain is enabled before setting cookies.
- **Issue:** Cookies inject but disappear after restart.
  - **Solution:** Confirm Obscura is launched with the dedicated X `--storage-dir` and the service user can write to that directory.
- **Issue:** Browser still redirects to login after injection.
  - **Solution:** Continue to P13-009 session health check; cookies may be expired and Faiz must export a fresh set from the laptop.
- **Issue:** Decrypted value appears in logs.
  - **Solution:** Treat as a security incident, rotate cookies, delete contaminated artifacts, and rerun secret scan with redacted evidence.

#### Notes

- This step is limited to cookie decryption, CDP injection, and persistence. Session health validation is P13-009.
- Do not use or expose an official X API token; this flow is browser-session based.
- Do not create a new age key for the current launch scope; reuse the existing Guinevere SOPS/age setup.
- All evidence must redact cookie values while preserving enough metadata to prove injection worked.
- Use post-launch wording for future multi-account or dedicated-key enhancements only.
