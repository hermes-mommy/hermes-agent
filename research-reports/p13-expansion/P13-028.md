#### 1. Context

The P13 integration test suite validates every layer of the X Auto Poster pipeline end-to-end, from S3 queue upload through caption generation, content moderation, rate limiting, error recovery, Discord commands, and monitoring. Ten distinct scenarios cover the happy path, every error class, immediate post override, night mode enforcement, dry-run simulation, edit command interaction, and deletion flow.

Each scenario is independent and can be run in isolation. Scenarios that require actual X posting (scenarios 1, 3, 4, 6, 7) use dry-run mode by default and must be explicitly enabled for live X runs via an environment variable. This protects Faiz's X account from test posts while still exercising the full code path.

The P13 GATE is the final verification step before production deployment. It iterates all 12 acceptance criteria, verifies evidence for each, checks safety and consent boundaries, and produces a 30-day production soak recommendation. The soak period is a recommendation — Faiz decides when to go live. The gate produces a structured report document.

#### 4. Implementation Requirements

**Test Scenarios:**

1. **Happy Path:** Upload image + sidecar → S3 pending/ → process → caption generated (LLM or sidecar) → posted → moved to posted/ → success notification sent. Validate every state transition, all 8 metrics incremented correctly, log row written with success status.

2. **Rate Limit Exceeded:** Submit 6 posts in a single simulated day (5/day cap). Verify 5th post proceeds, 6th post is deferred with rate limit reason. Verify daily counter persists across restart simulation. Verify minimum 3-hour interval between consecutive posts is respected.

3. **Night Mode Hold:** Simulate current time between 23:00-06:00 WIB. Upload a post with default schedule. Verify queue does not process it. Verify `"schedule": "immediate"` bypasses night mode. Verify queue resumes processing after simulated 06:00 WIB.

4. **Immediate Post:** Upload post with `"schedule": "immediate"`. Verify it bypasses the 3h interval check and current queue position (goes to front). Verify it still counts toward the 5/day cap. Verify night mode bypass works for immediate posts.

5. **Session Expired:** Set session health check to report expired. Verify queue moves all pending objects to `/held/`. Verify Discord alert sent to `#guinevere-alerts`. Verify p13_session_expired metric is 1. Verify no posts are attempted while session is expired.

6. **Network Error + Retry:** Simulate network failure during post action. Verify retry 1 fires at 30s, retry 2 at 2m, retry 3 at 5m. After 3rd failure, verify object moves to `/failed/` and notification sent with retry count = 3. Verify circuit breaker increments.

7. **DOM Change → Pause:** Simulate DOM selector failure (modify selector config or mock page structure). Verify posting pauses immediately. Verify Discord alert sent. Verify `/x-resume` can restart after fix.

8. **Content Blocked:** Upload post with content that triggers moderation (test-safe blocked content flag). Verify move to `/failed/` with reason `"content_blocked"`. Verify Discord notification sent to `#guinevere-alerts`. Verify p13_content_blocked_total increments. Verify caption is not posted.

9. **Dry-Run Mode:** Execute `/x-dryrun <filename>`. Verify session check runs. Verify caption generation runs. Verify rate limit check runs. Verify no S3 state transition (file stays in pending/). Verify no CDP navigation to compose/post. Verify Discord embed with generated caption returned.

10. **Edit Command Flow:** Upload post with sidecar caption "Original caption." Execute `/x-edit <filename> "Edited caption."` Verify sidecar JSON is updated. Verify old caption stored in confirmation embed. Verify post pipeline uses edited caption (not LLM-generated). Verify no duplicate posting.

**Test Infrastructure:**

- All test scenarios must pass in dry-run mode by default (P13_DRY_RUN=true).
- Each scenario must clean up its test objects after completion (delete from S3, remove log entries).
- Test data must use a dedicated test prefix `guinevere-assets/x-poster/test/` to avoid polluting production state.
- Use pytest fixtures for Obscura connection, S3 client, PostgreSQL session, and Prometheus test endpoint.
- Mock external services (X CDP interactions) for network and DOM failure scenarios.
- Time-sensitive tests (rate limit, night mode) must use injected time or mocked datetime — never real waits.

**P13 GATE:**

- Create a GATE verification script that checks all 12 acceptance criteria.
- For each AC, verify:
  - Implementation exists and is parent-verified.
  - Evidence documents exist and pass auditor review.
  - Safety and consent boundaries are preserved.
  - No BLOCKING violations in the implementation.
- AC-POSTING-001 through AC-POSTING-012 must each have a PASS/FAIL verdict.
- Any FAIL must include a reference to the specific issue.
- If all ACs pass, produce a 30-day production soak recommendation report.
- The soak recommendation report must include:
  - Recommended test parameters (post frequency, content diversity, time windows).
  - Monitoring thresholds to watch during soak.
  - Rollback plan template for any issues discovered during soak.
  - Check-in schedule (weekly review during 30 days).
  - Criteria for early graduation from soak (e.g., 7 consecutive days without critical failure).
- If any AC fails, the gate produces a FAIL report with fix recommendations and does not recommend production deployment.
- Write the GATE report to `docs/setup-evidence/P13/GATE/p13-gate-report.md`.

#### 8. Troubleshooting

- **Issue:** Happy path test fails because caption LLM is unavailable.
  - **Solution:** Fallback to sidecar caption in test setup (set `"skip_llm": true` in test sidecar); verify LLM-dependent paths separately with mocked LLM.
- **Issue:** Rate limit test depends on real time and is slow.
  - **Solution:** Mock `datetime.now()` or inject a time provider; never use real `time.sleep()` for rate limit tests.
- **Issue:** Session expired test requires real cookie manipulation.
  - **Solution:** Mock the session health check function to return expired; do not invalidate real cookies in tests.
- **Issue:** DOM change test requires real selector modification.
  - **Solution:** Inject a mock selector resolver that raises a configurable failure; verify the pause flow without real DOM changes.
- **Issue:** GATE verification script is too slow for every AC.
  - **Solution:** Divide into pre-checks (static: evidence files exist, audits pass) and runtime checks (S3 state, metric endpoints, log queries).
- **Issue:** Test scenarios interfere with each other (shared state).
  - **Solution:** Each scenario must use unique filenames with timestamps and clean up after itself; use pytest's `tmp_path` equivalent for S3 keys.
