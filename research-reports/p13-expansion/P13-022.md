#### 1. Context

Faiz needs real-time visibility into the X Auto Poster queue and the ability to intervene without SSH access. The five status commands provide queue depth inspection (per state), pending file listing, per-file cancellation, global hold, and resume after pause or circuit breaker. All commands must be restricted to Faiz only through the existing permission system.

`/x-status` is the primary diagnostic command. It reports queue depth for each state (pending, processing, posted today, failed today, held), last post time and link, daily post count against the 5/day cap, session health state, next scheduled post time, and circuit breaker state. This is Faiz's first stop when checking system health.

`/x-list` provides a detailed view of the pending queue. Each entry shows filename, age (time since upload), scheduled time from sidecar metadata, and estimated post time based on current queue position and rate limits. Useful before editing or cancelling.

`/x-cancel <filename>` moves a specific pending post to `/failed/` with reason `"cancelled_by_operator"`. This is for removing unwanted posts before they go live. The command should confirm the file exists in pending, execute the move, and report the result.

`/x-hold` pauses all posting immediately. The queue processor checks a persisted hold flag before each cycle. If posting was actively in progress, the current file finishes and no new files are acquired. Faiz uses this when investigating an issue or during maintenance.

`/x-resume` clears the hold flag and re-enables queue processing. It also closes an open circuit breaker if the breaker is the current pause reason. The response includes current queue depth and next action.

#### 4. Implementation Requirements

- Register five slash commands scoped to Faiz Discord ID via existing auth check.
- `/x-status` returns an embed with sections for each queue state depth, last post time and link, daily post count and cap, session health (healthy/expired), next scheduled post estimate, and circuit breaker state.
- `/x-list` returns an embed listing pending files with filename, age in hours/minutes, scheduled time from sidecar, and estimated post time based on queue position and rate limit.
- Truncate `/x-list` output at 15 entries to stay under Discord embed limits; include a note if more exist.
- `/x-cancel <filename>` accepts only the basename (without path prefix); validates existence in `guinevere-assets/x-poster/pending/`.
- `/x-cancel` moves both image and sidecar JSON from pending/ to failed/ with reason `"cancelled_by_operator"`.
- `/x-cancel` returns confirmation embed with filename, cancelled timestamp, and queue depth remaining.
- `/x-hold` sets a persisted hold flag in PostgreSQL (or Redis) and returns confirmation with current queue state.
- `/x-hold` does not abort an active post — the current file completes, then queue pauses.
- `/x-resume` clears the hold flag; if circuit breaker is open, calls the breaker's resume path to close or half-open.
- `/x-resume` returns embed with new queue state and number of pending files.
- All commands return ephemeral responses (visible only to Faiz).
- All commands record execution to audit logs with command name, timestamp, and result status.
- Handle edge case: `/x-cancel` on non-existent filename returns descriptive error.
- Handle edge case: `/x-list` on empty queue returns "Queue is empty."
- Handle edge case: `/x-hold` when already held returns current hold state.
- Handle edge case: `/x-resume` when not held returns "Posting is already active."

#### 8. Troubleshooting

- **Issue:** `/x-cancel` moves file but sidecar is orphaned.
  - **Solution:** Always move image and sidecar as a pair in the same operation; verify both exist before confirming.
- **Issue:** `/x-list` shows stale age because S3 LastModified lags.
  - **Solution:** Use the object's upload timestamp from sidecar metadata when available; fall back to LastModified.
- **Issue:** `/x-resume` does not restart queue polling.
  - **Solution:** The queue poller must re-read the hold flag before each cycle; verify the polling loop checks persistence, not an in-memory cache.
- **Issue:** command registration sync fails.
  - **Solution:** Discord command tree sync may need a `guild_id` scope during development; use global sync with caution and test in a staging guild first.
- **Issue:** ephemeral response exceeds Discord 2000-char limit.
  - **Solution:** Paginate `/x-list` across multiple embeds or compress output.

#### 9. Notes

- All commands are Faiz-only; do not expose operational controls to non-operator users.
- Ephemeral responses prevent state leakage to other channel members.
- The hold flag is distinct from the circuit breaker state — both can be active simultaneously.
- `/x-resume` should convey leftover state so Faiz knows what to investigate.
- Keep commands suitable for post-launch operations where Faiz may be on mobile.
- Command names are concise — no abbreviations for non-obvious cases like `/x-cancel`.
