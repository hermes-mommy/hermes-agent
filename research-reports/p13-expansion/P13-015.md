### Step P13-015: Media Upload (CDP)

**Type:** Application
**Status:** Not Started
**Risk:** High
**Git Commit:** `feat(P13): pending`

**Goal:** Implement CDP-based media upload for X posts, supporting one to four JPG, PNG, or WEBP images with size validation, thumbnail confirmation, retries, and alt text entry.
**Dependencies:** P13-003 Obscura 9223, P13-006 Sidecar Parser, P13-011 Caption Generator, P13-014 Compose Adapter.
**Cost Impact:** $0/month infrastructure increment; uses existing local processing and browser automation.
**ADR References:** ADR-015 secrets management, P13 media constraints, accessibility requirements for alt text.
**Acceptance Criteria:** AC-POSTING-001 Queue Flow and AC-POSTING-006 Caption Pipeline with distinct alt text.
**Estimated Time:** 3 hours

#### Context

The media upload adapter attaches one to four local image files to the ready X compose UI. Files are sourced from the S3 processing item after download or staging. Each file must be validated before browser upload.

Media constraints:

- 1 to 4 images per post.
- Maximum 5MB per file.
- Supported formats: JPG, PNG, WEBP.
- GIF and video are post-launch only.
- Thumbnail must appear within 10 seconds after upload.
- Retry media upload failures up to 3 attempts.
- Add alt text for each image using the X `Add description` flow.

Preferred upload paths:

1. `page.locator('input[data-testid="fileInput"]').setInputFiles(paths)`.
2. CDP `DOM.setFileInputFiles` when direct locator upload fails.

Alt text can come from sidecar `custom_alt` or LLM-generated alt text. Alt text is separate from caption text and must remain factual, visual, and accessibility-focused.

#### Troubleshooting

- **Issue:** File input selector is not visible.
  - **Solution:** Locate hidden input by selector and use `setInputFiles`; visibility is not required for Playwright file input handling.
- **Issue:** X accepts the file but no thumbnail appears.
  - **Solution:** Wait up to 10 seconds, retry upload, then classify as media upload failure after the retry limit.
- **Issue:** Alt text button label changes.
  - **Solution:** Centralize selectors and fail as DOM change when no supported alt text control can be found.
- **Issue:** Multiple images attach in the wrong order.
  - **Solution:** Preserve input path order and verify thumbnail count matches expected count before alt text entry.

#### Notes

- Media upload does not click the final post button; P13-016 owns final submission.
- P13-012 content moderation owns unsafe media blocking before upload.
- This step should keep media validation deterministic and independent of X behavior.
- Alt text must be factual and should not include calls to action, hashtags, or persona flourish.
- Uploaded file paths must not expose secrets or private local directories in public logs.
- Future post-launch support can add video or GIF handling, but Tier 1 accepts images only.
