### Step P12-016: Discord Draft UX

**Goal:** Implement Discord embed-based draft approval flow with reaction handlers (approve/reject/edit) and batch approval in a dedicated private email channel.
**Dependencies:** P12-015 (Draft Generation Engine — provides `DraftGenerator` class and Gmail draft_id for each generated draft)
**ADR References:** ADR-022 (Communication Channel Strategy — Discord as primary control surface for email), ADR-002 (Persona Safety — HARD STOP cross-channel propagation must halt draft interactions)
**Estimated Time:** 4 hours

#### Context

The Discord Draft UX is the human-in-the-loop control surface for Guinevere's email reply pipeline. When P12-015 generates a draft reply for a client or important email, the draft is first saved as a Gmail Draft (editable from Gmail web) and then presented to Faiz via a rich Discord embed in a dedicated private email channel. Faiz reviews the draft preview and reacts with emoji to approve (✅), reject (❌), or edit (✏️) the draft. This step bridges the gap between automated draft generation (P12-015) and actual email sending (P12-017).

The existing Discord bot codebase uses a consistent pattern across all 22 command files: a frozen dataclass `XxxEmbedData` holds all embed fields, a builder function `build_xxx_embed_data()` constructs the dataclass from domain objects, and a `to_discord_embed()` function converts the dataclass to a `discord.Embed`. This step follows the same pattern with `DraftApprovalEmbedData`, `build_draft_approval_embed_data()`, and `to_discord_embed()`.

The dedicated email channel is created during guild setup (extending `guild_setup.py`). All draft approval embeds, email notifications (P12-018), and morning briefings (P12-019) are posted to this channel. Channel creation is idempotent — if the channel already exists, the setup step is a no-op.

The edit flow allows Faiz to type corrections directly in the Discord email channel. Guinevere parses the message, updates the Gmail draft via `drafts.update()`, and refreshes the embed with the updated preview. This keeps the entire review workflow within Discord without requiring Faiz to open Gmail web.

Batch approval allows Faiz to react ✅ on multiple pending draft embeds in quick succession. Each reaction is processed independently by the reaction handler, triggering the P12-017 send flow for each approved draft. There is no batch-send API call — each draft is sent individually via `drafts.send()`.

Draft timeout: drafts that receive no reaction within 24 hours (configurable via environment variable `DRAFT_TIMEOUT_HOURS`) are automatically expired. The embed is updated to show "⏰ Draft expired" and the Gmail draft is optionally deleted. A daily cleanup task scans for expired drafts.

Safety: HARD STOP from any channel immediately suppresses all draft approval interactions. No new drafts are posted, pending reaction handlers are disabled, and existing embeds show a "⛔ HARD STOP active" footer. This follows ADR-002 cross-channel safety.

#### Troubleshooting

- **Issue:** Reaction handler fires multiple times for a single reaction (duplicate processing)
  - **Solution:** Implement idempotency via Redis lock: `SET draft:processing:{draft_id} 1 EX 30 NX`. If the key already exists, the handler returns early. Release the lock after processing completes. Discord's `on_raw_reaction_add` can fire multiple times for rapid reactions.

- **Issue:** Edit flow does not update the embed preview after `drafts.update()`
  - **Solution:** After calling `drafts.update()`, fetch the updated draft content via `drafts.get(draft_id)`, re-build the embed data with `build_draft_approval_embed_data()`, and call `message.edit(embed=to_discord_embed(new_data))`. Cache the message_id in Redis keyed by draft_id for lookup.

- **Issue:** Email channel not created during guild setup
  - **Solution:** Verify `guild_setup.py` includes the email channel in its channel list. Check that the bot has `MANAGE_CHANNELS` permission in the guild. Run the guild setup manually: `python -m src.discord.guild_setup --force`.

- **Issue:** Draft embed exceeds Discord's 6000 character limit
  - **Solution:** The `draft_preview` field is limited to 500 characters. Total embed size with all fields (subject, recipient, classification, etc.) should stay under 1500 characters. If the subject line is very long, truncate to 256 characters (Discord embed title limit).

- **Issue:** Batch approve causes rate limiting on Gmail API (`drafts.send()`)
  - **Solution:** Implement exponential backoff with jitter for `drafts.send()` calls. Gmail API allows 250 quota units per user per second; each `drafts.send()` costs 10 units, so maximum 25 sends/second. Add a 100ms delay between batch sends.

- **Issue:** HARD STOP flag not checked before posting draft embed
  - **Solution:** Every draft posting must call `check_hard_stop()` before sending. The function reads `redis.get("hard_stop:active")` and returns True if active. Add this check at the top of `post_draft_embed()` and in the reaction handler entry points.

#### Notes

- **Pattern Consistency:** The `DraftApprovalEmbedData` frozen dataclass follows the exact same pattern as `StatusEmbedData`, `MoodEmbedData`, `CostEmbedData`, `LoopStartEmbedData`, and 7 other existing embed dataclasses in the Discord bot codebase. All use `@frozen` decorator, `build_*_embed_data()` builder, and `to_discord_embed()` converter. Maintain this consistency.
- **Redis State Schema:** Draft state stored in Redis: `draft:{draft_id}` → JSON `{message_id, channel_id, gmail_message_id, thread_id, classification, created_at, expires_at, status}`. Status values: `pending`, `approved`, `rejected`, `expired`, `editing`.
- **Channel Strategy:** The dedicated email channel is private (not visible to other guild members). Only Faiz's user ID and the Guinevere bot role have `VIEW_CHANNEL` permission. This prevents email content from leaking to other Discord users in the guild.
- **No Auto-Send:** Drafts are NEVER sent without explicit Faiz approval. Even if a draft has a perfect importance score and classification, it must go through the Discord embed → reaction flow. This is a non-negotiable safety boundary per ADR-002 and PersonaSafetyPolicy.
- **Cross-Reference P12-017:** The approve handler does not send the email directly. It queues the draft_id for P12-017 `DraftSender` to process. This separation ensures send logic (error handling, metrics, conversation log update) is isolated from the UX layer.
- **Cross-Reference P12-015:** The `DraftGenerator` from P12-015 calls `DraftDiscordUX.post_draft_embed()` after successfully creating a Gmail draft. The UX module does not generate drafts — it only presents them for review.
- **Timeout Configuration:** `DRAFT_TIMEOUT_HOURS` environment variable defaults to 24. Can be set to 0 to disable timeout (drafts never expire). Maximum recommended value: 168 (7 days). Beyond 7 days, the Gmail draft may have been edited externally, making the Discord preview stale.
