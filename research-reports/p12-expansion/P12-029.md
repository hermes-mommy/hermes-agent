#### Context

P12-029 is the final piece connecting Gmail intake to the autonomous agent loop. When Faiz approves a loop trigger candidate (P12-028, ✅ reaction), the `EmailTaskContractBuilder` constructs a comprehensive TaskContract that includes email-specific context. This TaskContract is then passed to the existing `LoopManager.start()` method, which initiates the standard P5 SDLC 7-phase pipeline.

The existing `TaskContract` Pydantic model (defined in `src/loops/contract.py`) provides the contract structure: `agent_id`, `category`, `task_description`, `expected_output`, `required_tools`, `must_do`, `must_not_do`, `context_files`, `output_path`, `status`, `result`. The `build_contract()` function creates contracts and `contract_to_prompt()` generates LLM-ready delegation prompts.

The `EmailTaskContractBuilder` extends this system by enriching the TaskContract with email-specific context:

1. **Task description** — extracted from email subject + first paragraph of body
2. **Thread context** — last 3 messages in the Gmail thread (via Gmail threads API)
3. **Client dossier** — memory recall for the sender (past interactions, preferences, project history)
4. **Constraints** — deadlines and requirements extracted from email body
5. **Channel metadata** — source channel = "gmail", trigger email ID for traceability

The builder does NOT replace `build_contract()` — it wraps it, adding email context to the standard contract fields. The resulting TaskContract is fully compatible with the existing `LoopManager` and `contract_to_prompt()` pipeline.

#### Contract Builder Design

```python
class EmailTaskContractBuilder:
    """Builds TaskContract with email context. Wraps build_contract() from contract.py."""

    def __init__(self, gmail_client, memory_store, loop_manager) -> None:
        self.gmail_client = gmail_client
        self.memory_store = memory_store
        self.loop_manager = loop_manager

    async def build_contract(self, email, trigger_result) -> TaskContract:
        """Build TaskContract enriched with email context.

        1. Extract task description from subject + body
        2. Load thread history (last 3 messages via Gmail threads API)
        3. Recall client dossier from memory
        4. Extract constraints (deadlines, requirements)
        5. Build standard TaskContract with enriched context
        """
        task_desc = await self._extract_task_description(email)
        thread_msgs = await self._load_thread_history(email.thread_id, limit=3)
        dossier = await self._recall_client_dossier(email.sender)
        constraints = await self._extract_constraints(email.body, trigger_result)

        contract = build_contract(
            agent_id="guinevere-sdlc",
            category="email-triggered",
            task=task_desc,
            expected_output=f"Completed task from email: {email.subject}",
            required_tools=["gmail_api", "memory_recall", "discord_notify"],
            must_do=[
                f"Address client request: {email.subject}",
                f"Respect deadline: {constraints.get('deadline', 'none specified')}",
                "Report progress to Discord after each phase",
                "Store results as memory episodes linked to email thread",
            ],
            must_not_do=[
                "Auto-reply to client without Faiz approval",
                "Share internal implementation details with client",
                "Exceed cost budget without Faiz approval",
            ],
            context_files=self._build_context_files(thread_msgs, dossier, constraints),
            output_path=f"evidence/email-loops/{email.id}/",
        )
        return contract

    async def contract_to_prompt(self, contract: TaskContract) -> str:
        """Generate LLM prompt: standard sections + EMAIL CONTEXT."""
        base = contract_to_prompt(contract)
        return f"{base}\n\n{self._format_email_context(contract)}"

    async def start_loop(self, contract: TaskContract) -> str:
        """Start P5 SDLC loop. Returns loop_id."""
        return await self.loop_manager.start(contract)

    async def _extract_task_description(self, email) -> str: ...
    async def _load_thread_history(self, thread_id: str, limit: int = 3) -> list[dict]: ...
    async def _recall_client_dossier(self, sender_email: str) -> dict: ...
    async def _extract_constraints(self, body: str, trigger) -> dict: ...
    def _build_context_files(self, threads, dossier, constraints) -> list[str]: ...
    def _format_email_context(self, contract: TaskContract) -> str: ...
```

```python
# Integration flow (in P12-028 reaction handler):
async def _handle_approve(self, email_id: str, message_id: str) -> None:
    """Handle ✅ reaction — build contract and start loop."""
    
    # 1. Retrieve original email from cache
    email = await self.email_cache.get(email_id)
    trigger_result = await self.trigger_cache.get(email_id)
    
    # 2. Build TaskContract with email context
    contract = await self.contract_builder.build_contract(email, trigger_result)
    
    # 3. Generate enriched prompt
    prompt = await self.contract_builder.contract_to_prompt(contract)
    
    # 4. Start agent loop
    loop_id = await self.contract_builder.start_loop(contract)
    
    # 5. Notify Faiz
    await self.discord_bridge.send_message(
        channel_id=self.email_channel_id,
        content=(
            f"📋 **TaskContract Created**\n"
            f"**Loop ID:** `{loop_id}`\n"
            f"**Task:** {contract.task_description}\n"
            f"**Channel:** Gmail | **Email ID:** `{email_id}`\n"
            f"Agent loop starting 7-phase SDLC pipeline.\n"
            f"Progress will be reported to Discord after each phase."
        ),
    )
    
    # 6. Store loop reference for progress tracking
    await self.redis.set(
        f"guinevere:gmail:loop:{email_id}",
        loop_id,
        ex=86400 * 7,  # 7 day TTL
    )
```

**Loop Lifecycle:**
1. Faiz approves → TaskContract built → LoopManager.start()
2. Loop runs standard 7-phase SDLC pipeline (plan → research → implement → test → verify → deploy → report)
3. Progress reported to Discord after each phase (existing loop notification pattern)
4. Loop results stored as memory episodes linked to email thread ID
5. Costs tracked via CostTracker (Redis DB5) under `email-loop:{loop_id}`
6. On loop completion: Discord summary sent, episode stored, client draft (if applicable) queued for Faiz review

#### Troubleshooting
- **Issue:** `build_contract()` raises Pydantic validation error
  - **Solution:** The TaskContract Pydantic model requires `agent_id`, `category`, `task_description`, `expected_output` as mandatory fields. Verify all are provided. If `context_files` or `must_do` contain non-string values, the validation will fail. Check that thread messages are serialized to strings before adding to `context_files`.

- **Issue:** Thread history returns empty list
  - **Solution:** Verify Gmail threads API call: `grep -n "thread\|get_thread\|threads.get" src/gmail/client.py`. The thread ID comes from the email's `threadId` field. If the thread has only 1 message (the trigger email itself), history will be empty — this is valid. The contract should still work with empty thread context.

- **Issue:** Client dossier recall returns no results
  - **Solution:** New clients won't have memory entries. The `_recall_client_dossier()` method should return an empty dict (not raise an error) for unknown senders. The contract's context section will note "No prior interactions found for this client." Post-MVP, the dossier could be enriched from external sources (CRM, LinkedIn).

- **Issue:** Loop starts but progress never reports to Discord
  - **Solution:** Verify the progress tracker is registered with LoopManager: `grep -n "progress_tracker\|on_phase_complete\|EmailLoopProgress" src/loops/manager.py`. The LoopManager must call `progress_tracker.on_phase_complete()` after each phase. If the tracker is not wired, phases complete silently. Check Discord channel permissions for the bot.

- **Issue:** Cost tracking shows $0.00 for loops
  - **Solution:** Verify CostTracker is recording LLM usage during the loop. The loop phases must call `CostTracker.record()` after each LLM call. Check Redis DB5: `redis-cli -p 6380 -n 5 KEYS "guinevere:cost:*" | head -10`. If keys exist but show $0, the LLM calls may be using a model not tracked by CostTracker.

- **Issue:** `contract_to_prompt()` generates prompt that exceeds LLM context window
  - **Solution:** The thread history (3 messages) and client dossier can be large. Implement truncation: thread messages truncated to 500 chars each, dossier truncated to 1000 chars. Total prompt should be under 4000 tokens. Add a `_truncate_context()` method that enforces length limits on each context component.

#### Notes
- **Standard TaskContract:** P12-029 uses the existing `TaskContract` model from `src/loops/contract.py` (130 lines). It does NOT create a new model or modify the existing one. The `build_contract()` function in `contract.py` is reused as-is. Email context is added via the `context_files` and `must_do` fields, which are list-type and accept arbitrary string content.
- **7-Phase SDLC Loop:** The agent loop triggered by email uses the exact same 7-phase pipeline as Discord-triggered loops: Planning → Research → Implementation → Testing → Verification → Deployment → Report. No special "email mode" — the email context enriches the starting prompt, but the loop mechanics are identical.
- **Memory Episode Linking:** When the loop completes, results are stored as memory episodes with `metadata.trigger_email_id` and `metadata.thread_id` fields. This enables future recall of "what did Guinevere do for client X's email about feature Y?" via memory search. The episode links the email context to the loop's output artifacts.
- **Cost Tracking:** Each email-triggered loop tracks costs independently via Redis DB5 key `guinevere:cost:email-loop:{loop_id}`. This enables Faiz to see "how much did the loop for client X's request cost?" separately from general operating costs. The CostTracker aggregates: LLM token costs (GPT-5.5 + DeepSeek), API call costs, and total per-loop cost.
- **Cross-Reference P5:** The LoopManager, TaskContract, and 7-phase SDLC pipeline are all P5 components. P12-029 does not modify any P5 code — it only calls existing APIs. If P5's LoopManager.start() signature changes, this step must be updated to match.
- **Cross-Reference ADR-015:** ADR-015 defines the agent loop architecture. Email-triggered loops follow the same ADR-015 constraints: Faiz-only approval, cost tracking, phase-by-phase reporting, and no autonomous destructive operations. The email trigger is a new entry point, not a new loop type.
- **Safety Constraint — No Auto-Reply:** The TaskContract includes a `must_not_do` constraint: "Auto-reply to client without Faiz approval." Even if the agent loop produces a perfect draft response, it MUST be queued for Faiz's review via the draft pipeline (P12-013/014) before sending. The loop cannot bypass the draft approval flow.
- **Thread Context Window:** Loading last 3 messages from the Gmail thread provides sufficient context for the agent loop without overwhelming the LLM context window. If the thread is longer, only the most recent 3 messages are included. The full thread is accessible via the `trigger_email_id` stored in the contract for reference.
