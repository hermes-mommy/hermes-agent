### Step P12-001: GCP Project + API Enablement

**Type:** Infrastructure
**Status:** Not Started
**Risk:** Low
**Git Commit:** `feat(P12): pending`

**Goal:** Create the `guinevere-gmail-prod` GCP project with Gmail API and Pub/Sub API enabled, link billing account (free tier covers single-user usage), create a minimal-privilege service account `gmail-pubsub-reader` for Pub/Sub message consumption, and SOPS-encrypt the service account key for VPS deployment.
**Dependencies:** P8 (Observability — Prometheus, Grafana, Loki operational on VPS for metric ingestion from Gmail service).
**Cost Impact:** $0/month (Gmail API free tier: 1 billion API calls/day for personal use; Pub/Sub free tier: 10GB messages/month).
**ADR References:** ADR-022 (Communication Channel Strategy — requires revision from `guinevere@[domain].com` to personal Gmail), ADR-017 (Secrets Management via SOPS+age — service account key encryption), ADR-018 (Security Policy — minimal IAM principle).
**Acceptance Criteria:** AC-EMAIL-001 (Gmail connected, OAuth valid — project foundation), SRS-IR-011 (Gmail interface infrastructure).
**Estimated Time:** 1.5 hours

#### Context

P12 Gmail integration requires a dedicated GCP project to isolate Gmail API credentials and Pub/Sub subscriptions from any other Google Cloud usage. The project name `guinevere-gmail-prod` follows the convention established in the requirements document (`research-reports/p12-expansion/requirements-p12-gmail.md`, §2.3). This step creates the cloud infrastructure foundation that all subsequent P12 steps depend on: OAuth2 token management (P12-002) requires the GCP project's OAuth consent screen, the Gmail API client (P12-004) requires enabled Gmail API, and the sync engine (P12-005) requires Pub/Sub for push notifications.

The architecture uses **Pub/Sub StreamingPull** (outbound gRPC from VPS, no inbound webhook) per the research report `research-reports/gmail-push-vs-polling-comparison.md`. This means the VPS initiates the connection to Google's Pub/Sub servers — no firewall changes, no public URL required, no Cloud Run deployment. The service account `gmail-pubsub-reader` needs only the `roles/pubsub.subscriber` role, following minimal-privilege principle per ADR-018.

ADR-022 currently references `guinevere@[domain].com` for email integration. Faiz has decided to use his personal Gmail account instead (§2.1 of requirements). ADR-022 must be formally revised — this step documents the revision requirement but does not perform the ADR edit (parent-only governance task).

After this step, the project will have: (1) a GCP project with Gmail API and Pub/Sub API enabled, (2) a service account with minimal Pub/Sub subscriber permissions, (3) a SOPS-encrypted service account key ready for VPS deployment, and (4) billing linked (free tier sufficient).

#### Implementation Commands

```bash
# 1. Create the GCP project
gcloud projects create guinevere-gmail-prod \
  --name="Guinevere Gmail Integration" \
  --set-as-default

# 2. Link billing account (use the billing account ID from gcloud billing accounts list)
gcloud billing projects link guinevere-gmail-prod \
  --billing-account=$(gcloud billing accounts list --format="value(name)" --filter="open=true" | head -1)

# 3. Enable Gmail API
gcloud services enable gmail.googleapis.com --project=guinevere-gmail-prod

# 4. Enable Pub/Sub API
gcloud services enable pubsub.googleapis.com --project=guinevere-gmail-prod

# 5. Verify both APIs are enabled
gcloud services list --enabled --project=guinevere-gmail-prod \
  --filter="config.name:(gmail.googleapis.com OR pubsub.googleapis.com)"

# 6. Create the service account with minimal permissions
gcloud iam service-accounts create gmail-pubsub-reader \
  --project=guinevere-gmail-prod \
  --display-name="Gmail Pub/Sub Reader" \
  --description="Minimal service account for Guinevere Gmail Pub/Sub message consumption"

# 7. Grant only Pub/Sub Subscriber role (minimal privilege per ADR-018)
gcloud projects add-iam-policy-binding guinevere-gmail-prod \
  --member="serviceAccount:gmail-pubsub-reader@guinevere-gmail-prod.iam.gserviceaccount.com" \
  --role="roles/pubsub.subscriber"

# 8. Generate service account key (JSON format)
gcloud iam service-accounts keys create secrets/gmail-pubsub-sa-key.json \
  --iam-account=gmail-pubsub-reader@guinevere-gmail-prod.iam.gserviceaccount.com \
  --project=guinevere-gmail-prod

# 9. Verify the key file exists and has valid JSON content
python -c "import json; data=json.load(open('secrets/gmail-pubsub-sa-key.json')); print(f'Key type: {data[\"type\"]}, Project: {data[\"project_id\"]}')"

# 10. SOPS-encrypt the service account key using age
sops --config .sops.yaml -e secrets/gmail-pubsub-sa-key.json > secrets/gmail-pubsub-sa-key.enc

# 11. Verify encrypted file is valid SOPS ciphertext
sops --config .sops.yaml -d secrets/gmail-pubsub-sa-key.enc | python -c "import json,sys; json.load(sys.stdin); print('Decryption OK')"

# 12. Remove plaintext key (only encrypted version committed to repo)
shred -u secrets/gmail-pubsub-sa-key.json 2>/dev/null || rm -f secrets/gmail-pubsub-sa-key.json

# 13. Verify plaintext is gone
test ! -f secrets/gmail-pubsub-sa-key.json && echo "CLEAN" || echo "WARNING: plaintext key still exists"

# 14. Create Pub/Sub topic for Gmail push notifications
gcloud pubsub topics create gmail-notifications \
  --project=guinevere-gmail-prod \
  --message-retention-duration=7d

# 15. Create Pub/Sub subscription with StreamingPull support
gcloud pubsub subscriptions create gmail-notifications-sub \
  --project=guinevere-gmail-prod \
  --topic=gmail-notifications \
  --ack-deadline=60 \
  --message-retention-duration=7d \
  --expiration-period=never

# 16. Verify topic and subscription exist
gcloud pubsub topics list --project=guinevere-gmail-prod
gcloud pubsub subscriptions list --project=guinevere-gmail-prod
```

#### Troubleshooting

- **Issue:** `gcloud projects create` fails with "Project ID already in use"
  - **Solution:** Project IDs are globally unique across all GCP. If `guinevere-gmail-prod` is taken (unlikely), append a date suffix: `guinevere-gmail-prod-20260603`. Update all subsequent commands and references accordingly.
- **Issue:** `gcloud billing projects link` fails with "Billing account not found"
  - **Solution:** Run `gcloud billing accounts list` to find available billing accounts. If none exist, create one at console.cloud.google.com/billing. Free tier requires a valid payment method but charges $0 for Gmail API usage.
- **Issue:** `gcloud services enable gmail.googleapis.com` fails with "billing not enabled"
  - **Solution:** Billing must be linked before enabling APIs. Re-run step 2 (billing link) and verify with `gcloud billing projects describe guinevere-gmail-prod`.
- **Issue:** `gcloud iam service-accounts keys create` fails with "key type not allowed"
  - **Solution:** Organization policy may restrict key types. Use `--key-file-type=json` explicitly. If organization policy blocks all key creation, use workload identity federation instead (out of scope for single-user setup).
- **Issue:** SOPS encryption fails with "no matching key found"
  - **Solution:** Verify `.sops.yaml` configuration has a creation rule matching `secrets/gmail-pubsub-sa-key.json`. Check age public key in `.sops.yaml` matches the key available on the system: `age-keygen -y < key.txt`.
- **Issue:** `gcloud pubsub subscriptions create` fails with "topic does not exist"
  - **Solution:** Ensure topic creation (step 14) completed before subscription creation (step 15). Add a brief wait: `sleep 5` between the two commands.
