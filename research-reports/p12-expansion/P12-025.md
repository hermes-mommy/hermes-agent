**Estimated Time:** 5 hours

#### Context

P12-025 delivers the observability layer for the Gmail integration. Faiz confirmed that the 13 metrics specified in requirements §8.1 are sufficient — no additional metrics needed. The metrics cover the complete Gmail pipeline: connection state, email flow (received → classified → notified), draft lifecycle (created → approved/rejected), security events (injection + secret detection), operational health (quota, token age, watch status, latency).

Guinevere already runs Prometheus + Grafana + Loki from P8. The Gmail service exposes metrics on a dedicated port (9101) following the same pattern as the WhatsApp metrics exporter (P11-021). Prometheus scrapes this endpoint at 15s intervals. Grafana dashboards are provisioned via file (not UI), ensuring reproducibility and version control.

The dashboard uses `grafanalib` (Python library) to generate dashboard JSON from Python code. This approach (dashboard-as-code) means the dashboard definition lives in the repository alongside the metrics code. The generated JSON is placed in Grafana's provisioning directory for automatic loading. TimescaleDB serves as the long-term storage backend for Prometheus via remote-write, enabling historical queries beyond Prometheus's retention window.

Alert rules are defined in Grafana (not Prometheus Alertmanager) to leverage the existing Guinevere notification channel (Discord webhook). Each alert maps to a specific operational response: disconnected → investigate OAuth/watch, injection detected → review security logs, quota high → throttle API calls, token aging → schedule re-auth.

#### Dashboard Design

**Panel 1 — Overview:**
- Stat: `gmail_connected` (green/red gauge, "Connected"/"Disconnected")
- Time series: `rate(gmail_emails_received_total[1h])` — emails per hour
- Pie chart: `gmail_emails_classified_total` grouped by `category` label (8 segments)
- Stat: `gmail_emails_notified_total` vs `gmail_emails_received_total` — notification rate

**Panel 2 — Security:**
- Stat: `gmail_injection_detected_total` (red counter, "Injection Attempts")
- Stat: `gmail_secrets_detected_total` (orange counter, "Secrets Detected")
- Time series: `increase(gmail_injection_detected_total[24h])` by `pattern_type`
- Time series: `increase(gmail_secrets_detected_total[24h])` by `secret_type`
- Table: Last 10 injection/secret detection events (from Loki logs)

**Panel 3 — Operations:**
- Gauge: `gmail_api_quota_usage` (0-100% with 80% threshold marker)
- Gauge: `gmail_oauth_token_age_seconds` (days, with 50-day threshold marker)
- Stat: `gmail_watch_active` (green/red, "Watch Active"/"Watch Inactive")
- Heatmap: `gmail_processing_latency_seconds` histogram by `stage`

**Panel 4 — Draft Pipeline:**
- Stat: `gmail_drafts_created_total` (total drafts)
- Stat: `gmail_drafts_approved_total` (approved, green)
- Stat: `gmail_drafts_rejected_total` (rejected, red)
- Bar gauge: approval rate = `approved / (approved + rejected)` as percentage
- Time series: `increase(gmail_drafts_created_total[24h])` stacked with approved/rejected

"""Prometheus metrics for Gmail integration.

Exposes 13 metrics on port 9101 for Prometheus scraping.
Follows the same pattern as src/monitoring/whatsapp_metrics.py.
"""
from prometheus_client import Counter, Gauge, Histogram, start_http_server

# Connection state
gmail_connected = Gauge(
    "gmail_connected",
    "Gmail API connection state (1=connected, 0=disconnected)",
)

# Email flow counters
gmail_emails_received_total = Counter(
    "gmail_emails_received_total",
    "Total emails received via Gmail API",
)
gmail_emails_classified_total = Counter(
    "gmail_emails_classified_total",
    "Total emails classified by category",
    ["category"],
)
gmail_emails_notified_total = Counter(
    "gmail_emails_notified_total",
    "Total emails that triggered Discord notification",
)

# Draft lifecycle counters
gmail_drafts_created_total = Counter(
    "gmail_drafts_created_total",
    "Total draft replies created",
)
gmail_drafts_approved_total = Counter(
    "gmail_drafts_approved_total",
    "Total drafts approved by Faiz",
)
gmail_drafts_rejected_total = Counter(
    "gmail_drafts_rejected_total",
    "Total drafts rejected by Faiz",
)

# Security event counters
gmail_injection_detected_total = Counter(
    "gmail_injection_detected_total",
    "Total prompt injection attempts detected in emails",
    ["pattern_type"],
)
gmail_secrets_detected_total = Counter(
    "gmail_secrets_detected_total",
    "Total secrets detected in email content",
    ["secret_type"],
)

# Operational health gauges
gmail_api_quota_usage = Gauge(
    "gmail_api_quota_usage",
    "Gmail API quota usage as fraction (0.0 to 1.0)",
)
gmail_oauth_token_age_seconds = Gauge(
    "gmail_oauth_token_age_seconds",
    "Age of current OAuth token in seconds",
)
gmail_watch_active = Gauge(
    "gmail_watch_active",
    "Gmail watch subscription active (1=active, 0=inactive)",
)

# Processing latency histogram
gmail_processing_latency_seconds = Histogram(
    "gmail_processing_latency_seconds",
    "Email processing latency by stage",
    ["stage"],
    buckets=[0.1, 0.25, 0.5, 1.0, 2.5, 5.0, 10.0, 30.0],
)

def start_metrics_server(port: int = 9101) -> None:
    """Start the Prometheus metrics HTTP server."""
    start_http_server(port)
DESIGN

        Row(title="Security", panels=[...]),        # Panel 2

#### Troubleshooting
- **Issue:** `curl http://localhost:9101/metrics` returns connection refused
  - **Solution:** The metrics server may not be started. Verify `start_metrics_server()` is called during Gmail service startup: `grep -n "start_metrics_server\|metrics" src/gmail/main.py`. If the function exists but port is already in use, check: `ss -tlnp | grep 9101`. Kill the conflicting process or change the port.

- **Issue:** Prometheus shows `guinevere-gmail` target as DOWN
  - **Solution:** Check Prometheus scrape errors: `curl -s http://localhost:9090/api/v1/targets | python3 -m json.tool | grep -A10 "guinevere-gmail"`. Common causes: (1) metrics endpoint not reachable from Prometheus (firewall), (2) metrics endpoint returning non-200 status, (3) scrape timeout too short for the metrics page. Verify with direct curl: `curl -v http://localhost:9101/metrics`.

- **Issue:** Grafana dashboard does not appear after provisioning
  - **Solution:** Check Grafana provisioning logs: `sudo journalctl -u grafana-server -n 20 --no-pager | grep -i "provision\|gmail\|error"`. Common causes: (1) JSON syntax error in dashboard file — validate with `python3 -m json.tool deploy/grafana/gmail-dashboard.json`, (2) provisioning YAML syntax error — validate with `python3 -c "import yaml; yaml.safe_load(open('deploy/grafana/gmail-provision.yaml'))"`, (3) wrong file path in provisioning config — verify `path:` points to the actual dashboard JSON location.

- **Issue:** Alert rules do not fire when threshold is exceeded
  - **Solution:** Verify alert rules loaded: `curl -s http://localhost:3000/api/v1/provisioning/alert-rules -H "Authorization: Bearer $GRAFANA_API_KEY"`. Check the notification channel (Discord webhook) is configured: Grafana UI → Alerting → Contact Points → verify Discord webhook. Test alert manually: set `gmail_connected` to 0 and wait 10 minutes, or use Grafana's "Test Rule" button.

- **Issue:** `grafanalib` installation fails
  - **Solution:** Try installing with explicit version: `uv pip install "grafanalib>=0.7.0"`. If Python version conflict, check compatibility: `python --version` (should be 3.12). As fallback, generate dashboard JSON manually without grafanalib — the JSON structure follows Grafana's dashboard model schema.

- **Issue:** TimescaleDB remote-write not receiving Gmail metrics
  - **Solution:** Check Prometheus remote-write config: `grep -A5 "remote_write" /etc/prometheus/prometheus.yml`. Verify TimescaleDB Prometheus adapter is running: `sudo systemctl status prometheus-timescaledb-adapter`. Check adapter logs for write errors: `sudo journalctl -u prometheus-timescaledb-adapter -n 10`.

#### Notes
- **grafanalib Pattern:** Dashboard-as-code means the dashboard definition is reproducible and reviewable in git. The Python file generates JSON which is then placed in Grafana's provisioning directory. Changes to the dashboard require regenerating the JSON and restarting Grafana (or waiting for the `updateIntervalSeconds: 60` auto-reload).
- **Metric Naming Convention:** All Gmail metrics use the `gmail_` prefix (not `guinevere_gmail_`) for brevity in PromQL queries. This follows the convention established by WhatsApp metrics (`whatsapp_` prefix). The `device` label used by WhatsApp is not needed for Gmail since there is only one account.
- **Port Allocation:** Port 9101 is allocated for Gmail metrics, following 9100 used by WhatsApp metrics (P11-021). Both are scraped by the same Prometheus instance. If port conflicts arise during development, use the `--metrics-port` flag on the Gmail service.
- **Alert Escalation:** Critical alerts (disconnected, injection, watch inactive) fire immediately to Discord with @here mention. Warning alerts (quota, token age, latency) fire to Discord without mention. All alerts include a runbook link in the annotation.
- **Cross-Reference P11-021:** WhatsApp metrics (P11-021) established the pattern: `src/monitoring/{channel}_metrics.py` with prometheus_client library, port-based endpoint, Prometheus scrape target, Grafana dashboard. P12-025 follows this exact pattern.
- **Cross-Reference ADR-032:** ADR-032 mandates that all new integrations expose Prometheus metrics from day 1. The 13 metrics satisfy this requirement. Post-MVP metrics (e.g., per-sender statistics, classification accuracy tracking) are deferred.
- **Token Age Alert:** The 50-day threshold provides a 7-day buffer before the 7-day OAuth token expiry in testing mode. When the alert fires, Faiz has time to run `!email-reauth` before the token actually expires. In production (post-testing-mode), this threshold should be adjusted to match the actual token lifetime.
- **No Modifying Existing Files:** This step creates new files only. The Prometheus config addition (scrape target) and Grafana provisioning are additive — they do not modify existing WhatsApp or core dashboards/alerts.
