#### Context

P11-004 defines the `ChannelAdapter` abstract base class and `UnifiedMessage` dataclass as the multi-channel abstraction layer. At the time of P12 development, P11-004 is spec-only — the interface is defined but not yet implemented for any channel. P12 builds `GmailAdapter` against this spec, becoming the first concrete adapter implementation.

`ChannelAdapter` defines 5 abstract methods: `connect()`, `disconnect()`, `send_message()`, `to_unified_message()`, `from_unified_response()`. It also provides 2 concrete methods inherited by all adapters: `check_hard_stop()` (reads shared Redis flag for cross-channel HARD STOP per ADR-002) and `compute_content_hash()` (SHA-256 of sender_id + content + timestamp for deduplication per SRS-IR-009).

`GmailAdapter` must handle Gmail-specific concerns that don't exist in other channels: thread-based conversations (Gmail groups messages by `threadId`), label-based organization (system labels like INBOX/IMPORTANT plus user labels), MIME message construction for sending (base64URL-encoded RFC 2822), and metadata enrichment (subject, cc, labels, delivery_status in `UnifiedMessage.metadata`).

The adapter uses `ChannelType.GMAIL` which is already defined in the `ChannelType` enum (P11-004 spec). `UnifiedMessage` uses a flexible `metadata` dict for channel-specific fields — no schema change needed to the core dataclass. Gmail-specific metadata keys: `subject`, `thread_id`, `labels`, `cc`, `has_attachments`, `delivery_status`.

Error handling must cover: OAuth token expiry (trigger refresh), API quota exhaustion (backoff + retry), network failures (exponential backoff), and Gmail-specific errors (403 for scope violations, 404 for missing messages).

#### Troubleshooting
- **Issue:** `TypeError: Can't instantiate abstract class GmailAdapter with abstract methods`
  - **Solution:** One or more abstract methods are not implemented. Check that all 5 methods have concrete implementations: `connect`, `disconnect`, `send_message`, `to_unified_message`, `from_unified_response`.
- **Issue:** MIME message rejected by Gmail API — invalid base64URL encoding
  - **Solution:** Gmail requires base64**URL** encoding (replace `+` with `-`, `/` with `_`, strip `=` padding). Use `base64.urlsafe_b64encode()` and `rstrip(b'=')`. Do not use standard base64.
- **Issue:** Thread replies not grouping in Gmail — wrong headers
  - **Solution:** All three conditions must be met: (1) `threadId` set in the API call, (2) `In-Reply-To` header matches original `Message-ID`, (3) `Subject` matches (Gmail handles `Re:` prefix automatically). Missing any one breaks threading.
- **Issue:** `to_unified_message()` produces inconsistent `content_hash` for same email
  - **Solution:** Ensure deterministic hash input: normalize sender email to lowercase, strip whitespace from content, use ISO format for timestamp. Do not include mutable metadata (labels can change) in hash computation.
- **Issue:** OAuth token refresh during `send_message()` causes message loss
  - **Solution:** Implement retry pattern: if 401 received, refresh token, then retry the send call exactly once. If retry fails, raise `GmailOAuthExpiredError` and alert via Discord for manual re-auth.

#### Notes
- P11-004 is a spec-only dependency. The `ChannelAdapter` ABC and `UnifiedMessage` dataclass are defined in spec but may not be implemented yet. P12 builds against the spec interface. When P11-004 is eventually implemented, `GmailAdapter` should work without changes if the spec is followed correctly.
- `UnifiedMessage.metadata` is intentionally a `dict` (not typed dataclass) to accommodate channel-specific fields. GmailAdapter documents its own metadata keys: `subject`, `thread_id`, `labels`, `cc`, `has_attachments`, `delivery_status`.
- The default send behavior is `as_draft=True` — GmailAdapter creates Gmail drafts, not sent messages. Faiz must approve each draft via Discord before sending (P12 draft pipeline). Direct send is only used when explicitly requested via `kwargs["as_draft"]=False`.
- `GmailResponse` is separate from `UnifiedResponse` (defined in P11-004 spec). `GmailResponse` contains Gmail-specific fields (`thread_id`, `in_reply_to`, `references`) needed for MIME construction. `from_unified_response()` converts `UnifiedResponse` → `GmailResponse` → Gmail API payload.

- Cross-reference P12-006 (Pub/Sub) for incoming message flow: Pub/Sub notification → HistorySync → SyncEngine → GmailAdapter.to_unified_message().
