## 2. structlog — Status: DECLARED (declared but possibly not installed in active venv)

### Declaration

**`pyproject.toml` line 19:**
```toml
dependencies = [
    ...
    "structlog>=24",
    ...
]
```

**`uv.lock` — confirmed present** (3 references, fully resolved version available).

### Source usage

`structlog` is imported in **163 source files** across the entire `src/` tree. Every module uses it for structured logging:
```python
import structlog
logger: Final = structlog.get_logger(__name__)
```

One test file directly imports it:
- `tests/persona/test_ritual_midnight.py:23`: `from structlog.testing import LogCapture`

### Verdict

**Declared-vs-installed mismatch.** structlog is correctly declared in `pyproject.toml` and resolvable by uv. The `ModuleNotFoundError` during test collection means:

1. The active Python interpreter (used by `pytest`) is **not** the uv-managed venv, OR
2. The uv venv was created but `uv sync` was never run, OR
3. The venv was created before structlog was added to pyproject.toml and never updated.

**Fix:** Run `uv sync` (or `uv sync --group test`) in the project root.

## 3. pgvector (Python package) — Status: UNDECLARED (missing from pyproject.toml)

### Declaration

**`pyproject.toml` — NOT PRESENT.** Zero mention of `pgvector` in `[project.dependencies]` or `[project.optional-dependencies]`.

**`uv.lock` — NOT FOUND.** No `name = "pgvector"` entry exists, confirming it was never installed or locked.

### Secondary declaration (non-standard)

**`plugins/memory/guinevere_memory/plugin.yaml` line 7:**
```yaml
pip_dependencies:
  - "pgvector>=0.2"
```

This is a **Hermes plugin manifest**, not a standard Python packaging file. Hermes may or may not respect this during plugin installation. It is **not** consulted by `uv sync`.

### Source usage

`pgvector` (the Python SQLAlchemy adapter package) is imported in **core source code**, not just plugin code:

| File | Import |
|------|--------|
| `src/memory/models.py:6` | `from pgvector.sqlalchemy import Vector` |
| `alembic/versions/e401bb5fd274_initial_schema_47_tables.py:13` | `import pgvector` |

When pytest collects `tests/phase7/test_T4_memory_pipeline.py`, it imports `from src.memory.models import Episodes`, which triggers `from pgvector.sqlalchemy import Vector` → **ModuleNotFoundError**.

### Verdict

**Undeclared dependency bug.** The `pgvector` Python package is used as a direct import in `src/memory/models.py` (a core module imported by tests and production code), and in `alembic/versions/` (migration code), but it is **never listed in `pyproject.toml`**. This means:

1. `uv sync` never installs it.
2. Every fresh venv or CI environment will be missing it.
3. Test collection fails before any test runs.

**This is the root cause** of the Phase 5 T1-T9 collection failure. The import chain is:

```
pytest collects test_T4_memory_pipeline.py
  → from src.memory.models import Episodes
    → from pgvector.sqlalchemy import Vector
      → ModuleNotFoundError: No module named 'pgvector'
```

## 4. Why T10 Passes

`tests/phase7/test_T10_monitoring_health.py` tests **config file integrity** (Prometheus YAML, Grafana JSON, systemd templates). It does **not import** any `src.*` module, so it never triggers the pgvector or structlog import chain. It runs successfully because it only reads files from disk.

## 5. The T4 Import Chain (Detailed)

```
test_T4_memory_pipeline.py
  imports:
    src.memory.dnr           → uses structlog
    src.memory.consolidation → uses structlog
    src.memory.embeddings    → uses structlog
    src.memory.models        → uses structlog + pgvector ← FATAL
```

T4 fails at import time (during test collection, before any test runs). Even if pgvector were fixed, structlog would also stop collection if the venv is out-of-sync.

## 6. Minimum Safe Remediation

### Step 1: Add pgvector to `pyproject.toml`

Insert into the `[project.dependencies]` list in `pyproject.toml`:

```toml
    "pgvector>=0.2",
```

Place it after the existing SQLAlchemy entry for logical grouping (or at the end with the other ML-related deps like `sentence-transformers` and `scipy`).

### Step 2: Regenerate lockfile and install

```bash
uv sync --group test
```

This installs both `pgvector` (newly declared) and `structlog` (already declared) into the uv-managed venv.

### Step 3: Verify

```bash
uv run python -c "from pgvector.sqlalchemy import Vector; print('pgvector OK')"
uv run python -c "import structlog; print('structlog:', structlog.__version__)"
```

### Step 4: Run tests

```bash
uv run pytest tests/phase7/ -v --tb=short
```

## 9. Caveats

1. **`plugins/memory/guinevere_memory/plugin.yaml` declares `pgvector>=0.2`** — this would be picked up by Hermes agent's plugin installer, but not by `uv sync`. If Hermes is the primary runtime, the plugin manifest covers it at deploy time. For local test collection, `pyproject.toml` must declare it.
2. **The PostgreSQL `pgvector` extension** (C extension on the DB server) is separate from the Python `pgvector` package (SQLAlchemy adapter). The VPS has the DB extension installed (P0-015, vector 0.8.2). The Python package is needed for the import `from pgvector.sqlalchemy import Vector`.
3. **No `requirements.txt` or `dev-requirements.txt`** — the project relies entirely on uv. Adding a `requirements.txt` for non-uv users is out of scope but could be considered.
4. **`[project.optional-dependencies] test` only contains `pytest-cov>=7`** — other test-only dependencies (pytest-asyncio, pytest-benchmark, etc.) may also be missing if the venv is synced without `--group test`.
