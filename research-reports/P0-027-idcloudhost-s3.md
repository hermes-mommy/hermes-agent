## 1. S3 Endpoint URL

| Item | Value |
|---|---|
| **S3 Endpoint** | `is3.cloudhost.id` |
| **HTTPS endpoint** | `https://is3.cloudhost.id` |
| **DNS-style bucket template** | `%(bucket)s.is3.cloudhost.id` |
| **Path-style URL** | `https://is3.cloudhost.id/<bucket-name>` |
| **Alternative bucket URL** | `https://<bucket-name>.is3.cloudhost.id` |

**Source**: [s3cmd config guide (sirius.miraheze.org)](https://sirius.miraheze.org/wiki/S3cmd:_Config_S3_IDCloudHost), [Cyberduck guide (idcloudhost.com)](https://idcloudhost.com/panduan/cara-akses-object-storage-idcloudhost-menggunakan-cyberduck/)

## 2. Authentication

- **Mechanism**: Standard AWS S3-compatible **Access Key ID + Secret Access Key**.
- **Format**: Same as AWS IAM user credentials — a key ID string and a secret string generated by the idcloudhost console.
- **Scope**: Keys are **per-account**, not per-bucket. One set of credentials works for all buckets under the same account.
- **Where to obtain**: Login to [console.idcloudhost.com](https://console.idcloudhost.com/) → Storage → Create bucket → click on the bucket → Access Key ID and Secret Access Key are displayed.
- **No IAM policies**: idcloudhost does not offer AWS-style IAM — there is no way to scope permissions per-bucket. The credentials have full read/write access to all buckets.

**Source**: [Nyobain Object Storage dari IDCloudHost (farrelf.blog)](https://farrelf.blog/nyobain-object-storage-dari-idcloudhost/)

## 3. Bucket Creation & Management

### Via Console
1. Login to [console.idcloudhost.com](https://console.idcloudhost.com/)
2. Navigate to **Storage** → **Create New Storage** / **+New**
3. Enter a **Storage Name** (bucket name):
   - Allowed characters: lowercase letters, numbers, hyphens (`-`)
   - Must be **globally unique** across all idcloudhost customers
4. Click **Create**

### Via Terraform
```hcl
resource "idcloudhost_s3" "mybucket" {
  name              = "mybucket"
  billing_account_id = 000000
}
```

**Source**: [Membuat Bucket (sukabumikode.com)](https://www.sukabumikode.com/v/144/membuat-bucket-di-object-storage-idcloudhost), [Terraform provider (github.com/rizalmf)](https://github.com/rizalmf/terraform-provider-idcloudhost)

## 5. Pricing

| Component | Price |
|---|---|
| **Storage** | ~Rp507/GB/month (~$0.034/GB/month or ~$34/TB/month) |
| **Request fees** | None reported |
| **Bandwidth (in/out)** | None reported — included in storage price |
| **Free tier** | 75 GB storage + 75 GB bandwidth/month (requires credit card for verification) |

**Billing model**:
- Pay-per-use: you're charged only for the actual storage used (no rounding to 1GB blocks)
- Flexible: hourly or monthly billing option
- Can stop the service anytime to stop billing

**Note**: At ~Rp507/GB, idcloudhost is more expensive than global providers like Backblaze B2 (~$6/TB) or Wasabi (~$7/TB), but competitive for an Indonesian provider with local datacenters and no egress fees.

**Source**: [Nyobain Object Storage (farrelf.blog)](https://farrelf.blog/nyobain-object-storage-dari-idcloudhost/), [IDCloudHost object storage page](https://idcloudhost.com/object-storage/)

## 6. S3 API Compatibility

### Verified Working Tools
| Tool | Status | Notes |
|---|---|---|
| **AWS CLI** | ✅ Working | Standard `aws s3` / `aws s3api` commands work |
| **s3cmd** | ✅ Working | Config: endpoint `is3.cloudhost.id`, DNS template `%(bucket)s.is3.cloudhost.id` |
| **Cyberduck** | ✅ Working | Amazon S3 protocol, server `is3.cloudhost.id` |
| **s3fs (FUSE)** | ✅ Working | Can mount bucket as local filesystem |
| **Laravel (league/flysystem-aws-s3-v3)** | ✅ Working | AWS SDK v3, `use_path_style_endpoint: false` |
| **Rclone** | ✅ Working | S3-compatible remote type |

### Claims from Provider
IDCloudHost states their Object Storage has **full S3 API protocol support** ("Kompatibel Protokol S3 — sudah mendukung penuh Protokol S3 (S3 API)").

### Known Limitations / Quirks
1. **No built-in file browser** — The console does not have a native file manager. You must use third-party tools (Cyberduck, s3fs, Rclone, etc.) to browse/upload files.
2. **Some AWS-specific S3 features may not work** — As with all S3-compatible providers, advanced features like:
   - S3 Object Lock / WORM
   - Bucket policies / IAM policies
   - S3 replication
   - S3 event notifications
   - May not be fully supported.
3. **One set of credentials for all buckets** — No per-bucket or per-operation access control.
4. **s3fs stability reported as "kurang stabil" (less stable)** — One user reported occasional mount issues requiring remount.

**Source**: [Farrelf's blog](https://farrelf.blog/nyobain-object-storage-dari-idcloudhost/), [Lukmanlab backup blog](https://www.lukmanlab.com/backup-data-vps-ke-layanan-object-storage-idcloudhost/)

## 7. Restic Configuration

Restic uses the MinIO Go client library for S3, which works with any S3-compatible endpoint. Based on the endpoint details above, here is the recommended configuration:

### Environment Variables
```bash
export RESTIC_REPOSITORY="s3:https://is3.cloudhost.id/<bucket-name>"
export RESTIC_PASSWORD="<your-strong-encryption-password>"
export AWS_ACCESS_KEY_ID="<your-access-key>"
export AWS_SECRET_ACCESS_KEY="<your-secret-key>"

# Optional but recommended:
export AWS_DEFAULT_REGION="us-east-1"
```

### Initialize Repository
```bash
restic init
```

### Backup
```bash
restic backup /path/to/data
```

### Important Notes for Restic
- **Use HTTPS endpoint** (`https://is3.cloudhost.id/`) — not just the hostname.
- **Path-style vs DNS-style**: The endpoint `https://is3.cloudhost.id/<bucket>` uses path-style. DNS-style (`https://<bucket>.is3.cloudhost.id`) also works.
- **No known issues**: No specific restic + idcloudhost issues found in public sources, but since it uses standard S3 API via MinIO client, it should work.
- **Connection count**: Default is 5 concurrent connections; you may need to adjust with `-o s3.connections=3` if you hit rate limits.
- **ListObjectsV1**: If you encounter listing issues, try `-o s3.list-objects-v1=true`.

### Comparison: idcloudhost vs Other S3 Backups for Restic

| Aspect | idcloudhost | Backblaze B2 | Wasabi |
|---|---|---|---|
| Storage cost | ~$34/TB/mo | ~$6/TB/mo | ~$7/TB/mo |
| Egress cost | Included | Free up to 3x storage | Free |
| Indonesia DC | ✅ Yes | ❌ No | ❌ No (Singapore available) |
| S3 API compat | Good (basic S3) | Good | Good |
| Object Lock | ❌ Not confirmed | ✅ Yes | ✅ Yes (90d min) |
