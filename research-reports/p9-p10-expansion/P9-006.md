### Step P9-006: Transaction Classification (15+ Indonesian Spending Categories)

**Type:** Application
**Status:** Not Started
**Risk:** Low
**Git Commit:** `feat(P9): pending`

**Goal:** Build a rules-based transaction classifier that assigns each parsed transaction to one of 15+ Indonesian spending categories using keyword matching against 150+ merchant patterns with confidence scoring.
**Dependencies:** P9-005 (SMS parser writing to `financial.transactions`), P9-002 (TransactionRepository with update support for `category` and `category_confidence` fields), P9-001 (financial schema with `category`, `category_confidence`, `classified_at` columns on transactions table).
**Cost Impact:** $0/month (application logic only; no new infrastructure)
**ADR References:** ADR-023 (Financial Data Integration — confidence scoring and correction flows), ADR-024 (Data Classification — all financial data = CRITICAL)
**Acceptance Criteria:** AC-FIN-005 (Transaction classification with 15+ categories and confidence scoring functional)
**Estimated Time:** 3 hours

#### Context

After P9-005 parses an SMS into structured fields (amount, merchant, transaction_type, timestamp), the transaction still lacks a spending category. This step builds the classifier that maps merchant names to Indonesian spending categories: Food/Minimarket, Transport, Subscriptions, Utilities, Shopping, Health, Education, Entertainment, Insurance, LLM/API Costs, Infrastructure, Salary/Income, Transfer, Cash Withdrawal, Other. The rule engine uses a PostgreSQL-stored keyword-to-category mapping table for live updates without redeploy. Classification runs asynchronously — P9-005 fires a classification event after each successful parse. Confidence scoring follows ADR-023: exact merchant match = 1.0, substring match = 0.7, no match = 0.3 with fallback to `transaction_type` heuristic (debit = likely expense, credit = likely income). A manual override endpoint allows Faiz to reclassify via PATCH. LLM/API cost transactions integrate with existing Redis DB5 `ToolCostTracker` data — transactions with `source='tool_cost_tracker'` auto-classify as LLM/API Costs.

#### Troubleshooting

- **Issue:** Classifier always returns `Other` for legitimate Indonesian merchants.
  - **Solution:** Check `financial.merchant_category_rules` for missing keywords. Add new rule: `INSERT INTO financial.merchant_category_rules (keyword, category, is_regex, priority) VALUES ('nama_merchant_baru', 'CategoryName', false, 10)`. Rules table is live — no redeploy needed.
- **Issue:** Two categories match the same merchant (e.g., GoFood matches both Food and Transport).
  - **Solution:** Classifier resolves ties by `priority` field descending. Higher priority wins. Default: Food > Transport for GoFood/GrabFood (they are food delivery, category = Food). Adjust priority values in rules table.
- **Issue:** LLM cost transactions not auto-classifying.
  - **Solution:** Verify `source` column on transaction is `tool_cost_tracker`. P9-005 parser sets source based on `device_id` — SMS from phone is `sms`, Redis bridge data is `tool_cost_tracker`. Check Redis DB5 key patterns for tool cost data.
- **Issue:** Batch reclassify endpoint times out on large historical datasets.
  - **Solution:** Classifier processes in chunks of 100 with async gather. Increase timeout on FastAPI endpoint or use background task (`BackgroundTasks.add_task`).

#### Notes

- Merchant keyword rules stored in PostgreSQL `financial.merchant_category_rules` for live updates. Adding a new merchant takes one SQL INSERT — no code change, no redeploy.
- Classification runs async via an event hook: P9-005 parser publishes `transaction.classify` event after successful parse; classifier subscribes and processes. This decouples parsing from classification so parser throughput is not constrained.
- LLM/API cost integration with Redis DB5 `ToolCostTracker` is a bridge: classifier queries Redis for tool cost records without a corresponding `financial.transactions` row, creates them with `category='LLM/API Costs'` and `source='tool_cost_tracker'`. This is the first half of the Redis-to-PostgreSQL cost bridge (second half in P9-012).
- Manual override sets `classified_by = 'faiz_manual'` and `category_confidence = 1.0`. Automated reclassification skips any row where `classified_by = 'faiz_manual'` to preserve manual corrections.
- Rules are simple keyword/substring matches by default. Regex support is available via `is_regex=true` flag on the rules table for complex patterns (e.g., `\bPLN\b.*\bTOKEN\b` for electricity token purchases).
