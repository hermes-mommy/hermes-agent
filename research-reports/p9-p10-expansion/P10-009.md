### Step P10-009: CD via systemd Timer

**Type:** Infrastructure
**Status:** ⬜ Not Started
**Risk:** High
**Git Commit:** `feat(P10): CD via systemd timer`

**Goal:** Automated continuous deployment via systemd timer that checks for new successful CI builds on `main` and deploys automatically.
**Dependencies:** P10-007 (deploy script operational), P10-008 (CI pipeline passing on main), P10-010 (rollback script for failure recovery)
**Cost Impact:** $0/month (runs on existing VPS)
**ADR References:** ADR-016, ADR-014
**Acceptance Criteria:** AC-OPS-005, AC-CORE-001
**Estimated Time:** 3 hours

#### Context

ADR-016 requires an automated deployment pipeline, and ADR-014 mandates that Guinevere services be self-managing where safe. After CI passes on `main`, a systemd timer checks every 5 minutes whether the local deployment is behind the remote HEAD. If behind, the timer triggers: `git pull`, install dependencies, run migrations, restart services, verify health. The deploy script from P10-007 is invoked as a subprocess. The timer respects maintenance windows — no automatic deployments during 23:00-06:00 WIB or during active incidents. A Discord notification is sent on every deploy attempt (success or failure) to the operator channel.

#### Pre-flight Checks
- [ ] P10-007 deploy script (`scripts/deploy.sh`) is operational and tested manually
- [ ] P10-008 CI pipeline is passing on the latest `main` commit
- [ ] P10-010 rollback script (`scripts/rollback.sh`) exists (if not yet, CD deploys without auto-rollback)
- [ ] `guinevere` system user exists with sudo privileges limited to `systemctl restart guinevere-*`
- [ ] Git deploy key or token configured at `/home/guinevere/.ssh/id_ed25519_deploy`
- [ ] Discord webhook URL available in SOPS-encrypted env for deployment notifications
- [ ] Health check endpoint returns 200 on the running instance

#### Commands

```bash
# 1. Create CD check script
cat > /home/guinevere/scripts/cd-check.sh << 'CDEOF'
#!/usr/bin/env bash
set -euo pipefail

LOG_FILE="/home/guinevere/logs/cd-check.log"
CONFIG_FILE="/home/guinevere/config/cd-config.json"
REPO_DIR="/home/guinevere/guinevere"
DEPLOY_SCRIPT="/home/guinevere/scripts/deploy.sh"
ROLLBACK_SCRIPT="/home/guinevere/scripts/rollback.sh"
DISCORD_WEBHOOK="${DISCORD_DEPLOY_WEBHOOK:-}"

log() { echo "[$(date -Iseconds)] $*" | tee -a "$LOG_FILE"; }

# --- Maintenance Window Check ---
check_maintenance_window() {
    local now_hour wib_hour
    wib_hour=$(TZ=Asia/Jakarta date +%H)
    wib_hour=${wib_hour#0}
    if [[ -f "$CONFIG_FILE" ]] && jq -e '.maintenance.active' "$CONFIG_FILE" > /dev/null 2>&1; then
        log "Maintenance window active — skipping CD"
        return 1
    fi
    if [[ $wib_hour -ge 23 ]] || [[ $wib_hour -lt 6 ]]; then
        log "Outside deployment hours (23:00-06:00 WIB) — skipping CD"
        return 1
    fi
    return 0
}

# --- Discord Notification ---
notify_discord() {
    local status="$1" msg="$2"
    if [[ -n "$DISCORD_WEBHOOK" ]]; then
        curl -sf -H "Content-Type: application/json" \
            -d "{\"content\":\"[CD Timer] **${status}**: ${msg}\"}" \
            "$DISCORD_WEBHOOK" || true
    fi
}

# --- Check if local is behind remote on main ---
check_behind() {
    cd "$REPO_DIR"
    git fetch origin main 2>&1 | tee -a "$LOG_FILE"
    local local_sha remote_sha
    local_sha=$(git rev-parse HEAD)
    remote_sha=$(git rev-parse origin/main)
    if [[ "$local_sha" == "$remote_sha" ]]; then
        log "Already at latest commit ($(echo "$local_sha" | head -c 8))"
        return 1
    fi
    log "Behind remote: local=$(echo "$local_sha" | head -c 8) remote=$(echo "$remote_sha" | head -c 8)"
    return 0
}

# --- Main CD Logic ---
main() {
    mkdir -p "$(dirname "$LOG_FILE")"
    log "=== CD Check starting ==="

    check_maintenance_window || { log "CD aborted: maintenance or off-hours"; exit 0; }

    check_behind || { log "CD skipped: no new commits"; exit 0; }

    notify_discord "DEPLOY STARTING" "New commits detected, running deploy..."

    if bash "$DEPLOY_SCRIPT" >> "$LOG_FILE" 2>&1; then
        log "Deploy completed successfully"
        notify_discord "DEPLOY SUCCESS" "Deploy to $(git -C "$REPO_DIR" rev-parse --short HEAD) completed."
    else
        log "ERROR: Deploy failed — triggering rollback"
        notify_discord "DEPLOY FAILED" "Rolling back..."
        if bash "$ROLLBACK_SCRIPT" >> "$LOG_FILE" 2>&1; then
            log "Rollback successful"
            notify_discord "ROLLBACK SUCCESS" "System rolled back to last known good commit."
        else
            log "CRITICAL: Rollback also failed!"
            notify_discord "CRITICAL" "Both deploy and rollback failed. Manual intervention required."
        fi
        exit 1
    fi
}

main
CDEOF

chmod +x /home/guinevere/scripts/cd-check.sh
chown guinevere:guinevere /home/guinevere/scripts/cd-check.sh

# 2. Create systemd service unit
cat > /etc/systemd/system/guinevere-cd.service << 'UNITEOF'
[Unit]
Description=Guinevere Continuous Deployment Check
After=network-online.target
Wants=network-online.target
ConditionPathExists=/home/guinevere/scripts/cd-check.sh

[Service]
Type=oneshot
User=guinevere
Group=guinevere
EnvironmentFile=/home/guinevere/config/env.secrets
ExecStart=/usr/bin/bash /home/guinevere/scripts/cd-check.sh
StandardOutput=journal
StandardError=journal
SyslogIdentifier=guinevere-cd
Nice=19
IOSchedulingClass=idle
PrivateTmp=yes

# Security hardening
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/home/guinevere/logs /home/guinevere/guinevere
ReadOnlyPaths=/home/guinevere/scripts /home/guinevere/config
UNITEOF

# 3. Create systemd timer unit
cat > /etc/systemd/system/guinevere-cd.timer << 'TIMEREOF'
[Unit]
Description=Guinevere CD Timer — check every 5 minutes
Requires=guinevere-cd.service

[Timer]
OnCalendar=*:0/5
AccuracySec=5s
RandomizedDelaySec=20s
Persistent=true

[Install]
WantedBy=timers.target
TIMEREOF

# 4. Reload systemd, enable, and start
systemctl daemon-reload
systemctl enable guinevere-cd.timer
systemctl start guinevere-cd.timer

# 5. Verify timer is active
systemctl list-timers guinevere-cd.timer
journalctl -u guinevere-cd.service -n 20 --no-pager
```

#### Troubleshooting

- **Issue:** Timer is not firing
  - **Solution:** Run `systemctl list-timers guinevere-cd.timer` to verify timer state. Check `journalctl -u guinevere-cd.timer` for errors. Ensure `OnCalendar=*:0/5` syntax is correct (every minute divisible by 5). Restart timer: `systemctl restart guinevere-cd.timer`.

- **Issue:** Git authentication failure during `git fetch`
  - **Solution:** Verify deploy key exists at `/home/guinevere/.ssh/id_ed25519_deploy`. Test manually: `sudo -u guinevere ssh -i /home/guinevere/.ssh/id_ed25519_deploy -T git@github.com`. Ensure the key is added as a deploy key in GitHub repo settings. Use SSH config at `/home/guinevere/.ssh/config` to force key usage for `github.com`.

- **Issue:** Health check timeout after deploy
  - **Solution:** Increase the sleep/retry loop in `deploy.sh` (P10-007). Default wait time should be 30 seconds with up to 5 retries. If timeout persists, investigate whether the application is actually failing (check `journalctl -u guinevere-*` for crash logs).

- **Issue:** `systemctl start guinevere-cd.service` fails with permission denied
  - **Solution:** Check that the `guinevere` user has sudo permissions for `systemctl restart guinevere-*` via sudoers. Add: `echo "guinevere ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart guinevere-*, /usr/bin/systemctl start guinevere-*, /usr/bin/systemctl stop guinevere-*" > /etc/sudoers.d/guinevere-deploy`.

- **Issue:** Random CD deployment during active incident
  - **Solution:** Create `/home/guinevere/config/cd-config.json` with `{"maintenance": {"active": true, "reason": "incident response", "set_by": "faiz"}}`. The timer reads this config on each run and skips deployment. Remove the file or set `active: false` to resume.

#### Notes

- CD is autonomous but NOT reckless. It respects maintenance windows, requires CI pass (precondition of P10-007 deploy script), and rolls back automatically on failure via P10-010.
- First deployment always requires Faiz approval per AC-PHASE-007 — this is enforced in the deploy script (P10-007), not the CD timer. The CD timer invokes the deploy script, which gates on approval.
- Timer runs under the `guinevere` system user with limited sudo (only `systemctl restart guinevere-*`). The `PrivateTmp=yes` and `ProtectSystem=strict` directives limit blast radius.
- `RandomizedDelaySec=20s` prevents thundering-herd if multiple timers fire simultaneously. `Persistent=true` ensures missed triggers (e.g., during server reboot) fire immediately on startup.
- Discord webhook should be configured as a SOPS-encrypted environment variable in `/home/guinevere/config/env.secrets` and decrypted at service startup.
- The CD timer does NOT run database migrations that are destructive (drop column, drop table). Destructive migrations must use the expand-contract pattern and be run manually by Faiz.
