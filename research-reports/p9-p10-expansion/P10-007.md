### Step P10-007: Self-Deploy Pipeline

**Type:** Infrastructure
**Status:** Not Started
**Risk:** High
**Git Commit:** `feat(P10): pending`

**Goal:** Automated deployment pipeline: git push to main branch triggers deployment with preflight checks, atomic service restart, health validation, automatic rollback on failure within 60 seconds, and Discord notification.
**Dependencies:** P10-008 (CI/CD workflow) should be operational for the full pipeline — but P10-007 creates the deploy script, P10-008 creates the CI trigger; they can be developed in parallel. All P10 hardening steps (P10-001 through P10-006) should be complete before enabling autonomous deploys.
**Cost Impact:** $0/month (GitHub Actions free tier, no additional infrastructure)
**ADR References:** ADR-016 (Self-Deploy Governance), ADR-029 (Automated Testing Gates)
**Acceptance Criteria:** AC-OPS-005 (Health-validated deploy with rollback on failure), AC-PHASE-007 (High-blast-radius changes require Guinevere recommend + Faiz approve)
**Estimated Time:** 4 hours

#### Context

Guinevere must self-deploy when code is pushed to the main branch. ADR-016 governs the deploy pipeline: preflight validation (disk space, service status, backup freshness), deploy gates (all CI checks pass), atomic restart (stop old + start new with health check), automatic rollback within 60 seconds on health check failure. ADR-029 requires an automated testing gate before deploy and safety-critical classification for deploy scripts. AC-OPS-005 validates: health checks before and after deploy, evidence capture (before/after state), automatic rollback on ANY failure, and Faiz approval for high-blast-radius changes. AC-PHASE-007: high-blast-radius deploy gates require Guinevere to recommend the deploy and Faiz to explicitly approve. The deploy script (`scripts/deploy.sh`) must be idempotent — running it twice produces the same result. The GitHub Actions workflow (P10-008) triggers this script. First deploy after setup requires Faiz approval; subsequent deploys are autonomous if CI passes.

#### Pre-flight Checks
- [ ] Git repository accessible: `git remote -v` shows origin
- [ ] GitHub Actions enabled on the repository (check repo Settings > Actions)
- [ ] Systemd services running: `systemctl is-active guinevere-*`
- [ ] Deploy script directory exists: `mkdir -p scripts/`
- [ ] `scripts/` is tracked in git: `git ls-files scripts/`
- [ ] Discord webhook URL available for notifications (stored in GitHub Secrets or .env)
- [ ] DEPLOY_KEY or SSH deploy key configured for GitHub Actions (if using SSH-based deploy)
- [ ] Health endpoint available: `curl -f http://localhost:8080/health` (or actual health endpoint)
- [ ] All P10 hardening steps (P10-001 through P10-006) verified — do not enable autonomous deploys on unhardened infrastructure

#### Commands

```bash
# 1. Create deploy script — scripts/deploy.sh
cat > scripts/deploy.sh << 'DEPLOYEOF'
#!/bin/bash
# Guinevere Self-Deploy Pipeline
# ADR-016: Preflight validation, atomic restart, health check, rollback within 60s
set -euo pipefail

TIMESTAMP=$(date -Iseconds)
LOG_DIR="docs/setup-evidence/P10/STEP-P10-007/deploy-logs"
mkdir -p "${LOG_DIR}"
LOG_FILE="${LOG_DIR}/deploy-$(date +%Y%m%d-%H%M%S).log"
exec > >(tee -a "${LOG_FILE}") 2>&1

echo "=== Guinevere Deploy: ${TIMESTAMP} ==="

# ── Preflight Checks ────────────────────────────────────────
echo "[PREFLIGHT] Starting preflight checks..."

# Disk space: require >= 2GB free
DISK_FREE=$(df -BG / | tail -1 | awk '{print $4}' | sed 's/G//')
if [ "${DISK_FREE}" -lt 2 ]; then
  echo "[PREFLIGHT] FAIL: Insufficient disk space (${DISK_FREE}GB < 2GB)"
  exit 1
fi
echo "[PREFLIGHT] PASS: Disk space OK (${DISK_FREE}GB free)"

# Service status: none in failed state
FAILED_SVCS=$(systemctl list-units --type=service --state=failed --no-legend | grep guinevere | wc -l)
if [ "${FAILED_SVCS}" -gt 1 ]; then
  echo "[PREFLIGHT] FAIL: ${FAILED_SVCS} services in failed state"
  exit 1
fi
echo "[PREFLIGHT] PASS: No failed services"

# Backup freshness: last backup < 25 hours ago (24h RPO + 1h buffer)
LAST_BACKUP=$(aws s3 ls s3://guinevere-backups/ --endpoint-url https://s3.idcloudhost.com 2>/dev/null | sort | tail -1 | awk '{print $1 " " $2}')
if [ -z "${LAST_BACKUP}" ]; then
  echo "[PREFLIGHT] WARN: Cannot verify backup freshness (S3 not accessible)"
else
  echo "[PREFLIGHT] PASS: Last backup: ${LAST_BACKUP}"
fi

# Git workspace clean (no uncommitted changes)
if ! git diff-index --quiet HEAD --; then
  echo "[PREFLIGHT] FAIL: Git workspace has uncommitted changes"
  exit 1
fi
echo "[PREFLIGHT] PASS: Git workspace clean"

echo "[PREFLIGHT] All checks passed"

# ── Before State Capture ────────────────────────────────────
echo "[BEFORE] Capturing pre-deploy state..."
systemctl list-units --type=service --state=running --no-legend | grep guinevere \
  > "${LOG_DIR}/before-services.txt"
git rev-parse HEAD > "${LOG_DIR}/before-commit.txt"

# ── Deploy ──────────────────────────────────────────────────
echo "[DEPLOY] Pulling latest code..."
git pull origin main

echo "[DEPLOY] Installing dependencies..."
uv sync --frozen

echo "[DEPLOY] Running database migrations..."
uv run alembic upgrade head

echo "[DEPLOY] Restarting services (rolling)..."
SERVICES=$(systemctl list-units --type=service --no-legend | grep guinevere | awk '{print $1}')
DEPLOY_FAILED=0

for svc in ${SERVICES}; do
  echo "[DEPLOY] Restarting ${svc}..."
  systemctl restart "${svc}"
  sleep 3

  # Health check: service must be active
  if ! systemctl is-active --quiet "${svc}"; then
    echo "[DEPLOY] FAIL: ${svc} is not active after restart"
    DEPLOY_FAILED=1
    break
  fi
  echo "[DEPLOY] ${svc} restarted and active"
done

if [ "${DEPLOY_FAILED}" -eq 1 ]; then
  echo "[DEPLOY] Deployment failed — initiating ROLLBACK"
  # ── Rollback ──────────────────────────────────────────────
  ROLLBACK_START=$(date +%s)
  PREV_COMMIT=$(cat "${LOG_DIR}/before-commit.txt")
  echo "[ROLLBACK] Reverting to commit: ${PREV_COMMIT}"
  git checkout "${PREV_COMMIT}"

  echo "[ROLLBACK] Reinstalling dependencies..."
  uv sync --frozen

  echo "[ROLLBACK] Restarting services..."
  for svc in ${SERVICES}; do
    systemctl restart "${svc}"
    sleep 2
  done

  # Health check after rollback
  sleep 5
  ROLLBACK_FAILED=0
  for svc in ${SERVICES}; do
    if ! systemctl is-active --quiet "${svc}"; then
      echo "[ROLLBACK] CRITICAL: ${svc} failed after rollback"
      ROLLBACK_FAILED=1
    fi
  done

  ROLLBACK_END=$(date +%s)
  ROLLBACK_DURATION=$((ROLLBACK_END - ROLLBACK_START))
  echo "[ROLLBACK] Duration: ${ROLLBACK_DURATION}s"

  if [ "${ROLLBACK_DURATION}" -gt 60 ]; then
    echo "[ROLLBACK] WARN: Rollback exceeded 60s target (${ROLLBACK_DURATION}s)"
  fi

  if [ "${ROLLBACK_FAILED}" -eq 1 ]; then
    echo "[ROLLBACK] CRITICAL: Manual intervention required — SSH to VPS"
  else
    echo "[ROLLBACK] Rollback successful — system restored to ${PREV_COMMIT}"
  fi
  exit 1
fi

# ── Health Check (full) ─────────────────────────────────────
echo "[HEALTH] Running full health checks..."

# Application health endpoint
HEALTH_URL="http://localhost:8080/health"
if curl -sf --max-time 10 "${HEALTH_URL}" > /dev/null 2>&1; then
  echo "[HEALTH] PASS: Application health endpoint OK"
else
  echo "[HEALTH] WARN: Health endpoint not reachable (non-blocking)"
fi

# Database connectivity
if psql -U guinevere -h localhost -d guinevere -c "SELECT 1" > /dev/null 2>&1; then
  echo "[HEALTH] PASS: Database connectivity OK"
else
  echo "[HEALTH] FAIL: Database connectivity failed"
  DEPLOY_FAILED=1
fi

# Redis connectivity
if redis-cli -p 6380 PING | grep -q PONG; then
  echo "[HEALTH] PASS: Redis connectivity OK"
else
  echo "[HEALTH] FAIL: Redis connectivity failed"
  DEPLOY_FAILED=1
fi

if [ "${DEPLOY_FAILED}" -eq 1 ]; then
  echo "[HEALTH] Health checks failed — aborting deploy"
  exit 1
fi

# ── After State Capture ─────────────────────────────────────
echo "[AFTER] Capturing post-deploy state..."
systemctl list-units --type=service --state=running --no-legend | grep guinevere \
  > "${LOG_DIR}/after-services.txt"
git rev-parse HEAD > "${LOG_DIR}/after-commit.txt"

# ── Discord Notification ────────────────────────────────────
DISCORD_WEBHOOK="${DISCORD_WEBHOOK_URL:-}"
NEW_COMMIT=$(cat "${LOG_DIR}/after-commit.txt")
PREV_COMMIT=$(cat "${LOG_DIR}/before-commit.txt")
COMMIT_MSG=$(git log -1 --pretty=%B "${NEW_COMMIT}")

if [ -n "${DISCORD_WEBHOOK}" ]; then
  curl -s -H "Content-Type: application/json" \
    -d "{\"content\": \"**Guinevere Deployed Successfully**\n\`\`\`\nFrom: ${PREV_COMMIT:0:7}\nTo:   ${NEW_COMMIT:0:7}\nMsg:  ${COMMIT_MSG:0:200}\n\`\`\`\"}" \
    "${DISCORD_WEBHOOK}" > /dev/null 2>&1 || true
  echo "[NOTIFY] Discord notification sent"
fi

echo "=== Deploy Complete: $(date -Iseconds) ==="
exit 0
DEPLOYEOF

chmod +x scripts/deploy.sh
echo "Deploy script created: scripts/deploy.sh"

# 2. Verify deploy script is syntactically valid
bash -n scripts/deploy.sh && echo "PASS: Script syntax valid" || echo "FAIL: Script has syntax errors"

# 3. Create GitHub Actions workflow to trigger deploy (for P10-008 integration)
mkdir -p .github/workflows
cat > .github/workflows/deploy.yml << 'WFEOF'
name: Deploy Guinevere

on:
  push:
    branches: [main]
  workflow_dispatch:  # Allow manual trigger

jobs:
  deploy:
    runs-on: ubuntu-latest
    if: github.event_name == 'workflow_dispatch' || github.ref == 'refs/heads/main'
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Deploy to Production
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.DEPLOY_HOST }}
          username: ${{ secrets.DEPLOY_USER }}
          key: ${{ secrets.DEPLOY_KEY }}
          script: |
            cd /opt/guinevere
            git pull origin main
            bash scripts/deploy.sh
WFEOF
echo "GitHub Actions workflow created: .github/workflows/deploy.yml"

# 4. Create deploy script verification (dry-run mode)
cat > scripts/deploy-check.sh << 'CHECKEOF'

set -euo pipefail
echo "=== Deploy Pre-Check ==="

# Syntax check
bash -n scripts/deploy.sh && echo "[CHECK] PASS: Syntax valid" || { echo "[CHECK] FAIL: Syntax error"; exit 1; }

# Required tools check
for tool in git uv alembic systemctl psql redis-cli curl; do
  if command -v "${tool}" &>/dev/null; then
    echo "[CHECK] PASS: ${tool} available"
  else
    echo "[CHECK] FAIL: ${tool} not found"
  fi
done

# Script is executable
if [ -x scripts/deploy.sh ]; then
  echo "[CHECK] PASS: scripts/deploy.sh is executable"
else
  echo "[CHECK] FAIL: scripts/deploy.sh is not executable"
fi

# Idempotency check: verify deploy.sh uses set -euo pipefail
if grep -q "set -euo pipefail" scripts/deploy.sh; then
  echo "[CHECK] PASS: Strict error handling enabled"
else
  echo "[CHECK] FAIL: Missing 'set -euo pipefail'"
fi

echo "=== Pre-Check Complete ==="
CHECKEOF

chmod +x scripts/deploy-check.sh

# 5. Verify deploy-check script
bash scripts/deploy-check.sh \
  2>&1 | tee docs/setup-evidence/P10/STEP-P10-007/deploy-check-output.txt

# 6. Test deploy script in dry-run mode (no actual restart)
#    This validates the preflight checks work without touching services
echo "Testing preflight checks..."

  > docs/setup-evidence/P10/STEP-P10-007/preflight-test.txt

#    (Manual verification: after first deploy, run again and verify no errors)
```

#### Troubleshooting
- **Issue:** Deploy script fails on `git pull` — merge conflicts or divergent branches
  - **Solution:** Ensure `git pull --ff-only` in the script to reject non-fast-forward merges. If conflicts exist, they must be resolved manually — deploy script should fail fast, not auto-merge
- **Issue:** Health check fails after deploy — service starts but crashes within seconds
  - **Solution:** Rollback triggers automatically. Check: `journalctl -u guinevere-<svc> -n 50 --no-pager`. Common causes: missing environment variable, incompatible schema migration, Python import error after `uv sync`
- **Issue:** Rollback takes > 60 seconds — disk I/O or large dependencies
  - **Solution:** Profile the rollback: add timestamps to each step. Common slow points: `uv sync` (reinstalling dependencies), large git checkouts. Consider keeping previous virtualenv as a backup rather than reinstalling
- **Issue:** GitHub Actions SSH connection fails — "Permission denied (publickey)"
  - **Solution:** Verify DEPLOY_KEY is an SSH private key (not the public key) and the corresponding public key is in `/home/guinevere/.ssh/authorized_keys`. Test manually: `ssh -i /path/to/key guinevere@host "echo ok"`
- **Issue:** Discord webhook notification fails silently — `curl` exits 0 but message not delivered
  - **Solution:** The script uses `|| true` to make notifications non-blocking. Remove the `|| true` for debugging. Verify webhook URL is valid: `curl -X POST -H "Content-Type: application/json" -d '{"content":"test"}' <WEBHOOK_URL>`
- **Issue:** Deploy script run from wrong directory — git commands fail
  - **Solution:** Add `cd /opt/guinevere || exit 1` at the top of the script. GitHub Actions SSH step already does this, but direct SSH invocations may not

#### Notes
- First deploy after setup requires Faiz explicit approval per AC-PHASE-007 (high-blast-radius change). Subsequent deploys to main are autonomous IF all CI checks pass. Changes classified as "high-blast-radius" (database migrations, auth changes, security configs, service file changes) always require Faiz approval regardless of deploy count
- The deploy script is idempotent by design: `git pull` is a no-op if already at latest, `uv sync --frozen` is a no-op if dependencies match, `systemctl restart` is safe to re-run, health checks are read-only. Running the script twice on the same commit produces identical results
- Rollback target: 60 seconds. This is aggressive — `uv sync --frozen` alone may take 30+ seconds. Acceptable degradation: up to 120 seconds. If rollback consistently exceeds 120 seconds, optimize by keeping a pre-built virtualenv snapshot
- Never deploy during an active incident (SEV1/SEV2). The deploy script doesn't check for active incidents — this is a procedural check, not a script check. Add an incident flag file if needed: `test -f /tmp/guinevere-incident-active && exit 1`
- Discord notifications are non-blocking (`|| true`). If the webhook fails, the deploy still succeeds. This prevents a Discord outage from blocking deployments
- The GitHub Actions workflow uses `appleboy/ssh-action@v1` for SSH-based deploy. Alternative: self-hosted runner on the VPS. Self-hosted runner avoids SSH credential management but adds maintenance overhead
- Shared VPS: the deploy script restarts ONLY Guinevere services (grep guinevere). It does not touch PostgreSQL, Redis, or Aizanta services. Verify the grep pattern matches only Guinevere services before first deploy
- The `scripts/deploy-check.sh` script should be run locally before every push to main. It validates syntax, tool availability, and idempotency markers. Make it a git pre-push hook for full automation
