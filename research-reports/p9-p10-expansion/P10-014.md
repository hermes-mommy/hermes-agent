### Step P10-014: CORS Configuration

**Type:** Security
**Status:** ⬜ Not Started
**Risk:** Medium
**Git Commit:** `feat(P10): CORS origin restriction`

**Goal:** Restrict CORS origins to known Tailscale-internal origins with proper credential handling, preventing cross-origin attacks while allowing legitimate dashboard access.
**Dependencies:** FastAPI application with middleware stack, Tailscale VPN operational (ADR-019)
**Cost Impact:** $0/month (configuration change only)
**ADR References:** ADR-018, ADR-019
**Acceptance Criteria:** AC-CORE-002, AC-SEC-001
**Estimated Time:** 2 hours

#### Context

ADR-018 requires defense-in-depth security measures including proper CORS configuration. ADR-019 mandates that all access to Guinevere is via Tailscale VPN. Since all legitimate access flows through Tailscale, CORS origins should be restricted to the Tailscale MagicDNS domain (`*.guinevere.ts.net`) and localhost for development. CORS is primarily a defense-in-depth measure against accidental browser-based access from non-Tailscale networks. Credentials (cookies, Authorization headers) must only be sent to trusted origins. Preflight caching (max-age) reduces OPTIONS request overhead. Grafana, Prometheus, and other monitoring dashboards that consume Guinevere APIs need their origins explicitly whitelisted.

"""CORS configuration for Guinevere FastAPI application.

Allows only Tailscale-internal origins in production.
Development mode additionally allows localhost origins.
"""

import os
from typing import List


def get_allowed_origins() -> List[str]:
    """Return list of allowed CORS origins based on environment."""
    env = os.getenv("ENV", "production").lower()

    # Always allowed: Tailscale MagicDNS origins
    tailscale_origins = [
        "https://guinevere.ts.net",
        "https://*.guinevere.ts.net",
        "https://guinevere-api.ts.net",
        "https://grafana.guinevere.ts.net",
        "https://prometheus.guinevere.ts.net",
    ]

    # Production: Tailscale only
    if env == "production":
        return tailscale_origins

    # Development: additionally allow localhost
    dev_origins = [
        "http://localhost:3000",
        "http://localhost:5173",
        "http://localhost:8000",
        "http://localhost:9090",
        "http://localhost:3001",
        "http://127.0.0.1:3000",
        "http://127.0.0.1:5173",
        "http://127.0.0.1:8000",
        "http://127.0.0.1:9090",
        "http://127.0.0.1:3001",
    ]
    return tailscale_origins + dev_origins


CORS_CONFIG = {
    "allow_origins": get_allowed_origins(),
    "allow_origin_regex": None,
    "allow_methods": ["GET", "POST", "PUT", "DELETE", "PATCH", "OPTIONS"],
    "allow_headers": [
        "Authorization",
        "Content-Type",
        "X-Request-ID",
        "X-Discord-User-Id",
        "X-Guild-Id",
        "Accept",
        "Origin",
    ],
    "allow_credentials": True,
    "expose_headers": [
        "X-RateLimit-Limit",
        "X-RateLimit-Remaining",
        "X-RateLimit-Reset",
        "X-Request-ID",
        "Retry-After",
    ],
    "max_age": 3600,
}

#### Troubleshooting

- **Issue:** Grafana dashboard cannot fetch data from Guinevere API — CORS error in browser console
  - **Solution:** Add Grafana's Tailscale hostname to `get_allowed_origins()`. The origin must match EXACTLY what the browser sends (including protocol, hostname, and port). Grafana typically sends `Origin: https://grafana.guinevere.ts.net`. If Grafana is accessed via a different hostname, add that hostname. Restart Guinevere API after adding.

- **Issue:** `Access-Control-Allow-Origin` header is missing entirely from responses
  - **Solution:** Check that `CORSMiddleware` is added BEFORE any route handlers. Starlette middleware executes in reverse order of addition — the CORS middleware must be the first middleware added (outermost layer). Also verify the middleware is not being overridden by Caddy or nginx reverse proxy headers. Check: `curl -v http://localhost:8000/api/health -H "Origin: https://guinevere.ts.net"` directly against the FastAPI port to isolate proxy issues.

- **Issue:** `*` is being sent as `Access-Control-Allow-Origin` instead of the specific origin
  - **Solution:** Starlette's `CORSMiddleware` returns `*` when `allow_credentials=False` AND `allow_origins=["*"]`. When `allow_credentials=True`, it MUST return the specific origin. Verify `allow_credentials` is `True` (as configured) and `allow_origins` contains the exact origin sent by the client. If the origin has a trailing slash or different casing, it won't match. Origins must match EXACTLY.

- **Issue:** CORS preflight requests (OPTIONS) are returning 405 Method Not Allowed
  - **Solution:** The route handler may not include OPTIONS in its `@app.route(methods=[...])`. The CORS middleware handles OPTIONS requests BEFORE they reach the route handler (it intercepts them), but this only works if the middleware is properly configured. Verify `allow_methods` includes `OPTIONS`. If using a custom middleware that runs before CORS, ensure it passes OPTIONS requests through.

- **Issue:** Development requests from localhost being blocked in production mode
  - **Solution:** This is expected behavior — production mode intentionally excludes localhost. If you are developing against a production-like environment, either set `ENV=development` or temporarily add your local IP to the allowed origins list. Do NOT commit local IPs to the production config permanently.

#### Notes

- Since all access is Tailscale-internal (ADR-019), CORS is primarily defense-in-depth. The primary threat is accidental browser-based access from non-Tailscale networks (e.g., a browser tab left open on a public WiFi network). CORS would prevent JavaScript on a malicious page from reading Guinevere API responses.
- The `allow_origin_regex` field is `None` because wildcard subdomain matching (`*.guinevere.ts.net`) is handled by Starlette's origin matching. Starlette compares the `Origin` header against each allowed origin using `fnmatch` — the `*.guinevere.ts.net` pattern matches any subdomain. If this doesn't work as expected, an alternative is to set `allow_origin_regex="https://.*\.guinevere\.ts\.net"` and set `allow_origins=[]`.
- Preflight cache (`max_age=3600`) means the browser caches the CORS preflight response for 1 hour. During this hour, the browser skips the OPTIONS request for subsequent same-origin requests. This reduces latency and server load. If CORS configuration changes, browsers with cached preflight responses will use the old cached response until it expires.
- Credentials (`allow_credentials=True`) is required because the API uses the `Authorization` header for Discord tokens and API keys. When `allow_credentials` is true, the `Access-Control-Allow-Origin` cannot be `*` — it must be the specific requesting origin. This is enforced by the browser, not the server.
