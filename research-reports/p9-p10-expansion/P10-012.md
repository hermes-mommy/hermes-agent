### Step P10-012: Log Rotation

**Type:** Infrastructure
**Status:** ⬜ Not Started
**Risk:** Low
**Git Commit:** `feat(P10): logrotate configuration`

**Goal:** Configure logrotate for all Guinevere application log files with appropriate rotation, compression, retention policies, and special handling for audit logs.
**Dependencies:** None (standalone; Guinevere services must be writing logs to identifiable paths)
**Cost Impact:** $0/month (uses system `logrotate`, already installed on Ubuntu 24.04)
**ADR References:** ADR-017
**Acceptance Criteria:** AC-SEC-007, AC-OPS-002
**Estimated Time:** 2 hours

#### Context

Guinevere services generate logs via systemd journal (handled by `journald` rotation) and application-level log files at `/home/guinevere/logs/`. Without rotation, these files grow unbounded, consuming disk space and degrading grep performance. AC-SEC-007 requires audit logs to capture actor, action, resource, purpose, result, timestamp, and evidence link — audit logs need longer retention (90 days) for compliance and incident investigation, and must remain uncompressed for the first 30 days for rapid grep access. Standard application logs rotate daily with 7-day retention and compression. The systemd journal has its own rotation configured in `/etc/systemd/journald.conf` (handled separately). This step covers application-level log files only.

#### Pre-flight Checks
- [ ] Guinevere application logs are written to `/home/guinevere/logs/` (or a known, consistent path)
- [ ] Audit logs are in a separate file or have a distinguishable filename pattern (e.g., `audit-*.log` or `*_audit.log`)
- [ ] `logrotate` is installed (`which logrotate` returns `/usr/sbin/logrotate`)
- [ ] Current disk usage on `/home` and `/var` partitions is known (`df -h`)
- [ ] Services that write logs support log file handle refresh (via `systemctl reload` or SIGHUP/USR1 signal)
- [ ] Disk usage monitoring alert exists (Prometheus node_exporter or simple cron check)

#### Commands

```bash
# 1. Identify all Guinevere log paths
echo "Log paths to configure:"
find /home/guinevere/logs/ -type f -name "*.log" 2>/dev/null || echo "No logs found at /home/guinevere/logs/"
find /var/log/ -type f -name "guinevere-*" 2>/dev/null || echo "No logs at /var/log/guinevere-*"

# 2. Create logrotate configuration for Guinevere
cat > /etc/logrotate.d/guinevere << 'LREOF'
# Guinevere Standard Application Logs
# Daily rotation, 7-day retention, compressed

/home/guinevere/logs/*.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    create 0640 guinevere guinevere
    dateext
    dateformat -%Y%m%d
    sharedscripts
    postrotate
        # Notify services to reopen log file handles
        /usr/bin/systemctl reload guinevere-api.service > /dev/null 2>&1 || true
        /usr/bin/systemctl reload guinevere-bot.service > /dev/null 2>&1 || true
    endscript
}

# Guinevere Audit Logs
# Daily rotation, 90-day retention, uncompressed (rapid grep access)

/home/guinevere/logs/audit*.log {
    daily
    rotate 90
    nocompress
    missingok
    notifempty
    create 0640 guinevere guinevere
    dateext
    dateformat -%Y%m%d
    sharedscripts
    postrotate
        /usr/bin/systemctl reload guinevere-api.service > /dev/null 2>&1 || true
    endscript
}

# Guinevere Deployment and Operations Logs
# Weekly rotation, 30-day retention, compressed

/home/guinevere/logs/deploy*.log
/home/guinevere/logs/cd-check.log
/home/guinevere/logs/rollback.log
/home/guinevere/logs/emergency-rotations.log {
    weekly
    rotate 4
    compress
    delaycompress
    missingok
    notifempty
    create 0640 guinevere guinevere
    dateext
    dateformat -%Y%m%d
}

# Guinevere Access Logs (if written to file instead of journald)
/var/log/guinevere-access*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    create 0640 guinevere www-data
    dateext
    dateformat -%Y%m%d
}
LREOF

# 3. Validate logrotate configuration
logrotate --debug /etc/logrotate.d/guinevere

# 4. Force a rotation to test
logrotate --force /etc/logrotate.d/guinevere

# 5. Verify rotation worked
ls -lah /home/guinevere/logs/
echo "---"
echo "Check for rotated files with date extension (e.g., *.log-20260603.gz)"

# 6. Verify services can still write to logs after rotation
echo "Test log entry $(date -Iseconds)" | sudo -u guinevere tee -a /home/guinevere/logs/cd-check.log

# 7. Add disk usage monitoring alert (cron-based, simple approach)
cat > /etc/cron.d/guinevere-disk-check << 'CRONEOF'
# Check disk usage every hour, alert to journal if above 80%
5 * * * * root df -h /home | awk 'NR==2 {gsub(/%/,""); if($5>80) print "WARNING: /home disk usage at "$5"% — near capacity"}' | systemd-cat -t disk-monitor -p warning
CRONEOF

# 8. Set up logrotate status tracking
# logrotate maintains state at /var/lib/logrotate/status — verify it's being written
stat /var/lib/logrotate/status

# 9. Manual run to confirm daily cron will handle it
# logrotate is triggered by /etc/cron.daily/logrotate (default on Ubuntu)
# Verify the cron job exists
ls -la /etc/cron.daily/logrotate
```

#### Troubleshooting

- **Issue:** `logrotate --debug` reports "error: guinevere: unknown option"
  - **Solution:** Check for syntax errors in the config file. Common issues: missing opening brace, incorrect indentation of directives, trailing whitespace in directive names. Validate with `logrotate -d /etc/logrotate.d/guinevere` for detailed line-by-line parsing.

- **Issue:** Services fail to write logs after rotation (file handle stale)
  - **Solution:** The `postrotate` script attempts `systemctl reload` on the services. If the service does not support `reload`, change to `systemctl restart` (causes brief downtime) or configure the application to use log file reopening via SIGHUP. Check if the application uses Python's `logging.handlers.WatchedFileHandler` instead of `FileHandler` — WatchedFileHandler automatically reopens the file when it detects rotation.

- **Issue:** Audit logs are being compressed despite `nocompress`
  - **Solution:** Check if the audit log files match the standard log pattern (`*.log` matches `audit*.log`). The first matching stanza in logrotate wins (top to bottom). Place the audit log stanza BEFORE the standard log stanza to ensure it takes priority. Alternatively, use a more specific path pattern that does not overlap.

- **Issue:** Disk fills up despite rotation
  - **Solution:** Check if logs are growing faster than rotation can handle (e.g., debug-level logging in production). Reduce log verbosity in the application: set log level to INFO or WARNING. Investigate what is generating excessive log volume with `wc -l /home/guinevere/logs/*.log`. If a specific component is logging excessively, fix the log level at the source rather than increasing retention.

- **Issue:** `dateformat` extension not working
  - **Solution:** Requires logrotate 3.8.1+ (Ubuntu 24.04 ships with logrotate 3.21). If `dateformat` is not recognized, remove the `dateformat` line and the default numeric extension (`.1`, `.2`, etc.) will be used instead.

#### Notes

- systemd journal rotation is handled by `journald.conf` with settings `SystemMaxUse=`, `SystemMaxFileSize=`, `MaxRetentionSec=`. This step does NOT modify journald configuration — it only handles application-level log files written to `/home/guinevere/logs/` and `/var/log/guinevere-*`.
- Audit logs MUST NOT be compressed for the first 30 days because rapid grep access is needed during incident investigation. After 30 days, audit logs older than 30 days may be manually compressed if disk space is a concern. The logrotate config leaves audit logs uncompressed for their full 90-day lifetime for simplicity.
- The `dateext` and `dateformat` directives make rotated filenames human-readable (e.g., `app.log-20260603.gz` instead of `app.log.1.gz`). This is critical for compliance and incident response — you can instantly identify which date range a rotated file covers.
- Logrotate runs daily via `/etc/cron.daily/logrotate` by default on Ubuntu. No additional timer or cron job configuration is needed. The cron job is part of the `logrotate` package installation.
- Disk usage alerting at 80% is a minimum safety measure. For production hardening, integrate disk usage into the Prometheus metrics pipeline (node_exporter exposes `node_filesystem_avail_bytes`) with a Grafana alert threshold.
