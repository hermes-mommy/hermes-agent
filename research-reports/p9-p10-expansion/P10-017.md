### Step P10-017: Connection Pool Monitoring

**Type:** Application
**Status:** Not Started
**Risk:** Low
**Git Commit:** `feat(P10): pending`

**Goal:** Monitor PgBouncer connection pool statistics and Redis connection tracking with Prometheus metrics and Grafana alerting — detecting pool exhaustion before it causes cascading failures.
**Dependencies:** P10-002 (PostgreSQL Tuning — PgBouncer configured with admin console on port 6432), P10-003 (Redis Tuning — maxclients and memory limits set), P10-015 (Health Check Enhancement — Prometheus metrics infrastructure and Grafana dashboard patterns)
**Cost Impact:** $0/month (metrics embedded in existing Prometheus + PgBouncer admin, no new infrastructure)
**ADR References:** ADR-017 (Observability Stack), ADR-027 (Connection Pooling Strategy)
**Acceptance Criteria:** AC-OPS-001 (Prometheus metrics exported for all critical services), AC-OPS-002 (Grafana dashboards with core health panels)
**Estimated Time:** 2 hours

#### Context

Connection pool exhaustion is a silent killer — when PgBouncer or Redis hits its connection limit, new requests queue up, timeouts cascade, and the service becomes unresponsive without a clear error. PgBouncer's admin console (port 6432) exposes SHOW STATS, SHOW POOLS, and SHOW CLIENTS — providing: active connections, waiting clients, average query time, server connection reuse rate, and transaction duration. Redis INFO clients and INFO stats expose: connected_clients, blocked_clients, rejected_connections, evicted_keys. These metrics are leading indicators for capacity planning — pool exhaustion shows up in metrics 5-15 minutes before user-facing errors. Both PgBouncer and Redis connection stats must be exported as Prometheus gauges with alert thresholds and Grafana dashboards.

#### Pre-flight Checks
- [ ] PgBouncer running with admin console on port 6432: `systemctl is-active pgbouncer`

async def _collect_pgbouncer_stats() -> bool:
    """Query PgBouncer admin console for pool statistics.

    Returns True on success, False on failure.
    """
    try:
        import asyncpg
        conn = await asyncio.wait_for(
            asyncpg.connect(
                host="127.0.0.1",
                port=6432,
                user="pgbouncer",
                database="pgbouncer",
            ),
            timeout=STATS_TIMEOUT,
        )
        try:
            # SHOW POOLS — per-database connection counts
            pools = await conn.fetch("SHOW POOLS")
            for row in pools:
                db = row["database"]
                if db == "pgbouncer":
                    continue  # Skip admin database
                pg_bouncer_active_conns.labels(database=db).set(
                    int(row["cl_active"])
                )
                pg_bouncer_waiting_clients.labels(database=db).set(
                    int(row["cl_waiting"])
                )

            # SHOW STATS — aggregate performance metrics
            stats = await conn.fetch("SHOW STATS")
            for row in stats:
                if row["database"] == "pgbouncer":
                    continue
                pg_bouncer_total_xact_count.set(int(row["total_xact_count"]))
                pg_bouncer_total_query_count.set(int(row["total_query_count"]))
                pg_bouncer_total_received.set(int(row["total_received"]))
                pg_bouncer_total_sent.set(int(row["total_sent"]))
                pg_bouncer_avg_query_time.set(
                    int(row["avg_query_count"]) / 1_000_000.0
                    if int(row["avg_query_count"]) > 0
                    else 0.0
                )
                pg_bouncer_avg_xact_time.set(
                    int(row["avg_xact_count"]) / 1_000_000.0
                    if int(row["avg_xact_count"]) > 0
                    else 0.0
                )

            return True
        finally:
            await conn.close()
    except asyncio.TimeoutError:
        logger.warning("PgBouncer stats collection timed out after %.1fs", STATS_TIMEOUT)
        return False
    except Exception as exc:
        logger.error("Failed to collect PgBouncer stats: %s", exc)
        return False


async def _collect_redis_stats() -> bool:
    """Query Redis INFO for connection and memory statistics.

    Returns True on success, False on failure.
    """
    try:
        from redis.asyncio import Redis
        from src.core.config import get_settings

        settings = get_settings()
        client = Redis(
            host="127.0.0.1",
            port=6380,
            username="guinevere_core",
            password=settings.redis_core_password,
            socket_timeout=STATS_TIMEOUT,
        )

        try:
            info_clients = await client.info("clients")
            info_stats = await client.info("stats")
            info_memory = await client.info("memory")

            redis_connected_clients.set(
                int(info_clients.get("connected_clients", 0))
            )
            redis_blocked_clients.set(
                int(info_clients.get("blocked_clients", 0))
            )
            redis_rejected_connections.set(
                int(info_stats.get("rejected_connections", 0))
            )
            redis_evicted_keys.set(
                int(info_stats.get("evicted_keys", 0))
            )
            redis_keyspace_hits.set(
                int(info_stats.get("keyspace_hits", 0))
            )
            redis_keyspace_misses.set(
                int(info_stats.get("keyspace_misses", 0))
            )

            used_memory = int(info_memory.get("used_memory", 0))
            maxmemory_str = info_memory.get("maxmemory", "0")
            maxmemory = int(maxmemory_str) if maxmemory_str != "0" else 0
            if maxmemory > 0:
                redis_used_memory_pct.set((used_memory / maxmemory) * 100)

            return True
        finally:
            await client.close()
    except asyncio.TimeoutError:
        logger.warning("Redis stats collection timed out after %.1fs", STATS_TIMEOUT)
        return False
    except Exception as exc:
        logger.error("Failed to collect Redis stats: %s", exc)
        return False


async def collect_all_pool_metrics() -> Dict[str, bool]:
    """Collect all pool metrics from PgBouncer and Redis.

    Returns dict of collection statuses.
    """
    pgbouncer_ok, redis_ok = await asyncio.gather(
        _collect_pgbouncer_stats(),
        _collect_redis_stats(),
        return_exceptions=True,
    )
    return {
        "pgbouncer": bool(pgbouncer_ok),
        "redis": bool(redis_ok),
    }


async def pool_monitor_loop() -> None:
    """Background coroutine: collect pool metrics on fixed interval.

    Run as an asyncio task during application startup.
    Errors are logged but never crash the loop.
    """
    logger.info(
        "Pool monitor started — collecting every %.1fs", COLLECT_INTERVAL
    )
    while True:
        try:
            results = await collect_all_pool_metrics()
            if not results["pgbouncer"]:
                logger.debug("PgBouncer stats collection failed (will retry)")
            if not results["redis"]:
                logger.debug("Redis stats collection failed (will retry)")
        except asyncio.CancelledError:
            logger.info("Pool monitor cancelled — shutting down")
            break
        except Exception as exc:
            logger.error("Unexpected error in pool monitor loop: %s", exc)
        await asyncio.sleep(COLLECT_INTERVAL)


def start_pool_monitor() -> asyncio.Task:
    """Start the pool monitor background task.

    Returns the asyncio Task for lifecycle management.
    Call during application startup.
    """
    return asyncio.create_task(pool_monitor_loop())

#### Troubleshooting
- **Issue:** PgBouncer connection refused on port 6432
  - **Solution:** PgBouncer admin console must be enabled in pgbouncer.ini: `admin_users = pgbouncer` and `listen_addr = 127.0.0.1`. Restart: `sudo systemctl restart pgbouncer`. Verify port: `ss -tlnp | grep 6432`
- **Issue:** PgBouncer SHOW POOLS returns "permission denied"
  - **Solution:** The user connecting to PgBouncer admin must be in `admin_users` or `stats_users` in pgbouncer.ini. Add: `stats_users = pgbouncer_monitor` and connect as that user. If using pgbouncer user, ensure it's in admin_users
- **Issue:** Redis INFO returns "NOPERM this user has no permissions"
  - **Solution:** The Redis ACL user must have the INFO command allowed. Check ACL: `redis-cli -h 127.0.0.1 -p 6380 ACL GETUSER guinevere_core`. Add INFO: `redis-cli ACL SETUSER guinevere_core +INFO`. Save: `redis-cli ACL SAVE`
- **Issue:** Pool metrics gauge values stuck at 0
  - **Solution:** Check pool monitor task is running: `journalctl -u guinevere-gateway | grep "Pool monitor started"`. Check for errors: `journalctl -u guinevere-gateway | grep "pool_monitor"`. Ensure `start_pool_monitor()` is called in app startup
- **Issue:** PgBouncer avg_query_time shows 0 even under load
  - **Solution:** The avg_query_time from SHOW STATS is in microseconds (avg_query_count column). The code divides by 1,000,000 to convert to seconds — if values are small (<500us), they round to 0. This is expected for fast queries. Check the raw SHOW STATS output to confirm non-zero microsecond values
- **Issue:** Redis rejected connections counter always 0 (never tested)
  - **Solution:** This is a cumulative counter — it only increments when maxclients is exceeded. To test: temporarily lower maxclients: `redis-cli CONFIG SET maxclients 5`, generate connections, verify counter increments, then restore: `redis-cli CONFIG SET maxclients 10000`

#### Notes
- PgBouncer admin queries (SHOW POOLS, SHOW STATS, SHOW CLIENTS) are lightweight — <1ms each. Running every 15 seconds adds negligible overhead
- Redis INFO commands are O(1) and safe to call frequently. Do not use MONITOR command (blocking, high overhead)
- Connection pool metrics are the leading indicator for capacity planning. Waiting clients > 0 means you need more pool connections or faster queries
- The pool monitor shares the METRICS_REGISTRY from the health check module to avoid Prometheus duplicate registration errors. If the health module registry changes, update the import
- Alert thresholds are intentionally conservative: PgBouncer waiting > 5 for 30s (warning), > 20 for 15s (critical). Adjust based on your production pool size (default_pool_size in pgbouncer.ini)
- Redis cache hit rate panel (keyspace_hits / (hits + misses)) is a long-term metric — expect >90% hit rate. Below 80% indicates cache is too small or key patterns need review
- Byte throughput metrics (pg_bouncer_total_received/sent) use Prometheus rate() function in Grafana. Raw counters are cumulative and will grow indefinitely — always use rate() for graphing
