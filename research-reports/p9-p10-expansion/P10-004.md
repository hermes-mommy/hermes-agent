### Step P10-004: Systemd Resource Limits

**Type:** Infrastructure
**Status:** Not Started
**Risk:** High
**Git Commit:** `feat(P10): pending`

**Goal:** Fine-tune systemd service resource limits for all Guinevere services based on 6+ months of observed usage patterns, applying defense-in-depth hardening directives with explicit Python CFFI caveat handling.
**Dependencies:** P10-002 complete (PostgreSQL tuned), P10-003 complete (Redis tuned), all Guinevere systemd services running and generating predictable resource usage.
**Cost Impact:** $0/month (configuration-only, no additional resources)
**ADR References:** ADR-014 (Systemd Service Management)
**Acceptance Criteria:** AC-CORE-001 (All services start cleanly within 30s of boot), AC-CORE-006 (Resource limits prevent runaway resource consumption without impacting normal operation)
**Estimated Time:** 3 hours

#### Context

Guinevere runs as systemd-managed services under the `guinevere` user on Ubuntu 24.04. Resource limits set during P0 (Phase 0 bootstrap) may need adjustment based on 6+ months of observed usage. Research findings identify 22 systemd hardening directives recommended for defense-in-depth, BUT MemoryDenyWriteExecute conflicts with Python CFFI modules (cryptography, pydantic-core) that require writable+executable memory for JIT compilation. Must test individually per service. Key directives: MemoryMax, CPUQuota, ProtectSystem=strict, ProtectHome=yes, NoNewPrivileges=yes, PrivateTmp=yes, RestrictAddressFamilies, SystemCallFilter. This step is HIGH RISK because incorrect resource limits can cause service startup failures or OOM kills in production.

#### Commands

```bash
# 1. Analyze current resource usage via journalctl — last 30 days
journalctl --since "30 days ago" --no-pager \
  | grep -i "memory\|cpu\|oom\|limit\|throttl\|cgroup" \
  > docs/setup-evidence/P10/STEP-P10-004/resource-history.txt

# 2. Per-service current resource usage snapshot
for svc in $(systemctl list-units --type=service --no-legend | grep guinevere | awk '{print $1}'); do
  echo "=== $svc ===" >> docs/setup-evidence/P10/STEP-P10-004/resource-snapshot.txt
  systemctl show "$svc" --property=MemoryCurrent,CPUUsageNSec,MainPID \
    >> docs/setup-evidence/P10/STEP-P10-004/resource-snapshot.txt
  echo "" >> docs/setup-evidence/P10/STEP-P10-004/resource-snapshot.txt
done

# 3. Check for historical OOM kills
dmesg -T | grep -i "oom\|out of memory\|killed process" \
  > docs/setup-evidence/P10/STEP-P10-004/oom-history.txt

# 4. Check systemd-cgtop history for peak usage (if available)
journalctl -u guinevere.slice --since "30 days ago" --no-pager \
  | grep -i "memory\|cpu" \
  > docs/setup-evidence/P10/STEP-P10-004/cgroup-history.txt

# 5. Create hardened service file for a NON-CFFI service first (example: guinevere-api)
#    Test MemoryDenyWriteExecute on this service as proof-of-concept
cat > /etc/systemd/system/guinevere-api.service.d/P10-004-hardening.conf << 'EOF'
[Service]
# Resource limits — based on observed peak + 50% headroom
MemoryMax=512M
CPUQuota=200%
# Security hardening (safe for non-CFFI Python services)
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectControlGroups=yes
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK
RestrictRealtime=yes
RestrictSUIDSGID=yes
LockPersonality=yes
MemoryDenyWriteExecute=yes
SystemCallFilter=@system-service
SystemCallErrorNumber=EPERM
ReadWritePaths=/var/lib/guinevere /var/log/guinevere /tmp
ReadOnlyPaths=/etc/guinevere
EOF
systemctl daemon-reload
systemctl restart guinevere-api
sleep 5
systemctl is-active guinevere-api && echo "PASS: Hardened service started" || echo "FAIL: Service failed — check journalctl"

# 6. If step 5 fails with MemoryDenyWriteExecute:
#    This service uses CFFI modules — remove that directive, document the exception
cat > /etc/systemd/system/guinevere-api.service.d/P10-004-hardening.conf << 'EOF'
[Service]
# Resource limits
MemoryMax=512M
CPUQuota=200%
# Security hardening (WITHOUT MemoryDenyWriteExecute — CFFI modules: cryptography, pydantic-core)
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectControlGroups=yes
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK
RestrictRealtime=yes
RestrictSUIDSGID=yes
LockPersonality=yes
SystemCallFilter=@system-service
SystemCallErrorNumber=EPERM
ReadWritePaths=/var/lib/guinevere /var/log/guinevere /tmp
ReadOnlyPaths=/etc/guinevere
EOF
systemctl daemon-reload
systemctl restart guinevere-api
systemctl is-active guinevere-api

# 7. Apply hardened configuration to ALL Guinevere services
#    Template: replace <SERVICE>, <MEMORY_MB>, <CPU_PCT> per service
for svc in guinevere-api guinevere-worker guinevere-scheduler guinevere-bot; do
  # Skip if service doesn't exist on this host
  systemctl list-units --type=service "$svc.service" &>/dev/null || continue

  # Determine resource limits based on step 2 analysis
  # Default: 256M memory, 100% CPU — adjust per service
  MEMORY="256M"
  CPU="100%"
  case "$svc" in
    guinevere-worker) MEMORY="512M"; CPU="200%" ;;
    guinevere-bot)    MEMORY="384M"; CPU="150%" ;;
  esac

  # Check if service uses CFFI (determined by Python imports)
  # Skip MemoryDenyWriteExecute if cryptography or pydantic-core is imported
  CFFI_CHECK=$(grep -r "import cryptography\|import pydantic_core\|from cryptography\|from pydantic_core" /opt/guinevere/src/ 2>/dev/null)
  DENY_WX="MemoryDenyWriteExecute=yes"
  if [ -n "$CFFI_CHECK" ]; then
    DENY_WX="# MemoryDenyWriteExecute DISABLED — CFFI modules in use (cryptography/pydantic-core)"
  fi

  mkdir -p "/etc/systemd/system/${svc}.service.d"
  cat > "/etc/systemd/system/${svc}.service.d/P10-004-hardening.conf" << EOF
[Service]
MemoryMax=${MEMORY}
CPUQuota=${CPU}
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectControlGroups=yes
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK
RestrictRealtime=yes
RestrictSUIDSGID=yes
LockPersonality=yes
${DENY_WX}
SystemCallFilter=@system-service
SystemCallErrorNumber=EPERM
ReadWritePaths=/var/lib/guinevere /var/log/guinevere /tmp
ReadOnlyPaths=/etc/guinevere
EOF
done

# 8. Reload and restart all services
systemctl daemon-reload
for svc in $(systemctl list-units --type=service --no-legend | grep guinevere | awk '{print $1}'); do
  echo "Restarting $svc..."
  systemctl restart "$svc"
  sleep 3
  if systemctl is-active --quiet "$svc"; then
    echo "  PASS: $svc started"
  else
    echo "  FAIL: $svc failed — rolling back..."
    rm -f "/etc/systemd/system/${svc}.d/P10-004-hardening.conf"
    systemctl daemon-reload
    systemctl restart "$svc"
    echo "  $svc restored to pre-hardening state"
  fi
done

# 9. Verify all services healthy after 30 seconds
sleep 30
systemctl list-units --type=service --state=failed | grep guinevere \
  > docs/setup-evidence/P10/STEP-P10-004/failed-services.txt

# 10. Monitor for 1 hour — capture resource usage at 5-minute intervals
for i in $(seq 1 12); do
  echo "=== $(date -Iseconds) ===" >> docs/setup-evidence/P10/STEP-P10-004/monitoring-1hr.txt
  systemd-cgtop --depth=1 -b -n 1 | grep guinevere >> docs/setup-evidence/P10/STEP-P10-004/monitoring-1hr.txt
  sleep 300
done

# 11. Document CFFI exceptions in a permanent reference file
cat > docs/setup-evidence/P10/STEP-P10-004/cffi-exceptions.txt << 'EOF'
# CFFI Module Exceptions for MemoryDenyWriteExecute
#
# The following services use Python CFFI modules that require
# writable+executable memory for native code execution.
# MemoryDenyWriteExecute is DISABLED for these services.

# Service: guinevere-api
# Reason: pydantic-core (Pydantic v2) uses CFFI for validation
#         cryptography library uses CFFI for OpenSSL bindings
# Risk: LOW — mitigated by all other hardening directives

# Service: guinevere-worker
# Reason: Same as API — pydantic-core + cryptography
# Risk: LOW — mitigated by all other hardening directives

# Service: guinevere-bot
# Reason: Same as API — pydantic-core + cryptography
# Risk: LOW — mitigated by all other hardening directives

# For services WITHOUT CFFI, MemoryDenyWriteExecute=yes is active.
EOF

# 12. Verify cgroup limits (P0-009) are not exceeded post-tuning
systemctl show guinevere.slice --property=MemoryMax,MemoryCurrent,CPUQuota \
  > docs/setup-evidence/P10/STEP-P10-004/cgroup-verification.txt
```

#### Troubleshooting
- **Issue:** Service fails startup with "Operation not permitted" after hardening
  - **Solution:** Check journalctl for the specific syscall denied: `journalctl -u guinevere-<svc> -n 50 --no-pager | grep "Operation not permitted"`. The SystemCallFilter or RestrictAddressFamilies may be too restrictive. Add the required syscall to the allowlist or remove the filter for that service
- **Issue:** Service starts but crashes with SIGSEGV when MemoryDenyWriteExecute=yes
  - **Solution:** CFFI module trying to JIT or mmap writable+executable memory. Remove MemoryDenyWriteExecute for this service and document the CFFI dependency. Verify with: `strace -e mmap,mprotect -p <PID> 2>&1 | grep "PROT_WRITE\|PROT_EXEC"`
- **Issue:** OOM kill despite MemoryMax being set — service exceeds limit
  - **Solution:** Increase MemoryMax by 50% increments. Check for memory leaks: `systemctl show guinevere-<svc> --property=MemoryCurrent` over time. If memory grows monotonically, this is a leak (not a limit issue) — file a bug
- **Issue:** CPUQuota throttling causes task processing delays
  - **Solution:** Increase CPUQuota. For I/O-bound services (API, bot), 100% may be fine. For CPU-bound services (worker), 200%+. Monitor: `systemctl show guinevere-<svc> --property=CPUUsageNSec`
- **Issue:** ProtectSystem=strict blocks legitimate writes to /etc/guinevere
  - **Solution:** Add explicit ReadWritePaths=/etc/guinevere (already in template). If other paths needed, add them to ReadWritePaths

#### Notes
- MemoryDenyWriteExecute is a strong defense-in-depth measure that prevents services from creating new executable memory regions (blocks JIT spraying attacks). However, Python CFFI modules (cryptography for SSL, pydantic-core for validation) use native code that requires writable+executable memory. Test EACH service individually before enabling
- The 22 hardening directives are defense-in-depth: no single directive prevents all attacks, but the combination significantly raises the exploitation bar. An attacker who compromises Guinevere via a Python RCE would still need to escape: NoNewPrivileges, ProtectSystem, RestrictAddressFamilies, and PrivateTmp
- Shared VPS: do NOT change system-wide cgroup limits from P0-009. The `guinevere.slice` MemoryMax and CPUQuota were negotiated with Aizanta during Phase 0. Changing them could starve Aizanta services
- One-hour monitoring window (step 10) with 12 samples at 5-minute intervals is minimum. If possible, extend to 24 hours for confidence
- Service restart during hardening will cause brief downtime (~5 seconds per service). Schedule during low-usage window. If zero-downtime required, use a rolling restart with health checks between each service
- The override files in `/etc/systemd/system/<service>.service.d/` take precedence over the main unit file. To revert, remove the override directory — the original unit file is untouched
