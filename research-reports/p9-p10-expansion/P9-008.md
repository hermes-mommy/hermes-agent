#### Context

Faiz interacts with Guinevere primarily via Discord (ADR-022). These two slash commands provide quick financial visibility without needing to open Grafana or query PostgreSQL directly. `/finance summary` renders a rich embed showing: total monthly spend, remaining budget, per-category breakdown with progress bars, days remaining in month, alert status, and the top 5 expense categories. `/finance add amount:float category:str description:str` creates a manual transaction — useful for cash purchases, bank transfers not captured by SMS, or corrections. Manual transactions bypass the SMS parser but still flow through the classification pipeline (P9-006) and budget tracker (P9-007) to ensure consistent category assignment and budget enforcement. Both commands are owner-only via Discord user ID check. The summary embed uses color coding: green (<50% spent), yellow (50-80%), red (>80%) per category and overall.

#### Troubleshooting

- **Issue:** `/finance` commands not appearing in Discord slash menu.
  - **Solution:** Commands must be synced with Discord after registration. Run `bot.tree.sync()` or restart bot with `sync_on_startup=True`. Discord caches commands — it may take up to 1 hour for changes to propagate. Force-refresh: close and reopen Discord client.
- **Issue:** Summary embed exceeds Discord's 6000-character embed limit.
  - **Solution:** Limit category breakdown to top 10 categories. If more categories exist, show top 10 with "and N more..." footer. Paginate via Discord button components if needed (future enhancement, not MVP).
- **Issue:** Permission check fails for Faiz (owner cannot use own commands).
  - **Solution:** Verify `DISCORD_OWNER_ID` environment variable matches Faiz's Discord user ID exactly (18-digit numeric string). Check for leading/trailing whitespace in env var. Use `interaction.user.id` not `interaction.user.name` for comparison.
- **Issue:** Transaction added via `/finance add` not appearing in budget tracker.
  - **Solution:** Manual transactions must flow through the same event pipeline as SMS-parsed transactions. Verify the command publishes to `transaction.created` event after insert. If using direct DB insert, call `BudgetTracker.check_budget()` explicitly after insert.
- **Issue:** Progress bars render incorrectly (negative values or >100%).
  - **Solution:** Clamp progress ratio to [0.0, 1.0]. If `current_spent > monthly_limit`, render bar at 100% with overflow indicator `[██████████] 120% OVER`. Add red color for overflow.

#### Notes

- Commands are implemented as a Discord.py `Cog` class (`FinanceCommands`) for clean separation from other bot modules. The cog is loaded in `src/discord/bot.py` startup via `load_extension`.
- Owner check uses `interaction.user.id == int(os.environ["DISCORD_OWNER_ID"])`. No role-based permission — owner ID is the single source of truth. Guild-only check optional (commands work in DMs if configured).
- `/finance add` categories are validated against `financial.budget_categories` — invalid category names return an ephemeral error message listing valid categories. This prevents manual entries with typos from breaking budget tracking.
- Summary embed color mapping: `discord.Color.green()` for <50%, `discord.Color.gold()` for 50-80%, `discord.Color.red()` for >80%. Global spend ratio determines the embed's sidebar color; per-category fields use text-based progress bars.
- Progress bar format: 10 segments using `█` (filled) and `░` (empty). Ratio = `current_spent / monthly_limit`, clamped to [0.0, 1.0]. Rendered as: `[████████░░] 80% Rp240.000 / Rp300.000`.
- Days remaining is computed as: `(last_day_of_month - today).days + 1` (inclusive of today). Display format: "18 days remaining in June 2026".
- Manual transactions skip SMS parsing but MUST still be classified. The `/finance add` handler calls `TransactionClassifier.classify_single()` after insert. Budget tracker hook fires after classification completes.
