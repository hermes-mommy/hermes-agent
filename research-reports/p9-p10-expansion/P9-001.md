#### Context

PostgreSQL `financial` schema has 4 tables migrated via alembic — `transactions` (TimescaleDB hypertable), `project_costs`, `monthly_reports`, `optimization_log` — but ZERO CRUD code exists. `src/financial/__init__.py` is a 1-line empty stub. The `OptimizationLog` model is missing `ClassificationMetaMixin` (schema inconsistency — all financial tables must carry `classification_level`, `data_owner`, `encryption_key_id` per ADR-024). Redis DB5 cost tracking is FULLY BUILT (CostTracker, BudgetEnforcer, ToolCostTracker, LoopCostTracker — 4 service classes, 11+ Redis key patterns). This step is the FOUNDATION for all P9 work: no CRUD layer means P9-002/003/004 have nothing to write to.

#### Troubleshooting
- **Issue:** `psql: FATAL: database "guinevere" does not exist`
  - **Solution:** Verify PostgreSQL data directory and service; check `PGDATABASE` env var
- **Issue:** `timescaledb_information.hypertables` returns zero rows for financial.transactions
  - **Solution:** Run `SELECT create_hypertable('financial.transactions', 'created_at', chunk_time_interval => INTERVAL '1 month')` — but only if table schema has `created_at TIMESTAMPTZ NOT NULL`
- **Issue:** Alembic autogenerate creates no migration (schema already has classification columns)
  - **Solution:** Manual verification passes — no migration needed. Document that schema is already compliant
- **Issue:** `ClassificationMetaMixin` import fails because `surveillance.classification` defines it differently than expected
  - **Solution:** Copy the mixin class definition into `src/financial/classification.py` as standalone, decoupled from surveillance module
