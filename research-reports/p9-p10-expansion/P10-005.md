### Step P10-005: Backup Automation Full Test

**Type:** Testing
**Status:** Not Started
**Risk:** High
**Git Commit:** `feat(P10): pending`

**Goal:** End-to-end backup test: full backup to both S3 (idcloudhost) and R2 (Cloudflare), restore verification, and data integrity check validating the dual-provider backup strategy under real conditions.
**Dependencies:** P0 backup scripts operational (restic + pg_dump + redis-cli BGSAVE), S3 credentials configured for idcloudhost Jakarta, R2 credentials configured for Cloudflare, SOPS+age keys available for decryption verification.
**Cost Impact:** $2-5/month (S3 storage ~$0.02/GB + R2 storage ~$0.015/GB, estimated 5-10GB total)
**ADR References:** ADR-025 (Backup Strategy), ADR-032 (Dual-Provider Backup — idcloudhost S3 primary + Cloudflare R2 secondary)
**Acceptance Criteria:** AC-OPS-003 (Backup completes within RTO of 4 hours, restore verified), AC-DATA-006 (Restored data respects deletion/do-not-recall obligations)
**Estimated Time:** 4 hours

#### Context

Dual-provider backup strategy per ADR-032: idcloudhost S3 (primary, Jakarta region — low latency) + Cloudflare R2 (secondary, global — geographic diversity). Backup includes: PostgreSQL dump (pg_dump -Fc), Redis dump (BGSAVE .rdb), configuration files (/etc/guinevere, /etc/systemd/system/guinevere-*), secrets encrypted via SOPS+age, application code (git — already on GitHub, backup as secondary copy), and evidence files. Must verify: backup completeness (no missing files), encryption at rest (age headers present), restore within RTO (target < 2 hours, hard limit 4 hours per AC-OPS-003), data integrity (pg_restore with checksums, Redis key counts match), and deletion/do-not-recall obligations honored during restore (AC-DATA-006). Test restore MUST use separate directory/instance — never overwrite production data.

#### Commands

```bash
# 1. Document test start time and backup metadata
echo "BACKUP_TEST_START=$(date -Iseconds)" \
  > docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt
echo "PG_ROWS_BEFORE=$(psql -U guinevere -h localhost -d guinevere -t -c 'SELECT count(*) FROM financial.transactions')" \
  >> docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt
echo "REDIS_KEYS_BEFORE=$(redis-cli -p 6380 DBSIZE)" \
  >> docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt

# 2. Trigger full PostgreSQL dump (custom format with compression)
pg_dump -U guinevere -h localhost -d guinevere \
  -Fc --no-owner --no-acl --verbose \
  -f /tmp/guinevere-backup-test/postgresql-$(date +%Y%m%d-%H%M%S).dump \
  2>&1 | tee docs/setup-evidence/P10/STEP-P10-005/pgdump-output.txt
PG_DUMP_SIZE=$(stat --format=%s /tmp/guinevere-backup-test/postgresql-*.dump)
echo "PG_DUMP_SIZE_BYTES=${PG_DUMP_SIZE}" \
  >> docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt

# 3. Trigger Redis BGSAVE (non-blocking snapshot)
redis-cli -p 6380 BGSAVE
# Wait for BGSAVE to complete (check lastsave changes)
sleep 5
while redis-cli -p 6380 INFO persistence | grep -q "rdb_bgsave_in_progress:1"; do
  echo "Waiting for Redis BGSAVE to complete..."
  sleep 2
done
# Copy the RDB file to backup directory
cp /var/lib/redis/dump.rdb \
  /tmp/guinevere-backup-test/redis-$(date +%Y%m%d-%H%M%S).rdb
REDIS_DUMP_SIZE=$(stat --format=%s /tmp/guinevere-backup-test/redis-*.rdb)
echo "REDIS_DUMP_SIZE_BYTES=${REDIS_DUMP_SIZE}" \
  >> docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt

# 4. Backup configuration files and secrets (tar + SOPS encrypt)
tar -czf /tmp/guinevere-backup-test/configs-$(date +%Y%m%d-%H%M%S).tar.gz \
  /etc/guinevere/ \
  /etc/systemd/system/guinevere-* \
  /etc/pgbouncer/pgbouncer.ini \
  /etc/redis/redis.conf
# Encrypt the config tarball with SOPS+age
sops --encrypt --age $(grep "public key: age" .sops.yaml | head -1 | awk '{print $4}') \
  /tmp/guinevere-backup-test/configs-*.tar.gz \
  > /tmp/guinevere-backup-test/configs-$(date +%Y%m%d-%H%M%S).tar.gz.enc
CONFIG_SIZE=$(stat --format=%s /tmp/guinevere-backup-test/configs-*.tar.gz.enc)
echo "CONFIG_ENCRYPTED_SIZE_BYTES=${CONFIG_SIZE}" \
  >> docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt

# 5. Upload to S3 (idcloudhost — primary)
aws s3 sync /tmp/guinevere-backup-test/ \
  s3://guinevere-backups/full-test-$(date +%Y%m%d)/ \
  --endpoint-url https://s3.idcloudhost.com \
  --storage-class STANDARD \
  2>&1 | tee docs/setup-evidence/P10/STEP-P10-005/s3-upload-output.txt

# 6. Upload to R2 (Cloudflare — secondary)
rclone sync /tmp/guinevere-backup-test/ \
  r2:guinevere-backups/full-test-$(date +%Y%m%d)/ \
  --progress \
  2>&1 | tee docs/setup-evidence/P10/STEP-P10-005/r2-upload-output.txt

# 7. Verify S3 upload — list objects
aws s3 ls s3://guinevere-backups/full-test-$(date +%Y%m%d)/ \
  --endpoint-url https://s3.idcloudhost.com \
  --recursive \
  > docs/setup-evidence/P10/STEP-P10-005/s3-verify.txt

# 8. Verify R2 upload — list objects
rclone ls r2:guinevere-backups/full-test-$(date +%Y%m%d)/ \
  > docs/setup-evidence/P10/STEP-P10-005/r2-verify.txt

# 9. Encryption verification — check file headers for age encryption markers
for encfile in /tmp/guinevere-backup-test/*.enc; do
  echo "=== $encfile ===" >> docs/setup-evidence/P10/STEP-P10-005/encryption-verify.txt
  head -c 100 "$encfile" | xxd | head -5 \
    >> docs/setup-evidence/P10/STEP-P10-005/encryption-verify.txt
  # Should show "age-encryption.org/v1" in the header
done

# 10. RESTORE TO TEST DIRECTORY (never production)
RESTORE_DIR="/tmp/guinevere-restore-test"
mkdir -p "${RESTORE_DIR}/pgdata" "${RESTORE_DIR}/redis" "${RESTORE_DIR}/configs"

# 10a. Restore PostgreSQL to test directory (requires temp PG instance)
#     Use a temporary PostgreSQL cluster to avoid impacting production
export PGDATA="${RESTORE_DIR}/pgdata"
initdb -D "${PGDATA}" --username=guinevere
pg_ctl -D "${PGDATA}" -l "${RESTORE_DIR}/pg-restore.log" start -o "-p 5433"
sleep 3
# Create database and extensions
createdb -p 5433 -U guinevere guinevere_restore
psql -p 5433 -U guinevere -d guinevere_restore \
  -c "CREATE EXTENSION IF NOT EXISTS timescaledb"
psql -p 5433 -U guinevere -d guinevere_restore \
  -c "CREATE EXTENSION IF NOT EXISTS vector"
# Restore the dump
pg_restore -p 5433 -U guinevere -d guinevere_restore \
  --verbose --no-owner --no-acl \
  /tmp/guinevere-backup-test/postgresql-*.dump \
  2>&1 | tee docs/setup-evidence/P10/STEP-P10-005/pg-restore-output.txt

# 10b. Data integrity check — row counts match pre-backup
PG_ROWS_AFTER=$(psql -p 5433 -U guinevere -d guinevere_restore \
  -t -c "SELECT count(*) FROM financial.transactions")
echo "PG_ROWS_AFTER=${PG_ROWS_AFTER}" \
  >> docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt
PG_ROWS_BEFORE=$(grep PG_ROWS_BEFORE docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt | cut -d'=' -f2)
if [ "$PG_ROWS_BEFORE" = "$PG_ROWS_AFTER" ]; then
  echo "PASS: PostgreSQL row count matches (${PG_ROWS_BEFORE} rows)"
else
  echo "FAIL: PostgreSQL row count mismatch (before: ${PG_ROWS_BEFORE}, after: ${PG_ROWS_AFTER})"
fi

# 10c. Check table-level row counts for key tables
for table in financial.transactions financial.project_costs surveillance.events memory.conversations; do
  COUNT=$(psql -p 5433 -U guinevere -d guinevere_restore -t -c "SELECT count(*) FROM ${table}" 2>/dev/null || echo "TABLE_NOT_FOUND")
  echo "${table}: ${COUNT}" >> docs/setup-evidence/P10/STEP-P10-005/table-row-counts.txt
done

# 10d. Restore Redis to test instance (separate port)
redis-server --port 6381 --dir "${RESTORE_DIR}/redis" --daemonize yes
sleep 2
# Copy RDB into test Redis dir and restart
cp /tmp/guinevere-backup-test/redis-*.rdb "${RESTORE_DIR}/redis/dump.rdb"
redis-cli -p 6381 SHUTDOWN NOSAVE
redis-server --port 6381 --dir "${RESTORE_DIR}/redis" --daemonize yes
sleep 2
REDIS_KEYS_AFTER=$(redis-cli -p 6381 DBSIZE)
REDIS_KEYS_BEFORE=$(grep REDIS_KEYS_BEFORE docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt | cut -d'=' -f2)
echo "REDIS_KEYS_AFTER=${REDIS_KEYS_AFTER}" \
  >> docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt
if [ "$REDIS_KEYS_BEFORE" = "$REDIS_KEYS_AFTER" ]; then
  echo "PASS: Redis key count matches (${REDIS_KEYS_BEFORE} keys)"
else
  echo "FAIL: Redis key count mismatch (before: ${REDIS_KEYS_BEFORE}, after: ${REDIS_KEYS_AFTER})"
fi

# 10e. Configuration file diff — original vs restored
sops --decrypt /tmp/guinevere-backup-test/configs-*.tar.gz.enc \
  > "${RESTORE_DIR}/configs/restored-configs.tar.gz"
tar -xzf "${RESTORE_DIR}/configs/restored-configs.tar.gz" -C "${RESTORE_DIR}/configs/"
diff -r /etc/guinevere/ "${RESTORE_DIR}/configs/etc/guinevere/" \
  > docs/setup-evidence/P10/STEP-P10-005/config-diff.txt 2>&1
# Diff should be empty (configs unchanged between backup and restore)

# 11. Cleanup test instances
redis-cli -p 6381 SHUTDOWN NOSAVE
pg_ctl -D "${PGDATA}" stop
echo "BACKUP_TEST_END=$(date -Iseconds)" \
  >> docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt

# 12. Calculate backup size and duration metrics
START_TS=$(grep BACKUP_TEST_START docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt | cut -d'=' -f2)
END_TS=$(grep BACKUP_TEST_END docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt | cut -d'=' -f2)
echo "TOTAL_DURATION: $(($(date -d "$END_TS" +%s) - $(date -d "$START_TS" +%s))) seconds"
echo "TOTAL_BACKUP_SIZE: $(du -sh /tmp/guinevere-backup-test/ | cut -f1)"
echo "PG_DUMP_SIZE: $(grep PG_DUMP_SIZE_BYTES docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt | cut -d'=' -f2) bytes"
echo "REDIS_DUMP_SIZE: $(grep REDIS_DUMP_SIZE_BYTES docs/setup-evidence/P10/STEP-P10-005/test-metadata.txt | cut -d'=' -f2) bytes"
```

#### Troubleshooting
- **Issue:** S3 upload timeout — network bandwidth insufficient for backup size
  - **Solution:** Use multipart upload: `aws s3 cp` with `--multipart-chunksize`. If still slow, compress with zstd before upload. Check network: `speedtest-cli`. Expected: >= 10 Mbps upload
- **Issue:** R2 authentication failure — "InvalidAccessKeyId" or "SignatureDoesNotMatch"
  - **Solution:** Verify R2 API token in rclone config: `rclone config show r2:`. R2 uses S3-compatible API but requires Cloudflare-specific endpoint and token (not AWS credentials). Recreate token in Cloudflare dashboard
- **Issue:** pg_restore fails with "extension 'timescaledb' is not available"
  - **Solution:** Install TimescaleDB on the test PostgreSQL cluster or exclude hypertable data from test restore: `pg_restore --exclude-table-data=financial.transactions`. Full restore test requires TimescaleDB
- **Issue:** Redis restore shows fewer keys — some keys expired during the test window
  - **Solution:** Redis keys with TTL may expire between backup and restore. Document expected TTL-based key loss. For cost tracking keys (DB5), TTL should NOT be set — they are permanent
- **Issue:** Encryption verification fails — no age header found
  - **Solution:** The config tarball may not have been encrypted. Check SOPS config: `.sops.yaml` must specify age recipient. Re-run encryption step with explicit recipient: `sops --encrypt --age <KEY> input > output.enc`
- **Issue:** Restore time > 2 hours (approaching 4h RTO)
  - **Solution:** Identify bottleneck: pg_restore speed, disk I/O, or Redis load time. Consider parallel pg_restore: `pg_restore -j 4` for multi-core. Pre-warm test cluster with extensions before restore

#### Notes
- Total backup should complete within 30 minutes for the expected data volume (< 10GB). Full restore target: < 2 hours (well within 4-hour RTO per AC-OPS-003). If restore time exceeds 2 hours, investigate pg_restore parallelism and disk I/O
- Test restore MUST use separate directory/instance on separate ports (5433 for PostgreSQL, 6381 for Redis). Never overwrite production data during a test
- AC-DATA-006: deletion/do-not-recall obligations mean that if a user requested data deletion between the backup timestamp and the restore timestamp, the restored data must NOT contain that deleted data. This is verified by checking the deletion audit log against the restored dataset
- Dual-provider strategy: S3 (idcloudhost Jakarta) is primary due to geographic proximity (lower latency). R2 (Cloudflare global) is secondary for disaster recovery — if Jakarta datacenter has an extended outage, R2 is the recovery source
- Test backups in `/tmp/guinevere-backup-test/` are temporary. Remove them after verification to free disk space. The S3/R2 copies are the persistent test artifacts
- For production automation: the backup script should have a cron job (daily), with monitoring (alert if backup fails or exceeds time threshold). This test validates the manual procedure — automation via cron is scope of P10-005's production deployment, not this test step
- PostgreSQL temp cluster on port 5433: ensure it doesn't conflict with any existing service. Check: `ss -tlnp | grep 5433` before starting
