**Goal:** Create comprehensive operational runbooks covering common incident scenarios with step-by-step diagnosis, resolution, verification, and escalation procedures -- enabling rapid incident response (reduced MTTR) and knowledge transfer for operators.
**Dependencies:** P10-005 (Backup Verification), P10-006 (DR Drill), P10-012 (Log Rotation), P10-013 (Rate Limiting), P10-015 (Health Checks), P10-017 (Pool Monitoring). Runbooks reference procedures from all prior P10 hardening steps.

**Acceptance Criteria:** AC-OPS-006 (Production documentation includes runbook + incident response + postmortem template with file-based evidence for material work)
**Estimated Time:** 4 hours

#### Context

Runbooks are the operational backbone of a production service. They reduce mean time to resolution (MTTR) during incidents, serve as onboarding material for new operators, and provide a structured escalation path when initial fixes fail. Each runbook follows a consistent template: symptoms (what you observe), diagnosis (commands to confirm), resolution (step-by-step fix), verification (how to confirm it worked), and escalation (when to get help). Runbooks must be testable -- an operator unfamiliar with Guinevere should be able to follow them and resolve the issue. These are living documents; every incident produces either a new runbook or an update to an existing one. Linked from Grafana alert annotations for one-click access during alerts.

#### Troubleshooting
- **Issue:** Runbook verification grep fails on a section
  - **Solution:** Check that section header is exactly `## SectionName` (case-sensitive). Some shells may have issues with grep patterns containing spaces. Use `grep -F "## Resolution"` for literal matching
- **Issue:** Runbook commands reference environment variables not set on the operator's machine
  - **Solution:** All sensitive variables (REDIS_CORE_PASS, API keys) are intentionally not hardcoded. The operator must have these in their environment or retrieve from 1Password. Add a "Prerequisites" section to each runbook if needed
- **Issue:** Runbook template (10-template.md) feels too minimal
  - **Solution:** The template is intentionally minimal -- it's a starting point. Each real incident adds detail. The 01-09 runbooks serve as worked examples of the template filled in
- **Issue:** Grafana annotations linking to private GitHub repository
  - **Solution:** The runbooks are in a private repo. Grafana alert annotations can link to the raw GitHub URL if the operator is authenticated. Alternative: self-host runbooks on the VPS behind Tailscale and link via `http://100.x.x.x:NNNN/runbooks/`
