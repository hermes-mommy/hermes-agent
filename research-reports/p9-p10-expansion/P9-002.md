#### Context

The `financial.transactions` table already exists as a TimescaleDB hypertable from an earlier alembic migration. This step verifies the schema supports all fields needed for SMS-parsed bank transaction data: bank identification, raw SMS text, parsed amount with Indonesian rupiah convention (IDR, NUMERIC(15,2)), transaction type (credit/debit), optional merchant and category, confidence score from parsing, and traceability to the original SMS source. The schema must also carry `ClassificationMetaMixin` fields (verified from P9-001). Indexing strategy targets the three primary query patterns: category-based budget tracking, bank+account lookup, and source filtering.

#### Troubleshooting
- **Issue:** Hypertable creation fails with `cannot create a unique index without the partition column`
  - **Solution:** Ensure `created_at` is part of the primary key or any unique indexes. TimescaleDB requires the partition column in all unique indexes
- **Issue:** `ALTER TABLE ... ADD CONSTRAINT` fails because data violates the constraint
  - **Solution:** Check existing data first: `SELECT * FROM financial.transactions WHERE parsed_amount < 0` — fix data or add `NOT VALID` clause: `ALTER TABLE ... ADD CONSTRAINT ... CHECK (...) NOT VALID`
- **Issue:** Alembic autogenerate creates duplicate columns (already in schema but different casing)
  - **Solution:** Manually inspect the generated migration. Check for case-sensitivity: PostgreSQL folds unquoted identifiers to lowercase
- **Issue:** Compression policy errors — `timescaledb.compress` setting not recognized
  - **Solution:** Verify TimescaleDB version >= 2.0: `SELECT extversion FROM pg_extension WHERE extname='timescaledb'`

#### Notes
- Indonesian decimal convention: `parsed_amount` is `NUMERIC(15,2)` to support amounts up to 999 trillion IDR with sen precision. Store as positive for both credit and debit — `transaction_type` column (credit/debit) disambiguates direction
- `raw_sms_text` is `TEXT` — stores the full SMS body verbatim for audit trail. Parsing happens in P9-005 (not here)
- `confidence_score` is `NUMERIC(3,2)` — 0.00 to 1.00 range, indicating parser confidence. Initially NULL until P9-005 populates it
- `category` is nullable — transactions start unclassified and get categorized later via P9-008 (classification engine)
- Source enum: `tasker` (SMS from phone), `manual` (operator entry), `api` (future bank API integration)
- TimescaleDB chunk interval of 1 month — at < 1000 transactions/month, each chunk is < 1 MB. If transaction volume grows (e.g., multiple bank accounts), reduce to 1 week
- Compression after 3 months segments historical data from active; most queries target current and prior month for budget tracking
- All queries must include `classification_level` filter per ADR-024 data access policy
