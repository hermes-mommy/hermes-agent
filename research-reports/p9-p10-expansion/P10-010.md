### Step P10-010: Rollback Automation

**Type:** Infrastructure
**Status:** ⬜ Not Started
**Risk:** High
**Git Commit:** `feat(P10): automated rollback mechanism`

**Goal:** Automated rollback mechanism using git revert + redeploy + health check, triggered automatically on deploy failure or manually via CLI/Discord command.
**Dependencies:** P10-007 (deploy script with health check), P10-009 (CD timer invokes rollback on failure)
**Cost Impact:** $0/month (infrastructure-only, no additional services)
**ADR References:** ADR-016, ADR-029
**Acceptance Criteria:** AC-OPS-005
**Estimated Time:** 3 hours

#### Context

ADR-016 requires automated failure recovery, and ADR-029 mandates safety for the production system. When deployment fails its post-deploy health check, automatic rollback must complete within 60 seconds. The rollback mechanism: identifies the last known good commit, checks out that commit, reinstalls Python dependencies from the previous `requirements-freeze.txt`, runs `alembic downgrade -1` if a migration was applied, restarts systemd services, and runs the health check. A manual rollback command (`scripts/rollback.sh` or Discord `/rollback`) is also supported. Evidence is captured for both the failed deploy and the successful rollback. A circuit breaker prevents cascading failures: more than 3 rollbacks in 10 minutes pauses the CD timer.

#### Pre-flight Checks
- [ ] P10-007 deploy script writes a "last good commit" marker on successful deployment
- [ ] `requirements-freeze.txt` or equivalent lock file is generated at deploy time
- [ ] Alembic migration history is accessible (`alembic current` returns clean state)
- [ ] `guinevere` user can execute `git checkout`, `git reset`, `alembic downgrade`, `systemctl restart`
- [ ] Health check endpoint (`/health`) returns 200 when services are healthy
- [ ] PostgreSQL backup exists for worst-case recovery scenario

#### Commands

```bash
# 1. Create rollback script
cat > /home/guinevere/scripts/rollback.sh << 'RLEOF'
#!/usr/bin/env bash
set -euo pipefail

LOG_FILE="/home/guinevere/logs/rollback.log"
HISTORY_FILE="/home/guinevere/config/known-good-commits.json"
REPO_DIR="/home/guinevere/guinevere"
CIRCUIT_BREAKER_FILE="/home/guinevere/config/rollback-circuit.json"
HEALTH_URL="http://localhost:8000/health"
MAX_RETRIES=30
RETRY_INTERVAL=2

log() { echo "[$(date -Iseconds)] $*" | tee -a "$LOG_FILE"; }

# --- Circuit Breaker ---
check_circuit_breaker() {
    if [[ ! -f "$CIRCUIT_BREAKER_FILE" ]]; then
        echo '{"count":0,"window_start":""}' > "$CIRCUIT_BREAKER_FILE"
    fi
    local now count window
    now=$(date +%s)
    count=$(jq '.count' "$CIRCUIT_BREAKER_FILE")
    window=$(jq -r '.window_start' "$CIRCUIT_BREAKER_FILE")
    if [[ -n "$window" ]] && [[ "$window" != "null" ]]; then
        local window_epoch
        window_epoch=$(date -d "$window" +%s 2>/dev/null || echo 0)
        if (( now - window_epoch > 600 )); then
            count=0
        fi
    fi
    if (( count >= 3 )); then
        log "CIRCUIT BREAKER TRIPPED: 3+ rollbacks in 10 minutes — aborting"
        return 1
    fi
    jq -n --arg now "$(date -Iseconds)" --argjson cnt "$((count + 1))" \
        '{count: $cnt, window_start: (if .window_start == "" then $now else .window_start end)}' \
        > "$CIRCUIT_BREAKER_FILE"
    return 0
}

# --- Identify Last Known Good Commit ---
get_last_good_commit() {
    if [[ -f "$HISTORY_FILE" ]]; then
        jq -r '.commits[0].sha' "$HISTORY_FILE" 2>/dev/null || true
    fi
}

# --- Record Successful Rollback in History ---
record_rollback() {
    local sha="$1"
    local history
    history=$(jq --arg sha "$sha" --arg date "$(date -Iseconds)" \
        '[{$sha, $date}] + .commits[0:4]' "$HISTORY_FILE" 2>/dev/null || echo '{"commits":[]}')
    echo "$history" | jq '.' > "$HISTORY_FILE"
}

# --- Alembic Downgrade with Safety Review ---
safe_alembic_downgrade() {
    log "Generating alembic downgrade SQL for review..."
    cd "$REPO_DIR"
    alembic downgrade -1 --sql > /tmp/alembic_downgrade.sql 2>&1 || true
    log "Downgrade SQL saved to /tmp/alembic_downgrade.sql"
    if grep -qiE 'DROP (TABLE|COLUMN|CONSTRAINT|INDEX)' /tmp/alembic_downgrade.sql; then
        log "WARNING: Downgrade contains DROP operations. Review /tmp/alembic_downgrade.sql before proceeding."
        log "Skipping automatic downgrade — manual review required."
        return 1
    fi
    log "Downgrade appears safe. Executing alembic downgrade -1..."
    alembic downgrade -1
}

# --- Health Check ---
health_check() {
    local attempt=0
    while (( attempt < MAX_RETRIES )); do
        if curl -sf "$HEALTH_URL" > /dev/null 2>&1; then
            log "Health check passed after $(( attempt * RETRY_INTERVAL ))s"
            return 0
        fi
        sleep "$RETRY_INTERVAL"
        ((attempt++))
    done
    log "Health check FAILED after ${MAX_RETRIES} retries"
    return 1
}

# --- Main Rollback ---
main() {
    mkdir -p "$(dirname "$LOG_FILE")" "$(dirname "$HISTORY_FILE")"
    log "=== Rollback initiated ==="

    check_circuit_breaker || exit 1

    local good_sha
    good_sha=$(get_last_good_commit)
    if [[ -z "$good_sha" ]]; then
        log "FATAL: No known good commit in history. Manual intervention required."
        exit 1
    fi

    log "Rolling back to commit: $(echo "$good_sha" | head -c 8)"
    cd "$REPO_DIR"

    # Record failed commit for audit
    local failed_sha
    failed_sha=$(git rev-parse --short HEAD)
    log "Failed commit: $failed_sha"

    # Step 1: Git checkout known good
    git fetch origin
    git checkout "$good_sha"

    # Step 2: Reinstall dependencies from lock file
    if [[ -f requirements-freeze.txt ]]; then
        pip install -r requirements-freeze.txt
    else
        pip install -e "."
    fi

    # Step 3: Alembic downgrade (safe only)
    safe_alembic_downgrade || log "Alembic downgrade skipped or reviewed manually"

    # Step 4: Restart services
    sudo systemctl restart guinevere-api.service guinevere-bot.service guinevere-worker.service || true

    # Step 5: Health check
    if health_check; then
        log "Rollback SUCCESS — system healthy at $good_sha"
        record_rollback "$good_sha"
        log "=== Rollback complete ==="
        exit 0
    else
        log "CRITICAL: Rollback to $good_sha failed health check"
        log "=== Rollback FAILED === manual intervention required"
        exit 1
    fi
}

main
```

#### Troubleshooting

- **Issue:** Rollback itself fails — git checkout fails or health check still fails after rollback
  - **Solution:** SSH directly into the VPS. Manually inspect: `git log --oneline -5`, `systemctl status guinevere-*`, `journalctl -u guinevere-api -n 100`. If services are down, start them manually. If database is corrupted, restore from latest backup. This is the emergency path — the rollback script failing is a "wake Faiz up" event.

- **Issue:** Alembic downgrade is destructive (contains DROP TABLE/COLUMN)
  - **Solution:** The script skips automatic downgrade and logs a warning. Manually review `/tmp/alembic_downgrade.sql`. If the migration added a column (non-destructive), it is safe to leave it. If it dropped a column, you need the expand-contract pattern — the migration should have been a multi-step process (add new column, migrate data, drop old column in separate migration).

- **Issue:** Multiple rapid rollbacks trigger circuit breaker
  - **Solution:** The circuit breaker pauses CD for 10 minutes. Investigate the root cause of repeated failures — likely a broken commit on `main` that needs to be reverted upstream. Reset the circuit breaker manually: `echo '{"count":0,"window_start":""}' > /home/guinevere/config/rollback-circuit.json`.

- **Issue:** `requirements-freeze.txt` is stale or missing
  - **Solution:** Update P10-007 deploy script to generate `pip freeze > requirements-freeze.txt` after every successful `pip install`. If the file is missing, the rollback script falls back to `pip install -e "."`, which installs the latest versions from `pyproject.toml` — this may install different versions than the known-good deployment.

#### Notes

- Database rollback is the riskiest component. The script deliberately skips automatic `alembic downgrade` if the SQL preview contains DROP statements. Non-destructive migrations (add column, add table, add index) are safe to downgrade. Destructive migrations MUST use the expand-contract pattern: (1) deploy new column/table, (2) backfill data, (3) deploy code that reads both old and new, (4) deploy code that writes only new, (5) deploy migration that drops old column/table. Each step is a separate deploy, ensuring rollback never needs to restore dropped data.
- The circuit breaker resets after 10 minutes without a rollback. This prevents one bad commit from blocking all future deployments indefinitely.
- Rollback does NOT touch SOPS-encrypted secrets. If a deploy changed encrypted secrets, the rollback must also revert those files — this is left manual for safety (secrets changes are rare).
- Discord `/rollback` command integration (for manual trigger) is handled in P9-005 (Slash Commands batch) and should call this script directly.
