#### Troubleshooting
- **Issue:** Multiple FAIL checks in hardening report
  - **Solution:** Address each FAIL individually in order. The report lists each check with its command -- re-run the failing command to see the specific error. Common failures: missing evidence files (step wasn't completed), service not running (systemd issue), configured value not matching expected
- **Issue:** nmap shows unexpected open port
  - **Solution:** Identify the process: `ss -tlnp | grep <PORT>`. If it's a Guinevere service not documented, add it to the expected list. If it's an unknown process, investigate immediately -- possible security breach (Runbook 06). If it's an Aizanta service on shared VPS, document as out-of-scope
- **Issue:** Backup freshness check fails (no backup < 24h)
  - **Solution:** Check backup cron/systemd timer: `systemctl status guinevere-backup.timer`. If timer failed, check logs: `journalctl -u guinevere-backup`. Manually trigger backup: `sudo systemctl start guinevere-backup`. Update P10-005 evidence after backup completes
- **Issue:** Rate limiter never returns 429 even with 25 rapid requests
  - **Solution:** Check rate limiter config: `redis-cli -n 5 GET "ratelimit:config"`. The rate limit for health endpoints may be higher (or disabled) to allow monitoring. Test against a limited endpoint like `/api/v1/status` instead of `/health/shallow`
