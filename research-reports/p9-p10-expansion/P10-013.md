**Type:** Application
**Status:** ⬜ Not Started
**Risk:** Medium

**Goal:** Per-endpoint rate limiting on FastAPI using Redis-backed sliding window algorithm to prevent API abuse and protect against runaway agent loops.
**Dependencies:** P0-020 (Redis 7 operational), FastAPI application with route structure defined

**Acceptance Criteria:** AC-SEC-001, AC-CORE-002

#### Context

ADR-018 mandates defense-in-depth measures including API rate limiting. Guinevere serves multiple client types with different access patterns and risk profiles: authenticated Discord commands (high volume, trusted user), webhook endpoints from P9-004 (potential external source), health checks (should be unlimited), MCP tools (moderate volume, per-tool limits), and unauthenticated endpoints (baseline protection). The rate limiter uses a Redis-backed sliding window algorithm for distributed accuracy — critical for future multi-instance deployment, but also ensures accurate counting even within a single instance. On Redis connection failure, the rate limiter fails open (allows requests) because blocking Faiz's own commands is worse than temporarily allowing unthrottled access. Rate limit metrics are exported to Prometheus for monitoring and alerting. Abuse events (when a limit is hit) are logged with IP and identifier for investigation.

"""Redis-backed sliding window rate limiter for FastAPI.

Uses Redis DB0 with key pattern: ratelimit:{endpoint}:{identifier}
Fails open on Redis connection failure (allows requests, logs warning).
"""

import time
import hashlib
import logging
from typing import Optional
from dataclasses import dataclass

import redis.asyncio as aioredis
from fastapi import Request, HTTPException

logger = logging.getLogger("guinevere.rate_limiter")


@dataclass
class RateLimitConfig:
    """Per-endpoint rate limit configuration."""
    max_requests: int
    window_seconds: int
    identifier: str  # endpoint name for metrics/logging


# Default rate limits per endpoint category
DEFAULT_LIMITS: dict[str, RateLimitConfig] = {
    "discord_command": RateLimitConfig(max_requests=100, window_seconds=60, identifier="discord_command"),
    "webhook": RateLimitConfig(max_requests=60, window_seconds=60, identifier="webhook"),
    "health": RateLimitConfig(max_requests=9999, window_seconds=60, identifier="health"),
    "mcp_tool": RateLimitConfig(max_requests=30, window_seconds=60, identifier="mcp_tool"),
    "unauthenticated": RateLimitConfig(max_requests=10, window_seconds=60, identifier="unauthenticated"),
    "default": RateLimitConfig(max_requests=200, window_seconds=60, identifier="default"),
}

EXEMPT_IPS: set[str] = {
    "127.0.0.1",
    "::1",
    "100.64.0.0/10",  # Tailscale CGNAT range
}

# Circuit state for fail-open behavior
_redis_failing: bool = False
_redis_fail_since: float = 0.0


def _get_client_ip(request: Request) -> str:
    """Extract client IP, preferring X-Forwarded-For if behind proxy."""
    forwarded = request.headers.get("X-Forwarded-For")
    if forwarded:
        return forwarded.split(",")[0].strip()
    client = request.client
    return client.host if client else "unknown"


def _is_exempt(ip: str) -> bool:
    """Check if an IP is in the exemption list (exact or CIDR range)."""
    if ip in EXEMPT_IPS:
        return True
    # Simple Tailscale prefix check (100.64.0.0/10 = 100.64.0.0 to 100.127.255.255)
    if ip.startswith("100."):
        try:
            second_octet = int(ip.split(".")[1])
            return 64 <= second_octet <= 127
        except (IndexError, ValueError):
            pass
    return False


class SlidingWindowRateLimiter:
    """Redis-backed sliding window rate limiter."""

    def __init__(self, redis_client: aioredis.Redis, prefix: str = "ratelimit"):
        self.redis = redis_client
        self.prefix = prefix

    async def _is_redis_healthy(self) -> bool:
        global _redis_failing, _redis_fail_since
        try:
            await self.redis.ping()
            if _redis_failing:
                logger.info("Redis recovered — rate limiting re-engaged")
                _redis_failing = False
                _redis_fail_since = 0.0
            return True
        except Exception:
            if not _redis_failing:
                logger.warning("Redis unavailable — rate limiting disabled (fail-open)")
                _redis_failing = True
                _redis_fail_since = time.monotonic()
            return False

    async def is_rate_limited(
        self,
        endpoint: str,
        identifier: str,
        max_requests: int,
        window_seconds: int,
    ) -> tuple[bool, int, int]:
        """Check if a request is rate limited.

        Returns: (is_limited, remaining, reset_seconds)
        """
        if _is_exempt(identifier) and endpoint in ("health",):
            return False, max_requests, window_seconds

        if not await self._is_redis_healthy():
            return False, max_requests, window_seconds  # fail-open

        key = f"{self.prefix}:{endpoint}:{identifier}"
        now_ms = int(time.time() * 1000)
        window_ms = window_seconds * 1000
        cutoff_ms = now_ms - window_ms

        try:
            async with self.redis.pipeline(transaction=True) as pipe:
                pipe.zremrangebyscore(key, 0, cutoff_ms)
                pipe.zcard(key)
                pipe.zadd(key, {str(now_ms): now_ms})
                pipe.expire(key, window_seconds + 1)
                pipe.zrange(key, 0, 0, withscores=True)
                results = await pipe.execute()

            current_count: int = results[1]
            oldest_ts: float = results[4][0][1] / 1000 if results[4] else now_ms / 1000
            remaining = max(0, max_requests - current_count)
            reset_seconds = max(0, int(oldest_ts + window_seconds - time.time()))

            if current_count > max_requests:
                logger.warning(
                    "Rate limit hit: endpoint=%s identifier=%s count=%d limit=%d",
                    endpoint, identifier, current_count, max_requests,
                )
                return True, 0, reset_seconds

            return False, remaining, reset_seconds

        except Exception:
            logger.exception("Redis error during rate limit check — failing open")
            return False, max_requests, window_seconds


def get_rate_limit_for_route(route_name: str) -> RateLimitConfig:
    """Map route names to rate limit configurations."""
    endpoint_map = {
        "health": "health",
        "webhook": "webhook",
        "mcp": "mcp_tool",
        "discord": "discord_command",
    }
    for prefix, category in endpoint_map.items():
        if route_name.startswith(prefix):
            return DEFAULT_LIMITS.get(category, DEFAULT_LIMITS["default"])
    return DEFAULT_LIMITS["default"]


async def rate_limit_dependency(request: Request) -> None:
    """FastAPI dependency for per-endpoint rate limiting."""
    limiter: Optional[SlidingWindowRateLimiter] = getattr(
        request.app.state, "rate_limiter", None
    )
    if limiter is None:
        return  # rate limiter not configured — allow

    ip = _get_client_ip(request)
    if _is_exempt(ip):
        return  # internal/Tailscale traffic bypasses rate limiting

    route_name = request.scope.get("route", {}).get("name", request.url.path)
    config = get_rate_limit_for_route(route_name)

    limited, remaining, reset_sec = await limiter.is_rate_limited(
        endpoint=config.identifier,
        identifier=ip,
        max_requests=config.max_requests,
        window_seconds=config.window_seconds,
    )

    if limited:
        raise HTTPException(
            status_code=429,
            detail={
                "error": "Too Many Requests",
                "retry_after_seconds": reset_sec,
                "limit": config.max_requests,
                "window_seconds": config.window_seconds,
            },
            headers={
                "Retry-After": str(reset_sec),
                "X-RateLimit-Limit": str(config.max_requests),
                "X-RateLimit-Remaining": "0",
                "X-RateLimit-Reset": str(reset_sec),
            },
        )

#### Troubleshooting

- **Issue:** Redis connection failure blocks all requests (rate limiter is failing closed)
  - **Solution:** Verify the fail-open logic in `_is_redis_healthy()` is working. The `except Exception` in `is_rate_limited` should catch Redis errors and return `(False, max_requests, window_seconds)`. If the Redis client hangs instead of raising, add a connection timeout: `aioredis.from_url(settings.REDIS_URL, socket_connect_timeout=2, socket_timeout=2)`.

- **Issue:** Rate limit is too aggressive, blocking legitimate usage
  - **Solution:** Tune per-endpoint rate limits in the `DEFAULT_LIMITS` dictionary. Discord commands may need 100-200/min depending on Faiz's usage patterns. Monitor actual usage via metrics before adjusting. Each endpoint category can be tuned independently without affecting others.

- **Issue:** Rate limit keys accumulate in Redis and consume memory
  - **Solution:** The `expire` call on each key ensures keys auto-expire after `window_seconds + 1`. If keys are not expiring, verify the Redis instance does not have `maxmemory-policy noeviction` set — change to `allkeys-lru` or `volatile-lru`. Monitor Redis memory with `redis-cli INFO memory`.

- **Issue:** `X-Forwarded-For` header spoofing bypasses rate limits
  - **Solution:** Since Guinevere sits behind Caddy (which sets `X-Forwarded-For`), the first IP in the chain is the client's real IP. Caddy strips any pre-existing `X-Forwarded-For` header from untrusted proxies. Verify Caddy config includes `trusted_proxies` directive with the Tailscale subnet. If Caddy is not the only proxy, ensure intermediate proxies also strip the header.

- **Issue:** Rate limiter slows down every request (Redis roundtrip per request)
  - **Solution:** The Redis sliding window operation uses a pipeline (single roundtrip for multiple commands). If latency is still high, consider a local in-memory cache as a first-pass filter before hitting Redis. For Guinevere's scale (single user), the Redis roundtrip is negligible (sub-millisecond on localhost).

#### Notes

- Fail-open on Redis failure is a deliberate choice for Guinevere's threat model. As a personal assistant, availability (Faiz's commands always work) takes priority over rate limiting. In a multi-tenant production API, fail-closed would be appropriate. Document this trade-off.
- Rate limits are stored in Redis DB0 with key pattern `ratelimit:{endpoint}:{identifier}`. The identifier is typically the client IP (from `_get_client_ip`). For authenticated endpoints, consider using the Discord user ID as the identifier for per-user rate limiting instead of per-IP.
- MCP tools rate limiting (30/min per tool) is designed to prevent runaway agent loops — if an agent calls a tool in an infinite loop, the rate limiter will throttle it after 30 calls in a minute, giving the system time to detect and interrupt the loop.
- Health checks are effectively unlimited (9999/min) because Kubernetes-style health probes and monitoring systems need unrestricted access. If health checks are being abused, they are hitting the wrong endpoint — health checks should be lightweight and not trigger expensive operations.
