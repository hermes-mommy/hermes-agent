### Step P10-001: Security Audit (Pen Test + Vuln Scan)

**Type:** Security
**Status:** Not Started
**Risk:** High
**Git Commit:** `feat(P10): pending`

**Goal:** Comprehensive security audit combining network scanning (nmap), system auditing (lynis), Python security scanning (bandit + semgrep + trivy + pip-audit), and Tailscale/access control review to validate defense-in-depth hardening before production use.
**Dependencies:** All MVP phases (P0-P8) complete, all Guinevere services running under systemd, Tailscale VPN operational, PostgreSQL/Redis accessible.
**Cost Impact:** $0/month (scanning tools are open-source, no additional infrastructure)
**ADR References:** ADR-018 (Defense-in-Depth Architecture), ADR-019 (Tailscale-Only Admin Access)
**Acceptance Criteria:** AC-SEC-001 (Security audit completed with zero CRITICAL open findings), AC-SEC-004 (Break-glass procedure validated), AC-CORE-002 (All services expose no public ports)
**Estimated Time:** 6 hours

#### Context

First step of Phase 10 production hardening. Must validate defense-in-depth per ADR-018: zero public admin ports (all admin access via Tailscale-only per ADR-019), RBAC/ABAC default deny, service isolation via systemd + UFW. Break-glass procedure per AC-SEC-004: SEV0/SEV1 incidents only, maximum 4-hour window, narrowest possible scope, complete audit trail required. Research findings identify five scanning layers — network (nmap), system (lynis), Python SAST (bandit + semgrep), container/dependency CVE (trivy), and known Python vulnerabilities (pip-audit). All findings classified as CRITICAL/HIGH/MEDIUM/LOW with remediation SLA. CRITICAL findings must be resolved before P10-020 (Hardening Verification gate). Scan from INSIDE the Tailscale network (not public internet) to validate internal attack surface.

#### Commands

```bash
# 1. Network scan from INSIDE Tailscale network (100.0.0.0/8 range)
#    Scan all 65535 ports, service detection, OS fingerprint
nmap -sS -sV -O -p- -T4 --script vuln \
  -oA docs/setup-evidence/P10/STEP-P10-001/nmap-scan \
  100.x.x.x  # Replace with actual Tailscale IP
# Also scan localhost to verify no unexpected listeners
nmap -sS -sV -p- -T4 localhost \
  -oA docs/setup-evidence/P10/STEP-P10-001/nmap-localhost

# 2. Lynis system audit (run as root)
lynis audit system --no-colors \
  2>&1 | tee docs/setup-evidence/P10/STEP-P10-001/lynis-audit.txt

# 3. Bandit SAST scan (Python security linting, severity low+)
uv run bandit -r src/ -ll -f json \
  -o docs/setup-evidence/P10/STEP-P10-001/bandit-results.json
uv run bandit -r src/ -ll -f txt \
  -o docs/setup-evidence/P10/STEP-P10-001/bandit-results.txt

# 4. Semgrep pattern-based scanning (auto config)
semgrep --config auto src/ --json \
  -o docs/setup-evidence/P10/STEP-P10-001/semgrep-results.json \
  2>&1 | tee docs/setup-evidence/P10/STEP-P10-001/semgrep-results.txt

# 5. Trivy filesystem vulnerability scan
trivy fs --scanners vuln,misconfig --severity HIGH,CRITICAL \
  --format json -o docs/setup-evidence/P10/STEP-P10-001/trivy-results.json \
  .
trivy fs --scanners vuln,misconfig --severity HIGH,CRITICAL \
  --format table . \
  2>&1 | tee docs/setup-evidence/P10/STEP-P10-001/trivy-results.txt

# 6. pip-audit known vulnerability check
uv run pip-audit --format json \
  -o docs/setup-evidence/P10/STEP-P10-001/pip-audit-results.json
uv run pip-audit --format columns \
  2>&1 | tee docs/setup-evidence/P10/STEP-P10-001/pip-audit-results.txt

# 7. Tailscale ACL review — verify zero public ports
tailscale status --json > docs/setup-evidence/P10/STEP-P10-001/tailscale-status.json
# Verify each service binds to Tailscale interface or localhost
ss -tlnp | grep -v "127.0.0.1\|::1\|100\." \
  > docs/setup-evidence/P10/STEP-P10-001/public-listeners.txt
# If any line appears above, a service is exposed publicly — CRITICAL finding

# 8. UFW rule audit — verify default deny + explicit allows only
ufw status numbered \
  > docs/setup-evidence/P10/STEP-P10-001/ufw-rules.txt
# Expected: default deny incoming, allow Tailscale subnet, allow SSH on Tailscale IP only

# 9. Check for world-readable secrets or credentials
grep -r "token\|password\|secret\|api_key\|private_key" \
  --include="*.py" --include="*.yaml" --include="*.yml" --include="*.json" \
  --include="*.env" --include="*.toml" src/ \
  > docs/setup-evidence/P10/STEP-P10-001/secrets-in-code.txt
# Each hit must be verified: either env var reference or false positive

# 10. File permission audit — sensitive files must NOT be world-readable
find . -type f \( -name "*.env" -o -name "*.key" -o -name "*.pem" -o -name "*.age" \) \
  -perm /o+r 2>/dev/null \
  > docs/setup-evidence/P10/STEP-P10-001/world-readable-secrets.txt

# 11. Generate findings report with severity classification
cat > docs/setup-evidence/P10/STEP-P10-001/findings-report.md << 'EOF'
```

#### Troubleshooting
- **Issue:** nmap scan blocked by UFW — shows "filtered" on all ports
  - **Solution:** Scan from the Tailscale IP (100.x.x.x), not the public interface. UFW allows Tailscale subnet. If still blocked, temporarily: `ufw allow from 100.0.0.0/8` then remove after scan
- **Issue:** lynis reports hardening warnings for Apache/nginx (not running on this host)
  - **Solution:** These are false positives from the shared VPS running Aizanta services. Document them in `docs/setup-evidence/P10/STEP-P10-001/aizanta-exceptions.txt` as "shared VPS — managed by Aizanta, not Guinevere scope"
- **Issue:** semgrep reports hundreds of low-severity findings (style, formatting)
  - **Solution:** Create `.semgrepignore` file to exclude known patterns: `tests/`, `migrations/`, `venv/`. Re-run scan after tuning
- **Issue:** bandit flags `subprocess=True` or `shell=True` — legitimate use for systemd health checks
  - **Solution:** Mark as `# nosec` with justification comment. Document each suppression in findings report
- **Issue:** trivy scan times out on large directory
  - **Solution:** Exclude venv and node_modules: `trivy fs --scanners vuln --skip-dirs venv,node_modules,.git .`
- **Issue:** pip-audit finds vulnerability in transitive dependency with no fix available
  - **Solution:** Document in findings report as "accepted risk — no upstream fix, mitigated by Tailscale-only access and UFW default-deny"

#### Notes
- Scan from INSIDE Tailscale network (not public internet). The goal is to validate internal attack surface — what an attacker who has already breached Tailscale would see. Public internet attack surface should be zero by design (ADR-018/ADR-019)
- Document Aizanta service exceptions separately in `aizanta-exceptions.txt`. Do NOT flag Aizanta services as Guinevere findings — they are a different project on the same VPS
- Break-glass procedure test: as part of this step, simulate a SEV0 scenario — temporarily open port 22 to Tailscale subnet, document the access grant, verify it works, then close it. Full audit trail required per AC-SEC-004
- All CRITICAL findings must be resolved before P10-020 (Hardening Verification gate). HIGH findings must have remediation plan with owner and deadline. MEDIUM/LOW findings can be deferred to Phase 11 maintenance
- The `.semgrepignore` and bandit `# nosec` suppressions must be version-controlled and reviewed — they become part of the security posture
- Shared VPS constraint: nmap and lynis may detect Aizanta services running on the same host. Do NOT attempt to remediate Aizanta findings — document them as out-of-scope
- Scanning tools (nmap, lynis, trivy) may require root. Run with `sudo` where needed, but do NOT leave root-owned files in the evidence directory — `chown guinevere:guinevere` after scans complete
