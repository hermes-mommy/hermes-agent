### Step P10-003: Redis maxmemory Tuning

**Type:** Infrastructure
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P10): pending`

**Goal:** Optimize Redis 7 memory usage, eviction policy, persistence, and ACL configuration for the observed Guinevere production workload, with special protection for cost tracking keys in DB5.
**Dependencies:** P0 complete (Redis 7 running on port 6380), P0-021 complete (Redis ACL users configured), P9-004 complete (Redis DB5 cost tracking populated with real data).
**Cost Impact:** $0/month (configuration tuning, no additional resources)
**ADR References:** ADR-030 (Redis for Caching + Real-Time Tracking)
**Acceptance Criteria:** AC-CORE-005 (Redis memory usage stable under < 80% maxmemory, zero cost tracking key evictions, AOF + RDB persistence operational, latency < 1ms p99 for hot keys)
**Estimated Time:** 2 hours

#### Context

Redis 7 on shared VPS, DB0-DB5 assigned: DB0 (caching), DB1 (sessions), DB2 (rate-limiting), DB3 (task queues), DB4 (pubsub), DB5 (cost tracking via CostTracker/BudgetEnforcer/ToolCostTracker/LoopCostTracker — 11+ key patterns). Research findings: allkeys-lfu eviction policy is optimal for mixed workloads (frequently-accessed keys survive, cold keys evicted first), AOF+RDB hybrid persistence for durability, active-defrag for memory fragmentation on long-running instances, ACL hardening per-user from P0-021. DB5 cost tracking keys must NEVER be evicted — financial data loss is unacceptable. Memory limit calculated as observed peak usage + 50% headroom, constrained by 8GB cgroup cap shared with PostgreSQL.

#### Commands

```bash
# 1. Redis INFO memory analysis — capture full snapshot before tuning
redis-cli -p 6380 INFO memory \
  > docs/setup-evidence/P10/STEP-P10-003/redis-info-memory-before.txt
redis-cli -p 6380 INFO stats \
  > docs/setup-evidence/P10/STEP-P10-003/redis-info-stats-before.txt
# Key metrics to note: used_memory_human, used_memory_rss_human,
# mem_fragmentation_ratio, evicted_keys, keyspace_hits, keyspace_misses

# 2. Per-DB key count and memory breakdown
for db in 0 1 2 3 4 5; do
  echo "=== DB$db ===" >> docs/setup-evidence/P10/STEP-P10-003/per-db-analysis.txt
  redis-cli -p 6380 -n $db DBSIZE >> docs/setup-evidence/P10/STEP-P10-003/per-db-analysis.txt
  redis-cli -p 6380 -n $db INFO keyspace >> docs/setup-evidence/P10/STEP-P10-003/per-db-analysis.txt
done

# 3. Analyze observed memory usage over time (journalctl for OOM/eviction events)
journalctl -u redis-server --since "7 days ago" --no-pager \
  | grep -i "oom\|evict\|maxmemory\|out of memory" \
  > docs/setup-evidence/P10/STEP-P10-003/redis-oom-history.txt

# 4. Calculate maxmemory: peak observed + 50% headroom, capped at system limit
#    Example: if used_memory_rss = 200MB, set maxmemory = 300MB
#    Constraint: maxmemory + PostgreSQL shared_buffers + app memory < 8GB cgroup
OBSERVED_MB=200  # Replace with actual from step 1
HEADROOM_MB=$((OBSERVED_MB / 2))
MAXMEMORY_MB=$((OBSERVED_MB + HEADROOM_MB))
echo "Setting maxmemory to ${MAXMEMORY_MB}MB (observed: ${OBSERVED_MB}MB + ${HEADROOM_MB}MB headroom)"

# 5. Apply memory and eviction configuration
redis-cli -p 6380 CONFIG SET maxmemory "${MAXMEMORY_MB}mb"
redis-cli -p 6380 CONFIG SET maxmemory-policy allkeys-lfu
# Persist to redis.conf:
redis-cli -p 6380 CONFIG REWRITE

# 6. Enable AOF persistence with everysec fsync + RDB hybrid
redis-cli -p 6380 CONFIG SET appendonly yes
redis-cli -p 6380 CONFIG SET appendfsync everysec
redis-cli -p 6380 CONFIG SET aof-use-rdb-preamble yes
redis-cli -p 6380 CONFIG SET auto-aof-rewrite-percentage 100
redis-cli -p 6380 CONFIG SET auto-aof-rewrite-min-size 64mb
# RDB snapshot schedule (900s/1key, 300s/10keys, 60s/10000keys):
redis-cli -p 6380 CONFIG SET save "900 1 300 10 60 10000"
redis-cli -p 6380 CONFIG REWRITE

# 7. Enable active defragmentation for memory fragmentation
redis-cli -p 6380 CONFIG SET activedefrag yes
redis-cli -p 6380 CONFIG SET active-defrag-threshold-lower 10
redis-cli -p 6380 CONFIG SET active-defrag-threshold-upper 100
redis-cli -p 6380 CONFIG SET active-defrag-cycle-min 1
redis-cli -p 6380 CONFIG SET active-defrag-cycle-max 25
redis-cli -p 6380 CONFIG REWRITE

# 8. ACL list review — verify per-DB users from P0-021 still correct
redis-cli -p 6380 ACL LIST \
  > docs/setup-evidence/P10/STEP-P10-003/acl-list.txt
# Verify each user has appropriate DB access:
redis-cli -p 6380 ACL WHOAMI
# Check that DB5 cost tracking user has no evict override yet

# 9. Protect DB5 cost tracking keys — create eviction-exempt user
#    DB5 keys (cost:*, budget:*, usage:* etc.) must NEVER be evicted
#    Strategy: separate ACL user for cost tracker with noevict on DB5
redis-cli -p 6380 ACL SETUSER guinevere_cost \
  on ">$(grep REDIS_COST_PASSWORD .env | cut -d'=' -f2)" \
  ~cost:* ~budget:* ~usage:* ~tool:* ~loop:* ~project:* \
  &* -@dangerous +get +set +del +exists +incr +incrby +decr +decrby \
  +hget +hset +hdel +hexists +hincrby +hgetall +hkeys +hlen \
  +zadd +zrange +zrangebyscore +zrem +zcard +zcount \
  +expire +ttl +type +keys +scan \
  > doc/setup-evidence/P10/STEP-P10-003/acl-cost-user.txt
# Verify the user was created:
redis-cli -p 6380 ACL LIST | grep guinevere_cost

# 10. Redis slow log analysis — queries > 10ms
redis-cli -p 6380 SLOWLOG RESET  # Clear old entries first
# Wait for workload to generate slow queries (or leave overnight)
redis-cli -p 6380 SLOWLOG GET 20 \
  > docs/setup-evidence/P10/STEP-P10-003/slowlog.txt

# 11. Latency monitoring — sample for 60 seconds during normal load
redis-cli -p 6380 --latency-history \
  > docs/setup-evidence/P10/STEP-P10-003/latency-monitor.txt &
LATENCY_PID=$!
sleep 60
kill $LATENCY_PID 2>/dev/null

# 12. Verify final configuration state
redis-cli -p 6380 INFO memory \
  > docs/setup-evidence/P10/STEP-P10-003/redis-info-memory-after.txt
redis-cli -p 6380 CONFIG GET maxmemory
redis-cli -p 6380 CONFIG GET maxmemory-policy
redis-cli -p 6380 CONFIG GET appendonly
redis-cli -p 6380 CONFIG GET activedefrag
```

#### Troubleshooting
- **Issue:** Redis OOM kills despite maxmemory setting — eviction not fast enough
  - **Solution:** Reduce maxmemory headroom from 50% to 25%. If still OOM, investigate write spikes: `redis-cli -p 6380 INFO stats | grep instantaneous_ops_per_sec`
- **Issue:** allkeys-lfu evicts cost tracking keys (DB5)
  - **Solution:** Verify `guinevere_cost` ACL user is being used by the application. Check app config for `REDIS_COST_USER` env var. Allkeys-lfu is DB-wide — DB5 needs a separate Redis instance or the ACL user must use `noevict`-equivalent pattern (Redis 7 ACLs don't directly support eviction exemption per-user, so either: separate Redis instance for DB5, or tag DB5 keys with high LFU counter via periodic TOUCH)
- **Issue:** AOF rewrite causes latency spike during heavy write load
  - **Solution:** Increase `auto-aof-rewrite-min-size` to 128MB. Schedule rewrites during low-usage windows. Monitor: `redis-cli -p 6380 INFO persistence | grep aof_rewrite`
- **Issue:** active-defrag increases CPU usage > 10%
  - **Solution:** Reduce `active-defrag-cycle-max` to 10. If CPU still high, disable active-defrag and accept fragmentation (monitor `mem_fragmentation_ratio` — if < 1.5, fragmentation is acceptable)
- **Issue:** Latency p99 spikes > 5ms after enabling AOF
  - **Solution:** Ensure `appendfsync everysec` (not `always`). Check disk I/O: `iostat -x 1 5`. If disk is spinning HDD (not SSD), consider `appendfsync no` with RDB as primary persistence

#### Notes
- allkeys-lfu eviction policy is preferred over allkeys-lru for Guinevere's mixed workload: frequently-accessed surveillance keys survive, cold financial cache keys evict first. LFU tracks access frequency over time, not just recency
- DB5 cost tracking keys must use a separate eviction-exempt strategy. Redis 7 ACLs can restrict key patterns but cannot exempt from eviction. Practical approach: create `guinevere_cost` ACL user restricted to DB5 key prefixes, and set a high initial LFU counter via `OBJECT FREQ` on startup to make them "sticky" under LFU
- AOF rewrite at 100% growth: when AOF file doubles in size, Redis auto-rewrites to compact it. This balances disk usage against rewrite frequency
- RDB save schedule (900/1, 300/10, 60/10000): save if 1+ key changed in 900s, 10+ keys in 300s, or 10000+ keys in 60s. Cost tracking writes to Redis at high frequency — the 60/10000 rule ensures frequent saves
- active-defrag threshold: start defrag when fragmentation > 10%, stop when < 10%. Cycle CPU: use 1-25% of CPU for defrag. This is conservative for a shared VPS
- Shared VPS constraint: Redis memory competes with PostgreSQL shared_buffers (2GB from P10-002) and application memory. Total: Redis maxmemory + 2GB + ~1GB application < 8GB cgroup cap. Monitor with `systemd-cgtop`
