### Step P9-007: Budget Tracking + Alert Levels (Real-Time Threshold Enforcement)

**Type:** Application
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P9): pending`

**Goal:** Build real-time budget tracking that checks each classified transaction against monthly category limits and triggers escalating alerts at 50% (info), 80% (warning Discord alert), and 100% (freeze non-critical work per AC-FIN-002) thresholds.
**Dependencies:** P9-006 (transaction classifier running with category assignment), P9-003 (BudgetRepository with `financial.budget_categories` table populated), P9-001 (financial schema validated), existing Redis DB5 BudgetEnforcer (cost tracking for tool usage already operational).
**Cost Impact:** $0/month (application logic only; Redis DB5 and PostgreSQL already provisioned)
**ADR References:** ADR-023 (Financial Data Integration — correction flows, budget-aware predictions), ADR-017 (Monitoring Stack — Prometheus metrics for budget gauge), ADR-030 (Redis DB5 for cost enforcement bridge)
**Acceptance Criteria:** AC-FIN-001 (Real-time budget tracking with category limits), AC-FIN-002 (Autonomous freeze of non-critical work at 100% budget), AC-FIN-004 (Safety-critical operations exempt from freeze)
**Estimated Time:** 3 hours

#### Context

With transactions parsed (P9-005) and classified (P9-006), the system needs to enforce the $30/month hard cap and per-category sub-allocations. This step bridges the new PostgreSQL financial schema with the existing Redis DB5 cost infrastructure. When a classified transaction arrives, the budget tracker checks `financial.budget_categories` for the matching category limit, computes spent-to-date for the current month, and determines alert level: 50% = info log only, 80% = Discord alert to Faiz via existing notification pipeline, 100% = freeze signal sent to the agent loop that blocks all non-critical LLM calls (safety-critical operations like distress detection, HARD STOP processing, and emergency surveillance remain exempt per AC-FIN-004). Budget state is dual-written to Redis (for real-time checks by the agent loop) and PostgreSQL (for persistence and reporting). Monthly reset runs on the 1st via systemd timer, zeroing all category totals and resetting freeze flags.

#### Troubleshooting

- **Issue:** Budget tracker shows stale totals (Redis and PG disagree).
  - **Solution:** Eventual consistency with 30-second sync window is by design. If discrepancy persists beyond 60 seconds, check Redis connection health: `redis-cli -p 6380 --user guinevere_core PING`. Force resync: restart budget tracker daemon.
- **Issue:** Freeze flag stuck at `frozen` after monthly reset.
  - **Solution:** Monthly reset job must clear `budget:freeze_status` in both Redis and PostgreSQL. Check systemd timer logs: `journalctl -u guinevere-budget-reset --since "2026-06-01"`. Manually trigger reset: `uv run python -m src.financial.budget_reset`.
- **Issue:** Discord alert not firing at 80%.
  - **Solution:** Verify Discord bot token valid and channel ID correct. Check `src/financial/budget_tracker.py` notification channel config. Alerts use the existing Discord notification pipeline from the bot infrastructure — ensure bot is online: `systemctl status guinevere-discord`.
- **Issue:** Safety-critical operations blocked by freeze.
  - **Solution:** Distress detection, HARD STOP, and emergency surveillance are hardcoded exemption list in `BudgetTracker.SAFETY_EXEMPT_CATEGORIES`. If a legitimate safety operation is blocked, add its category to this list and redeploy.

#### Notes

- The $30/month global cap is enforced by summing all category spends and comparing to the global limit. Category budgets are sub-allocations within the $30 cap, not independent pools.
- Budget state is dual-written: Redis DB5 for sub-millisecond reads by the agent loop (prevents LLM calls before they happen), PostgreSQL for persistence, reporting, and Grafana dashboards. Redis is the source of truth for freeze decisions; PostgreSQL is the source of truth for history.
- Freeze logic only blocks non-critical LLM calls. Safety-critical operations (distress detection, HARD STOP processing, emergency surveillance, consent verification) are exempt per AC-FIN-004. The agent loop checks `budget:freeze_status` in Redis before every LLM call.
- Monthly reset runs at `00:00:00` on the 1st via systemd timer. The `Persistent=true` flag ensures the timer fires even if the system was down at midnight on the 1st (runs immediately on next boot).
- Prometheus gauge `guinevere_budget_category_spent_ratio` enables Grafana dashboard showing per-category progress bars. Alert rules in Prometheus can also trigger independently of the application-level Discord alerts.
- This step consolidates the existing Redis BudgetEnforcer (which tracks tool costs in isolation) with the new PostgreSQL financial schema. The Redis-PG sync bridge is completed in P9-012; this step only writes to both stores without a reconciliation layer.
