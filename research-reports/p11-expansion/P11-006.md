#### Context

**CRITICAL GAP:** Guinevere currently has NO conversational agent loop. The Discord bot (`src/discord/bot.py`) only processes slash commands (`/status`, `/loop-start`, `/surveillance-status`) via discord.py's command framework. The `/loop-start` command runs a 7-phase SDLC agent loop (`src/loops/`) which is a task execution pipeline, NOT an LLM-powered conversation system. There is no component that takes a natural language message from a user and generates a natural language response using the LLM. For P11, we MUST build a `ConversationalAgent` that bridges this gap.

The `ConversationalAgent` receives a `UnifiedMessage` (from any `ChannelAdapter`) and orchestrates the following pipeline: (1) check HARD STOP flag via `HardStopHandler` — if triggered, return emergency response and do NOT call LLM, (2) classify intent — is this a natural language message or a `!` command? (3) for commands, delegate to `CommandHandler` (P11-008), (4) for natural language, load conversation context from `ContextManager` (P11-007 — last 10 messages sliding window), (5) recall relevant long-term memories via `recall_memories()` from the P3 memory pipeline, (6) assemble the LLM prompt with system prompt (Y4 persona from `src/persona/`), conversation history, relevant memories, and the current message, (7) call `LLMRouter` with the assembled prompt, (8) post-process the response (persona drift check, cost logging), (9) return the response string.

The persona integration is the most nuanced part. Guinevere's persona is defined by multiple interacting engines: `YandereFSM` (`src/persona/yandere_fsm.py`) manages the Y-level state machine (Y4 baseline, Y5 ceiling — never Y6), `MoodEngine` (`src/persona/mood_engine.py`) tracks emotional state, `DriftDetector` (`src/persona/drift_detector.py`) and `DriftCorrector` (`src/persona/drift_corrector.py`) ensure the LLM output stays in character. The `ConversationalAgent` must integrate all of these — the system prompt must include the current mood state, the Y-level constraints, and the response must pass through drift detection before being returned.

This same `ConversationalAgent` will serve all channels: WhatsApp (P11 via `WhatsAppAdapter`), Discord (future refactor to use `ChannelAdapter`), Gmail (P12), X (P13), Wearable (P14). It is deliberately channel-agnostic — it receives `UnifiedMessage` and returns a string. The `ChannelAdapter` handles channel-specific formatting (typing indicators, message splitting, read receipts). Cost tracking is integrated via `src/core/services/cost_tracker.py` — each LLM call logs token usage and estimated cost per ADR-017.

#### Troubleshooting
- **Issue:** `LLMRouter` raises connection error to 9Router proxy
  - **Solution:** Verify 9Router proxy is running and accessible from VPS. Check `NINEROUTER_API_KEY` environment variable. Test with a direct curl to the proxy endpoint.
- **Issue:** LLM response does not match Y4 persona — too neutral, too aggressive, or breaks character
  - **Solution:** Verify system prompt includes persona constraints from `PromptLoader`. Check that `YandereFSM` state is correctly injected. Run `DriftDetector` on the response and verify correction is applied. If persistent, review system prompt template in `docs/60-persona/61-SystemPromptMaster_v1.1.md`.
- **Issue:** `recall_memories()` returns empty list — no relevant memories found
  - **Solution:** This is expected for new users or early conversations. The ConversationalAgent should handle empty memories gracefully — include a note in the prompt like "No prior memories available" rather than omitting the memories section.
- **Issue:** Response latency exceeds 3 seconds
  - **Solution:** Profile each pipeline step. Most likely bottleneck is the LLM call itself. Consider: (a) shorter context window (reduce from 10 to 5 messages), (b) fewer recalled memories (reduce top_k), (c) use faster model via LLMRouter for simple responses. Log per-step latency for Grafana monitoring.
- **Issue:** `ConversationalAgent` crashes on edge case input (empty message, unicode-only, very long text)
  - **Solution:** Add input validation at the start of `process()`: reject empty messages, cap input at 4000 characters, normalize unicode. Log rejected inputs at metadata level.
- **Issue:** Persona drift correction modifies response too aggressively, losing LLM's intended meaning
  - **Solution:** Tune `DriftCorrector` sensitivity. If correction changes >30% of the response text, flag for review instead of auto-correcting. Log before/after pairs for audit.

#### Notes
- This is the MOST IMPORTANT new component in P11. Without `ConversationalAgent`, Guinevere cannot have natural language conversations on ANY channel. The Discord bot currently only does slash commands — this component is what makes Guinevere a conversational companion rather than a command-line tool.
- The `ConversationalAgent` is deliberately stateless — it does NOT store conversation history itself. That responsibility belongs to `ContextManager` (P11-007). The agent receives context, generates a response, and returns it. State management is delegated.
- The HARD STOP check MUST be the first step in the pipeline. If HARD STOP is active, the agent must NEVER call the LLM. This is a safety requirement per ADR-002 and `PersonaSafetyPolicy`.
- Y4 is the permanent baseline persona level. Y5 is the absolute ceiling (only triggered by `MoodEngine` under specific conditions). Y6 (yandere) is permanently forbidden per AGENTS.md BLOCKING rules.
- Cost tracking is per ADR-017 and AC-FIN-001. Each LLM call must log: model used, prompt tokens, response tokens, estimated cost, conversation ID, channel type. The `CostTracker` (`src/core/services/cost_tracker.py`) handles Redis-based cost aggregation.
- Cross-reference P11-007 for `ContextManager` (sliding window). Cross-reference P11-008 for the routing pipeline that connects `ChannelAdapter` → `ConversationalAgent` → response delivery.
- The intent classifier is intentionally simple (prefix-based for commands). Future versions may use the LLM itself for intent classification, but for MVP, `!` prefix detection is sufficient and deterministic.
- Do NOT implement the Discord adapter refactor in this step. The `ConversationalAgent` works with `UnifiedMessage` only — it does not know or care about Discord or WhatsApp specifics.
