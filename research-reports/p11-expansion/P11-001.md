#### Context

ADR-022 currently mandates "WhatsApp via Baileys (WhatsApp Web MD protocol)" with a Node.js subprocess architecture. Research completed on 2026-06-03 (see `research-reports/whatsapp-integration-research-2026-06-03.md`) evaluated 7 solutions and concluded that Neonize (v0.3.18, 399★, MIT license) is the optimal choice for Guinevere: pure Python via `pip install neonize`, zero additional runtimes (no Node.js, no Docker sidecar), pre-built 6MB wheels with Go whatsmeow (6.2K★, production-proven in mautrix-whatsapp Matrix bridges) compiled in. This **replaces** the ADR-022 Baileys decision entirely. ADR-022 must be formally revised — this step documents the revision requirement but does not perform the ADR edit (that is a parent-only governance task).

The existing codebase at `src/` has 9 modules (`core/`, `discord/`, `financial/`, `loops/`, `mcp/`, `memory/`, `observability/`, `persona/`, `surveillance/`) but zero channel abstraction layer. The `pyproject.toml` uses hatchling build system, Python `>=3.12`, and `uv` for dependency management. Neonize requires Python `>=3.10` and provides pre-built wheels, so no Go compiler (Go 1.19+) is needed on the VPS — just a standard `uv pip install neonize`.

After this step, the project will have: (1) Neonize installed and importable in the existing virtual environment, (2) empty `src/channels/` directory tree ready for the ChannelAdapter abstraction (P11-004+), and (3) empty `src/agent/` directory tree ready for the ConversationalAgent (P11-006+). These directories are scaffolds only — no implementation code is written in this step.

#### Troubleshooting
- **Issue:** `uv add neonize` fails with "No matching distribution found for neonize"
  - **Solution:** Verify platform is `linux_x86_64` (VPS). Neonize provides pre-built wheels for Linux x86_64 and macOS. If running on ARM, Go 1.19+ compiler is required: `apt install golang-go`. Check available wheels: `pip index versions neonize`
- **Issue:** `ImportError: libneonize.so: cannot open shared object file` or cgo linking error
  - **Solution:** Install missing system libraries. Neonize cgo bindings may require `libc6` and `libstdc++6` (standard on Ubuntu). Run: `apt install libc6 libstdc++6`. Verify with `ldd $(python -c "import neonize; import os; print(os.path.dirname(neonize.__file__))")/libneonize.so`
- **Issue:** `NewClient()` instantiation panics with Go runtime error or segfault
  - **Solution:** This indicates an incompatible Neonize version or corrupted wheel. Pin exact version: `uv add neonize==0.3.18`. If persists, check VPS architecture: `uname -m` must be `x86_64`
- **Issue:** Existing dependencies break after adding Neonize (version conflict)
  - **Solution:** Run `uv lock --upgrade-package neonize` to resolve. If conflict is in a shared transitive dependency, check `uv pip tree | grep neonize` for the conflict path
- **Issue:** `ruff check` reports errors on empty `.py` files
  - **Solution:** Empty files should pass ruff. If not, add `# noqa` or check ruff configuration in `pyproject.toml` for rules requiring module docstrings

#### Notes
- **ADR-022 Revision Required:** ADR-022 currently states "WhatsApp via Baileys (WhatsApp Web MD protocol)" with Node.js subprocess architecture. This must be revised to "WhatsApp via Neonize (pure Python, whatsmeow Go via cgo)" with direct Python integration. The revision should: (1) replace "Baileys" with "Neonize" throughout, (2) replace "Node.js subprocess" with "Python-native Neonize client", (3) replace "HTTP bridge" with "direct Python integration", (4) add version pinning `neonize>=0.3.18,<0.4.0`, (5) add whatsmeow protocol break handling strategy, (6) update risk assessment for Neonize's smaller community (399★ vs Baileys' ~5K). ADR revision is a **parent-only governance task** — do not edit ADR files in this step.
- **Ban Risk Awareness:** Neonize uses the same unofficial WhatsApp Multi-Device protocol as Baileys. All ban risk mitigation strategies from `research-reports/whatsapp-unofficial-api-production-risks.md` apply: reactive-only messaging (<2% annual ban rate), rate limiting (8/min, 30/hour, 200/day), datacenter IP awareness (check VPS ASN against known-blocked providers), Gaussian jitter on response timing. These are implemented in P11-005 (rate limiter) and P11-003 (connection handler).
- **No Go Compiler Needed:** Neonize ships pre-built wheels (~6MB) with Go whatsmeow compiled in. The VPS does not need Go 1.19+ installed. Only building from source requires Go.
- **Cross-Reference P11-002:** This step only installs Neonize and creates scaffolds. Session authentication (QR scan, pairing, SOPS encryption) is implemented in P11-002.
- **Cross-Reference P11-003:** The NeonizeClient wrapper with event handlers is implemented in P11-003, which builds on the `src/channels/whatsapp/neonize_client.py` scaffold created here.
- **Python Version:** `pyproject.toml` requires `>=3.12`. Neonize requires `>=3.10`. No conflict.
- **Shared VPS Constraint:** Neonize runs in the same Python process as the existing FastAPI server and Discord bot. Memory footprint is ~50-100MB (WebSocket-native, no browser). This is acceptable on the shared VPS.
