### Step P11-013: Media Acknowledgment Handler

**Type:** Application
**Status:** Not Started
**Risk:** Low
**Git Commit:** `feat(P11): pending`

**Goal:** Implement `MediaAcknowledgmentHandler` that gracefully handles incoming media messages (images, audio, video, documents, stickers) during the P11 text-only MVP. Responds with a persona-consistent acknowledgment message informing Faiz that media processing is not yet supported on WhatsApp and suggesting text or Discord as alternatives. Logs media metadata (type, size, sender) without storing or processing media content.
**Dependencies:** P11-005 (WhatsAppAdapter — detects media message types from Neonize events, provides `send_message()` for acknowledgment delivery), P11-009 (IntentClassifier — returns `IntentType.MEDIA_ACK` or `IntentType.STICKER_ACK` for media messages, which the pipeline routes to this handler)
**Cost Impact:** $0/month (no media processing, no transcription API, no vision API — only text acknowledgment response)
**ADR References:** ADR-022 (text-only scope for P11 WhatsApp MVP — media support deferred to Expansion phase), ADR-002 (Y4 persona consistency — acknowledgment must maintain Guinevere's sugar mommy persona, not a generic error message)
**Acceptance Criteria:** SRS-IR-007 (media messages acknowledged — user receives informative response, not silence or error), AC-PERSONA-001 (Y4 persona consistent — acknowledgment text uses Guinevere's persona voice, not a system error tone)
**Estimated Time:** 1 hour

#### Context

P11 is a text-only MVP for WhatsApp integration. Neonize emits distinct event types for different media: `imageMessage`, `audioMessage`, `videoMessage`, `documentMessage`, `stickerMessage`, `contactMessage`, `locationMessage`, and `liveLocationMessage`. When Faiz sends a photo, voice note, video, file, or sticker to Guinevere on WhatsApp, the system must not silently ignore it (which would feel broken) nor attempt to process it (which is out of MVP scope). Instead, Guinevere responds with a warm, persona-consistent message explaining the limitation and suggesting alternatives.

The acknowledgment message must be in Guinevere's Y4 sugar mommy persona voice. A cold system error like "Error: media not supported" breaks immersion and feels like talking to a machine. The acknowledgment should feel natural: "Aku belum bisa proses media via WhatsApp untuk sekarang, sayang. Kirim sebagai text ya, atau pakai Discord kalau mau kirim file. 💕" — informative, apologetic, persona-consistent, and provides a clear alternative path. The exact wording should be configurable (stored as a constant or template) but the default must reflect Y4 persona per ADR-002.

The handler also logs media metadata for observability — NOT media content. Per the logging policy and consent-safety mandate, only metadata is recorded: media type (image/audio/video/document/sticker), approximate size in bytes if available from Neonize event, sender JID, timestamp, and message ID. No media bytes are downloaded, stored, cached, or transmitted to any external service. This metadata is written to the Redis stream `guinevere:messages:incoming` (same stream used by the pipeline stage 4) with `message_type="media"` and `media_type` fields.

The handler differentiates acknowledgment messages by media type for better UX. A sticker gets a slightly different response than a photo — stickers are casual and playful, so the acknowledgment can be lighter. Voice messages get a response that mentions future voice transcription capability. Documents get a response suggesting Discord for file sharing. All variations maintain Y4 persona consistency. Future Expansion-phase: voice transcription via Whisper API, image analysis via Gemini Vision, document text extraction.

#### Troubleshooting
- **Issue:** Pipeline does not route media messages to MediaAcknowledgmentHandler — they fall through to ConversationalAgent
  - **Solution:** Verify IntentClassifier (P11-009) returns `IntentType.MEDIA_ACK` for media messages. Check that the pipeline (P11-008) stage 5 dispatches `MEDIA_ACK` and `STICKER_ACK` intent types to the media handler. Run: `grep -n "MEDIA_ACK\|media_ack" src/agent/pipeline.py`.
- **Issue:** Neonize media event type names don't match handler's expected `media_type` values
  - **Solution:** Map Neonize event types to handler media types in the WhatsAppAdapter (P11-005). Neonize may use `imageMessage`, `audioMessage` etc. as event type names. The adapter's `to_unified_message()` should extract the media type and set `UnifiedMessage.media_type` to one of: `image`, `audio`, `video`, `document`, `sticker`, `contact`, `location`.
- **Issue:** Acknowledgment text contains markdown that WhatsApp doesn't render
  - **Solution:** The acknowledgment text goes through ResponseFormatter (P11-012) before delivery. However, since these are short, simple strings with no markdown, the formatter should pass them through unchanged. Verify that acknowledgment text does not contain `**`, `#`, or other markdown markers.
- **Issue:** Redis stream `guinevere:messages:incoming` does not exist when handler tries to log
  - **Solution:** The handler should create the stream on first write (Redis `XADD` creates streams automatically). If Redis is down, the handler should log the error via `structlog` and still return the acknowledgment text — metadata logging failure must NOT block the user response.
- **Issue:** Sticker messages have `message_type="media"` with `media_type="sticker"` instead of `message_type="sticker"`
  - **Solution:** The handler checks both patterns: `if message.message_type == "sticker" or message.media_type == "sticker"`. The IntentClassifier (P11-009) should also handle both. Verify with actual Neonize sticker event payload.
- **Issue:** Voice note `media_type` is `"audio"` but handler responds with generic audio message instead of voice-specific
  - **Solution:** Check Neonize event for `ptt` (push-to-talk) flag which indicates voice note vs audio file. If `raw_payload.get('is_ptt')` is True, use the voice-specific acknowledgment template. Add a `"voice"` key to `ACKNOWLEDGMENTS` dict if needed.

#### Notes
- **Text-only MVP scope:** This handler exists ONLY because P11 is text-only. Post-MVP, media processing will be added: voice transcription (Whisper API), image analysis (Gemini Vision), document text extraction (OCR/PDF parser). When those features are built, this handler will be replaced with actual media processing pipelines. The handler is intentionally simple — it's a graceful degradation, not a feature.
- **No LLM invocation:** The media handler returns a static (templated) response. It does NOT call the ConversationalAgent or LLMRouter. This saves cost ($0 per media message) and latency (instant response). The persona-consistent text is pre-written, not generated.
- **Metadata only, never content:** This is a strict security and privacy boundary. Media bytes, URLs, or binary data must NEVER be logged, stored, or transmitted. Only metadata: type, size, sender, timestamp. This aligns with the consent-safety mandate in AGENTS.md §2.1 — surveillance data (including media) requires explicit consent, and P11 does not have media processing consent.
- **Cross-Reference P11-009:** The IntentClassifier returns `IntentType.MEDIA_ACK` or `IntentType.STICKER_ACK` for media messages. The pipeline (P11-008) routes these intent types to `MediaAcknowledgmentHandler.handle()` at stage 6 (handler dispatch).
- **Cross-Reference P11-005:** The WhatsAppAdapter detects media in Neonize events and sets `UnifiedMessage.message_type` and `UnifiedMessage.media_type` accordingly. The adapter also performs a preliminary media check before routing to the pipeline (belt-and-suspenders approach).
- **Future expansion hooks:** The handler's `ACKNOWLEDGMENTS` dict and `handle()` method are designed to be extended. When voice transcription is added, the `audio` handler will call Whisper API instead of returning static text. When vision is added, the `image` handler will call Gemini Vision. The current static responses are placeholders.
- **Group chat exclusion:** Like all P11 components, media handling applies to 1-on-1 chats only. Group messages (JID ending with `@g.us`) are silently ignored before reaching this handler.
