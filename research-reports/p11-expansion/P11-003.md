### Step P11-003: Neonize Connection Handler — Send/Receive, Events

**Type:** Application
**Status:** Not Started
**Risk:** Medium
**Git Commit:** `feat(P11): pending`

**Goal:** Build the core `NeonizeClient` wrapper in `src/channels/whatsapp/neonize_client.py` that manages the WhatsApp connection lifecycle: connect with authenticated session, register async event handlers for incoming messages (`MessageEv`), connection state changes (`ConnectedEv`, `DisconnectedEv`), and pairing status (`PairStatusEv`). Emit structured internal events (not raw Neonize objects) for downstream processing. Implement metadata-only structured logging (timestamp, direction, sender JID hash — never message content per ADR-015/privacy policy). Handle connection drops with auto-reconnect (max 3 retries, exponential backoff: 30s, 60s, 120s) and Prometheus metrics export.
**Dependencies:** P11-002 (Session authentication working — `auth.py` provides `NewClient` with valid session at `SESSION_STORE_PATH`, `session_crypto.py` provides SOPS helpers, Redis metadata initialized).
**Cost Impact:** $0/month
**ADR References:** ADR-022 (WhatsApp connection management — per-channel contract defines connection lifecycle, failure behavior, and fallback chain), ADR-015 (Metadata-only logging — no message content in logs, no secrets in logs, JID hashed before logging)
**Acceptance Criteria:** SRS-IR-006 (WhatsApp connected and receiving events), SRS-IR-007 (Text-only handling — media messages acknowledged but not processed)
**Estimated Time:** 4 hours

#### Context

The `NeonizeClient` wrapper is the lowest abstraction layer in the WhatsApp integration stack — every P11 component above it (WhatsAppAdapter in P11-004, ConversationalAgent in P11-006, Discord mirror in P11-008) depends on the events this handler emits. It wraps the raw `neonize.NewClient` with Guinevere-specific concerns: structured logging via `structlog` (already a project dependency), Prometheus metrics via `prometheus-client` (already a project dependency), auto-reconnection with exponential backoff, and event normalization from Neonize's internal types to Guinevere's own `WhatsAppEvent` dataclasses.

Neonize's event model uses decorator-based registration: `@client.on(MessageEv)` for incoming messages, `@client.on(ConnectedEv)` for connection established, `@client.on(PairStatusEv)` for authentication status changes. The `NewClient.connect()` call is **blocking** — it enters the WhatsApp WebSocket event loop. For Guinevere's architecture (separate `guinevere-whatsapp.service` systemd unit), the connection handler must run as the main event loop in its own process, not inside the FastAPI async loop.

The privacy logging constraint is non-negotiable: per ADR-015 and the SurveillanceDataPolicy, **no message content** may appear in any log, metric label, or evidence artifact. Only metadata is logged: timestamp (ISO 8601), direction (`inbound`/`outbound`), sender JID SHA-256 hash (first 12 chars), message type (`text`/`media`/`command`), and byte length. The `structlog` processor chain must include a redaction processor that strips any field containing message body text before serialization.

Ban risk mitigation begins at this layer: the connection handler tracks message velocity counters (messages sent per minute/hour/day) and exposes them as Prometheus gauges. If velocity approaches WhatsApp's observed safe thresholds (8/min, 30/hour, 200/day — from `research-reports/whatsapp-unofficial-api-production-risks.md`), the handler emits a `RateLimitWarning` event that downstream rate limiter (P11-005) acts on. The handler itself does NOT enforce rate limits — that is the rate limiter's responsibility.

"""NeonizeClient wrapper — WhatsApp connection lifecycle management.

Wraps neonize.NewClient with Guinevere-specific concerns:
- Structured metadata-only logging (structlog with JID hashing)
- Prometheus metrics export (connection state, message counters)
- Auto-reconnection with exponential backoff (30s, 60s, 120s, max 3 retries)
- Event normalization from Neonize types to internal WhatsAppEvent dataclasses

This is the lowest layer in the WhatsApp stack. All downstream components
(WhatsAppAdapter, ConversationalAgent, Discord mirror) consume the
structured events emitted by this handler.

Privacy constraint (ADR-015): NO message content in logs, metrics, or evidence.
Only metadata: timestamp, direction, JID hash, message type, byte length.
"""

import hashlib
import time
from collections.abc import Callable
from dataclasses import dataclass, field
from enum import Enum
from typing import Optional

import structlog
from prometheus_client import Counter, Gauge, Histogram

from neonize import NewClient
from neonize.events import ConnectedEv, MessageEv, PairStatusEv

from src.channels.whatsapp.auth import SESSION_STORE_PATH


# --- Prometheus Metrics ---

WHATSAPP_CONNECTED = Gauge(
    "whatsapp_connected",
    "WhatsApp connection state (1=connected, 0=disconnected)",
)
WHATSAPP_MESSAGES_RECEIVED = Counter(
    "whatsapp_messages_received_total",
    "Total WhatsApp messages received",
    ["direction"],
)
WHATSAPP_MESSAGES_SENT = Counter(
    "whatsapp_messages_sent_total",
    "Total WhatsApp messages sent",
    ["direction"],
)
WHATSAPP_RESPONSE_LATENCY = Histogram(
    "whatsapp_response_latency_seconds",
    "Time from message received to response sent",
    buckets=[0.5, 1.0, 1.5, 2.0, 3.0, 5.0, 10.0],
)
WHATSAPP_RECONNECT_ATTEMPTS = Counter(
    "whatsapp_reconnect_attempts_total",
    "Total reconnection attempts",
)
WHATSAPP_SESSION_AGE = Gauge(
    "whatsapp_session_age_seconds",
    "Age of current WhatsApp session since pairing",
)
WHATSAPP_RATE_LIMIT_HITS = Counter(
    "whatsapp_rate_limit_hits_total",
    "Total rate limit threshold warnings",
)


# --- Structured Logger ---

def _hash_jid(jid: str) -> str:
    """SHA-256 hash of JID, first 12 chars. Never log plaintext JID."""
    return hashlib.sha256(jid.encode()).hexdigest()[:12]


logger = structlog.get_logger("guinevere.whatsapp")


# --- Event Dataclasses ---

class EventType(str, Enum):
    """Internal WhatsApp event types emitted by NeonizeClient."""
    MESSAGE_RECEIVED = "message_received"
    MESSAGE_SENT = "message_sent"
    CONNECTED = "connected"
    DISCONNECTED = "disconnected"
    PAIR_SUCCESS = "pair_success"
    PAIR_FAILED = "pair_failed"
    RECONNECT_ATTEMPT = "reconnect_attempt"
    RECONNECT_EXHAUSTED = "reconnect_exhausted"
    RATE_LIMIT_WARNING = "rate_limit_warning"
    ERROR = "error"


class ConnectionState(str, Enum):
    """WhatsApp connection state machine."""
    DISCONNECTED = "disconnected"
    CONNECTING = "connecting"
    CONNECTED = "connected"
    RECONNECTING = "reconnecting"
    FAILED = "failed"


@dataclass
class WhatsAppEvent:
    """Normalized event emitted to downstream consumers.

    Never contains raw Neonize objects or message content.
    """
    event_type: EventType
    timestamp: float = field(default_factory=time.time)
    jid_hash: Optional[str] = None
    message_type: Optional[str] = None  # "text", "media", "command"
    byte_length: Optional[int] = None
    metadata: dict = field(default_factory=dict)


# --- Reconnection Config ---

@dataclass
class ReconnectConfig:
    """Auto-reconnection parameters."""
    max_retries: int = 3
    backoff_base_seconds: float = 30.0
    backoff_multiplier: float = 2.0  # 30s → 60s → 120s
    max_backoff_seconds: float = 120.0


# --- NeonizeClient Wrapper ---

class NeonizeClient:
    """Wrapper around neonize.NewClient with Guinevere lifecycle management.

    Responsibilities:
    - Initialize NewClient with session store path from auth module
    - Register Neonize event handlers and normalize to WhatsAppEvent
    - Track connection state and emit Prometheus metrics
    - Handle auto-reconnection with exponential backoff
    - Log metadata only (no message content, JID hashed)

    This class does NOT:
    - Authenticate (handled by auth.py in P11-002)
    - Rate limit (handled by rate_limiter.py in P11-005)
    - Process message content (handled by ConversationalAgent in P11-006+)
    - Mirror to Discord (handled by discord_bridge in P11-008+)
    """

    def __init__(
        self,
        store_path: str = str(SESSION_STORE_PATH),
        reconnect_config: ReconnectConfig | None = None,
    ) -> None:
        self._store_path = store_path
        self._reconnect_config = reconnect_config or ReconnectConfig()
        self._state = ConnectionState.DISCONNECTED
        self._reconnect_count = 0
        self._client: NewClient | None = None
        self._event_handlers: list[Callable[[WhatsAppEvent], None]] = []

    @property
    def state(self) -> ConnectionState:
        """Current connection state."""
        return self._state

    @property
    def is_connected(self) -> bool:
        """True if WhatsApp connection is active."""
        return self._state == ConnectionState.CONNECTED

    def register_handler(self, handler: Callable[[WhatsAppEvent], None]) -> None:
        """Register a downstream event handler for WhatsAppEvent."""
        self._event_handlers.append(handler)

    def _emit(self, event: WhatsAppEvent) -> None:
        """Dispatch event to all registered handlers."""
        for handler in self._event_handlers:
            try:
                handler(event)
            except Exception:
                logger.exception(
                    "whatsapp_event_handler_error",
                    handler=handler.__name__ if hasattr(handler, "__name__") else str(handler),
                )

    def _initialize_client(self) -> NewClient:
        """Create and configure Neonize NewClient instance."""
        client = NewClient(self._store_path)
        # Register Neonize event handlers
        # Note: exact decorator API depends on neonize v0.3.18 — verify during implementation
        return client

    async def connect(self) -> None:
        """Establish WhatsApp connection. Blocking — runs WebSocket event loop.

        On first run, triggers QR scan / pairing flow (handled by auth.py).
        On subsequent runs with valid session, auto-reconnects to WhatsApp servers.
        """
        self._state = ConnectionState.CONNECTING
        logger.info("whatsapp_connecting", store_path=self._store_path)

        self._client = self._initialize_client()
        # client.connect() enters the WhatsApp WebSocket event loop
        # Exact API: verify whether connect() is sync/async in neonize v0.3.18

    async def disconnect(self) -> None:
        """Gracefully disconnect from WhatsApp servers."""
        self._state = ConnectionState.DISCONNECTED
        WHATSAPP_CONNECTED.set(0)
        logger.info("whatsapp_disconnected", reason="graceful_shutdown")
        self._emit(WhatsAppEvent(event_type=EventType.DISCONNECTED))

    async def send_text(self, jid: str, text: str) -> None:
        """Send a text message. Logs metadata only.

        Args:
            jid: WhatsApp JID (e.g., "628123456789@s.whatsapp.net").
            text: Message text content (NOT logged).
        """
        jid_hash = _hash_jid(jid)
        byte_length = len(text.encode("utf-8"))

        logger.info(
            "whatsapp_message_sent",
            jid_hash=jid_hash,
            direction="outbound",
            message_type="text",
            byte_length=byte_length,
        )
        WHATSAPP_MESSAGES_SENT.labels(direction="outbound").inc()

    def _on_connected(self) -> None:
        """Internal handler for Neonize ConnectedEv."""
        self._state = ConnectionState.CONNECTED
        self._reconnect_count = 0
        WHATSAPP_CONNECTED.set(1)
        logger.info("whatsapp_connected")
        self._emit(WhatsAppEvent(event_type=EventType.CONNECTED))

    def _on_message(self, jid: str, is_text: bool, byte_length: int) -> None:
        """Internal handler for Neonize MessageEv — metadata extraction only."""
        jid_hash = _hash_jid(jid)
        message_type = "text" if is_text else "media"

        logger.info(
            "whatsapp_message_received",
            jid_hash=jid_hash,
            direction="inbound",
            message_type=message_type,
            byte_length=byte_length,
        )
        WHATSAPP_MESSAGES_RECEIVED.labels(direction="inbound").inc()

        self._emit(WhatsAppEvent(
            event_type=EventType.MESSAGE_RECEIVED,
            jid_hash=jid_hash,
            message_type=message_type,
            byte_length=byte_length,
        ))

    async def _reconnect(self) -> None:
        """Attempt reconnection with exponential backoff."""
        import asyncio

        config = self._reconnect_config
        if self._reconnect_count >= config.max_retries:
            self._state = ConnectionState.FAILED
            logger.error(
                "whatsapp_reconnect_exhausted",
                max_retries=config.max_retries,
            )
            WHATSAPP_CONNECTED.set(0)
            self._emit(WhatsAppEvent(event_type=EventType.RECONNECT_EXHAUSTED))
            return

        self._state = ConnectionState.RECONNECTING
        self._reconnect_count += 1
        WHATSAPP_RECONNECT_ATTEMPTS.inc()

        delay = min(
            config.backoff_base_seconds * (config.backoff_multiplier ** (self._reconnect_count - 1)),
            config.max_backoff_seconds,
        )
        logger.warning(
            "whatsapp_reconnect_attempt",
            attempt=self._reconnect_count,
            max_retries=config.max_retries,
            delay_seconds=delay,
        )
        self._emit(WhatsAppEvent(
            event_type=EventType.RECONNECT_ATTEMPT,
            metadata={"attempt": self._reconnect_count, "delay": delay},
        ))

        await asyncio.sleep(delay)
        await self.connect()

#### Troubleshooting
- **Issue:** `from neonize.events import DisconnectedEv` fails — disconnect event has a different name
  - **Solution:** Inspect available events: `uv run python -c "import neonize.events; print(dir(neonize.events))"`. Neonize may use a different event name for disconnection (e.g., `StreamErrorEv`, `LoggedOutEv`). Adapt the event handler registration accordingly. If no disconnect event exists, implement periodic health check (60s interval) that detects stale connections.
- **Issue:** `client.connect()` is synchronous and blocks the event loop, preventing async handlers from working
  - **Solution:** Run `client.connect()` in a separate thread via `asyncio.to_thread()` or `loop.run_in_executor()`. Neonize's cgo bindings may require running in the main thread — verify with `uv run python -c "import threading; from neonize import NewClient; t=threading.Thread(target=NewClient('test.db').connect); t.start()"`. If threading fails, use `multiprocessing` instead.
- **Issue:** Neonize event decorator syntax differs from expected `@client.on(MessageEv)` pattern
  - **Solution:** Check Neonize source for actual registration API: `uv run python -c "from neonize import NewClient; c=NewClient('/dev/null'); print([m for m in dir(c) if 'on' in m.lower() or 'event' in m.lower() or 'handler' in m.lower()])"`. Adapt decorator usage. Some versions use `client.add_event_handler(MessageEv, callback)` instead of decorators.
- **Issue:** `structlog` processor chain not configured — logs output as raw dict instead of formatted
  - **Solution:** Verify existing logging setup in `src/core/` or `src/core/logging.py`. If no shared structlog config exists, add a local processor chain: `structlog.configure(processors=[structlog.processors.add_log_level, structlog.processors.TimeStamper(fmt="iso"), structlog.dev.ConsoleRenderer()])`. Ensure this does not conflict with existing logging configuration.
- **Issue:** Prometheus metric registration conflicts with existing metrics (e.g., `whatsapp_connected` already registered)
  - **Solution:** Use `prometheus_client.REGISTRY.unregister()` before re-registering, or use unique metric names prefixed with `guinevere_`. Check for conflicts: `uv run python -c "from prometheus_client import REGISTRY; print([m.name for m in REGISTRY.collect()])"`.
- **Issue:** JID hash is inconsistent across runs (different hash for same JID)
  - **Solution:** Ensure `_hash_jid()` uses deterministic `hashlib.sha256(jid.encode()).hexdigest()[:12]`. Do NOT use Python's built-in `hash()` function which is randomized per-process (PYTHONHASHSEED). The current implementation uses SHA-256 which is deterministic.

#### Notes
- **Blocking connect():** Neonize's `NewClient.connect()` enters the WhatsApp WebSocket event loop and blocks. The `guinevere-whatsapp.service` systemd unit will run this as the main process. For async compatibility, the implementation must either: (a) run `connect()` in a dedicated thread, or (b) use `asyncio.to_thread()`. Verify which approach works with Neonize's cgo bindings during implementation.
- **Event Normalization Rationale:** Downstream components (WhatsAppAdapter, ConversationalAgent) must not import Neonize types directly. The `WhatsAppEvent` dataclass provides a stable internal API that survives Neonize version upgrades. If Neonize changes `MessageEv.Message.conversation` to `MessageEv.text`, only `NeonizeClient._on_message()` needs updating.
- **Text-Only MVP (SRS-IR-007):** The `_on_message()` handler classifies messages as `text` or `media` based on Neonize message type. Media messages are acknowledged with a "belum bisa proses media" response (implemented in P11-004+ WhatsAppAdapter), but the NeonizeClient itself only logs the metadata.
- **Rate Limit Awareness:** The `WHATSAPP_MESSAGES_SENT` counter is available for the rate limiter (P11-005) to query. The rate limiter checks `.labels(direction='outbound').get()` against thresholds (8/min, 30/hour, 200/day). This handler does NOT enforce limits — it only provides the counters.
- **Datacenter IP Risk:** The VPS connects to WhatsApp servers from a datacenter IP. This is an elevated ban risk factor (documented in `research-reports/whatsapp-unofficial-api-production-risks.md` §5.2). Mitigation is reactive-only messaging pattern (no proactive messages to unknown contacts) enforced at the ConversationalAgent layer, not this connection handler.
